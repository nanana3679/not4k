# not4k — 게임 설계 개요

> 4레인 노트낙하형 가변 손배치 PC 리듬게임

설계의 출발점과 만들려는 플레이 경험은 [설계 의도](rationale.md)를 참고한다.
이 문서는 게임이 **어떻게 작동하는지**를 설명한다.

---

## 핵심 메커니즘

### 4레인 + 레인당 다중키 바인딩

- 화면에는 항상 4개의 레인이 존재한다.
- 유저는 각 레인에 2개 이상의 키를 바인딩한다.
- 같은 레인의 노트는 바인딩된 키 중 아무 키로든 처리할 수 있다.
- 단, 노트 타입에 따라 특정 입력 방식이 요구될 수 있다(트릴 노트, 더블 노트).

### 가변 손배치

- 유저가 어떤 키를 어떤 손가락으로 누를지는 전적으로 유저의 선택이다.
- 차트의 복잡도에 따라 유저가 사용하는 키 수가 4개에서 8개 이상으로 확장될 수 있다.
- 레인 구조 자체는 변하지 않으므로, 키 수가 달라도 같은 난이도 체계를 공유한다.

패턴을 한 번 본 뒤 의도된 연주 방법을 파악하고, 다음 시도에서 더 수월하게 연주하는 경험을 핵심에 둔다([RFD 0045](../rfd/0045-target-players-and-pattern-solving.md)).

## 피스 표기법

리듬게임 차트를 텍스트로 표현하기 위한 규칙이다. 아래는 간략한 수평 표기법이며, 확장 수직 표기법은 `piece-notation.md`를 참고한다.

- 간격은 백틱 블록 앞에 정의한다.
- 각 레인에 숫자로 번호를 붙인다 (1～4).
- 동시 입력은 공백 없이 붙여 쓴다.
- 각 공백은 처음 정의된 만큼의 간격을 의미한다.

**예시**:

16bit```
2 2 2 2

```

→ 2번 레인에 4개의 노트를 16비트 간격으로 배치.

16bit```
12 23 12 23
```

→ 1+2 동시치기, 2+3 동시치기가 16비트 간격으로 교대. 2번 레인은 매 비트마다 등장하므로, 고정배치에서는 연타가 되지만 가변 손배치에서는 트릴로 처리 가능.

## 노트 타입과 피스 요약

자세한 스펙은 `note-system.md`를 참고한다.

### 노트 타입

개별 요소. **모든 노트 타입은 Lv.1부터 등장할 수 있다.**

| 노트 타입     | 설명                                                                                                                | 요구하는 바인딩 키 수 |
| ------------- | ------------------------------------------------------------------------------------------------------------------- | --------------------- |
| **싱글 노트** | 레인에 바인딩된 키 중 아무 키 하나를 누른다                                                                         | 1개 이상              |
| **롱 노트**   | 키를 누르고 있다가 끝 지점에서 뗀다. 시작점·바디·끝점 구조. 시작점에 헤드 노트를 배치하면 최대 2회 판정. 홀드 교대로 다른 키에 홀드를 이어받을 수 있다 | 1개 이상              |
| **트릴 노트** | `trillZone` 안에서, 직전 노트와 다른 키를 눌러야 한다                                                                 | 2개 이상              |
| **더블 노트** | 같은 레인의 서로 다른 키 2개를 동시에 누른다. 더블클릭 불가                                                         | 2개 이상              |

### 피스

복수의 노트가 배치를 통해 상호작용하여 난이도를 발생시키는 단위. 각 피스는 고유한 **PLv.(피스 레벨)**를 가진다. 정식 정의는 `piece-definition.md`의 PP-000 체계에서 관리한다.

요구 입력과 동작 계획이 같고 표현만 다르면 같은 피스로 묶는다. 자료 구조나 제작 제약에 따른 모양의 차이만으로 별도 피스를 나누지 않는다([glossary](glossary.md#피스-piece)).

| 피스                 | 설명                                                               | PLv.   |
| -------------------- | ------------------------------------------------------------------ | ------ |
| **짧은 트릴**        | 짧은 구간에서 트릴 키 교대를 익히는 배치                            | PLv.1  |
| **롱노트 끝 탭**     | 롱노트 끝에서 다른 키로 탭하는 배치. 트릴 연결은 선택적                       | PLv.4  |
| **싱글→더블 전환**   | 싱글 홀드에 키를 추가하여 더블 홀드로 전환 (o-D=)                  | PLv.4  |
| **앵커**        | 한 손을 트릴에 전담시키고 반대 손이 나머지 레인 처리               | PLv.7  |
| **롱노트 중 탭**     | 롱노트 유지 중 같은 레인에 탭 노트가 나오는 배치                   | PLv.7  |
| **비트 복합 트릴**   | 하나의 `trillZone`에 서로 다른 비트 분할이 복합 등장                 | PLv.10 |
| **수평 이동**         | 2/2 분할 경계를 넘어 파지로 부담 분산                              | PLv.11 |
| **가변 분할**        | 2/2 이외의 레인 분할(1/3, 3/1). 해당 손배치 유지도 포함하며 수평 이동은 선택적 | PLv.11 |


> **노트 타입 vs 피스**: 노트 타입은 개별 요소이며 Lv.1부터 사용할 수 있다. 피스는 노트들의 배치가 상호작용하여 난이도를 만드는 것이다. 예: 롱노트와 싱글노트는 각각 Lv.1부터 사용할 수 있지만, 롱노트 끝에서 같은 레인의 다른 키로 탭하는 롱노트 끝 탭 피스는 PLv.4부터 본격 활용된다. 사용 중인 피스와 통합 ID 이력은 정식 피스 카탈로그인 `piece-definition.md`에서 확인한다.

## 난이도 철학: 단순한 입력 요구와 실시간 동작 계획

**not4k는 입력 요구를 단순하고 명확하게 제시하고, 그 요구를 어떤 손·손가락·키의 조합과 순서로 수행할지 플레이 중 판단하는 것을 핵심 난이도로 삼는다.**

인지 부하에는 요구사항을 파악하는 **독해 부담**과, 파악한 요구사항을 행동으로 옮기기 위해 판단하는 **동작 계획 부담**이 있다. not4k가 지향하는 것은 후자다. 노트 종류·시점·유지 조건은 명확히 읽혀야 하며, 가림이나 모호한 표현으로 독해 부담을 높이는 것을 핵심 도전으로 삼지 않는다. 용어의 풀 정의는 [glossary](glossary.md#인지-부하-cognitive-load), 결정 근거는 [RFD 0101](../rfd/0101-cognitive-load-and-action-planning.md)을 따른다.

가변 손배치에서는 현재 유지 중인 키와 뒤따르는 노트를 고려해, 양손이 각각 어떤 레인을 맡고 어느 키를 사용할지 계속 판단해야 한다. 개별 요구를 알아본 뒤에도 손배치를 선택하고 전환하는 어려움은 남는다. 이 동작 계획은 입력 속도·손가락 독립·손 이동·지구력 등에 따른 물리 부하 및 타이밍 정밀도와 구별되는 핵심 도전이다. 물리 부하에는 동작 자체를 수행하는 어려움과 누적 피로가 모두 포함된다([glossary](glossary.md#물리-부하-physical-load)).

시각적으로 제시하는 요구는 노트 종류·속성·동시 조건의 조합까지 단순하게 유지한다. 단순한 요구의 배치와 연결에서 손배치 판단의 깊이를 만든다. 동작 계획의 학습 목표는 **한 번 눈에 익힌 뒤 다시 하면 대응할 수 있는 정도**다. 초견에서 놓치는 전환이 있어도 다음 시도에는 흐름을 알고 손배치를 시도할 수 있어야 한다. 실제 속도·정확도를 맞추는 데는 반복 연습이 필요할 수 있으며, 긴 손순서의 과도한 암기는 요구하지 않는다. 차트 Lv.의 평가에는 처음 읽는 독해 부담도 포함한다([glossary](glossary.md#차트-레벨-lv)).

이 철학은 게임 설계 전반에 반영된다:

- **트릴 노트**: "직전과 다른 키를 눌러야 한다"는 요구를 시각적으로 명시한다. 어떤 키 조합으로 교대하고 다른 레인과 손을 나눌지는 플레이어가 판단한다.
- **더블 노트**: "두 키를 동시에 눌러야 한다"는 요구를 명시한다. 어떤 손가락 조합을 쓰고 다음 노트를 위해 손배치를 어떻게 준비할지는 플레이어가 판단한다.
- **Grace 노트**: 학습·부담 조절·연출을 위해 선택적으로 사용한다. 손배치가 단순해도 해당 난이도에 비해 리듬이 복잡하거나 입력 속도가 빠르면 활용할 수 있다. 복잡한 손배치와 정밀한 타이밍을 함께 요구하는 패턴도 해당 레벨에 맞으면 허용한다([glossary](glossary.md#grace-노트-grace-note)).

> **핵심 원칙**: 요구는 단순하고 명확하게, 수행 방법은 플레이어가 판단하게 한다. 한 번 눈에 익힌 뒤에는 다시 보고 대응할 수 있는 난이도를 지향한다.

## 난이도 설계 요약

자세한 설계는 `../spec/difficulty-design.md`를 참고한다.

**모든 노트 타입은 가장 쉬운 레벨(Lv.1)부터 사용할 수 있다.** 각 차트에 모든 타입을 넣을 필요는 없으며, 차트의 의도에 맞춰 선택한다. 난이도는 타입의 해금보다 사용한 노트와 입력방식의 빈도·밀도·복합도로 조절한다([glossary](glossary.md#노트-타입)).

### 난이도 체계

- **Lv. (차트 레벨)**: 클리어와 특정 랭크 달성의 어려움을 기준으로 평가하는 차트 난이도 수치. 초견 독해·동작 계획·물리 부하와 비행 규칙·배치 위치를 함께 고려하며, 구체적 기준은 미정이다([glossary](glossary.md#차트-레벨-lv)).
- **PLv. (피스 레벨)**: 개별 피스의 본격 활용 기준 레벨. 충분히 느리고 단순한 짧은 체험은 더 낮은 레벨에서도 허용한다.
- **난이도 등급**: 레벨 구간을 묶은 분류(입문/초급/중급/상급/최상급).

### 등급별 핵심 경험

| 등급       | 레벨 구간 | 유저 키 바인딩             | 핵심 경험                                                                   |
| ---------- | --------- | -------------------------- | --------------------------------------------------------------------------- |
| **입문**   | Lv.1～3    | 4키 중심, 보조키 짧게 체험 | 싱글 중심 + 실제 부담이 낮은 트릴·더블의 짧은 체험. 외측 레인도 허용 |
| **초급**   | Lv.4～6    | 엄지 비중 상승 (6키)       | `trillZone`이 명확해지고, 더블이 흐름에 삽입                                  |
| **중급**   | Lv.7～10   | 8키 입문 (약지 추가)       | 앵커 본격화, 롱노트 중 탭 등장                                              |
| **상급**   | Lv.11～13  | 8키 활성화                 | 수평 이동·가변 분할 등장. 모든 피스가 복합 결합                              |
| **최상급** | Lv.14～15  | 16키 완전 활용             | 새 피스 없이 빠른 손배치 전환과 복합 입력 수행 |

> **용어 규칙**: 차트 단위는 **Lv.**, 피스 단위는 **PLv.**, 구간 분류는 **난이도 등급**으로 통일한다.
