# not4k — 튜토리얼 설계

이 문서는 노트 연주법과 판정 방식을 단계적으로 소개하는 튜토리얼의 설계를 정의한다.

> **학습 범위**: 노트의 연주 방법과 판정 규칙을 다룬다. 키 추가·손배치 발견을 단계적으로 체험하는 튜토리얼 과정은 별도로도, 이 학습에 통합해서도 두지 않는다. 실습에 필요한 키가 부족하면 실제 설정을 먼저 수정하도록 안내한다([RFD 0104](../rfd/0104-no-keybinding-discovery-tutorial.md)).

---

## 세분화의 이유

not4k의 입력과 판정에는 직관적이지 않은 부분이 존재한다.

- 바디의 연결 유지 자체에는 점수가 없고, 명시된 탭·릴리즈·틱 노트만 점수를 만든다. 유지 실패는 무점수 Miss로 기록된다.
- 릴리즈 노트는 실제 떼는 타이밍을 판정한다. 릴리즈 없는 바디 끝에서는 떼지 않아도 되며, 틱 노트는 그 순간의 바디 상태로 판정한다.
- 트릴 노트에서 교대 실패 시 Good으로 고정된다.
- 싱글→더블 전환은 뒤 바디의 두 hold를 채워야 하며, 전환 자체가 릴리즈 점수를 만들지는 않는다.
- 더블→싱글 전환에서 떼기를 판정하려면 감소 지점에 릴리즈 노트를 명시한다.
- 더블 릴리즈 노트는 두 몫을 각각 정산한다.

이러한 규칙을 한 번에 제시하면 유저가 압도된다. **최초 튜토리얼에서는 플레이만 가능하도록 노트의 연주 방법만 소개하고, 후속 튜토리얼에서 복합 패턴을 소개하며 판정 방식을 알려줘야 한다.**

## 튜토리얼 구조

### 메트로놈에 맞춘 시연과 실습

시연과 직접 입력 실습 모두 메트로놈의 박자 소리에 맞춰 진행한다. 처음 재생을 시작할 때만 첫 입력 전에 메트로놈을 4박 들려주는 준비 구간을 둔다. 반복 예제의 구간 자체에 다음 입력을 준비할 여유를 포함한다. 별도의 4박 준비 구간은 첫 재생 앞에만 두며, 이후 패턴을 반복할 때는 다시 추가하지 않는다. 예제 차트의 박자와 메트로놈, 화면의 노트와 판정 시간을 맞춘다. 튜토리얼 전용 음악은 요구하지 않는다([RFD 0083](../rfd/0083-tutorial-metronome.md)). 곡 선택 팝업에 구현했다(2026-10-31).

첫 시작은 **모달 열기·레슨 변경·재진입·재시작으로 보이는 active 슬롯의 레슨을 처음부터 시작하는 매회**다. 보이지 않는 대기 슬롯에서는 준비를 소진하지 않는다. 반복·시연/직접 입력 전환·도식 OK·일시정지 재개에는 준비를 다시 추가하지 않는다. 4박은 시작 BPM으로 들려주며, 준비 중에는 입력을 채점하지 않는다. 표시 시각은 음수 준비 시각에도 시각 오프셋을 적용하므로, 양수 오프셋이면 소리의 루프 0ms보다 먼저 첫 노트 위치로 진행할 수 있다. 준비 중에는 첫 실제 반복(절대 차수 0)의 노트만 미리 표시한다. 음수·0·양수 시각 오프셋 모두에서 절대 차수가 음수인 이전 복사본은 존재하지 않으므로 숨기며, 준비가 끝나도 가짜 이전 반복을 표시하지 않는다. 네 번째 클릭 다음 박에 루프 0ms로 진입한다. 0박 도식이 있으면 준비 뒤 도식에서 멈추고 OK로 도식 끝 시각부터 이어간다.

- **소리와 시계:** Web Audio로 약 30ms의 짧은 클릭을 합성하고 마디 첫 박을 약하게 강조한다. 설정의 `masterVolume`을 즉시 적용하며 별도 음악은 재생하지 않는다. 각 박은 차트의 BPM 이벤트와 마디 정보를 사용한다.
- **동기화:** AudioContext가 running인 뒤 서로 다른 25ms 관측에서 유효한 `getOutputTimestamp()`를 2회 연속 얻으면 출력 대응을 확정한다. 약 200ms 안에 얻지 못하면 `baseLatency + outputLatency`를 사용한다. 첫 클릭을 AudioContext 현재 시각보다 25ms 뒤로 예약하고 그 원점에 차트의 박 시각을 더해 모든 클릭을 예약한다. 소리가 들리는 시각에서 루프의 performance 원점을 역산하며, timestamp와 보고 지연을 중복 적용하지 않는다. 이 재생 중에는 이후 출력 대응 변화로 시계나 클릭을 재보정하지 않는다. 재개로 원점을 옮길 때도 같은 출력 대응을 사용한다.
- **시간 기준:** 들리는 클릭의 루프 시각이 `J`다. 판정·세션·반복 경계는 `J`, 표시는 `V = J + settings.visualOffsetMs`, 직접 입력은 `J − handlerDelay + settings.inputOffsetMs`를 따른다([RFD 0031](../rfd/0031-audio-first-timing-model.md)). 시각 오프셋의 양수·음수와 준비 구간에도 같은 부호를 쓰고, 앞뒤 3벌 표시의 활성 복사본과 세션 차수 차이를 `V`에 맞춘다. 종료한 반복은 최종 snapshot을 해당 반복의 표시 복사본이 남아 있는 동안 보존하고 각 복사본에 그 반복의 상태를 적용한다. 도식 대기·`paused`·재개 대기 동안은 표시 반복 차수도 고정하고 그 기준으로 종료 이력을 정리한다. `connected-long-note-switch`에서 `visualOffsetMs=-1000`으로 한 반복을 마친 뒤 다음 도식을 8초 넘게 열어 두거나 일시정지해도, 재개 후 완료한 릴리즈가 판정 전 상태로 다시 나타나지 않는다. 시연의 경계 정산과 직접 입력의 마지막 판정 기한 뒤에도 성공한 노트가 다시 나타나지 않는다. 긴 프레임으로 건너뛴 반복에는 다른 반복의 결과를 붙이지 않는다. 무음 Lab은 기존 표시 시각을 유지한다.
- **정지와 수명:** active 슬롯만 소리를 낸다. `paused`·설정·도식 대기에서는 예약한 소리를 취소한다. 일시정지 해제와 도식 OK에서는 출력 지연 + 25ms 동안 시계·화면·판정을 함께 멈춰 예약할 시간을 확보한 뒤 같은 박자 위상에서 잇는다(출력 지연 80ms이면 105ms 대기). 480ms에 멈췄다면 대기 후 20ms 뒤의 500ms 박도 들려준다. 렌더·판정·도식과 재개 대기 검사는 해당 프레임의 rAF 시각으로 통일한다. 콜백 실행 중 `performance.now()`가 대기 끝을 지났더라도 rAF 시각이 끝보다 이르면 마지막 장면을 유지한다. 입력 이벤트의 준비·재개 대기는 그 이벤트의 timestamp로 별도 검사한다. 레슨 변경은 이전 예약을 해제한다. AudioContext는 모달마다 지연 생성해 두 슬롯이 공유하고 모달 닫기에 해제한다.
- **브라우저 자동 재생 제한:** 제스처 없는 자동 열기에서 AudioContext가 suspended이면 준비·화면은 무음으로 진행한다. 첫 pointer/key 상호작용에서 resume을 요청하고 출력 대응을 확정한 뒤 기존 루프에 소리를 합류시킨다. 준비 대기와 출력 지연 때문에 이미 예약할 수 없는 박은 건너뛰며, 레슨·4박 준비·루프 시계를 재시작하지 않는다.

튜토리얼 창을 열면 곡 선택 화면의 프리뷰 재생과 재생 전 대기를 즉시 중단한다(페이드아웃 꼬리도 남기지 않는다). 창을 닫으면 `autoPlay`가 true이거나 열기 직전에 프리뷰가 재생 중이었을 때만, 그때 선택된 곡을 기준으로 1초 기다린 뒤 프리뷰를 처음부터 다시 재생한다. 일반 곡 포커스 변경은 기존처럼 즉시 재생하며, 일반 1초 대기는 별도 후속 작업이다([RFD 0089](../rfd/0089-required-preview-audio-file.md)).

### 시연 후 직접 입력으로 통과

입력을 배우는 항목은 **시연 → 직접 입력 실습 → 항목별 요구 횟수만큼 누적 성공 시 통과**로 구성한다. 제시된 동작이나 짧은 패턴을 직접 연주하며, 시연을 본 것만으로 실습을 통과한 것으로 처리하지 않는다([glossary](../context/glossary.md#튜토리얼), [RFD 0081](../rfd/0081-tutorial-demonstration-and-three-practice-successes.md)). 실습 중 실패해도 성공 횟수를 줄이거나 초기화하지 않는다. 구체적인 실습 세부는 [PRD §12](../prd.md#12-미정-사항)에서 관리한다.

튜토리얼 완료·통과를 차트 선택의 선행 조건으로 두지 않는다. 실습을 통과하지 않아도 모달을 바로 닫고 곡과 차트를 선택할 수 있다. Phase 1～4는 학습 내용의 구성으로 유지한다.

처음 실습에 들어갈 때부터 `직접 입력 / 시연` 토글을 사용한다. 플레이어가 직접 입력을 선택하면 실습으로 넘어가며, 시연 종료만으로 자동 전환하지 않는다. 별도의 실습 시작 버튼은 두지 않는다.

`AutoEvent`는 튜토리얼 시연 전용이며 일반 차트의 연출 기능으로 사용하지 않는다. 새 토글과 기존 이벤트를 연결하는 구현 방식은 [PRD §12](../prd.md#12-미정-사항)에서 관리한다.

실습 전에는 현재 바인딩이 해당 실습에 필요한 키를 갖췄는지 확인한다. 현재 키 설정으로 실습할 수 없어도 시연은 이용할 수 있다. `직접 입력 / 시연` 토글의 직접 입력 옵션을 비활성화하고 키가 부족한 이유와 실제 키 설정을 수정하는 경로를 안내한다. 실제 설정이 요구를 충족하면 직접 입력 옵션을 활성화하지만 자동으로 실습에 전환하지 않으며, 플레이어가 직접 선택해야 한다. 별도 실습 시작 버튼이나 임시 키 자동 배정은 추가하지 않는다. 시연용 표시 키 보충은 실제 실습의 키 요건을 충족한 것으로 취급하지 않는다. 부족하면 먼저 키 설정을 수정하도록 안내하고, 실제 설정이 요구를 충족한 뒤 실습을 시작한다. 실습 중에만 쓸 임시 키를 자동 배정하지 않는다. 아래 현재 구현의 자동 시연 프리뷰가 표시용 키를 보충하는 동작과 구별한다([키 바인딩 스펙](keybinding.md#튜토리얼-실습-전-키-설정)).

요구 성공 횟수는 개발자가 실습항목별로 정하는 양의 정수이며 기본값은 3회다. 플레이어가 목표 횟수를 바꾸는 설정 UI는 두지 않는다. 실습을 시작하면 성공·실패마다 버튼을 다시 누르지 않고 같은 실습을 자동 반복한다. 실패해도 성공 횟수는 유지하며, 항목별 요구 횟수만큼 누적 성공하면 반복을 마치고 통과 처리한다. 이미 통과한 항목을 다시 실습해도 새 실습에서 항목별 요구 횟수만큼 누적 성공하면 반복을 종료하며, 기존 통과 기록은 유지한다. 통과 전에도 모달을 닫을 수 있다.

항목 전체를 통과한 뒤에는 현재 항목에 머물며 `다음` 버튼을 누르면 다음 항목으로 이동한다. 통과만으로 자동 이동하지 않는다.

실습 중 시연을 다시 확인할 때는 별도 다시 보기 버튼 대신 `직접 입력 / 시연` 토글로 전환한다. 시연에 다녀와도 이미 쌓인 성공 횟수는 유지하며, 시연의 자동 입력은 성공 횟수에 포함하지 않는다.

직접 입력에서 시연으로 바꿀 때 이미 패턴이 재생 중이면 다음 패턴 시작부터 적용하고, 재생 중이 아니면 바로 적용한다. 시연에서 직접 입력으로 바꿀 때는 현재 재생 위치에서 즉시 적용한다. 시연 도중 직접 입력으로 바꾼 현재 패턴은 성공 집계에서 제외하고, 다음 패턴부터 성공 횟수를 집계한다. 남은 실습 세부는 [PRD §12](../prd.md#12-미정-사항)에서 관리한다. 이 규칙은 튜토리얼에 적용하며 옵저버의 Auto 전환 규칙과 구별한다.

각 통과 조건은 콤보 아래에 줄을 나눠 하나씩 표시한다. 충족한 조건에는 초록 체크 아이콘을, 실패한 조건에는 빨강 X 아이콘을 표시하며 중립 상태는 흰색 글씨로 표시한다. 조건 상태는 연주 도중 실시간으로 갱신한다. 조건 목록 바로 아래에는 성공 횟수 진행도를 `현재 성공 횟수/해당 항목의 요구 성공 횟수`로 표시한다(기본값 3회인 항목의 예: `1/3`). 성공 횟수는 패턴 결과가 확정될 때 집계하며, 성공이 확정되면 진행도도 즉시 갱신한다.

각 항목에는 Great 이하 판정 X개 이하와 추가 조건을 표시한다. Great 이하 판정은 Perfect가 아닌 Great·Good·`goodTrill`·Bad·Miss의 개수 합계이며, 바디 유지 실패의 무점수 Miss도 포함한다. 점수 가중치나 달성률은 성공 조건으로 쓰지 않는다. 실습 한 차례의 최종 결과가 표시된 조건을 모두 만족하면 1회 성공으로 세며, 이를 해당 항목의 요구 횟수만큼 누적하면 통과한다. 일반 Good도 허용 개수 안이면 성공할 수 있다. 현재 X의 잠정 기본값은 `DEFAULT_MAX_GREAT_OR_WORSE_COUNT`(1개), 요구 성공 횟수는 3회다. X 기본값의 조정은 [PRD §12](../prd.md#12-미정-사항)에서 관리한다([RFD 0105](https://github.com/nanana3679/not4k/blob/3edd80b4a66a0984e8db217286f86a4800253629/docs/rfd/0105-tutorial-list-explicit-migration.md)).

곡 선택 팝업에 직접 입력 실습·조건·진행도·`다음`·키 부족 안내를 구현했다(2026-10-31). 점수 항목이 없는 `hand-placement`에는 실습 토글을 표시하지 않고 시연만 제공한다. 나머지 Basic 16개·Advanced 8개는 현재 연주 방법이 각각 하나이며, 모두 Great 이하 판정 1개 이하·누적 3회 성공을 요구한다.

추가 조건 `goodTrill` 0회는 `trill-note`(연속 트릴의 키 교대)와 `connected-trill-long`(연결된 트릴 헤드의 키 교대)에 둔다. 트릴 롱노트를 유지하는 `long-note`·`connected-trill-long`에는 Miss 0회 조건도 둔다. 트릴 바디에는 틱 노트를 둘 수 없으므로, 바디를 일찍 떼는 실패는 무점수 바디 Miss를 포함한 Miss 조건으로 잡는다. 나머지 Basic과 Advanced 전체에는 Great 이하 판정 허용 개수만 적용한다. 실패 사례를 시연하는 Advanced 항목도 실습에서는 같은 차트를 연주해 이 조건을 충족해야 한다. 화면 라벨은 `Great 이하 1개 이하`, `Miss 0회`, `goodTrill 0회`이며 충족·실패·중립 아이콘은 유지한다.

팝업은 처음에 시연을 선택하며, 레슨 변경·재방문·모달 재개방 때 `createTutorialPracticeState`로 처음부터 시작한다. 직접 입력에서 콤보를 DOM으로 표시하고 그 아래 조건을 한 줄씩, 바로 아래 진행도를 배치한다. 실시간 표시는 실제 `ExplicitJudgmentSession.score`를 세션 준비·확정 효과 발생 때만 콜백으로 받아 `getTutorialConditionStatus`로 평가한다. 허용 개수를 넘으면 즉시 실패 상태로, 넘지 않고 모든 점수 항목이 정산되면 충족 상태로 표시한다. 충족 표시 뒤에도 무점수 바디 Miss가 추가될 수 있으므로 성공 횟수는 `ExplicitJudgmentSession.finalize().score`를 `patternFinished`에 전달해 `isTutorialPatternSuccess`의 `final` 평가로만 확정한다. `live` 평가는 성공을 확정하지 않는다. 프레임마다 점수를 복사하거나 React를 갱신하지 않는다. 끝난 패턴의 조건 상태는 `lastFinishedPattern`으로 보존하며, 다음 패턴의 첫 점수 항목이 정산되기 전까지 표시한다.

모달이 소유한 패턴 ID는 레슨과 연주 방법을 넘겨도 증가한다. 재생기 자체의 반복 차수는 ID로 사용하지 않는다. 재생기에는 선택 표시가 아닌 reducer의 적용 모드(`state.mode`)를 넘기며, 패턴 시작 콜백의 반환 모드를 다음 입력 전에 적용한다. 완료 콜백이 반복 중지를 반환하면 다음 시작 통지와 입력 진행을 멈춘다. 목표를 채우면 직접 입력을 일시정지하고 `다음`을 표시하며, 시연은 다시 선택할 수 있다. `다음`은 기존 화살표와 같이 같은 탭의 다음 레슨으로 순환한다. 자동 이동하지 않는다.

시연·실습 모두 설정 `judgmentMode`의 판정 창을 따른다. 직접 입력의 누적 시각은 `KeyboardEvent.timeStamp - loopStartNow + settings.inputOffsetMs`이며, `GameClock`과 같은 부호로 양수는 뒤로, 음수는 앞으로 보정한다(시작 이전은 0ms로 제한). 직접 입력의 세션 진행과 반복 경계는 실제 플레이처럼 `min(T, T + inputOffsetMs)`를 기준으로 삼는다. 음수 오프셋이면 보정 시각이 반복 끝에 도달할 때까지 정산을 늦춰 끝 안으로 보정되는 입력을 받는다. 양수 오프셋은 세션·반복을 화면보다 앞당기지 않는다. 시연 입력과 렌더 시계에는 입력 오프셋을 적용하지 않는다.

화면과 판정 세션의 반복 차수는 별도로 추적한다. 음수 입력 오프셋이나 경계 정산 대기로 세션이 이전 반복에 남아 있으면, 3벌 표시의 이전 복사본에만 그 판정 상태와 시각을 적용하고 현재 복사본은 판정 전으로 표시한다. `single-note`의 오프셋 −200ms에서는 화면이 1500ms에 다음 반복으로 넘어가도 새 노트를 숨기지 않으며, 1700ms 경계 관측 후 다음 프레임에 정산하면 새 세션을 현재 복사본에 적용한다. 시연과 0·양수 오프셋의 입력·정산 시각은 유지한다.

항목 전체 통과 기록의 브라우저 저장과 목록 체크를 구현했다(2026-10-31). `useTutorialPractice`의 `onItemPassed(itemId)`가 `isTutorialPracticeItemPassed`의 false→true 전환만 알리면 팝업이 통과 ID를 저장하고 목록을 즉시 갱신한다. 시연·부분 성공·중간 방법 완료는 저장하지 않으며 재실습으로 기존 통과 기록을 지우지 않는다. 열람 체크와 열람 캐시 읽기·쓰기는 제거했다. `e2e/game/tutorial-practice.spec.ts`에 실제 바인딩 입력으로 3회 성공·완료 정지·다음 이동, 실습의 도식 생략·시연 복귀, 컨트롤 동작 키 소유권, 즉시 통과 체크·재개방·새로고침 후 기록 유지와 키 부족 안내·Controls 진입을 검증하는 시나리오를 추가했다.

실습 과제는 올바른 연주 방법을 익히는 내용으로만 구성한다. 판정의 실패 사례는 시연으로 설명하고, 실패 동작을 직접 재현해야 통과하는 과제는 두지 않는다. 실습에서 실제로 발생한 실패는 일반 규칙대로 판정하며 항목별 Great 이하 판정 허용 개수·추가 조건으로 성공 여부를 판단한다.

### 실습 중 키 선택과 표시

실습에서는 노트를 보고 직접 사용할 키를 판단한다. 다음에 눌러야 할 키를 미리 알려주는 가이드는 표시하지 않는다. 시연에서 보여주는 입력 안내를 실습의 사전 키 안내로 이어서 표시하지 않으며, 실제 누른 키의 표시와 노트·`trillZone` 등 입력 요구를 알리는 시각 표시는 유지한다.

튜토리얼의 노트 낙하 속도는 튜토리얼용 고정값을 사용한다. 플레이어의 본 플레이 설정에 연동하지 않으며 본 플레이의 설정값도 변경하지 않는다. 구체적인 고정값은 [PRD §12](../prd.md#12-미정-사항)에서 관리한다.

### 명시 재생기의 직접 입력 연결

곡 선택 팝업과 `/lab/tutorial-explicit-player`가 공유하는 `TutorialPreviewPlayer`는 명시 정의에 한해 `inputMode: 'demonstration' | 'directInput'`을 받는다(기본 `demonstration`). `onPatternStarted(iteration)`은 최초 준비와 매 반복 시작을 0부터 알리고, `onPatternFinished({ iteration, result })`는 끝난 패턴의 정산 결과를 알린다. 모드 변경만으로 패턴·시계·렌더러를 다시 시작하지 않는다. prop은 이미 적용하기로 한 모드이므로 즉시 반영하며, 실습에서 시연 복귀를 다음 패턴까지 미루는 판단은 호출자 UI의 책임이며 곡 선택 팝업은 실습 reducer로 처리한다. Lab 스위치는 두 방향 모두 즉시 반영하여 연결을 확인한다. 시연 복귀 시 지나간 입력은 다시 넣지 않고 현재 위치 이후의 시연 입력을 사용하며 다음 패턴부터 전체 시연 계획을 사용한다.

직접 입력은 실제 `settings.keyBindings`를 `InputSystem`으로 수집하고 `KeyboardEvent.timeStamp - loopStartNow + settings.inputOffsetMs`를 누적 재생 시각으로 사용한다. 일시정지·도식 재개 보정은 재생기 시계가 맡는다. 반복 끝과 같은 시각까지의 입력은 이전 패턴에서 처리하고, 끝을 지난 입력은 다음 패턴의 시각으로 옮긴다. 직접 입력은 경계를 처음 관측한 프레임에서 이전 세션을 유지하고 다음 진행 프레임에 정산하여, 경계 프레임 직후 늦게 전달된 경계 이전·동일 timestamp 입력도 이전 패턴에 반영한다. 그 한 프레임의 대기보다 더 늦게 온 지난 패턴 입력은 hold만 동기화하며 이미 정산한 점수를 바꾸거나 다음 패턴의 0ms 입력으로 판정하지 않는다. 도식 진입과 겹쳐도 대기 중인 경계만 다음 프레임에 한 번 정산하며, 그 전에 모드 전환이나 도식 OK가 오면 모은 입력을 먼저 정산한다. 경계까지 전달한 hold만 다음 세션의 `preheldKeys`로 넘겨 새 탭을 만들지 않는다. 시연에서 직접 입력으로 바꾸면 남은 시연 큐를 버리고 `syncHeldKeys`로 시연 hold를 실제 hold로 바꾼다. 이 동기화는 점수를 내는 가짜 up을 생성하지 않는다. `paused`·도식 대기 중에는 새 판정 입력을 받지 않고 물리 hold만 추적하여 재개 때 맞춘다. 도식 OK는 실제 재개 timestamp를 입력 수락 기준으로 넘겨, 그보다 이른 대기 중 입력이 재개 뒤 도착해도 점수 없이 hold만 동기화한다.

직접 입력 표시에는 실제 설정만 사용하고 보충 안내·사전 레인 키 라벨은 숨긴다. 키빔·키보드 강조는 실제 누른 키를 따르며 노트·`trillZone` 표시는 유지한다. 재생기가 소유한 레인 키는 window capture 단계에서 수집하고 탐색 전달을 막으며 Escape는 항상 닫기로 통과시킨다. 입력란(`input`·`textarea`·`select`·contenteditable)과 포커스된 버튼·컨트롤의 동작 키는 수집·차단하지 않는다. `paused`·도식 대기 중에도 기본 동작·다른 핸들러 전달을 막지 않는다. 설정 키 캡처 등 다른 UI가 키보드를 소유하는 호출자는 `ownsKeyboardInput(event)`를 false로 반환한다. 소유권이 옮겨진 뒤에도 기존 held 키의 up은 추적하되 release 점수는 만들지 않는다. 곡 선택 모달은 탐색 키 핸들러를 bubble 단계에 유지하며, 입력 수집과 같은 소유권 규칙으로 편집 입력과 포커스된 컨트롤의 동작 키를 양보한다. 레인에 바인딩된 Enter·Space도 버튼 활성화에 사용할 수 있고, 탭의 방향키는 탭 탐색에 사용한다. 소비된 이벤트와 컨트롤이 소유하지 않은 직접 입력 레인 키로 레슨을 넘기지 않는다. 편집 입력이 소유하지 않은 Escape는 모달을 닫되 설정이 열려 있으면 설정만 조작한다. 설정 중에는 튜토리얼을 멈추고 키보드 소유권을 설정에 넘긴다. 구형 정의는 새 모드·콜백을 사용하지 않는다.

Lab의 시작·완료 횟수 표시는 실습 성공 집계가 아니며 곡 선택 팝업만 실습 reducer를 연결한다. 두 경로 모두 설정의 판정 창과 직접 입력 오프셋을 따른다. 곡 선택 팝업은 메트로놈을 사용하고 Lab 재생기는 기존 무음 경로를 유지한다. 키보드 없는 모바일 입력은 미구현이다.

### 통과 기록과 재진입

**현재 구현(2026-10-31, DB 마이그레이션 적용 전):** 항목 전체 통과만 계정과 동기화한다. 로그인 중에는 해당 계정의 서버 기록과 계정별 로컬 캐시를 표시하고, 로그아웃하면 아직 인계하지 않은 게스트 기록만 표시한다. 로그인 중 새 통과는 그 계정 캐시에 먼저 저장하고 서버에 중복 없이 추가한다. 성공 횟수·현재 방법·중간 방법 완료·마지막 선택 탭과 항목은 전송하지 않는다. 마지막 선택 위치의 영구 복원은 아직 미구현이다.

- **로컬 저장:** `not4k-tutorial-pass-state` 한 JSON에 `guestIds`, `accountPassedIdsByUser`, `pendingHandoffs`, `unresolvedPasses`를 분리한다. 구형 단일 `pendingHandoff`도 원래 계정·영수증을 보존해 배열로 읽는다. 새 키가 없을 때 기존 `not4k-tutorial-passed-ids`의 문자열 배열을 게스트 기록으로 읽는다. 새 키를 쓴 뒤에는 새 값만 권위로 사용하며 구형 키를 다시 합치지 않는다. 구형 JSON이 깨졌거나 배열이 아니면 빈 기록으로 시작하고 문자열 아닌 값은 무시한다. 새 저장값이 손상되면 빈 상태로 복구하며 구형 게스트를 재인계하지 않는다. 카탈로그 밖 문자열 ID도 보존한다. `not4k-tutorial-viewed-ids`는 읽거나 쓰거나 삭제하지 않는다.
- **자동 인계:** 곡 선택 화면에서 로그인 상태가 확인되면 팝업이 닫혀 있어도 게스트 기록을 인계한다. 예약 전에 서버 ID 형식에 맞는 기록만 골라 최대 100개를 인계한다. 잘못된 구형 ID와 100개를 넘는 나머지는 게스트 저장소에 그대로 남기며 전송·예약하지 않는다. 유효한 후보가 없으면 RPC를 호출하지 않아 기회를 소진하지 않는다. 이미 기회를 쓴 계정은 추가 게스트 기록을 받지 않으며, 남은 게스트 기록은 로그인 중 숨기고 로그아웃할 때 표시한다. 같은 계정으로 다른 기기에서 접속하거나 팝업을 다시 열면 서버 기록을 조회한다.
- **원자성:** `tutorial_passes`는 `(user_id, tutorial_id)` 기본 키와 `passed_at`을, `tutorial_guest_handoffs`는 계정 기본 키·요청 영수증·인계 시각을 저장한다. `handoff_tutorial_passes` RPC가 계정 기본 키를 먼저 선점한 요청에만 통과 INSERT를 허용한다. 두 INSERT는 한 트랜잭션이므로 실패하면 함께 롤백한다. 다른 기기의 경쟁 요청은 false를 받아 게스트 기록을 유지한다. 이미 저장한 같은 영수증 재확인은 true이며 새 기록을 추가하지 않는다. RLS는 익명 세션을 제외한 본인 행 조회·통과 INSERT만 허용하고, 인계 마커는 RPC에서만 만들며 클라이언트 UPDATE·DELETE는 없다.
- **완료 시 소유자:** `useAuth.sessionLoading`은 세션 주체를 아직 모른다는 뜻이며 admin·프로필 `loading`과 분리한다. 초기 조회가 실패하고 세션 이벤트도 없으면 `sessionLoading`은 true로 유지하고 `loading`만 false로 끝낸다. 성공한 세션 조회나 이후 세션 이벤트가 주체를 알려줘야 `sessionLoading`을 false로 바꾼다. 알려진 세션의 통과는 완료 시 계정에 고정해 즉시 캐시에 기록한다. 세션 미확정 통과는 완료 영수증·항목 ID를 `unresolvedPasses`에 영구 보관하고, 완료 시 시작한 세션 조회로만 소유자를 확정한다. 화면을 나가도 해당 조회와 로컬 저장은 계속되며 새 로그인 주체로 넘기지 않는다. 조회 도중 로그인·로그아웃이 발생하거나 조회가 실패하면 소유자를 추측하지 않는다. 브라우저 종료로 조회를 잃은 경우도 미확정 기록을 보존하고 이후 세션에 자동 귀속하지 않는다.
- **저장 한도:** `tutorial_id`는 영문 소문자·숫자·하이픈만 허용하는 1～64자(`^[a-z0-9-]+$`)이며 현재 Basic·Advanced 25개 ID가 모두 이 형식에 맞는다. 인계 RPC는 중복을 포함해 최대 100개 ID만 받으며 잘못된 ID·null 원소·초과 요청은 마커를 쓰기 전에 거부한다. 클라이언트도 예약 전 후보를 검증하고 전송 함수에서 재검증한다. 인증된 본인의 통과는 계정당 최대 200행이며 직접 INSERT와 RPC 모두 같은 SECURITY INVOKER BEFORE INSERT 트리거에서 계정별 `pg_advisory_xact_lock(hashtext(user_id::text))` 후 개수를 검사한다. 트리거는 RLS WITH CHECK보다 먼저 실행되므로 타인 `user_id`는 잠금·조회 없이 반환해 RLS가 일관되게 거절하도록 한다. `auth.uid()`가 없는 service role·유지보수 작업에는 한도를 적용하지 않는다. 본인 인증을 강제하는 SECURITY DEFINER RPC 안에서는 한도가 적용된다. 한도에서도 기존 ID의 중복 무시 재시도는 허용한다. 한도 초과로 RPC가 실패하면 인계 마커도 함께 롤백한다.
- **브라우저 간섭·응답 유실:** Web Locks로 같은 브라우저의 예약 읽기·쓰기를 직렬화한다. 전송 전에 검증한 게스트 배치를 영수증·대상 계정과 함께 영구 예약하고 게스트 목록에서 분리한다. 예약은 계정별 배치로 보관하며 A의 미확정 배치는 A만 재시도한다. 예약되지 않은 새 게스트 기록은 인계 기회가 남은 B로 넘길 수 있고, 한 배치의 완료·거절은 다른 계정의 예약을 지우지 않는다. SQLSTATE·PostgREST code 또는 HTTP 오류 status가 있는 서버 오류 응답은 트랜잭션이 적용되지 않은 확정 거절로 처리해 예약을 풀고 게스트로 복원한다. 이 실패는 계정의 인계 기회를 소진하지 않는다. 네트워크 예외·timeout·빈 code와 status 0·결과 불명 오류는 예약을 유지해 다른 계정에 보내지 않으며, 원래 계정의 다음 로그인·팝업 재개방에서 같은 영수증으로 확인한다. 결과 확인 전 배치는 게스트·계정 체크에서 일시적으로 숨긴다(서버 조회로 확인된 통과는 계정에 표시). RPC가 false를 반환해도 게스트로 되돌리고 성공이면 계정 캐시에 합친다. 새로 쌓은 게스트 기록과 기존 계정 캐시는 섞지 않는다. Web Locks가 없거나 영수증을 로컬에 저장할 수 없으면 인계만 보류한다.
- **연결 실패:** 조회 실패 시 해당 계정의 캐시를 계속 표시하며 계정 기록을 게스트로 재분류하지 않는다. 단일 통과 저장에는 인계 예약이나 1회 기회가 없으며 서버 거절·네트워크 실패 모두 완료 계정의 캐시에 남긴다. 로그인·팝업 재개방 때 조회에 성공하면 서버에 없는 계정 캐시 ID만 재전송한다. 인증 세대를 각 후속 요청 전에 검사해 로그아웃·계정 변경·화면 종료 뒤 새 조회·재전송을 중단한다. 이미 진행 중인 응답은 원래 계정 캐시에만 반영할 수 있다. 백그라운드 타이머·연결 복구 이벤트 재시도·실시간 기기 간 푸시는 없다. 저장소 자체가 차단되면 현재 화면의 기록은 유지하지만 다음 접속 복원은 보장하지 않는다. 쓰기 실패 뒤에는 오래된 메모리로 다른 탭의 인계 상태를 덮어쓰지 않도록 해당 곡 선택 화면 수명 동안 영구 저장·새 인계를 중단한다.

아래 재진입·실습 계약 중 마지막 선택 위치 영구 복원은 후속 작업이다.

튜토리얼을 닫았다 다시 열면 마지막으로 선택한 탭과 항목을 연다. 마지막으로 선택한 탭과 항목은 해당 기기의 브라우저에만 저장해 게임을 껐다 켜도 복원하며 계정과 동기화하지 않는다. 선택 이력이 없는 최초 진입은 `Basic` 첫 항목에서 시작한다. 항목 위치 복원과 미완료 실습의 성공 횟수 복원은 구별한다. 실습 기록으로는 항목 전체 통과 여부만 로그인 여부와 관계없이 브라우저에 저장한다. 로그인하면 항목 전체 통과 여부를 계정과 동기화해 다른 기기에서도 같은 통과 표시를 확인할 수 있게 한다. 게스트 튜토리얼의 항목 전체 통과 기록은 로그인 시 자동 인계하며 실제 기록을 넘긴 경우에만 계정당 1회 기회를 소진한다. 이미 인계한 게스트 기록은 다른 계정으로 재인계하지 않는다. 계정에 귀속된 통과 기록은 같은 계정의 여러 기기에서 계속 공유하며, 로컬에 표시된 계정 기록을 게스트 기록으로 재분류하거나 다른 계정으로 인계하지 않는다.  현재 방법·부분 성공 횟수·중간 방법 완료 여부는 현재 실습 세션에서만 유지하고 영구 저장·계정 동기화하지 않는다. 미완료 항목을 닫았다 다시 열거나 다른 항목에서 돌아오거나 게임을 재시작하면 첫 번째 방법의 성공 횟수 0회부터 시작한다. 이미 전체 통과한 항목의 재실습도 첫 번째 방법 0회부터 새로 진행하되 과거 항목 통과 기록은 지우지 않는다. 같은 항목 안에서 시연/직접 입력을 토글할 때는 현재 방법과 누적 성공 횟수를 유지하며 기존 전환·집계 규칙을 따른다. 튜토리얼 목록에서 통과한 항목에 체크 표시를 붙인다. 시연만 본 항목에는 통과 체크를 붙이지 않으며, 별도의 열람 표시도 두지 않는다. 여러 연주 방법을 각각 실습하는 항목은 필요한 모든 방법을 통과해야 항목 전체를 통과로 표시한다. 튜토리얼을 닫았다 다시 열면 미완료 실습은 성공 횟수 0회부터 시작한다. 누적 성공 1회·2회 같은 중간 진행도는 저장·복원하지 않으며, 이미 전체 통과한 항목의 기록은 유지한다. 같은 실습을 이어가는 동안 실패한 경우에는 기존 성공 횟수를 유지한다. 다른 튜토리얼 항목으로 이동했다 돌아오는 경우에도 미완료 실습의 성공 횟수는 0회로 초기화한다. 같은 항목에서 직접 입력/시연을 토글할 때는 성공 횟수를 유지한다.

### 피스 이름의 사용 범위

플레이어에게 공식 피스 이름은 튜토리얼 제목 정도에만 사용한다. 본문은 실제로 어떤 키를 누르고 유지하며 전환하는지 설명하고, 이름을 외워야 안내를 이해할 수 있게 만들지 않는다([glossary](../context/glossary.md#피스-piece), [RFD 0080](../rfd/0080-piece-names-in-tutorial-titles.md)). 모든 항목의 제목을 피스 이름으로 통일할 필요는 없다. 제작·분석 문서에서는 공식 이름과 ID를 계속 사용한다.

### 연주 방법 안내의 진입 원칙

플레이 결과에 따른 키 활용·연주 방법 안내는 플레이어가 도움말·튜토리얼을 선택했을 때 제공한다. 실패 결과만으로 자동 조언하거나 도움말을 열고 튜토리얼로 전환하지 않는다([RFD 0054](https://github.com/nanana3679/not4k/blob/56d6b7100682ad7bb18f597f04699499b533ba0f/docs/rfd/0054-player-requested-playing-guidance.md)). 첫 기동 온보딩의 진입 방식과는 별개의 원칙이다.

### 첫 기동의 튜토리얼 모달

첫 기동에는 프리셋 설정을 마친 뒤 곡 선택 화면 위에 튜토리얼 도움말 모달을 연다. 처음부터 바로 닫을 수 있으며, 항목 보기·실습·완료 확인이나 단계별 스킵을 닫기의 조건으로 두지 않는다. 닫으면 곡 선택 화면을 그대로 이용한다. 이후에는 곡 선택의 `?` 버튼으로 다시 연다([RFD 0055](../rfd/0055-first-launch-tutorial-modal.md)).

Phase 1～4는 학습 내용의 구성이다. 첫 기동에 순서대로 진행하거나 완료해야 하는 절차로 사용하지 않는다. 도움말 모달과 수동 재진입은 구현되어 있으나 첫 기동 자동 열기는 미구현이다.

### 곡 선택 도움말 팝업

> **현재 구현:** 아래 목록은 시연과 직접 입력 실습을 제공하며 게스트·계정별 항목 전체 통과 기록을 체크로 표시한다. 계정 동기화·게스트 1회 자동 인계는 구현했고 DB 마이그레이션 적용 전이다. 별도 열람 표시는 없다. 다시 열 때 마지막 선택 위치 복원은 미구현이며, 아래 첫 항목 진입 설명은 현재 구현에 해당한다.

곡 선택 화면 상단의 `?` 버튼은 기본 입력과 확정된 판정 규칙을 복습하는 도움말이다. `Basic` 탭은 입문 17개, `Advanced` 탭은 복합 판정 시연 8개를 제공한다. 중앙 팝업으로 열리며, 왼쪽 인덱스, 가운데 카드형 축소 재생기, 오른쪽 텍스트 전용 영역으로 분할된다. 팝업을 열면 `Basic` 첫 항목에서 시작한다. 좌우 화살표 버튼·키보드 방향키는 선택한 탭 안에서만 순환하고, 왼쪽 인덱스와 페이지 수 역시 그 탭의 항목만 표시한다. 열려 있는 동안 탭별 마지막 선택 위치를 기억한다. 탭에 포커스가 있으면 좌우 방향키와 Home/End는 탭 선택·포커스만 옮기며 레슨을 함께 넘기지 않는다. 탭은 `tablist`·`tab`·`tabpanel` 관계와 선택 상태를 제공한다. 여러 개의 짧은 튜토리얼 전용 차트를 순환하며, 항목 전체를 통과하면 인덱스 제목 옆에 `✓`와 접근성 이름 `Passed tutorial`을 즉시 표시한다. 시연만 보는 `hand-placement`와 아직 통과하지 않은 실습에는 체크를 붙이지 않는다. 시연·항목 이동은 기록을 바꾸지 않고, 팝업 재개방·새로고침 뒤에도 통과 체크를 복원한다. 게스트로 표시 중이고 개발환경이거나 admin이면 디버깅용 `Reset Passed` 버튼을 표시한다. 이 버튼은 인계하지 않은 게스트 기록만 지우고 두 탭의 게스트 체크를 즉시 지우며, 계정 캐시·진행 중 인계 예약·서버 기록·기존 열람 데이터·게임 설정·현재 실습 진행은 바꾸지 않는다. 실제 계정으로 로그인 중에는 이 버튼을 표시하지 않는다. 저장 형식·알 수 없는 ID 보존·기존 열람 데이터 처리는 [통과 기록과 재진입](#통과-기록과-재진입)을 따른다. 페이지를 넘길 때는 축소 재생기 슬롯 2개를 팝업이 열려 있는 동안 계속 마운트해 두고, 두 슬롯이 번갈아 보이지 않는 쪽에 다음 차트를 준비한다. 각 슬롯은 렌더러(WebGL 캔버스)를 유지한 채 차트만 바꿔 걸기 때문에, 레슨을 넘길 때마다 렌더러를 새로 만들지 않는다. 같은 레슨을 다시 방문해도 그 슬롯에 차트를 다시 걸어 처음부터 재생한다. 새 차트의 첫 프레임을 렌더링한 뒤 가운데 카드 뷰포트 안에서 이전 차트와 다음 차트를 좌우 캐러셀처럼 이동시켜 빈 프레임 깜빡임을 피하고 페이지 관계를 보여준다. 들어오는 재생기는 이동하는 동안 첫 프레임에 멈춰 있다가 자리를 잡은 뒤 차트를 처음부터 재생하고, 밀려나는 재생기는 이동이 끝날 때까지 이어서 재생한다. 보이지 않는 대기 슬롯은 재생을 진행하지 않는다. 모달을 열 때는 첫 프레임이 준비될 때까지 구동기를 카드 안에서 숨기고, 닫을 때는 구동기를 먼저 숨긴 뒤 짧은 종료 전환 후 언마운트해 캔버스 준비/정리 중 깨진 프레임이 보이지 않게 한다. 각 차트 안의 `tutorialInput` 이벤트가 어떤 레인의 어떤 키를 언제 누르고 떼는지 정의하고, 필요한 경우 `tutorialDiagram` 이벤트가 축소 재생기 위에 노트 패턴 도식을 표시한다. 키 입력 표시 영역은 최초 설정에서 선택한 키보드 프리셋(TKL 또는 Numpad)을 반영하며, `tutorialInput`은 레인 기준으로 현재 프리셋의 실제 바인딩 키에 매핑되어 표시된다. 시연의 `BindingN`과 기본 TKL/Numpad 키는 레인별 슬롯으로 해석하여 현재 바인딩에 매핑한다. 예를 들어 시연의 첫 키와 둘째 키는 사용자가 첫 슬롯에 W를 배정했어도 서로 다른 입력으로 유지된다. 매핑된 키는 키보드에서 강조하고, 매핑되지 않은 키는 비활성 상태처럼 어둡게 표시한다. 축소 재생기의 판정선 아래에는 레인별 대응 키를 큰 키 사각형으로 하나씩 표시하되, 입력 전 기본 라벨은 해당 레인의 가장 이른 입력 묶음을 보여주고, 입력 중에는 실제 눌리는 키 라벨로 바뀌며, 릴리즈 뒤에도 다음 입력 전까지 마지막 라벨을 유지한다. 더블 노트처럼 같은 레인에서 두 키를 동시에 누르면 시작 라벨과 입력 중 라벨 모두 두 키를 같은 큰 키 사각형 안에 함께 표시한다.

각 전용 차트는 4박 또는 8박을 채우기 위해 무관한 노트를 추가하지 않고, 레슨 내용에 맞는 길이의 루프를 사용한다. `Advanced`는 입력 시작 전 낙하 시간과 마지막 판정 기한 이후의 여백을 두어 실패 판정도 다음 반복 전에 확인할 수 있게 한다. 곡 선택 팝업은 `basicTutorialExplicitPreviews.ts`의 Basic 17개와 `advancedTutorialExplicitPreviews.ts`의 Advanced 8개 명시 정의(`tap`·`body`·`release`·`tick`)를 재생한다. 구형 차트를 실행 중 변환하지 않는다. 바인딩으로 옮긴 `tutorialInput`을 원래 timestamp별 down/up 묶음으로 명시 판정 controller(`ExplicitJudgmentSession`)에 넣고, 확정 효과는 `ExplicitJudgmentEffectSink`로 표시한다. 판정 창은 일반 플레이와 같은 `getJudgmentWindows(settings.judgmentMode)`를 사용한다(Normal: Perfect ±41ms·Great ±82ms·Good ±120ms·Bad ±160ms, Easy: ±50ms·±100ms·±150ms·±200ms). FAST/SLOW 표시 기준도 같은 모드의 Perfect 창을 따른다. `/lab/tutorial-explicit-player`의 명시 재생기도 같은 설정을 따른다. 시연에는 `inputOffsetMs`를 적용하지 않으며, 팝업의 직접 입력 실습에는 실제 플레이와 같은 입력 보정을 적용한다. 판정 모드를 바꾸면 같은 렌더러에 차트를 다시 걸고 새 세션으로 시작한다.

원본을 한 번만 검증·compile한 뒤 시각·박·노트와 바디 참조·trillZone 인덱스를 옮겨 합성한 표시 데이터 3벌을 합성 상태로 그리며, 패턴을 finalize할 때 결과를 알린다. 시연은 반복 경계에서, 직접 입력은 반복 경계와 해당 세션의 `latestJudgmentDeadlineMs`를 모두 지난 뒤 정산한다. 앞뒤 반복을 이어 붙인 표시 문서는 구간·이벤트를 그리는 데 사용하고 하나의 판정 차트로 검증·compile하지 않는다. 표시 문서는 `0 ≤ beat < loopBeats`인 BPM 이벤트만 복사본마다 같은 박 수만큼 옮겨 원본의 시간 맵을 반복하고, 박자표는 반복 길이가 마디로 나누어떨어지지 않을 수 있어 원본만 둔다. 명시 경계는 일시정지 시간을 제외한 경과 시간의 반복 차수로 감지하며, 긴 프레임 공백으로 여러 반복을 건너뛰어도 끝난 패턴은 한 번만 정산한다. `paused` 또는 이미 걸린 도식 확인 대기 중에는 반복을 정산하지 않고(경계를 넘은 프레임에 도식이 새로 걸리면 끝난 반복을 먼저 정산한다), 도식 OK로 끝 시점에서 재개할 때는 경계 차수의 기준도 새 시계에 맞춘다. 시연의 반복 경계에서는 이전 세션을 `loopMs`까지 진행하여 끝과 정확히 같은 시각의 릴리즈도 한 번 정산한 뒤 새 세션을 만든다. 시연은 다음 반복에 이전 누름·정산 상태를 넘기지 않으며, 정상 반복에서는 렌더러나 명시 차트를 다시 만들지 않는다. 이 순서는 `explicitTutorialPreviewPlayback.test.ts`와 실제 팝업의 두 번 반복을 확인하는 `e2e/game/tutorial-note-judgment.spec.ts`로 검증한다. 재생기는 마지막으로 끝난 반복의 차수·판정 수·달성률·경계 정산을 DOM data 속성에 공개하고 차트 재연결 때 비운다. `data-tutorial-loop-origin-now`는 확정된 루프 0ms의 performance 시각(첫 시작에는 준비 구간 끝)을, `data-tutorial-elapsed-ms`·`data-tutorial-loop-time-ms`는 실제 반복 시계를, `data-tutorial-input-mode`·`data-tutorial-paused`는 적용 모드와 정지를 공개한다. E2E는 Normal/Easy 모두에서 4000ms 경계 릴리즈 Perfect·전체 Perfect 3·Miss 0·100%를 확인하며, 입력 오프셋 137ms가 시연에 적용되지 않는지도 확인한다. 브라우저 검증 실행은 별도다.

재생기는 명시 정의에 `inputMode`(시연·직접 입력)를 받는다. 시연 모드에서는 같은 시연 timings를, 직접 입력 모드에서는 실제 키보드 입력을 명시 판정 controller에 넣는다. `paused` 또는 이미 걸린 도식 확인 대기 중에는 새 반복 경계를 만들지 않고(경계를 넘은 프레임에 도식이 새로 걸리면 시연은 즉시, 직접 입력은 판정 기한을 지킨 뒤 끝난 반복을 한 번 정산한다), 새 도식이 시작된 프레임의 명시 세션은 화면과 같은 도식 시작점까지만 진행한다. 명시 직접 입력 모드는 경계에서 다음 물리 판정 세션을 시작하고 경계까지 유지한 실제 키만 `preheldKeys`로 넘긴다. 이전 세션의 마지막 판정 기한이 `loopMs`를 넘으면 그 기한까지 이전 세션도 열어 둔다. 경계 뒤에는 경계에서 유지하던 키의 up만 이전 세션에 전달하며, 같은 up은 다음 세션의 hold만 풀고 릴리즈 점수나 새 입력을 만들지 않는다. 경계 뒤 down은 다음 세션에서만 판정한다. 열린 이전 세션의 판정 상태는 해당 반복의 표시 복사본에 계속 반영하고, 정산 뒤에는 최종 snapshot을 표시 수명 동안 유지한다. 새 세션은 새 반복에 해당하는 복사본에 반영한다. `onPatternFinished(N)` 뒤에만 `onPatternStarted(N+1)`을 UI·실습 reducer에 알리므로 물리 세션 시작과 시작 통지는 시점이 다를 수 있다. 입력에는 기존 부호의 `inputOffsetMs`를 적용하고, 음수 오프셋만큼 판정 시계·마지막 기한 도달을 늦추며 시연 시계는 바꾸지 않는다. 곡 선택 팝업은 실습 reducer가 적용한 모드로 시연과 직접 입력을 전환한다.


`TutorialPreviewPlayer`의 구형 정의·고정 Normal 판정 경로는 `/lab/note-assets`의 `NoteAssetPreviewPlayer`를 위해 보존한다. 그 경로만 `NoteJudgmentSession`·`SessionRendererAdapter`를 쓰며, 반복마다 head 표시 캐시를 초기화한다. 구형 Basic·Advanced 목록도 과도기 코드와 모듈 자체의 회귀 테스트를 위해 남긴다.

`tutorialDiagram`은 정적 설명 이미지가 아니라 에디터 `NoteRenderer`의 표기법을 따른 SVG 도식으로 표시한다. 롱노트 도식은 한 줄 방정식으로 배치하며, 시작점은 아래·끝점은 위로 읽는다. 에디터와 같은 5:1 노트 비율을 유지하되 노트 도형은 레인 중앙에서 0.5배 스케일로 표시한다. 롱노트 끝점은 별도 end cap으로 그리지 않고 body가 끝점 자리까지 이어지며, 롱노트 시작점에는 일반 노트 헤드를 함께 표시한다. 개발 중에는 `/lab/tutorial-pattern-diagram`에서 도식만 단독 렌더링해 캡처한다. 곡 선택 팝업의 도식은 시연에서만 표시하며, 직접 입력에서는 도식으로 멈추거나 확인 모달을 띄우지 않는다. 따라서 반복 시작과 세 번째 성공 뒤의 `다음`을 가리지 않는다. 시연으로 돌아가면 도식을 다시 활성화한다. 도식은 등장/퇴장 애니메이션을 가지며, 시연에서 도식 구간에 진입하면 화면 전체를 dim 한 확인 모달로 표시하고 축소 재생 시간은 도식 시작점에 멈춘다. 확인 모달은 축소 재생기 카드가 아니라 뷰포트 기준(문서 최상위로 portal)으로 그려, 카드가 화면 밖으로 밀리는 작은/가로 모바일에서도 도식과 OK 버튼이 잘리지 않고 항상 화면 중앙에 보이도록 한다. 도식 자체도 레인 폭(1fr)·`aspect-ratio`·`clamp` 글자 크기로 반응형이며, 큰 화면에서는 상한 높이까지만 커진다. 사용자가 OK를 누르면 도식 구간의 끝 시점으로 재개하며, 도식 퇴장 후에는 약 2초의 낙하 시간을 둔 뒤 실제 노트 시연으로 넘어간다. 이 팝업은 튜토리얼 Phase 진행 상태를 바꾸지 않으며, 메트로놈 소리에 맞춰 시연과 직접 입력 실습의 판정·정산을 진행하고 항목 전체 통과 기록을 저장한다. 전체 튜토리얼은 아래 Phase 구조에서 다룬다.

검증은 `basicTutorialExplicitPreviews.test.ts`·`advancedTutorialExplicitPreviews.test.ts`에서 차트 배치 제약·물리적으로 가능한 누름/떼기·실제 세션의 반복별 결과를 검사한다. 탭 내부 순환과 기존 체크 캐시 호환은 `tutorialCatalog.test.ts`, 실제 팝업의 탭·키보드·캐시·좁은 화면 동작은 `e2e/game/advanced-tutorial.spec.ts`에서 확인한다.

두 재생기 슬롯이 공유하는 스킨 텍스처는 `SkinManager`가 경로별 참조 수로 관리한다. 마지막 사용자가 사라질 때만 해제하고, 같은 경로의 비동기 로드·해제 순서를 보장한다. 렌더러와 스킨은 팝업을 닫을 때(또는 스킨·키보드 프리셋이 바뀔 때)만 정리하며, 이때 초기화가 진행 중이면 초기화를 마친 뒤 해당 재생기와 스킨을 함께 정리한다. 이전 초기화의 완료·실패가 새 슬롯의 자산을 해제해서는 안 된다. `SkinManager.test.ts`는 공유 자산과 비동기 해제 중 재진입을 검증한다. `GameRenderer.dispose()`는 해당 앱의 캔버스·자식만 정리하고 Pixi 전역 풀을 비우지 않는다. 다른 슬롯이 그 풀에서 받아 아직 쓰는 텍스트 텍스처와 bounds가 있기 때문이다. `GameRenderer.lifecycle.test.ts`는 한 슬롯을 닫은 뒤 다른 슬롯의 텍스처 반환·재사용과 늦은 프레임 무시를 검증한다. 같은 렌더러에 다른 차트를 걸 때는 `GameRenderer.resetTransientState()`가 이전 차트의 봄·판정 텍스트·키빔·키 눌림·이벤트 문구를 지우고, `updateTutorialKeyboardKeys()`가 키캡 배치를 유지한 채 차트별 키 라벨·매핑만 바꾸며, `setExplicitChart()`가 이전 명시 노트 표시를 교체한다. `/lab/note-assets`의 구형 경로는 `setChart()`로 Grace·그림자를 포함한 노트 풀을 비운다(`GameRenderer.reuse.test.ts`·`GameNoteRenderer.test.ts`). 두 슬롯이 레슨을 넘겨도 같은 캔버스와 렌더러 2개를 유지하는지는 `e2e/game/tutorial-preview-pingpong.spec.ts`에서 확인한다.

### Phase 1: 연주 방법 — "이렇게 치면 된다"

노트 타입별 기본 입력 방법만 소개한다. 판정의 세부 규칙은 언급하지 않는다.

| 항목 | 소개하는 것 | 소개하지 않는 것 |
|------|------------|-----------------|
| 싱글 노트 | 키를 누른다 | 판정 윈도우 수치 |
| 롱 노트 | 키를 유지하고 명시된 릴리즈에서 뗀다 | 홀드 교대, 유예 시간, 릴리즈 상향 |
| 트릴 노트 | `trillZone`에서 키를 번갈아 누른다 | 교대 실패 시 Good 고정 |
| 더블 노트 | 다른 키 2개를 동시에 누른다 | 독립 판정 × 2, 배드말림 해제 |

목표: 유저가 **모든 노트 타입을 처리할 수 있는 상태**가 된다. "왜 이 판정이 나왔는지"는 아직 알 필요 없다.

### Phase 2: 복합 패턴과 판정 — "왜 이렇게 되는가"

Phase 1의 연주 능력을 전제로, 복합 패턴에서 발생하는 판정 규칙을 소개한다.

실패 판정이 발생하는 동작은 시연으로 보여준다. 직접 입력 실습에서는 해당 규칙을 지키는 올바른 연주 방법을 연습한다.

- 연결된 바디의 무점수 유지, 명시된 감소·종료 릴리즈, 유지 실패의 차이
- 릴리즈 노트의 실제 떼기 타이밍 판정과 틱 노트의 바디 상태 판정
- 트릴 교대 실패 시 Good 고정 (`goodTrill`)
- 바디 연결의 hold 수 변화와 명시 릴리즈 배치의 구별
- 분할 릴리즈(`D=-`)의 판정 횟수

목표: 유저가 **자신의 판정 결과를 이해하고 개선 방향을 파악할 수 있는 상태**가 된다.

### Phase 3: 홀드 교대와 헤드 없는 롱노트 — "홀드의 확장"

홀드 교대는 기존 유지와 새 시작을 함께 이해해야 하는 동작이므로 튜토리얼에서 시연한다. 롱노트 진행 중에 다른 키로 홀드를 이어받을 수 있음을 실제 입력으로 보여준다. 이 문서의 학습 순서는 판정 규칙 학습 이후로 두되, 차트에서 해당 동작이 처음 등장할 수 있는 레벨을 정하는 제한으로 사용하지 않는다.

- 롱노트를 A로 유지하다가 B로 이어잡아도 끊기지 않는다는 것을 체험시킨다.
- 연결 head의 허용 창 안에서 A를 떼고 B를 눌러 교대할 수 있음을 시연한다. 같은 키의 재타격에도 같은 연결 보정을 적용한다.

롱노트 중 탭은 같은 노트 배치에서 다음 두 연주 방법을 모두 시연한다(사용자 확인, 2026-10-29).

- 기존 키를 계속 누른 채 같은 레인의 다른 키로 탭한다.
- 다른 키로 탭하면서 기존 키를 떼고, 새 키로 롱노트 유지를 이어받는다.

롱노트 중 탭은 한 항목 안에서 기존 키를 유지하는 방법을 먼저 시연·실습하고, 그 방법의 목표를 달성한 뒤 유지 키를 교대하는 방법을 시연·실습한다. 첫 방법의 목표를 달성하면 반복을 멈추고 현재 단계에 머물며, `다음` 버튼으로 두 번째 방법으로 이동한다. 자동으로 다음 방법으로 전환하지 않는다. 두 방법 모두 목표를 달성해야 항목 전체를 통과한다. 두 방법을 자유롭게 번갈아 선택하는 방식으로 만들거나 전체 튜토리얼 항목의 순서를 잠그는 것으로 확대하지 않는다. 각 방법에서 해당 항목의 요구 횟수만큼 성공을 누적한다. 성공 횟수를 방법별로 따로 집계하며, 한 방법의 성공 횟수를 다른 방법에 합산하지 않는다. 실습 중 실패해도 해당 방법에서 이미 쌓인 성공 횟수는 유지한다.

두 방법을 보여주는 시연 차트는 어느 방법으로도 의도한 연주가 성립하도록 구성한다. 홀드 교대를 이 배치를 처리하는 필수 전제로 안내하지 않는다. 피스 이름은 제목 정도에만 사용하고, 본문은 위와 같이 실제 입력 동작을 설명한다. 공개 목록은 위 명시 엔진 시연으로 전환했으며, 두 방법을 한 항목에서 순차 실습하는 흐름은 [PRD §12](../prd.md#12-미정-사항)의 후속 작업이다.

이어서 **헤드 없는 롱노트**를 소개한다. 시작 탭 노트 유무와 바디의 유지 요구를 구별해 이해하도록 홀드 교대를 학습한 직후에 배치한다. 난이도명 전용 패턴으로 안내하지 않는다.

- 헤드 없는 롱노트의 개념을 소개한다: 시작 타이밍 점수는 없고, 미리 누른 키 또는 시작 근처의 누름으로 바디를 유지한다.
- `.-` 패턴을 체험시킨다: 헤드 없는 롱노트의 시작 근처에서 눌러 바디를 활성화하고 끝에 맞춰 뗀다.
- `-=` 패턴(`o-=`)을 체험시킨다: 싱글 홀드 중 헤드 없는 롱노트가 추가되어 더블 홀드로 전환한다. `o-D=`와 달리 전환 시점에 노트 헤드 판정이 없다.
- 난이도명에 따른 사용 제한은 없으며, 실제 독해·연주 부담이 낮으면 낮은 레벨에서도 짧게 등장할 수 있음을 안내한다([배치 기준](https://github.com/nanana3679/not4k/blob/56d6b7100682ad7bb18f597f04699499b533ba0f/docs/spec/difficulty-design.md#%ED%97%A4%EB%93%9C-%EC%97%86%EB%8A%94-%EB%B0%94%EB%94%94-%ED%8C%A8%ED%84%B4%EC%9D%98-%EB%B0%B0%EC%B9%98-%EA%B8%B0%EC%A4%80)).

목표: 유저가 **롱노트 중 탭을 유지와 교대 두 방법으로 연주할 수 있음을 이해하고, 헤드 없는 롱노트의 개념을 이해한 상태**가 된다.

### Phase 4: 16키 — "한 레인에 4키 활용"

8키(레인당 2키)를 넘어, 기본 프리셋의 16키(레인당 4키)를 완전히 활용하는 단계를 소개한다.

- 3키 바인딩이 필요한 피스를 소개한다: 더블 홀드 + 싱글 노트 처리, 3박자 기반 트릴(24비트) 등.
- 3키 트릴(`A → B → C → A → B → C`)이 2키 트릴보다 자연스러운 상황을 체험시킨다.
- 32비트 고속 트릴에서 4키 교대(`A → B → C → D → A → B → C → D`)로 피로를 분산하는 방법을 소개한다.
- 더블 홀드 + 트릴: 4키 중 2키로 더블 홀드를 유지하면서 나머지 2키로 트릴을 처리하는 연습.

목표: 유저가 **16키 바인딩의 이점을 이해하고, 레인당 4키를 활용할 수 있는 상태**가 된다.
