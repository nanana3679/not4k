# not4k — 튜토리얼 설계

이 문서는 노트 연주법과 판정 방식을 단계적으로 소개하는 튜토리얼의 설계를 정의한다.

> **키 바인딩 튜토리얼과의 관계**: `keybinding.md`의 튜토리얼 흐름은 물리적 키 배치의 발견(4키 → 6키 → 8키)에 집중한다. 이 문서의 튜토리얼은 노트 메커니즘과 판정 규칙의 학습에 집중한다. 두 트랙은 병행 또는 순차적으로 진행될 수 있으며, 구체적인 결합 방식은 TBD.

---

## 세분화의 이유

not4k의 입력과 판정에는 직관적이지 않은 부분이 존재한다.

- 롱노트가 이어진 경우(`o-o-`) 중간의 일반 승계 성공에는 점수나 release 판정이 없으며, 유지 실패는 Miss로 기록된다.
- 실제 release는 떼는 타이밍에 따라 Perfect/Great/Good을 판정하고, `holdOnly`는 유효한 유지 상태로 release 요구를 면제한다.
- 트릴 노트에서 교대 실패 시 Good으로 고정된다.
- 싱글→더블 전환(`o-D=`)에서 전환 시점에 릴리즈가 발생하지 않는다.
- 더블→싱글 전환(`D=o-`)에서는 릴리즈가 발생한다.
- 분할 릴리즈(`D=-`)는 더블 롱노트에서만 가능하다.

이러한 규칙을 한 번에 제시하면 유저가 압도된다. **최초 튜토리얼에서는 플레이만 가능하도록 노트의 연주 방법만 소개하고, 후속 튜토리얼에서 복합 패턴을 소개하며 판정 방식을 알려줘야 한다.**

## 튜토리얼 구조

### 곡 선택 도움말 팝업

곡 선택 화면 상단의 `?` 버튼은 기본 입력과 확정된 판정 규칙을 복습하는 도움말이다. `Basic` 탭은 입문 17개, `Advanced` 탭은 복합 판정 시연 12개를 제공한다. 중앙 팝업으로 열리며, 왼쪽 인덱스, 가운데 카드형 축소 재생기, 오른쪽 텍스트 전용 영역으로 분할된다. 팝업을 열면 `Basic` 첫 항목에서 시작한다. 좌우 화살표 버튼·키보드 방향키는 선택한 탭 안에서만 순환하고, 왼쪽 인덱스와 페이지 수 역시 그 탭의 항목만 표시한다. 열려 있는 동안 탭별 마지막 선택 위치를 기억한다. 탭에 포커스가 있으면 좌우 방향키와 Home/End는 탭 선택·포커스만 옮기며 레슨을 함께 넘기지 않는다. 탭은 `tablist`·`tab`·`tabpanel` 관계와 선택 상태를 제공한다. 여러 개의 짧은 튜토리얼 전용 차트를 순환하며, 이미 본 항목은 인덱스 제목 옆에 체크 표시를 붙인다. 두 탭의 본 항목 체크 상태는 기존 ID를 유지한 채 브라우저 저장소의 `not4k-tutorial-viewed-ids`에 저장해 팝업을 닫았다가 다시 열어도 유지한다. 개발환경이거나 현재 유저가 admin이면 디버깅용 `Reset Viewed` 버튼을 표시하고, 이 버튼은 저장된 본 항목 캐시를 삭제한 뒤 `Basic` 첫 항목만 본 상태로 즉시 초기화한다. 페이지를 넘길 때는 축소 재생기 슬롯 2개를 항상 마운트해 두고, 보이지 않는 슬롯에 다음 차트를 준비한다. 새 재생기가 첫 프레임을 렌더링한 뒤 가운데 카드 뷰포트 안에서 이전 차트와 다음 차트를 좌우 캐러셀처럼 이동시켜 빈 프레임 깜빡임을 피하고 페이지 관계를 보여준다. 모달을 열 때는 첫 프레임이 준비될 때까지 구동기를 카드 안에서 숨기고, 닫을 때는 구동기를 먼저 숨긴 뒤 짧은 종료 전환 후 언마운트해 캔버스 준비/정리 중 깨진 프레임이 보이지 않게 한다. 각 차트 안의 `tutorialInput` 이벤트가 어떤 레인의 어떤 키를 언제 누르고 떼는지 정의하고, 필요한 경우 `tutorialDiagram` 이벤트가 축소 재생기 위에 노트 패턴 도식을 표시한다. 키 입력 표시 영역은 최초 설정에서 선택한 키보드 프리셋(TKL 또는 Numpad)을 반영하며, `tutorialInput`은 레인 기준으로 현재 프리셋의 실제 바인딩 키에 매핑되어 표시된다. 시연의 `BindingN`과 기본 TKL/Numpad 키는 레인별 슬롯으로 해석하여 현재 바인딩에 매핑한다. 예를 들어 시연의 첫 키와 둘째 키는 사용자가 첫 슬롯에 W를 배정했어도 서로 다른 입력으로 유지된다. 매핑된 키는 키보드에서 강조하고, 매핑되지 않은 키는 비활성 상태처럼 어둡게 표시한다. 축소 재생기의 판정선 아래에는 레인별 대응 키를 큰 키 사각형으로 하나씩 표시하되, 입력 전 기본 라벨은 해당 레인의 가장 이른 입력 묶음을 보여주고, 입력 중에는 실제 눌리는 키 라벨로 바뀌며, 릴리즈 뒤에도 다음 입력 전까지 마지막 라벨을 유지한다. 더블 노트처럼 같은 레인에서 두 키를 동시에 누르면 시작 라벨과 입력 중 라벨 모두 두 키를 같은 큰 키 사각형 안에 함께 표시한다.

각 전용 차트는 4박 또는 8박을 채우기 위해 무관한 노트를 추가하지 않고, 레슨 내용에 맞는 길이의 루프를 사용한다. `Advanced`는 입력 시작 전 낙하 시간과 마지막 판정 기한 이후의 여백을 두어 실패 판정도 다음 반복 전에 확인할 수 있게 한다. 축소 재생기의 판정 표시는 별도 간이 규칙을 만들지 않고 플레이 화면과 같은 `NoteJudgmentSession`에 `tutorialInput`을 원래 timestamp별 down/up 묶음으로 넣어 생성한다. 확정 효과와 unit 상태를 `SessionRendererAdapter`로 표시한다. 반복 경계에서는 이전 세션을 `loopMs`까지 진행하여 끝과 정확히 같은 시각의 release도 한 번 정산한 뒤, 세션과 head 표시 캐시를 초기화한다. 다음 반복에 이전 누름·정산 상태를 넘기지 않는다. 이 순서는 `tutorialPreviewSession.test.ts`와 실제 팝업의 두 번 반복을 확인하는 `e2e/game/tutorial-note-judgment.spec.ts`로 검증한다. `tutorialDiagram`은 정적 설명 이미지가 아니라 에디터 `NoteRenderer`의 표기법을 따른 SVG 도식으로 표시한다. 롱노트 도식은 한 줄 방정식으로 배치하며, 시작점은 아래·끝점은 위로 읽는다. 에디터와 같은 5:1 노트 비율을 유지하되 노트 도형은 레인 중앙에서 0.5배 스케일로 표시한다. 롱노트 끝점은 별도 end cap으로 그리지 않고 body가 끝점 자리까지 이어지며, 롱노트 시작점에는 일반 노트 헤드를 함께 표시한다. 개발 중에는 `/lab/tutorial-pattern-diagram`에서 도식만 단독 렌더링해 캡처한다. 도식은 등장/퇴장 애니메이션을 가지며, 도식 구간에 진입하면 화면 전체를 dim 한 확인 모달로 표시하고 축소 재생 시간은 도식 시작점에 멈춘다. 확인 모달은 축소 재생기 카드가 아니라 뷰포트 기준(문서 최상위로 portal)으로 그려, 카드가 화면 밖으로 밀리는 작은/가로 모바일에서도 도식과 OK 버튼이 잘리지 않고 항상 화면 중앙에 보이도록 한다. 도식 자체도 레인 폭(1fr)·`aspect-ratio`·`clamp` 글자 크기로 반응형이며, 큰 화면에서는 상한 높이까지만 커진다. 사용자가 OK를 누르면 도식 구간의 끝 시점으로 재개하며, 도식 퇴장 후에는 약 2초의 낙하 시간을 둔 뒤 실제 노트 시연으로 넘어간다. 이 팝업은 튜토리얼 Phase 진행 상태를 바꾸지 않으며, 오디오·결과 저장 없이 판정·정산을 재생하고 입력 시연을 표시한다. 전체 튜토리얼은 아래 Phase 구조에서 다룬다.

#### Basic 탭

| 번호 | 제목 | 안내 내용 |
|------|------|-----------|
| 0 | 손배치 | 낙하 노트 없이 설명 대상 키만 활성화한다. 왼손은 `Q W E C`에 올리고, 반대손은 현재 TKL/Numpad 배치와 바인딩에 맞춰 표시한다. 키 배치는 옵션에서 바꿀 수 있음을 안내한다. |
| 1 | 싱글 노트 | 한 레인에 여러 키를 바인딩할 수 있으며, 같은 노트를 다양한 키로 처리할 수 있음을 시연한다. |
| 2 | 더블 노트 | 같은 레인의 서로 다른 두 키로 처리한다. 정확히 같은 시각이 아니어도 각각 Good 창 안이면 된다. |
| 3 | 트릴 구간 / 트릴 노트 | 2레인과 3레인에서 교대 입력과 같은 키 입력을 각각 4노트씩 시연한다. 같은 키를 연속으로 누르면 `GOOD◇`으로 강등됨을 안내한다. |
| 4 | 롱노트 | 롱노트는 시작할 때 누르고 끝날 때 떼며, 싱글·더블·트릴 롱노트를 모두 시연한다. 트릴 롱노트는 트릴 구간 안에서 누른 키를 끝까지 유지한다. |
| 5 | 릴리즈탭 | 롱노트 끝에 노트가 함께 나올 수 있으며, 떼는 순간에 다른 키를 함께 누른다. 끝에 노트가 있으면 롱노트 떼기 판정이 없다. |
| 6 | 이어진 롱노트 - 갈아타기 | `o- + o- = o-o-` 도식과 함께 키를 갈아타는 `a-b-` 처리를 시연한다. 이 도식의 두 입력 노트는 하나는 아래, 하나는 위로 정렬해 연결 전후 위치 차이를 보여준다. 도식 뒤에는 약 2초의 낙하 시간을 둔 뒤 노트가 판정선에 도착한다. 연결 지점에서는 이전 키를 떼는 타이밍을 따로 판정하지 않음을 안내한다. |
| 7 | 이어진 롱노트 - 겹쳐 누르기 | `o--- + .o.. = o-o-` 도식과 함께 기존 키를 누른 채 새 키를 더하는 처리를 시연한다. 도식 뒤에는 약 2초의 낙하 시간을 둔 뒤 노트가 판정선에 도착한다. 연결 지점에서는 이전 키를 떼는 타이밍을 따로 판정하지 않음을 안내한다. |
| 8 | 이어진 트릴 롱노트 | 트릴 롱노트가 이어진 `t-t-`도 이어진 롱노트와 동일하게 갈아타기·겹쳐 누르기로 처리할 수 있음을 안내한다. 두 방식을 한 차트에서 나란히 보여준다(2레인은 갈아타기, 3레인은 겹쳐 누르기). 연결점이 트릴 헤드라 이어질 때마다 다른 키로 교대해야 하는 점은 별도 문구 없이 서로 다른 키를 쓰는 실연으로 보여주며, 도식은 생략한다. |
| 9 | 헤드 없는 롱노트 | 롱노트가 일반 노트 없이 시작될 수 있으며, 시작 근처의 유효한 누름 또는 연결된 바디의 승계로 시작하며 head 타이밍 점수는 없음을 안내한다. |
| 10 | 길이가 0인 롱노트 | 시작 근처에서 누른 뒤 떼며, 누름에는 점수 없이 떼기 타이밍만 판정하는 롱노트를 안내한다. |
| 11 | grace 노트 | Good 윈도우 안에 입력하면 Perfect로 승급되는 포인트 노트를 안내한다. |
| 12 | grace 롱노트 | 끝나는 시점에 떼지 않아도 되는 grace 롱노트 동작을 안내한다. |
| 13 | 길이가 0인 grace 롱노트 | 길이가 0인 hold-only 롱노트로, Good 윈도우 안에서 키를 누르고 있으면 되는 동작을 안내한다. |
| 14 | 휴지 구간 | 어둡게 표시된 레인은 그 구간 동안 노트가 나오지 않음을 안내한다. 한 손이 트릴을 처리하는 동안 쉬는 레인을 미리 보여주어, 휴지 구간을 이용해 다음 패턴을 위한 손 위치를 준비하도록 안내한다. |
| 15 | 수평 이동 | 고정된 손배치로 처리하기 어려운 패턴을 유동적인 손배치로 처리해 보도록 안내한다. |
| 16 | 수직 이동 | 수직으로 이동해서 노트를 처리할 수 있음을 안내한다. |

#### Advanced 탭

[RFD 0020](../rfd/0020-note-judgment-units-and-inheritance.md)와 [판정 사례 명세](note-judgment-cases.md)의 채택 규칙을 한국어 설명과 실제 입력 시연으로 소개한다. 정상 입력뿐 아니라 의도적인 실패도 보여주며, 프리뷰 판정을 임의로 성공으로 바꾸지 않는다. `Basic`의 사용자 표기인 grace 롱노트는 코드 속성 `holdOnly`에 해당한다.

| 순서 | 시연 ID | 안내 내용 | 한 반복의 기대 결과 |
|------|---------|-----------|---------------------|
| 0 | `advanced-double-hold` | 더블 롱노트의 두 키를 유지하고 다른 두 키로 중간 더블만 짧게 친다. | Perfect 6, Miss 0, 100%, Full Combo |
| 1 | `advanced-double-swap` | 같은 차트에서 연결 지점마다 두 키를 모두 갈아탄다. | Perfect 6, Miss 0, 100%, Full Combo |
| 2 | `advanced-single-head-double` | 더블 유지 중 싱글 시작 노트에서는 한 몫만 교대한다. | Perfect 5, Miss 0, 100%, Full Combo |
| 3 | `advanced-decrease` | 일반 `=-=-`는 각 감소에서 한 키를 떼고 증가에서 새로 누른다. | Perfect 5, Miss 0, 100%, Full Combo |
| 4 | `advanced-holdonly-decrease` | 감소에 `holdOnly`가 있으면 두 키를 유지해도 각각 Perfect이며, 다음 증가에도 이어 쓸 수 있다. | Perfect 7, Miss 0, 100%, Full Combo |
| 5 | `advanced-same-key` | 연결 시작 노트를 같은 키로 재타격해도 교대의 떼기를 가까운 마지막 release로 중복 사용하지 않는다. | Perfect 3, Miss 0, 100%, Full Combo |
| 6 | `advanced-recovery` | 앞 유지 실패는 Miss로 남고 다음 시작 노트부터 다시 잡는다. 무점수 유지 Miss도 콤보·고도에 영향을 주므로 100%여도 Full Combo는 아니다. | Perfect 3, Miss 1, 100%, Full Combo 아님 |
| 7 | `advanced-partial-double` | 더블 시작에서 한 키를 빠뜨려도 성공한 쪽은 유지·종료할 수 있다. | Perfect 2, Miss 1, 50%, Full Combo 아님 |
| 8 | `advanced-independent-holdonly` | 미리 누르던 키로 독립 양수 `holdOnly`를 시작할 수 없다. 뒤의 별도 롱노트는 새 입력으로 성공한다. | Perfect 1, Miss 1, 50%, Full Combo 아님 |
| 9 | `advanced-short-holdonly` | 끝을 지난 초단 `holdOnly`도 시작의 Good 창 안이면 첫 활성화가 가능하다. | Perfect 1, Miss 0, 100%, Full Combo |
| 10 | `advanced-zero-holdonly` | 길이 0 `holdOnly`는 간격 앞부터 유지한 키로도 완료한다. 새 release 권한은 생기지 않는다. | Perfect 2, Miss 0, 100%, Full Combo |
| 11 | `advanced-double-release` | 더블 끝에서 한 키를 임의로 두 번 눌렀다 떼도 나머지 한쪽의 release를 대신하지 못한다. | Perfect 3, Miss 1, 75%, Full Combo 아님 |

시연에 현재 설정보다 많은 키가 필요하면 프리뷰 안에서만 해당 레인의 키를 보충한다. 예를 들어 1번 레인에 `Q W`만 배정한 설정에서 네 키를 쓰는 시연은 `Q W S X`를 표시한다. 다른 레인의 설정 키와 중복하지 않으며, 보충한 배치와 옵션에서 키를 추가할 수 있다는 안내를 함께 표시한다. 사용자의 실제 설정은 변경하지 않는다. 이미 충분한 키가 있으면 현재 바인딩을 그대로 따른다.

검증은 `advancedTutorialPreviews.test.ts`에서 차트 배치 제약·물리적으로 가능한 누름/떼기·실제 세션의 반복별 결과를 검사한다. 탭 내부 순환과 기존 체크 캐시 호환은 `tutorialCatalog.test.ts`, 실제 팝업의 탭·키보드·캐시·좁은 화면 동작은 `e2e/game/advanced-tutorial.spec.ts`에서 확인한다.

두 재생기 슬롯이 공유하는 스킨 텍스처는 `SkinManager`가 경로별 참조 수로 관리한다. 마지막 사용자가 사라질 때만 해제하고, 같은 경로의 비동기 로드·해제 순서를 보장한다. 빠른 탭 전환이나 닫기 도중 초기화가 진행 중이면 초기화를 마친 뒤 해당 재생기와 스킨을 함께 정리한다. 이전 초기화의 완료·실패가 새 슬롯의 자산을 해제해서는 안 된다. `SkinManager.test.ts`는 공유 자산과 비동기 해제 중 재진입을 검증한다. `GameRenderer.dispose()`는 해당 앱의 캔버스·자식만 정리하고 Pixi 전역 풀을 비우지 않는다. 다른 슬롯이 아직 빌려 쓰는 텍스트 텍스처와 bounds가 있기 때문이다. `GameRenderer.lifecycle.test.ts`는 한 슬롯을 닫은 뒤 다른 슬롯의 텍스처 반환·재사용과 늦은 프레임 무시를 검증한다.

### Phase 1: 연주 방법 — "이렇게 치면 된다"

노트 타입별 기본 입력 방법만 소개한다. 판정의 세부 규칙은 언급하지 않는다.

| 항목 | 소개하는 것 | 소개하지 않는 것 |
|------|------------|-----------------|
| 싱글 노트 | 키를 누른다 | 판정 윈도우 수치 |
| 롱 노트 | 키를 누르고 있다가 뗀다 | 홀드 교대, 유예 시간, 릴리즈 상향 |
| 트릴 노트 | `trillZone`에서 키를 번갈아 누른다 | 교대 실패 시 Good 고정 |
| 더블 노트 | 다른 키 2개를 동시에 누른다 | 독립 판정 × 2, 배드말림 해제 |

목표: 유저가 **모든 노트 타입을 처리할 수 있는 상태**가 된다. "왜 이 판정이 나왔는지"는 아직 알 필요 없다.

### Phase 2: 복합 패턴과 판정 — "왜 이렇게 되는가"

Phase 1의 연주 능력을 전제로, 복합 패턴에서 발생하는 판정 규칙을 소개한다.

- 연결된 바디의 무점수 승계, 실제 감소·종료 release, 유지 실패의 차이
- 실제 release의 타이밍 판정과 `holdOnly`의 유지 상태 Perfect
- 트릴 교대 실패 시 Good 고정 (`goodTrill`)
- 롱노트 `connection` 시 키 수 변화에 따른 릴리즈 발생 규칙
- 분할 릴리즈(`D=-`)의 판정 횟수

목표: 유저가 **자신의 판정 결과를 이해하고 개선 방향을 파악할 수 있는 상태**가 된다.

### Phase 3: 홀드 교대와 헤드 없는 롱노트 — "홀드의 확장"

홀드 교대는 기존 유지와 새 시작을 함께 이해해야 하는 동작이므로 튜토리얼에서 시연한다. 롱노트 진행 중에 다른 키로 홀드를 이어받는 것은 기존 리듬게임에 없는 개념이며, 유저가 스스로 발견하기 어렵다. 고난이도에서만 사용되므로 판정 규칙 학습 이후에 배치한다.

- 롱노트를 A로 유지하다가 B로 이어잡아도 끊기지 않는다는 것을 체험시킨다.
- 연결 head의 허용 창 안에서 A를 떼고 B를 눌러 교대할 수 있음을 시연한다. 같은 키의 재타격에도 같은 연결 보정을 적용한다.
- 홀드 교대가 홀드 중 탭 피스의 전제 조건임을 소개한다.

이어서 **헤드 없는 롱노트**를 소개한다. HARD 차트에서만 등장하는 새로운 유형이므로, 홀드 교대를 학습한 직후에 배치한다.

- 헤드 없는 롱노트의 개념을 소개한다: 시작 타이밍 점수는 없지만 시작 근처의 새 누름 또는 정당한 연결 승계가 필요하다.
- `.-` 패턴을 체험시킨다: 헤드 없는 롱노트의 시작 근처에서 눌러 바디를 활성화하고 끝에 맞춰 뗀다.
- `-=` 패턴(`o-=`)을 체험시킨다: 싱글 홀드 중 헤드 없는 롱노트가 추가되어 더블 홀드로 전환한다. `o-D=`와 달리 전환 시점에 노트 헤드 판정이 없다.
- 이 패턴들이 HARD 차트에서만 등장한다는 것을 안내한다.

목표: 유저가 **롱노트 중 키 전환이 가능하다는 것을 체득하고, 헤드 없는 롱노트의 개념을 이해한 상태**가 된다.

### Phase 4: 16키 — "한 레인에 4키 활용"

8키(레인당 2키)를 넘어, 기본 프리셋의 16키(레인당 4키)를 완전히 활용하는 단계를 소개한다.

- 3키 바인딩이 필요한 피스를 소개한다: 더블 홀드 + 싱글 노트 처리, 3박자 기반 트릴(24비트) 등.
- 3키 트릴(`A → B → C → A → B → C`)이 2키 트릴보다 자연스러운 상황을 체험시킨다.
- 32비트 고속 트릴에서 4키 교대(`A → B → C → D → A → B → C → D`)로 피로를 분산하는 방법을 소개한다.
- 더블 홀드 + 트릴: 4키 중 2키로 더블 홀드를 유지하면서 나머지 2키로 트릴을 처리하는 연습.

목표: 유저가 **16키 바인딩의 이점을 이해하고, 레인당 4키를 활용할 수 있는 상태**가 된다.
