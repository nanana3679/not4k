# not4k — 튜토리얼 설계

이 문서는 노트 연주법과 판정 방식을 단계적으로 소개하는 튜토리얼의 설계를 정의한다.

> **학습 범위**: 노트의 연주 방법과 판정 규칙을 다룬다. 키 추가·손배치 발견을 단계적으로 체험하는 튜토리얼 과정은 별도로도, 이 학습에 통합해서도 두지 않는다. 실습에 필요한 키가 부족하면 실제 설정을 먼저 수정하도록 안내한다([RFD 0104](../rfd/0104-no-keybinding-discovery-tutorial.md)).

---

## 세분화의 이유

not4k의 입력과 판정에는 직관적이지 않은 부분이 존재한다.

- 롱노트가 이어진 경우(`o-o-`) 중간의 일반 승계 성공에는 점수나 release 판정이 없으며, 유지 실패는 Miss로 기록된다.
- 실제 release는 떼는 타이밍에 따라 Perfect/Great/Good을 판정하고, `holdOnly`는 유효한 유지 상태로 release 요구를 면제한다.
- 트릴 노트에서 교대 실패 시 Good으로 고정된다.
- 싱글→더블 전환(`o-D=`)에서 전환 시점에 릴리즈가 발생하지 않는다.
- 더블→싱글 전환(`D=o-`)에서는 릴리즈가 발생한다.
- 분할 릴리즈(`D=-`)는 더블 롱노트에서만 가능하다.

이러한 규칙을 한 번에 제시하면 유저가 압도된다. **최초 튜토리얼에서는 플레이만 가능하도록 노트의 연주 방법만 소개하고, 후속 튜토리얼에서 복합 패턴을 소개하며 판정 방식을 알려줘야 한다.**

---

## 튜토리얼 구조

### 메트로놈에 맞춘 시연과 실습

시연과 직접 입력 실습 모두 메트로놈의 박자 소리에 맞춰 진행한다. 처음 재생을 시작할 때만 첫 입력 전에 메트로놈을 4박 들려주는 준비 구간을 둔다. 이후 패턴을 반복할 때는 4박 준비 구간을 다시 넣지 않는다. 예제 차트의 박자와 메트로놈, 화면의 노트와 판정 시간을 맞춘다. 튜토리얼 전용 음악은 요구하지 않는다([RFD 0083](../rfd/0083-tutorial-metronome.md)). 아래 현재 구현에 적힌 오디오 없는 자동 시연과 구별하며, 메트로놈을 사용하는 새 학습 흐름은 미구현이다.

튜토리얼 창을 열면 곡 선택 화면의 프리뷰 재생과 재생 전 대기를 중단한다. 창을 닫으면 그때 선택된 곡을 기준으로 1초 기다린 뒤 프리뷰를 처음부터 다시 재생한다([RFD 0089](../rfd/0089-required-preview-audio-file.md)).

### 시연 후 직접 입력으로 통과

입력을 배우는 항목은 **시연 → 직접 입력 실습 → 항목별 요구 횟수만큼 누적 성공 시 통과**로 구성한다. 제시된 동작이나 짧은 패턴을 직접 연주하며, 시연을 본 것만으로 실습을 통과한 것으로 처리하지 않는다([glossary](../context/glossary.md#튜토리얼), [RFD 0081](../rfd/0081-tutorial-demonstration-and-three-practice-successes.md)). 실습 중 실패해도 성공 횟수를 줄이거나 초기화하지 않는다. 구체적인 실습 세부는 [PRD §12](../prd.md#12-미정-사항)에서 관리한다.

튜토리얼 완료·통과를 차트 선택의 선행 조건으로 두지 않는다. 실습을 통과하지 않아도 모달을 바로 닫고 곡과 차트를 선택할 수 있다. Phase 1～4는 학습 내용의 구성으로 유지한다.

처음 실습에 들어갈 때부터 `직접 입력 / 시연` 토글을 사용한다. 플레이어가 직접 입력을 선택하면 실습으로 넘어가며, 시연 종료만으로 자동 전환하지 않는다. 별도의 실습 시작 버튼은 두지 않는다.

`AutoEvent`는 튜토리얼 시연 전용이며 일반 차트의 연출 기능으로 사용하지 않는다. 새 토글과 기존 이벤트를 연결하는 구현 방식은 [PRD §12](../prd.md#12-미정-사항)에서 관리한다.

실습 전에는 현재 바인딩이 해당 실습에 필요한 키를 갖췄는지 확인한다. 부족하면 먼저 키 설정을 수정하도록 안내하고, 실제 설정이 요구를 충족한 뒤 실습을 시작한다. 실습 중에만 쓸 임시 키를 자동 배정하지 않는다. 아래 현재 구현의 자동 시연 프리뷰가 표시용 키를 보충하는 동작과 구별한다([키 바인딩 스펙](keybinding.md#튜토리얼-실습-전-키-설정)).

요구 성공 횟수는 개발자가 실습항목별로 정하는 양의 정수이며 기본값은 3회다. 플레이어가 목표 횟수를 바꾸는 설정 UI는 두지 않는다. 실습을 시작하면 성공·실패마다 버튼을 다시 누르지 않고 같은 실습을 자동 반복한다. 실패해도 성공 횟수는 유지하며, 항목별 요구 횟수만큼 누적 성공하면 반복을 마치고 통과 처리한다. 이미 통과한 항목을 다시 실습해도 새 실습에서 항목별 요구 횟수만큼 누적 성공하면 반복을 종료하며, 기존 통과 기록은 유지한다. 통과 전에도 모달을 닫을 수 있다.

항목 전체를 통과한 뒤에는 현재 항목에 머물며 `다음` 버튼을 누르면 다음 항목으로 이동한다. 통과만으로 자동 이동하지 않는다.

실습 중 시연을 다시 확인할 때는 별도 다시 보기 버튼 대신 `직접 입력 / 시연` 토글로 전환한다. 시연에 다녀와도 이미 쌓인 성공 횟수는 유지하며, 시연의 자동 입력은 성공 횟수에 포함하지 않는다.

직접 입력에서 시연으로 바꿀 때 이미 패턴이 재생 중이면 다음 패턴 시작부터 적용하고, 재생 중이 아니면 바로 적용한다. 시연에서 직접 입력으로 바꿀 때는 현재 재생 위치에서 즉시 적용한다. 시연 도중 직접 입력으로 바꾼 현재 패턴은 성공 집계에서 제외하고, 다음 패턴부터 성공 횟수를 집계한다. 항목별 목표 수치 등 남은 세부는 [PRD §12](../prd.md#12-미정-사항)에서 관리한다. 이 규칙은 튜토리얼에 적용하며 옵저버의 Auto 전환 규칙과 구별한다.

각 통과 조건은 콤보 아래에 줄을 나눠 하나씩 표시한다. 충족한 조건에는 초록 체크 아이콘을, 실패한 조건에는 빨강 X 아이콘을 표시하며 중립 상태는 흰색 글씨로 표시한다. 조건 상태는 연주 도중 실시간으로 갱신한다. 조건 목록 바로 아래에는 성공 횟수 진행도를 `현재 성공 횟수/해당 항목의 요구 성공 횟수`로 표시한다(기본값 3회인 항목의 예: `1/3`). 성공 횟수는 패턴 결과가 확정될 때 집계하며, 성공이 확정되면 진행도도 즉시 갱신한다.

각 항목에는 목표 달성률과 추가 조건을 표시한다. 실습 한 차례의 결과가 표시된 조건을 모두 만족하면 1회 성공으로 세며, 이를 해당 항목의 요구 횟수만큼 누적하면 통과한다. 일반 Good은 달성률에 반영하며 발생 자체만으로 실패 처리하지 않는다. 트릴 교대 학습에는 `goodTrill` 0회 조건을 두어 교대 실패를 성공으로 집계하지 않는다. 항목별 목표 수치와 추가 조건의 구체값은 [PRD §12](../prd.md#12-미정-사항)에서 관리한다.

직접 입력·항목별 요구 횟수만큼 누적 성공 통과는 아직 구현하지 않았다. 아래 곡 선택 도움말 팝업은 현재 구현을 설명하며, 새 목표인 실습형 튜토리얼과 구별한다.

실습 과제는 올바른 연주 방법을 익히는 내용으로만 구성한다. 판정의 실패 사례는 시연으로 설명하고, 실패 동작을 직접 재현해야 통과하는 과제는 두지 않는다. 실습에서 실제로 발생한 실패는 일반 규칙대로 판정하며 항목별 달성률·추가 조건으로 성공 여부를 판단한다.

### 실습 중 키 선택과 표시

실습에서는 노트를 보고 직접 사용할 키를 판단한다. 다음에 눌러야 할 키를 미리 알려주는 가이드는 표시하지 않는다. 시연에서 보여주는 입력 안내를 실습의 사전 키 안내로 이어서 표시하지 않으며, 실제 누른 키의 표시와 노트·`trillZone` 등 입력 요구를 알리는 시각 표시는 유지한다.

튜토리얼의 노트 낙하 속도는 튜토리얼용 고정값을 사용한다. 플레이어의 본 플레이 설정에 연동하지 않으며 본 플레이의 설정값도 변경하지 않는다. 구체적인 고정값은 [PRD §12](../prd.md#12-미정-사항)에서 관리한다.

### 통과 기록과 재진입

튜토리얼을 닫았다 다시 열면 마지막으로 선택한 탭과 항목을 연다. 마지막으로 선택한 탭과 항목을 브라우저에 저장해 게임을 껐다 켜도 복원한다. 로그인하면 마지막으로 선택한 탭과 항목도 계정과 동기화해 다른 기기에서 같은 위치를 이어 볼 수 있게 한다. 기기마다 마지막 열람 위치가 다르면 실제로 가장 최근에 선택한 탭과 항목을 사용한다. 동기화 요청이 나중에 도착했다는 이유로 더 오래된 선택 위치가 최신 위치를 덮어쓰지 않는다. 선택 이력이 없는 최초 진입은 `Basic` 첫 항목에서 시작한다. 항목 위치 복원과 미완료 실습의 성공 횟수 복원은 구별한다. 실습 기록으로는 항목 전체 통과 여부만 로그인 여부와 관계없이 브라우저에 저장한다. 로그인하면 항목 전체 통과 여부를 계정과 동기화해 다른 기기에서도 같은 통과 표시를 확인할 수 있게 한다. 브라우저와 계정 중 어느 쪽에서든 전체 통과한 항목은 합쳐 보존한다. 현재 방법·부분 성공 횟수·중간 방법 완료 여부는 현재 실습 세션에서만 유지하고 영구 저장·계정 동기화하지 않는다. 미완료 항목을 닫았다 다시 열거나 다른 항목에서 돌아오거나 게임을 재시작하면 첫 번째 방법의 성공 횟수 0회부터 시작한다. 이미 전체 통과한 항목의 재실습도 첫 번째 방법 0회부터 새로 진행하되 과거 항목 통과 기록은 지우지 않는다. 같은 항목 안에서 시연/직접 입력을 토글할 때는 현재 방법과 누적 성공 횟수를 유지하며 기존 전환·집계 규칙을 따른다. 튜토리얼 목록에서 통과한 항목에 체크 표시를 붙인다. 시연만 본 항목에는 통과 체크를 붙이지 않으며, 별도의 열람 표시도 두지 않는다. 여러 연주 방법을 각각 실습하는 항목은 필요한 모든 방법을 통과해야 항목 전체를 통과로 표시한다. 튜토리얼을 닫았다 다시 열면 미완료 실습은 성공 횟수 0회부터 시작한다. 누적 성공 1회·2회 같은 중간 진행도는 저장·복원하지 않으며, 이미 전체 통과한 항목의 기록은 유지한다. 같은 실습을 이어가는 동안 실패한 경우에는 기존 성공 횟수를 유지한다. 다른 튜토리얼 항목으로 이동했다 돌아오는 경우에도 미완료 실습의 성공 횟수는 0회로 초기화한다. 같은 항목에서 직접 입력/시연을 토글할 때는 성공 횟수를 유지한다.

### 피스 이름의 사용 범위

플레이어에게 공식 피스 이름은 튜토리얼 제목 정도에만 사용한다. 본문은 실제로 어떤 키를 누르고 유지하며 전환하는지 설명하고, 이름을 외워야 안내를 이해할 수 있게 만들지 않는다([glossary](../context/glossary.md#피스-piece), [RFD 0080](../rfd/0080-piece-names-in-tutorial-titles.md)). 모든 항목의 제목을 피스 이름으로 통일할 필요는 없다. 제작·분석 문서에서는 공식 이름과 ID를 계속 사용한다.

### 연주 방법 안내의 진입 원칙

플레이 결과에 따른 키 활용·연주 방법 안내는 플레이어가 도움말·튜토리얼을 선택했을 때 제공한다. 실패 결과만으로 자동 조언하거나 도움말을 열고 튜토리얼로 전환하지 않는다([RFD 0054](../rfd/0054-player-requested-playing-guidance.md)). 첫 기동 온보딩의 진입 방식과는 별개의 원칙이다.

### 첫 기동의 튜토리얼 모달

첫 기동에는 프리셋 설정을 마친 뒤 곡 선택 화면 위에 튜토리얼 도움말 모달을 연다. 처음부터 바로 닫을 수 있으며, 항목 보기·실습·완료 확인이나 단계별 스킵을 닫기의 조건으로 두지 않는다. 닫으면 곡 선택 화면을 그대로 이용한다. 이후에는 곡 선택의 `?` 버튼으로 다시 연다([RFD 0055](../rfd/0055-first-launch-tutorial-modal.md)).

Phase 1～4는 학습 내용의 구성이다. 첫 기동에 순서대로 진행하거나 완료해야 하는 절차로 사용하지 않는다. 도움말 모달과 수동 재진입은 구현되어 있으나 첫 기동 자동 열기는 미구현이다.

### 곡 선택 도움말 팝업

> **현재 구현:** 아래 자동 시연 목록과 본 항목 체크는 실습형 개편 전의 동작이다. 본 항목 체크는 열람 기록이며 직접 입력 실습의 통과 기록이 아니다. 개편 후에는 별도 열람 표시를 없애고 실습 통과 체크만 표시한다. 다시 열 때 마지막 선택 항목을 복원하는 동작도 개편 목표이며, 아래 첫 항목 진입 설명은 현재 구현에 해당한다.

곡 선택 화면 상단의 `?` 버튼은 기본 입력과 확정된 판정 규칙을 복습하는 도움말이다. `Basic` 탭은 입문 17개, `Advanced` 탭은 복합 판정 시연 12개를 제공한다. 중앙 팝업으로 열리며, 왼쪽 인덱스, 가운데 카드형 축소 재생기, 오른쪽 텍스트 전용 영역으로 분할된다. 팝업을 열면 `Basic` 첫 항목에서 시작한다. 좌우 화살표 버튼·키보드 방향키는 선택한 탭 안에서만 순환하고, 왼쪽 인덱스와 페이지 수 역시 그 탭의 항목만 표시한다. 열려 있는 동안 탭별 마지막 선택 위치를 기억한다. 탭에 포커스가 있으면 좌우 방향키와 Home/End는 탭 선택·포커스만 옮기며 레슨을 함께 넘기지 않는다. 탭은 `tablist`·`tab`·`tabpanel` 관계와 선택 상태를 제공한다. 여러 개의 짧은 튜토리얼 전용 차트를 순환하며, 이미 본 항목은 인덱스 제목 옆에 체크 표시를 붙인다. 두 탭의 본 항목 체크 상태는 기존 ID를 유지한 채 브라우저 저장소의 `not4k-tutorial-viewed-ids`에 저장해 팝업을 닫았다가 다시 열어도 유지한다. 개발환경이거나 현재 유저가 admin이면 디버깅용 `Reset Viewed` 버튼을 표시하고, 이 버튼은 저장된 본 항목 캐시를 삭제한 뒤 `Basic` 첫 항목만 본 상태로 즉시 초기화한다. 페이지를 넘길 때는 축소 재생기 슬롯 2개를 팝업이 열려 있는 동안 계속 마운트해 두고, 두 슬롯이 번갈아 보이지 않는 쪽에 다음 차트를 준비한다. 각 슬롯은 렌더러(WebGL 캔버스)를 유지한 채 차트만 바꿔 걸기 때문에, 레슨을 넘길 때마다 렌더러를 새로 만들지 않는다. 같은 레슨을 다시 방문해도 그 슬롯에 차트를 다시 걸어 처음부터 재생한다. 새 차트의 첫 프레임을 렌더링한 뒤 가운데 카드 뷰포트 안에서 이전 차트와 다음 차트를 좌우 캐러셀처럼 이동시켜 빈 프레임 깜빡임을 피하고 페이지 관계를 보여준다. 들어오는 재생기는 이동하는 동안 첫 프레임에 멈춰 있다가 자리를 잡은 뒤 차트를 처음부터 재생하고, 밀려나는 재생기는 이동이 끝날 때까지 이어서 재생한다. 보이지 않는 대기 슬롯은 재생을 진행하지 않는다. 모달을 열 때는 첫 프레임이 준비될 때까지 구동기를 카드 안에서 숨기고, 닫을 때는 구동기를 먼저 숨긴 뒤 짧은 종료 전환 후 언마운트해 캔버스 준비/정리 중 깨진 프레임이 보이지 않게 한다. 각 차트 안의 `tutorialInput` 이벤트가 어떤 레인의 어떤 키를 언제 누르고 떼는지 정의하고, 필요한 경우 `tutorialDiagram` 이벤트가 축소 재생기 위에 노트 패턴 도식을 표시한다. 키 입력 표시 영역은 최초 설정에서 선택한 키보드 프리셋(TKL 또는 Numpad)을 반영하며, `tutorialInput`은 레인 기준으로 현재 프리셋의 실제 바인딩 키에 매핑되어 표시된다. 시연의 `BindingN`과 기본 TKL/Numpad 키는 레인별 슬롯으로 해석하여 현재 바인딩에 매핑한다. 예를 들어 시연의 첫 키와 둘째 키는 사용자가 첫 슬롯에 W를 배정했어도 서로 다른 입력으로 유지된다. 매핑된 키는 키보드에서 강조하고, 매핑되지 않은 키는 비활성 상태처럼 어둡게 표시한다. 축소 재생기의 판정선 아래에는 레인별 대응 키를 큰 키 사각형으로 하나씩 표시하되, 입력 전 기본 라벨은 해당 레인의 가장 이른 입력 묶음을 보여주고, 입력 중에는 실제 눌리는 키 라벨로 바뀌며, 릴리즈 뒤에도 다음 입력 전까지 마지막 라벨을 유지한다. 더블 노트처럼 같은 레인에서 두 키를 동시에 누르면 시작 라벨과 입력 중 라벨 모두 두 키를 같은 큰 키 사각형 안에 함께 표시한다.

각 전용 차트는 4박 또는 8박을 채우기 위해 무관한 노트를 추가하지 않고, 레슨 내용에 맞는 길이의 루프를 사용한다. `Advanced`는 입력 시작 전 낙하 시간과 마지막 판정 기한 이후의 여백을 두어 실패 판정도 다음 반복 전에 확인할 수 있게 한다. 축소 재생기의 판정 표시는 별도 간이 규칙을 만들지 않고 플레이 화면과 같은 `NoteJudgmentSession`에 `tutorialInput`을 원래 timestamp별 down/up 묶음으로 넣어 생성한다. 확정 효과와 unit 상태를 `SessionRendererAdapter`로 표시한다. 반복 경계에서는 이전 세션을 `loopMs`까지 진행하여 끝과 정확히 같은 시각의 release도 한 번 정산한 뒤, 세션과 head 표시 캐시를 초기화한다. 다음 반복에 이전 누름·정산 상태를 넘기지 않는다. 이 순서는 `tutorialPreviewSession.test.ts`와 실제 팝업의 두 번 반복을 확인하는 `e2e/game/tutorial-note-judgment.spec.ts`로 검증한다. `tutorialDiagram`은 정적 설명 이미지가 아니라 에디터 `NoteRenderer`의 표기법을 따른 SVG 도식으로 표시한다. 롱노트 도식은 한 줄 방정식으로 배치하며, 시작점은 아래·끝점은 위로 읽는다. 에디터와 같은 5:1 노트 비율을 유지하되 노트 도형은 레인 중앙에서 0.5배 스케일로 표시한다. 롱노트 끝점은 별도 end cap으로 그리지 않고 body가 끝점 자리까지 이어지며, 롱노트 시작점에는 일반 노트 헤드를 함께 표시한다. 개발 중에는 `/lab/tutorial-pattern-diagram`에서 도식만 단독 렌더링해 캡처한다. 도식은 등장/퇴장 애니메이션을 가지며, 도식 구간에 진입하면 화면 전체를 dim 한 확인 모달로 표시하고 축소 재생 시간은 도식 시작점에 멈춘다. 확인 모달은 축소 재생기 카드가 아니라 뷰포트 기준(문서 최상위로 portal)으로 그려, 카드가 화면 밖으로 밀리는 작은/가로 모바일에서도 도식과 OK 버튼이 잘리지 않고 항상 화면 중앙에 보이도록 한다. 도식 자체도 레인 폭(1fr)·`aspect-ratio`·`clamp` 글자 크기로 반응형이며, 큰 화면에서는 상한 높이까지만 커진다. 사용자가 OK를 누르면 도식 구간의 끝 시점으로 재개하며, 도식 퇴장 후에는 약 2초의 낙하 시간을 둔 뒤 실제 노트 시연으로 넘어간다. 이 팝업은 튜토리얼 Phase 진행 상태를 바꾸지 않으며, 오디오·결과 저장 없이 판정·정산을 재생하고 입력 시연을 표시한다. 전체 튜토리얼은 아래 Phase 구조에서 다룬다.

| 8 | `advanced-independent-holdonly` | 미리 누르던 키로 독립 양수 `holdOnly`를 시작할 수 없다. 뒤의 별도 롱노트는 새 입력으로 성공한다. | Perfect 1, Miss 1, 50%, Full Combo 아님 |
| 9 | `advanced-short-holdonly` | 끝을 지난 초단 `holdOnly`도 시작의 Good 창 안이면 첫 활성화가 가능하다. | Perfect 1, Miss 0, 100%, Full Combo |
| 10 | `advanced-zero-holdonly` | 길이 0 `holdOnly`는 간격 앞부터 유지한 키로도 완료한다. 새 release 권한은 생기지 않는다. | Perfect 2, Miss 0, 100%, Full Combo |
| 11 | `advanced-double-release` | 더블 끝에서 한 키를 임의로 두 번 눌렀다 떼도 나머지 한쪽의 release를 대신하지 못한다. | Perfect 3, Miss 1, 75%, Full Combo 아님 |

시연에 현재 설정보다 많은 키가 필요하면 프리뷰 안에서만 해당 레인의 키를 보충한다. 예를 들어 1번 레인에 `Q W`만 배정한 설정에서 네 키를 쓰는 시연은 `Q W S X`를 표시한다. 다른 레인의 설정 키와 중복하지 않으며, 보충한 배치와 옵션에서 키를 추가할 수 있다는 안내를 함께 표시한다. 사용자의 실제 설정은 변경하지 않는다. 이미 충분한 키가 있으면 현재 바인딩을 그대로 따른다.

검증은 `advancedTutorialPreviews.test.ts`에서 차트 배치 제약·물리적으로 가능한 누름/떼기·실제 세션의 반복별 결과를 검사한다. 탭 내부 순환과 기존 체크 캐시 호환은 `tutorialCatalog.test.ts`, 실제 팝업의 탭·키보드·캐시·좁은 화면 동작은 `e2e/game/advanced-tutorial.spec.ts`에서 확인한다.

두 재생기 슬롯이 공유하는 스킨 텍스처는 `SkinManager`가 경로별 참조 수로 관리한다. 마지막 사용자가 사라질 때만 해제하고, 같은 경로의 비동기 로드·해제 순서를 보장한다. 렌더러와 스킨은 팝업을 닫을 때(또는 스킨·키보드 프리셋이 바뀔 때)만 정리하며, 이때 초기화가 진행 중이면 초기화를 마친 뒤 해당 재생기와 스킨을 함께 정리한다. 이전 초기화의 완료·실패가 새 슬롯의 자산을 해제해서는 안 된다. `SkinManager.test.ts`는 공유 자산과 비동기 해제 중 재진입을 검증한다. `GameRenderer.dispose()`는 해당 앱의 캔버스·자식만 정리하고 Pixi 전역 풀을 비우지 않는다. 다른 슬롯이 그 풀에서 받아 아직 쓰는 텍스트 텍스처와 bounds가 있기 때문이다. `GameRenderer.lifecycle.test.ts`는 한 슬롯을 닫은 뒤 다른 슬롯의 텍스처 반환·재사용과 늦은 프레임 무시를 검증한다. 같은 렌더러에 다른 차트를 걸 때는 `GameRenderer.resetTransientState()`가 이전 차트의 봄·판정 텍스트·키빔·키 눌림·이벤트 문구를 지우고, `updateTutorialKeyboardKeys()`가 키캡 배치를 유지한 채 차트별 키 라벨·매핑만 바꾸며, `setChart()`가 Grace·그림자를 포함한 노트 풀을 비운다(`GameRenderer.reuse.test.ts`·`GameNoteRenderer.test.ts`). 두 슬롯이 레슨을 넘겨도 같은 캔버스와 렌더러 2개를 유지하는지는 `e2e/game/tutorial-preview-pingpong.spec.ts`에서 확인한다.

### Phase 1: 연주 방법 — "이렇게 치면 된다"

노트 타입별 기본 입력 방법만 소개한다. 판정의 세부 규칙은 언급하지 않는다.

| 항목 | 소개하는 것 | 소개하지 않는 것 |
|------|------------|-----------------|
| 싱글 노트 | 키를 누른다 | 판정 윈도우 수치 |
| 롱 노트 | 키를 누르고 있다가 뗀다 | 홀드 교대, 유예 시간, 릴리즈 상향 |
| 트릴 노트 | `trillZone`에서 키를 번갈아 누른다 | 교대 실패 시 Good 고정 |
| 더블 노트 | 다른 키 2개를 동시에 누른다 | 독립 판정 × 2, 배드말림 해제 |

목표: 유저가 **모든 노트 타입을 처리할 수 있는 상태**가 된다. "왜 이 판정이 나왔는지"는 아직 알 필요 없다.

### Phase 2: 복합 패턴과 판정 — "왜 이렇게 되는가"

Phase 1의 연주 능력을 전제로, 복합 패턴에서 발생하는 판정 규칙을 소개한다.

실패 판정이 발생하는 동작은 시연으로 보여준다. 직접 입력 실습에서는 해당 규칙을 지키는 올바른 연주 방법을 연습한다.

- 연결된 바디의 무점수 승계, 실제 감소·종료 release, 유지 실패의 차이
- 실제 release의 타이밍 판정과 `holdOnly`의 유지 상태 Perfect
- 트릴 교대 실패 시 Good 고정 (`goodTrill`)
- 롱노트 `connection` 시 키 수 변화에 따른 릴리즈 발생 규칙
- 분할 릴리즈(`D=-`)의 판정 횟수

목표: 유저가 **자신의 판정 결과를 이해하고 개선 방향을 파악할 수 있는 상태**가 된다.

### Phase 3: 홀드 교대와 헤드 없는 롱노트 — "홀드의 확장"

홀드 교대는 기존 유지와 새 시작을 함께 이해해야 하는 동작이므로 튜토리얼에서 시연한다. 롱노트 진행 중에 다른 키로 홀드를 이어받을 수 있음을 실제 입력으로 보여준다. 이 문서의 학습 순서는 판정 규칙 학습 이후로 두되, 차트에서 해당 동작이 처음 등장할 수 있는 레벨을 정하는 제한으로 사용하지 않는다.

- 롱노트를 A로 유지하다가 B로 이어잡아도 끊기지 않는다는 것을 체험시킨다.
- 연결 head의 허용 창 안에서 A를 떼고 B를 눌러 교대할 수 있음을 시연한다. 같은 키의 재타격에도 같은 연결 보정을 적용한다.

롱노트 중 탭은 같은 노트 배치에서 다음 두 연주 방법을 모두 시연한다(사용자 확인, 2026-10-29).

- 기존 키를 계속 누른 채 같은 레인의 다른 키로 탭한다.
- 다른 키로 탭하면서 기존 키를 떼고, 새 키로 롱노트 유지를 이어받는다.

롱노트 중 탭은 한 항목 안에서 기존 키를 유지하는 방법을 먼저 시연·실습하고, 그 방법의 목표를 달성한 뒤 유지 키를 교대하는 방법을 시연·실습한다. 첫 방법의 목표를 달성하면 반복을 멈추고 현재 단계에 머물며, `다음` 버튼으로 두 번째 방법으로 이동한다. 자동으로 다음 방법으로 전환하지 않는다. 두 방법 모두 목표를 달성해야 항목 전체를 통과한다. 두 방법을 자유롭게 번갈아 선택하는 방식으로 만들거나 전체 튜토리얼 항목의 순서를 잠그는 것으로 확대하지 않는다. 각 방법에서 해당 항목의 요구 횟수만큼 성공을 누적한다. 성공 횟수를 방법별로 따로 집계하며, 한 방법의 성공 횟수를 다른 방법에 합산하지 않는다. 실습 중 실패해도 해당 방법에서 이미 쌓인 성공 횟수는 유지한다.

두 방법을 보여주는 시연 차트는 어느 방법으로도 의도한 연주가 성립하도록 구성한다. 홀드 교대를 이 배치를 처리하는 필수 전제로 안내하지 않는다. 피스 이름은 제목 정도에만 사용하고, 본문은 위와 같이 실제 입력 동작을 설명한다. 기존 공개 튜토리얼 목록의 개편은 [PRD §12](../prd.md#12-미정-사항)의 후속 작업이며, 이번 결정은 설계에 반영한 것이다.

이어서 **헤드 없는 롱노트**를 소개한다. 시작 탭 노트 유무와 바디의 유지 요구를 구별해 이해하도록 홀드 교대를 학습한 직후에 배치한다. 난이도명 전용 패턴으로 안내하지 않는다.

- 헤드 없는 롱노트의 개념을 소개한다: 시작 타이밍 점수는 없지만 시작 근처의 새 누름 또는 정당한 연결 승계가 필요하다.
- `.-` 패턴을 체험시킨다: 헤드 없는 롱노트의 시작 근처에서 눌러 바디를 활성화하고 끝에 맞춰 뗀다.
- `-=` 패턴(`o-=`)을 체험시킨다: 싱글 홀드 중 헤드 없는 롱노트가 추가되어 더블 홀드로 전환한다. `o-D=`와 달리 전환 시점에 노트 헤드 판정이 없다.
- 난이도명에 따른 사용 제한은 없으며, 실제 독해·연주 부담이 낮으면 낮은 레벨에서도 짧게 등장할 수 있음을 안내한다([배치 기준](difficulty-design.md#헤드-없는-바디-패턴의-배치-기준)).

목표: 유저가 **롱노트 중 탭을 유지와 교대 두 방법으로 연주할 수 있음을 이해하고, 헤드 없는 롱노트의 개념을 이해한 상태**가 된다.

### Phase 4: 16키 — "한 레인에 4키 활용"

8키(레인당 2키)를 넘어, 기본 프리셋의 16키(레인당 4키)를 완전히 활용하는 단계를 소개한다.

- 3키 바인딩이 필요한 피스를 소개한다: 더블 홀드 + 싱글 노트 처리, 3박자 기반 트릴(24비트) 등.
- 3키 트릴(`A → B → C → A → B → C`)이 2키 트릴보다 자연스러운 상황을 체험시킨다.
- 32비트 고속 트릴에서 4키 교대(`A → B → C → D → A → B → C → D`)로 피로를 분산하는 방법을 소개한다.
- 더블 홀드 + 트릴: 4키 중 2키로 더블 홀드를 유지하면서 나머지 2키로 트릴을 처리하는 연습.

목표: 유저가 **16키 바인딩의 이점을 이해하고, 레인당 4키를 활용할 수 있는 상태**가 된다.
