# not4k — 튜토리얼 설계

이 문서는 노트 연주법과 판정 방식을 단계적으로 소개하는 튜토리얼의 설계를 정의한다.

> **키 바인딩 튜토리얼과의 관계**: `keybinding.md`의 튜토리얼 흐름은 물리적 키 배치의 발견(4키 → 6키 → 8키)에 집중한다. 이 문서의 튜토리얼은 노트 메커니즘과 판정 규칙의 학습에 집중한다. 두 트랙은 병행 또는 순차적으로 진행될 수 있으며, 구체적인 결합 방식은 TBD.

---

## 세분화의 이유

not4k의 입력과 판정에는 직관적이지 않은 부분이 존재한다.

- 롱노트가 이어진 경우(`o-o-`)에는 `termination` 판정이 존재하지 않고 `connection` 판정으로 대체된다.
- `termination` 판정에서 Good 이상은 Perfect로 상향 처리된다.
- 트릴 노트에서 교대 실패 시 Good으로 고정된다.
- 싱글→더블 전환(`o-D=`)에서 전환 시점에 릴리즈가 발생하지 않는다.
- 더블→싱글 전환(`D=o-`)에서는 릴리즈가 발생한다.
- 분할 릴리즈(`D=-`)는 더블 롱노트에서만 가능하다.

이러한 규칙을 한 번에 제시하면 유저가 압도된다. **최초 튜토리얼에서는 플레이만 가능하도록 노트의 연주 방법만 소개하고, 후속 튜토리얼에서 복합 패턴을 소개하며 판정 방식을 알려줘야 한다.**

## 튜토리얼 구조

### 곡 선택 도움말 팝업

곡 선택 화면 상단의 `?` 버튼은 전체 튜토리얼 재진입 전에 기본 입력을 빠르게 떠올리는 경량 도움말이다. 중앙 팝업으로 열리며, 왼쪽 인덱스, 가운데 카드형 축소 재생기, 오른쪽 텍스트 전용 영역으로 분할된다. 팝업은 여러 개의 짧은 튜토리얼 전용 차트를 좌우 화살표 버튼 또는 왼쪽 인덱스로 순환하며, 이미 본 항목은 인덱스 제목 옆에 체크 표시를 붙인다. 본 항목 체크 상태는 브라우저 저장소의 `not4k-tutorial-viewed-ids`에 저장해 팝업을 닫았다가 다시 열어도 유지한다. 개발환경이거나 현재 유저가 admin이면 디버깅용 `Reset Viewed` 버튼을 표시하고, 이 버튼은 저장된 본 항목 캐시를 삭제한 뒤 첫 항목만 본 상태로 즉시 초기화한다. 페이지를 넘길 때는 축소 재생기 슬롯 2개를 항상 마운트해 두고, 보이지 않는 슬롯에 다음 차트를 준비한다. 새 재생기가 첫 프레임을 렌더링한 뒤 가운데 카드 뷰포트 안에서 이전 차트와 다음 차트를 좌우 캐러셀처럼 이동시켜 빈 프레임 깜빡임을 피하고 페이지 관계를 보여준다. 모달을 열 때는 첫 프레임이 준비될 때까지 구동기를 카드 안에서 숨기고, 닫을 때는 구동기를 먼저 숨긴 뒤 짧은 종료 전환 후 언마운트해 캔버스 준비/정리 중 깨진 프레임이 보이지 않게 한다. 각 차트 안의 `tutorialInput` 이벤트가 어떤 레인의 어떤 키를 언제 누르고 떼는지 정의하고, 필요한 경우 `tutorialDiagram` 이벤트가 축소 재생기 위에 노트 패턴 도식을 표시한다. 키 입력 표시 영역은 최초 설정에서 선택한 키보드 프리셋(TKL 또는 Numpad)을 반영하며, `tutorialInput`은 레인 기준으로 현재 프리셋의 실제 바인딩 키에 매핑되어 표시된다. 프리셋에 없는 키는 TKL/Numpad 기본 바인딩의 같은 슬롯 관계를 따라 현재 프리셋 키로 바꾼다. 매핑된 키는 키보드에서 강조하고, 매핑되지 않은 키는 비활성 상태처럼 어둡게 표시한다. 축소 재생기의 판정선 아래에는 레인별 대응 키를 큰 키 사각형으로 하나씩 표시하되, 입력 전 기본 라벨은 해당 레인의 가장 이른 입력 묶음을 보여주고, 입력 중에는 실제 눌리는 키 라벨로 바뀌며, 릴리즈 뒤에도 다음 입력 전까지 마지막 라벨을 유지한다. 더블 노트처럼 같은 레인에서 두 키를 동시에 누르면 시작 라벨과 입력 중 라벨 모두 두 키를 같은 큰 키 사각형 안에 함께 표시한다.

각 전용 차트는 4박 또는 8박을 채우기 위해 무관한 노트를 추가하지 않고, 레슨 내용에 맞는 3·4·5·7·8·9박 루프를 사용한다. 축소 재생기의 판정 표시는 별도 간이 규칙을 만들지 않고 플레이 화면과 같은 `JudgmentEngine`에 `tutorialInput` press/release를 넣어 생성한다. `tutorialDiagram`은 정적 설명 이미지가 아니라 에디터 `NoteRenderer`의 표기법을 따른 SVG 도식으로 표시한다. 롱노트 도식은 한 줄 방정식으로 배치하며, 시작점은 아래·끝점은 위로 읽는다. 에디터와 같은 5:1 노트 비율을 유지하되 노트 도형은 레인 중앙에서 0.5배 스케일로 표시한다. 롱노트 끝점은 별도 end cap으로 그리지 않고 body가 끝점 자리까지 이어지며, 롱노트 시작점에는 일반 노트 헤드를 함께 표시한다. 개발 중에는 `/lab/tutorial-pattern-diagram`에서 도식만 단독 렌더링해 캡처한다. 도식은 등장/퇴장 애니메이션을 가지며, 도식 구간에 진입하면 화면 전체를 dim 한 확인 모달로 표시하고 축소 재생 시간은 도식 시작점에 멈춘다. 확인 모달은 축소 재생기 카드가 아니라 뷰포트 기준(문서 최상위로 portal)으로 그려, 카드가 화면 밖으로 밀리는 작은/가로 모바일에서도 도식과 OK 버튼이 잘리지 않고 항상 화면 중앙에 보이도록 한다. 도식 자체도 레인 폭(1fr)·`aspect-ratio`·`clamp` 글자 크기로 반응형이며, 큰 화면에서는 상한 높이까지만 커진다. 사용자가 OK를 누르면 도식 구간의 끝 시점으로 재개하며, 도식 퇴장 후에는 약 2초의 낙하 시간을 둔 뒤 실제 노트 시연으로 넘어간다. 이 팝업은 튜토리얼 Phase 진행 상태를 바꾸지 않으며, 오디오·점수·결과 저장 없이 렌더링과 입력 시연만 실행한다. 전체 튜토리얼은 아래 Phase 구조에서 다룬다.

#### 곡 선택 도움말 팝업 단계

| 번호 | 제목 | 안내 내용 |
|------|------|-----------|
| 0 | 손배치 | 낙하 노트 없이 설명 대상 키만 활성화한다. 왼손은 `Q W E C`에 올리고, 반대손은 현재 TKL/Numpad 배치와 바인딩에 맞춰 표시한다. 키 배치는 옵션에서 바꿀 수 있음을 안내한다. |
| 1 | 싱글 노트 | 한 레인에 여러 키를 바인딩할 수 있으며, 같은 노트를 다양한 키로 처리할 수 있음을 시연한다. |
| 2 | 더블 노트 | 같은 레인의 두 키를 동시에 누른다. |
| 3 | 트릴 구간 / 트릴 노트 | 2레인과 3레인에서 교대 입력과 같은 키 입력을 각각 4노트씩 시연한다. 같은 키를 연속으로 누르면 `GOOD◇`으로 강등됨을 안내한다. |
| 4 | 롱노트 | 롱노트는 시작할 때 누르고 끝날 때 떼며, 싱글·더블·트릴 롱노트를 모두 시연한다. 트릴 롱노트는 트릴 구간 안에서 누른 키를 끝까지 유지한다. |
| 5 | 릴리즈탭 | 롱노트 끝에 노트가 함께 나올 수 있으며, 떼는 순간에 다른 키를 함께 누른다. 끝에 노트가 있으면 롱노트 떼기 판정이 없다. |
| 6 | 이어진 롱노트 - 갈아타기 | `o- + o- = o-o-` 도식과 함께 키를 갈아타는 `a-b-` 처리를 시연한다. 이 도식의 두 입력 노트는 하나는 아래, 하나는 위로 정렬해 연결 전후 위치 차이를 보여준다. 도식 뒤에는 약 2초의 낙하 시간을 둔 뒤 노트가 판정선에 도착한다. 연결 지점에서는 이전 키를 떼는 타이밍을 따로 판정하지 않음을 안내한다. |
| 7 | 이어진 롱노트 - 겹쳐 누르기 | `o--- + .o.. = o-o-` 도식과 함께 기존 키를 누른 채 새 키를 더하는 처리를 시연한다. 도식 뒤에는 약 2초의 낙하 시간을 둔 뒤 노트가 판정선에 도착한다. 연결 지점에서는 이전 키를 떼는 타이밍을 따로 판정하지 않음을 안내한다. |
| 8 | 이어진 트릴 롱노트 | 트릴 롱노트가 이어진 `t-t-`도 이어진 롱노트와 동일하게 갈아타기·겹쳐 누르기로 처리할 수 있음을 안내한다. 두 방식을 한 차트에서 나란히 보여준다(2레인은 갈아타기, 3레인은 겹쳐 누르기). 연결점이 트릴 헤드라 이어질 때마다 다른 키로 교대해야 하는 점은 별도 문구 없이 서로 다른 키를 쓰는 실연으로 보여주며, 도식은 생략한다. |
| 9 | 헤드 없는 롱노트 | 롱노트가 일반 노트 없이 시작될 수 있으며, 시작 타이밍에 맞춰 누르지 않아도 되지만 롱노트 안에서는 키를 유지해야 함을 안내한다. |
| 10 | 길이가 0인 롱노트 | 누르기·유지 판정 없이 떼기 판정만 존재하는 롱노트를 안내한다. |
| 11 | grace 노트 | Good 윈도우 안에 입력하면 Perfect로 승급되는 포인트 노트를 안내한다. |
| 12 | grace 롱노트 | 끝나는 시점에 떼지 않아도 되는 grace 롱노트 동작을 안내한다. |
| 13 | 길이가 0인 grace 롱노트 | 길이가 0인 hold-only 롱노트로, Good 윈도우 안에서 키를 누르고 있으면 되는 동작을 안내한다. |
| 14 | 수평 이동 | 고정된 손배치로 처리하기 어려운 패턴을 유동적인 손배치로 처리해 보도록 안내한다. |
| 15 | 수직 이동 | 수직으로 이동해서 노트를 처리할 수 있음을 안내한다. |

### Phase 1: 연주 방법 — "이렇게 치면 된다"

노트 타입별 기본 입력 방법만 소개한다. 판정의 세부 규칙은 언급하지 않는다.

| 항목 | 소개하는 것 | 소개하지 않는 것 |
|------|------------|-----------------|
| 싱글 노트 | 키를 누른다 | 판정 윈도우 수치 |
| 롱 노트 | 키를 누르고 있다가 뗀다 | 홀드 교대, 유예 시간, 릴리즈 상향 |
| 트릴 노트 | `trillZone`에서 키를 번갈아 누른다 | 교대 실패 시 Good 고정 |
| 더블 노트 | 다른 키 2개를 동시에 누른다 | 독립 판정 × 2, 배드말림 해제 |

목표: 유저가 **모든 노트 타입을 처리할 수 있는 상태**가 된다. "왜 이 판정이 나왔는지"는 아직 알 필요 없다.

### Phase 2: 복합 패턴과 판정 — "왜 이렇게 되는가"

Phase 1의 연주 능력을 전제로, 복합 패턴에서 발생하는 판정 규칙을 소개한다.

- 롱노트 `connection` 시 `termination` 판정 vs `connection` 판정의 차이
- `termination` 판정의 Good 이상 → Perfect 상향
- 트릴 교대 실패 시 Good 고정 (`goodTrill`)
- 롱노트 `connection` 시 키 수 변화에 따른 릴리즈 발생 규칙
- 분할 릴리즈(`D=-`)의 판정 횟수

목표: 유저가 **자신의 판정 결과를 이해하고 개선 방향을 파악할 수 있는 상태**가 된다.

### Phase 3: 홀드 교대와 헤드 없는 롱노트 — "홀드의 확장"

홀드 교대는 추가 키를 사용해야 하는 동작이므로 반드시 튜토리얼이 필요하다. 롱노트 진행 중에 다른 키로 홀드를 이어받는 것은 기존 리듬게임에 없는 개념이며, 유저가 스스로 발견하기 어렵다. 고난이도에서만 사용되므로 판정 규칙 학습 이후에 배치한다.

- 롱노트를 A로 유지하다가 B로 이어잡아도 끊기지 않는다는 것을 체험시킨다.
- 유예 시간(grace period)의 존재를 암시한다: A를 떼고 B를 약간 늦게 눌러도 유지된다.
- 홀드 교대가 홀드 중 탭 피스의 전제 조건임을 소개한다.

이어서 **헤드 없는 롱노트**를 소개한다. HARD 차트에서만 등장하는 새로운 유형이므로, 홀드 교대를 학습한 직후에 배치한다.

- 헤드 없는 롱노트의 개념을 소개한다: 시작점에 노트가 없으므로 프레스 판정이 없고, 키를 미리 유지하고 있어야 한다.
- `.-` 패턴을 체험시킨다: 헤드 없는 롱노트의 바디가 시작되는 시점에 키가 눌려 있어야 한다.
- `-=` 패턴(`o-=`)을 체험시킨다: 싱글 홀드 중 헤드 없는 롱노트가 추가되어 더블 홀드로 전환한다. `o-D=`와 달리 전환 시점에 노트 헤드 판정이 없다.
- 이 패턴들이 HARD 차트에서만 등장한다는 것을 안내한다.

목표: 유저가 **롱노트 중 키 전환이 가능하다는 것을 체득하고, 헤드 없는 롱노트의 개념을 이해한 상태**가 된다.

### Phase 4: 16키 — "한 레인에 4키 활용"

8키(레인당 2키)를 넘어, 기본 프리셋의 16키(레인당 4키)를 완전히 활용하는 단계를 소개한다.

- 3키 바인딩이 필요한 피스를 소개한다: 더블 홀드 + 싱글 노트 처리, 3박자 기반 트릴(24비트) 등.
- 3키 트릴(`A → B → C → A → B → C`)이 2키 트릴보다 자연스러운 상황을 체험시킨다.
- 32비트 고속 트릴에서 4키 교대(`A → B → C → D → A → B → C → D`)로 피로를 분산하는 방법을 소개한다.
- 더블 홀드 + 트릴: 4키 중 2키로 더블 홀드를 유지하면서 나머지 2키로 트릴을 처리하는 연습.

목표: 유저가 **16키 바인딩의 이점을 이해하고, 레인당 4키를 활용할 수 있는 상태**가 된다.
