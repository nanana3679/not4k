# not4k — 차트 편집기

이 문서는 차트 편집기의 요구사항과 차트의 데이터 모델을 정의한다.

## 적용 범위와 구현 상태

[RFD 0037](../rfd/0037-explicit-score-notes-and-body.md)의 명시 노트 제작·표시·선택·복사·삭제·Undo와 구형/신형 혼합 main/aux 저장을 구현했다. 명시 테스트 재생도 실제 입력·커서 시작·고정 3초 되감기·정산·복귀까지 연결해 검증했다. 구형 차트 1차 기계 변환의 모달·결과 화면·변환 검토 목록도 구현했다(#359). 별도로 승인·구현된 `trillZone` 위반 축소 차단은 현재 동작으로 보존한다.

| 구분 | 이 문서의 적용 범위 |
| --- | --- |
| 새 에디터 계약 | 아래 [새 에디터 채택 계약](#새-에디터-채택-계약). 새 바디·명시적 점수 노트의 편집과 과도기 수리·혼합 저장 요구이며 에디터에 구현했다. [명시 차트의 테스트 플레이](#명시-차트의-테스트-플레이)는 #346에서 연결했다 |
| 구형 편집 기록 | 아래 편집기 요구사항의 구형 노트 생성·선택·삭제·끝점 조작. 새 편집 요소에는 위 계약을 적용한다. 선택 해제 게이트는 제거했고 그 설명은 대조용 기록이다 |
| 과도기 수리 의미 | 구형 롱노트의 구성·끝점·`holdOnly` 등 판정·저장 의미. 미수정 구형 항목을 새 바디·명시 노트로 추정하지 않고 읽기·표시·편집·Undo·저장 왕복에서 보존한다 |
| 공통 요구사항 | 타임라인·뷰포트·이벤트·메타데이터·기존 저장 UI 등 새 계약에서 바꾸지 않은 동작 |

용어의 정본은 [glossary](../context/glossary.md)다. 미정 사항과 구현 이행은 [PRD §12](../prd.md#12-미정-사항)에서만 관리한다.

## 새 에디터 채택 계약

이 절은 [RFD 0037 §6](../rfd/0037-explicit-score-notes-and-body.md#6-위치-관계와-편집)·[§8](../rfd/0037-explicit-score-notes-and-body.md#8-구형-차트와-과도기)의 채택 계약이며 **에디터 런타임에 구현했다.** 아래 [명시 차트의 테스트 플레이](#명시-차트의-테스트-플레이)는 #346에서 연결했다. 용어와 판정 의미는 [glossary](../context/glossary.md)를 따르며, 여기서는 제작자가 수행하는 편집 동작을 정한다. 저장 필드·JSON 버전·ID·API 이름이나 새 UI 도구를 이 절에서 정하지 않는다.

### 편집 요소와 위치 관계

- [바디](../context/glossary.md#바디), [탭 노트](../context/glossary.md#탭-노트-tap), [릴리즈 노트](../context/glossary.md#릴리즈-노트), [틱 노트](../context/glossary.md#틱-노트-tick)는 서로 구별되는 편집 요소다. 바디는 hold 수를 요구하지만 점수 항목이나 down·up 소비를 만들지 않는다. 탭 노트는 down, 릴리즈는 실제 up을 요구하는 명시적 점수 노트이며 틱 노트는 바디 상태를 확인하는 명시적 노트다.
- 소속과 연결은 **같은 레인의 박 위치**에서 도출한다. 틱 노트는 바디의 시작·끝을 포함한 구간에 속하고, 두 바디의 공유 경계에서는 그 경계에서 시작하는 **뒤 바디에만** 속한다. 제작자에게 소속 ID 입력을 요구하거나 함께 생성한 이력으로 묶지 않는다.
- 릴리즈는 같은 레인의 바디 끝점 또는 바디 밖의 단독 위치에 둔다. 공유 경계에서는 **끝나는 앞 바디**에 대응한다. 바디 내부의 끝점 아닌 위치에 놓인 릴리즈와 바디 밖 틱 노트는 의미 위반이다. 잘못된 관계를 단독 릴리즈로 조용히 바꾸지 않는다.
- 현재는 같은 레인의 `trillZone` 시작·끝을 포함한 구간 안에 명시 릴리즈를 두지 않는다. 바디 끝·단독, 일반/Grace·싱글/더블에 예외를 두지 않는다([RFD 0038](../rfd/0038-release-notes-in-trill-zones.md)). 구형 `trillLong`의 과도기 편집 의미는 보존한다.
- 같은 레인·같은 시각의 탭+릴리즈, 탭+틱 노트, 릴리즈+틱 노트는 금지한다. Grace 여부도 이 금지를 바꾸지 않는다. 같은 의미의 수량을 나타내는 더블과 허용된 바디 위 노트 배치는 구별한다.
- 한 바디 내부·독립 길이 0 바디·1→2 증가·2→1 감소 위치의 틱 노트는 허용한다. 증가 경계에서는 뒤 더블 바디의 틱 2개, 감소 경계에서는 뒤 싱글 바디의 틱 1개다. 1→1·2→2의 같은 hold 수 연결점과 트릴 바디 위 틱 노트는 금지한다. 실제 앞뒤 바디 경계는 보존하며 자동 병합하지 않는다.
- 같은 레인에서 hold 수가 같은 두 바디가 맞닿으면 뒤 바디 시작의 탭이나 앞 바디 끝의 릴리즈가 필요하다. 둘 다 없으면 의미 위반이며 두 바디를 위반으로 표시한다. 같은 수 바디 끝에 맞닿은 길이 0 바디도 탭·릴리즈를 둘 수 없어 위반이다. 보조 레인도 같고 구형 롱노트는 구형 규칙을 따른다(사용자 결정, 2026-10-27). 트릴 바디와 일반 바디는 모양이 달라 구별되므로 트릴 바디 → 일반 바디(사용자 결정, 2026-10-27)와 일반 바디 → 트릴 바디(사용자 결정, 2026-10-28 정정)는 모두 이 규칙에서 빠지고, 위반은 트릴 여부가 같은 두 바디에만 표시한다. 근거는 [RFD 0037 §6-1](../rfd/0037-explicit-score-notes-and-body.md#6-1-배치와-소속)이다. 사용자 결정이 아닌 기존 규칙의 적용과 구현 세부: 메인·보조 레인의 트릴 바디는 기존대로 시작 트릴 탭이 필요하므로, 메인·보조 레인의 일반 바디 → 트릴 바디에 트릴 탭이 없으면 기존 `trillLongInvalid`로 보고한다. 메인·보조 레인의 트릴 바디 → 트릴 바디 경계에 시작 트릴 탭이 없을 때도 `trillLongInvalid`만 보고한다. 메인·보조 레인의 트릴 바디 → 일반 바디 접점은 기존 `trillZone` 배타 규칙이 별도로 막는다. 같은 레인 접점 박의 구형 Point 노트(`single`·`double`·`trill` 타입)도 경계의 탭으로 인정해 혼합 차트의 저장을 막지 않는다.
- 바디의 hold 수와 릴리즈 수가 다르다는 이유만으로 배치를 금지하거나 수량을 자동 보정하지 않는다. 더블 바디 끝의 싱글 릴리즈와 싱글 바디 끝의 더블 릴리즈도 명시된 수량을 보존한다. 2→1 감소 지점에는 싱글 릴리즈와 더블 릴리즈를 모두 둘 수 있다. 더블 릴리즈는 두 키를 모두 떼고 뒤 싱글을 새 키로 잡는 연주를 요구한다(사용자 결정, 2026-10-26, [RFD 0037 §4](../rfd/0037-explicit-score-notes-and-body.md#4-경계실패-종속)).
- 길이 0 바디는 단독 또는 틱 노트와 함께 존재할 수 있다. 같은 레인·같은 시각의 **길이 0 바디+탭, 길이 0 바디+릴리즈는 금지**한다. 틱 없는 길이 0 바디도 유효한 플레이 요소로서 무점수이며 바디의 hold 요구·실패 규칙은 유지한다.

### 생성

| 조작 | 생성·변경 결과 |
| --- | --- |
| 일반 탭 입력 상태에서 드래그 | 시작 탭·바디·끝 릴리즈를 함께 생성한다. 싱글 드래그는 싱글 릴리즈, 더블 드래그는 더블 릴리즈를 기본 생성한다 |
| `trillZone` 안에서 트릴 탭 드래그 | 트릴 탭·트릴 바디만 함께 생성한다. 끝 릴리즈나 숨은 점수 항목을 만들지 않는다 |
| Grace 모드에서 위 조합 드래그 | 생성하는 시작 탭과 끝 릴리즈를 **모두 Grace**로 만든다. 트릴 조합은 Grace 탭과 바디만 만든다. 바디에는 Grace나 구형 `holdOnly`를 붙이지 않으며 Grace 릴리즈의 실제 뗌 요구를 유지한다 |
| 기존 바디 위에 틱 노트 배치 | 해당 바디의 hold 수에 맞춰 싱글 틱 1개·더블 틱 2개를 한 번에 생성한다. 기존 바디 위에 길이 0 바디를 추가하지 않는다 |
| 바디 없는 빈 위치에 틱 노트 배치 | 길이 0 **싱글 바디와 틱 1개**를 함께 생성한다. 빈 위치 생성에 싱글·더블 선행 선택을 요구하지 않는다 |
| 틱 노트 배치 상태에서 같은 길이 0 싱글 틱 노트 재클릭 | 기존 바디를 더블로, 틱을 2개로 함께 변경한다. 일반 재클릭이며 빠른 더블클릭 시간 조건을 두지 않는다 |
| 이미 더블인 길이 0 틱 노트 재클릭 | 그대로 둔다. 싱글로 되돌리는 토글·중복 항목·변경 없는 Undo 기록을 만들지 않는다 |

탭·바디·릴리즈의 함께 생성과 빈 위치의 바디·틱 함께 생성은 각각 **한 생성·취소·Undo/Redo 단위**다. 바디 위 틱 배치와 길이 0 싱글→더블 변경도 각각 한 편집으로 처리한다. 이는 제작 편의 조작이며, 컴파일러가 명시하지 않은 릴리즈나 점수 항목을 생성하는 규칙이 아니다.

더블 탭·더블 릴리즈는 전체가 하나의 편집·삭제 단위다. 한 번 삭제로 싱글로 줄이지 않는다. 더블 바디 끝에 싱글 릴리즈 하나가 필요하면 기본 더블 릴리즈를 삭제하고 별도로 그린 싱글 롱노트의 릴리즈를 대상 끝점으로 옮길 수 있다. 이 흐름을 위해 별도의 종류 변경 조작을 도입하지 않는다.

하나의 더블 릴리즈는 일반/Grace 종류를 두 항목에 공통 적용한다. 일반 한 항목과 Grace 한 항목을 섞지 않으며 종류 변경·복사·저장 왕복에서도 이 제약을 보존한다.

### 선택과 히트테스트

직접 선택은 클릭을 뜻하며, 박스 선택은 별도 연산이다. 탭·틱 노트·릴리즈와 바디의 hit 영역이 겹치면 **해당 노트를 바디보다 우선**한다. 길이 0에서도 바디가 틱보다 커서 바디를 따로 클릭할 수 있으므로 동일한 규칙을 적용한다.

| 조작 | 선택 집합 |
| --- | --- |
| 바디를 클릭해 새로 선택 | 바디 + 같은 레인·같은 시작 시점의 탭 + 소속 틱 노트 + 끝점 릴리즈. 바디 중간의 탭은 포함하지 않는다 |
| 미선택 탭·틱 노트·릴리즈 클릭 | 해당 노트만 선택해 기존 선택을 교체한다 |
| 이미 선택된 탭·틱 노트·릴리즈를 누름 | 현재 선택을 유지하고, 끌면 선택 전체를 이동한다. 구형 노트와 같은 [RFD 0016](../rfd/0016-editor-selection-handle-model.md#6-구현-제약-실측-2026-07-09) §6-6의 "선택된 엔티티 위 드래그=이동"이다(사용자 결정, 2026-10-26) |
| 박스에 바디 일부 포함 | 바디와 위 연결 항목을 함께 선택한다. 바디 전체를 감쌀 필요는 없다 |
| 박스에 틱·릴리즈만 포함 | 들어온 항목만 선택한다 |
| 연결 항목 토글 해제 | 해당 항목만 선택에서 제외한다 |
| 바디 토글 해제 | 바디만 제외하고 이미 선택된 틱·릴리즈 등은 남긴다 |

선택 뒤에는 **실제 선택 집합**을 따른다. 바디가 선택돼 있다는 이유로 토글로 제외한 탭·틱·릴리즈를 다시 추가하지 않는다. 길이 0 틱만 선택했을 때도 바디를 강제로 선택하지 않는다. 선택 인덱스의 유효성·트릴 등 기존 정규화 규칙은 유지한다.

### 복사·붙여넣기와 이동

- 복사는 현재 선택 집합만 복제한다. 바디와 관계가 있다는 이유로 선택하지 않은 탭·틱 노트·릴리즈를 복사 명령에서 추가하지 않는다. 틱만 선택한 복사도 허용한다.
- 바디 전체 이동에서는 함께 선택한 연결 항목만 같은 박·레인 오프셋으로 옮긴다. 선택에서 제외한 틱·릴리즈는 원래 위치에 남긴다.
- 이동·붙여넣기의 미리보기 위치에서 관계와 위반을 다시 계산하며, 확정한 위치의 관계로 편집을 이어간다. 이전 소속을 고정하지 않는다.
- 틱 노트를 다른 바디로 옮겨 소속이 바뀌면 새 바디의 hold 수에 맞춰 틱 수를 자동 변경한다. 더블→싱글은 2→1, 싱글→더블은 1→2이며 명시 점수 항목 수와 이론 가중치도 함께 바뀐다.
- 바디 밖으로 옮기거나 붙여넣은 틱 노트에는 길이 0 바디를 임의 생성하지 않는다. 틱 수는 그 이동·붙여넣기를 시작할 때의 수로 돌리며, 지나온 다른 바디의 수를 남기지 않는다. 바디 밖 틱의 의미 위반을 표시하고 사용자가 고칠 수 있게 둔다. 빈 위치의 **새 생성**과 구별한다.

### 끝점 리사이즈

시작점 리사이즈를 새로 도입하지 않으며, 바디 전체 이동과 끝점 변경을 구별한다.

- **미선택 바디의 끝 핸들**을 바로 잡으면 바디 클릭과 같이 시작 탭·소속 틱 노트·끝점 릴리즈를 함께 선택한 뒤 리사이즈한다. 터치 끝 핸들 조작도 같은 원칙을 따른다.
- **이미 선택된 바디의 끝 핸들**에서는 현재 선택 집합을 재확장하거나 바디만으로 교체하지 않는다. 의도적으로 제외한 항목을 보존한다.
- 기본 끝 릴리즈처럼 탭·틱 노트·릴리즈가 바디 끝을 덮으면 겹친 자리는 **그 노트**를 잡는다. 끝 핸들은 그 노트 hit 바로 위 띠(끝에서 1/16～3/16박 뒤)에서 잡으며, 미선택 바디도 이 띠에서 바로 잡으면 위 동반 선택 뒤 리사이즈한다. 연결 경계처럼 이어진 뒤 바디가 이 띠를 덮으면 앞 바디를 먼저 선택했을 때만 띠가 앞 바디의 끝 핸들이고, 선택하지 않았으면 뒤 바디를 잡는다. 마우스·터치가 같다. 터치 끝 캡 롱프레스는 아래 롱프레스 규칙대로 선택과 무관하게 이 띠에서 앞 바디 끝을 리사이즈한다. 선택된 `trillZone`·`restZone`의 끝 캡은 끝에 놓인 노트보다 먼저 잡는다([RFD 0016](../rfd/0016-editor-selection-handle-model.md) §6-6).
- 함께 선택된 **끝점 릴리즈만 새 끝점을 따라간다.** 제외한 릴리즈는 원래 위치에 남고 결과의 관계를 다시 검증한다.
- 시작 탭·내부 틱 노트는 선택돼 있어도 끝점 리사이즈로 비례 이동하지 않는다. 틱을 조용히 삭제하지 않는다.
- **소속 틱 노트를 바디 밖으로 내보내는 끝점 축소는 막는다.** 먼저 틱을 옮기거나 삭제해야 한다. 틱을 선택에서 제외해도 이 보호는 유지한다. 틱을 남기고 바디 전체를 이동해 수리 가능한 의미 위반을 만드는 경우와 구별한다.
- 시작점 이전으로 끝점을 역전시키지 않는다. 길이 0 자체는 허용하되 탭·릴리즈와의 금지 조합은 의미 위반으로 표시한다. `trillZone` 위반 축소 차단(RFD 0017 추가 4, #344에서 구현)도 함께 적용한다.

### 삭제와 Cut 선검증

| 조작 | 삭제 대상과 보호 |
| --- | --- |
| 미선택 바디를 우클릭·Delete 모드로 직접 삭제 | 바디 + 같은 시작점 탭 + 소속 틱 노트 + 끝점 릴리즈를 한 편집으로 삭제한다. 중간 탭·다른 바디의 항목은 포함하지 않는다 |
| 선택된 바디 우클릭 | 클릭한 바디와 그 바디의 연결 항목 중 **현재 선택에 남은 것만** 삭제한다. 다른 선택 바디·노트와 제외한 탭·릴리즈는 남긴다 |
| `Delete` 키 | 선택 집합 전체가 대상이다. 우클릭의 클릭한 바디 쪽 삭제와 구별한다 |
| 탭·틱 노트·릴리즈 직접 삭제 | 해당 노트만 삭제한다. 더블 노트는 전체가 한 삭제 단위다 |
| 길이 0 바디의 틱만 삭제 | 틱만 지우고 바디는 남긴다. 빈 바디를 자동 삭제하지 않는다 |

바디와 소속 틱 노트를 모두 삭제할 수 있으면 한 편집 안에서 **틱을 먼저 제거한 뒤 바디를 제거**한다. 소속 틱 노트가 삭제 집합에서 빠졌다면 해당 바디 삭제와 Cut을 막는다. 함께 선택된 시작 탭·끝 릴리즈는 삭제하고, 제외한 릴리즈는 남겨 위치 관계를 다시 계산한다.

**Cut은 삭제 가능성을 먼저 검사**한다. 삭제가 거부되면 클립보드도 바꾸지 않는다. 같은 집합을 복사만 하는 것은 허용한다.

### 우클릭 드래그의 취소와 Undo

- 탭·틱 노트·릴리즈를 직접 삭제해 **드러난 바디는 같은 드래그가 끝날 때까지 후속 삭제 대상으로 삼지 않는다.** 그 바디도 지우려면 버튼을 뗀 뒤 새로 우클릭한다. 다른 위치에서 바디 자체를 대상으로 한 드래그 삭제까지 금지하지 않는다.
- 한 버튼 누름의 연속 삭제 전체를 **하나의 Undo/Redo 단위**로 기록한다. 길거나 중간에 멈춘 드래그도 시간으로 나누지 않으며, 별개의 드래그·앞뒤 다른 편집과 시간 기준으로 병합하지 않는다.
- 동반 삭제한 연결 항목도 같은 기록에서 함께 복구·재적용한다. 실제 삭제가 없으면 빈 기록을 만들지 않는다. 다른 편집의 기존 Undo 병합 정책은 이 결정으로 바꾸지 않는다.
- 드래그 도중 **Esc는 그 드래그에서 삭제한 항목만 모두 복구하고 조작을 취소**한다. 앞서 완료한 편집은 유지하고 취소된 드래그는 새 Undo/Redo 기록을 만들지 않는다.
- Esc 후 같은 버튼 누름의 후속 이동으로 삭제를 재개하지 않는다. 다시 삭제하려면 버튼을 뗀 뒤 새 조작을 시작한다.

### 미리보기·확정·선택 해제와 검증

새 에디터는 [RFD 0017](../rfd/0017-optimistic-edit-transient-invalid.md)의 낙관적 편집을 이어받되, **§3-5의 의미 위반 선택 해제 제한은 제거**한다. 바디·틱을 따로 선택해 고칠 수 있어야 한다.

| 상태·조작 | 채택 동작 |
| --- | --- |
| 미리보기 중 의미 위반 | 현재 미리보기 위치에서 관계를 계산해 기존 빨간 빗금·진단으로 표시한다. 바디 밖 틱과 바디 내부 릴리즈도 같은 방식이다 |
| 의미 위반이 남은 생성·붙여넣기·이동·리사이즈 확정 | 빗금 상태로도 확정할 수 있다. 위반을 고치거나 Undo로 되돌릴 수 있다 |
| 의미 위반 항목 선택 해제·선택 교체·부분 해제 | 허용한다. 위반 노트를 현재 선택에 강제로 붙잡아 두지 않는다 |
| 저장·플레이/프리뷰 진입 | 실제 의미 위반이 해소될 때까지 차단한다. 과도기 혼합 저장은 아래 별도 계약을 따른다 |
| 구조 위반을 만드는 편집 | 거부한다. 의미 위반 허용을 구조 위반 허용으로 확대하지 않는다 |
| 틱을 남기는 바디 삭제·틱을 밖으로 보내는 바디 축소 | 위의 별도 보호 규칙으로 막는다 |
| 트릴 노트를 구간 밖으로 보내는 `trillZone` 축소 | 마지막 유효 위치를 유지한다(RFD 0017 추가 4, #344에서 구현) |

위반 빗금·미니맵 지시자·툴바 위반 진단과 저장·플레이 검증은 유지한다. 의미 위반 선택 해제 허용을 선택 인덱스·트릴 동질성 등 기존 정규화 제거로 해석하지 않는다. 위반을 경고하면서 수정용 차트를 여는 경로도 유지한다.

### 과도기 구형 수리와 혼합 저장

- 구형 차트는 에디터에서 읽어 사람이 수정할 수 있어야 한다. 노트의 위치·길이·종류·속성·메타데이터를 타임라인과 기존 속성 확인·편집 경로에서 보존한다. JSON을 외부에서 먼저 손으로 바꾸도록 요구하지 않는다.
- **미수정 구형 항목은 계속 구형 의미**로 읽고 표시·선택·편집·Undo한다. 사용자가 명시적으로 새 구조로 바꾸거나 승인한 1차 기계 변환으로 옮긴 항목만 새 의미를 갖는다. 전체 문서의 버전만 바꿔 미수정 구형 끝점·`holdOnly`를 새 바디·릴리즈·틱 노트로 간주하지 않는다.
- 파일 버전이나 불러오기만으로 노트 배치를 바꾸는 자동 변환·일괄 재구성은 하지 않는다. 구형 노트가 있는 차트를 열 때 모달로 물어 사용자가 승인하면 [RFD 0037 §8-1](../rfd/0037-explicit-score-notes-and-body.md#8-1-구형-차트-1차-기계-변환)의 1차 기계 변환을 하고, 변환 검토 목록의 위치와 나머지는 사람이 고친다. 모달·결과 화면·변환 검토 목록의 동작은 아래 [구형 차트 변환 모달과 변환 검토 목록](#구형-차트-변환-모달과-변환-검토-목록)을 따른다. 읽기 호환과 수동 수리를 지원하는 연결은 유지하며, 충돌 항목을 조용히 삭제하거나 다른 의미로 바꾸지 않는다.
- **구형·신형 혼합 차트도 손실 없이 저장·재불러와 수리를 이어갈 수 있어야 한다.** 구형 항목의 존재 자체는 저장을 막지 않는다. 양쪽 의미와 main/aux 자료·메타데이터를 모두 보존한다.
- 구형 항목의 존재와 실제 배치 위반을 구별한다. 바디 밖 틱 노트·바디 내부 릴리즈 등 실제 의미 위반의 저장·플레이 제한은 유지한다. 구형이라는 이유로 별도 배지·라벨·강조·빗금을 추가하지 않으며 실제 위반의 기존 표시는 유지한다.
- 새 compiler/인게임 진입은 구형 의미가 남은 차트를 차단한다. 혼합 상태의 **저장·수리 가능성**과 새 의미의 **재생 가능성**을 따로 판단한다. #347 머지 뒤에는 일반 곡 선택도 명시 판정만 실행하므로 구형 게임 노트가 남은 차트는 다시 제작하기 전까지 곡 선택에서 플레이할 수 없다(사용자 결정, 2026-10-26, 운영 차트 현황은 [PRD §12](../prd.md#12-미정-사항)).
- main/aux는 하나의 편집 문서로 취급한다. main↔aux 이동·복사/붙여넣기·Undo/Redo·저장 왕복에서 새 필드와 미해결 구형 의미를 보존하며 **dirty 비교에서도 빠뜨리지 않는다.** 의미 위반 상태도 비교·수정·Undo할 수 있어야 하며 저장 불가 필드를 직렬화에서 제외해 clean으로 오인하지 않는다.
- 과도기의 수리 완료 범위는 저장소에 올라와 관리되는 차트다. 그 수리가 끝나고 **사용자가 종료 시점을 알릴 때까지** 구형 스펙과 읽기·편집 의미를 보존한다. 종료 뒤 저장소 밖에서 가져온 구형 차트까지 편집 지원을 보장할 필요는 없다.

### 구형 차트 변환 모달과 변환 검토 목록

[RFD 0037 §8-1](../rfd/0037-explicit-score-notes-and-body.md#8-1-구형-차트-1차-기계-변환)의 사용자 결정(2026-10-27～2026-10-28, #359)을 에디터에 구현했다. 변환 규칙은 [glossary `convertLegacyChart`](../context/glossary.md#convertlegacychart)를 따르고, 이 절은 사람이 보는 화면과 조작을 정한다.

**묻는 시점**

- 메인·보조 레인 어디든 구형 노트(`single`·`double`·`trill`·`long`·`doubleLong`·`trillLong`)가 있는 차트를 서버에서 새로 불러와 에디터가 열리면 **구형 차트 변환** 모달이 뜬다.
- 테스트 플레이에서 돌아와 이미 불러온 곡으로 들어올 때는 묻지 않는다. 구형 노트가 없는 차트도 묻지 않는다.
- 모달은 에디터 화면이 열린 뒤에 뜬다. 그 전에 차트를 불러오며 `savedChartJson`을 불러온 구형 차트의 직렬화로 정해 두었으므로([dirty 상태](#dirty-상태)) 변환은 이 값을 바꾸지 않는다.
- 한 번 답하면(**변환** 또는 **구형 그대로 열기**) 같은 세션에서 에디터 화면이 다시 마운트돼도(권한 재확인 등) 다시 묻지 않는다. 다시 마운트될 때 지금 차트에 구형 노트가 없으면 개수가 모두 0인 모달을 띄우지 않는다.

**변환 전 모달**

- 변환하기 전에 같은 변환 함수를 미리 실행한 결과로 `탭 n · 바디 n · 릴리즈 n · 틱 n · 검토할 항목 n`을 보인다. 개수는 변환이 새로 만드는 노트이고 기존 명시 노트는 세지 않는다.
- 버튼은 **변환**과 **구형 그대로 열기**다. 바깥을 눌러도 닫히지 않고, 모달이 열린 동안 에디터 단축키는 동작하지 않는다.
- 모달이 열린 동안(결과 화면 포함) 키보드 포커스는 모달의 버튼 사이에서만 돈다(Tab·Shift+Tab). 뒤의 툴바·캔버스는 포커스와 클릭을 받지 않으므로 키보드로도 누를 수 없다. 모달이 닫히면 열리기 전에 포커스가 있던 요소로 돌아간다.
- 변환 결과에 구조 위반(구간 역전 등)이 남으면 편집 게이트가 그 차트를 받지 않는다. 이때 모달은 구조 위반 수를 알리고 **변환**을 막는다. 구형 그대로 열어 위반을 고치고 **저장한 뒤** 에디터를 다시 열면 다시 묻는다. 모달은 서버에서 차트를 새로 불러올 때만 뜨므로 저장하지 않고 다시 열면 고치기 전 차트로 돌아간다.
- 제약: 편집 게이트는 구조 위반이 하나라도 남는 편집을 받지 않는다(변환 기능 전부터 있던 동작이며 바꾸지 않았다). 그래서 구조 위반이 2건 이상이면 하나씩 고칠 수 없고, 한 번의 편집으로 모두 없애야 한다(예: 위반 노트를 함께 선택해 한 번에 지우기). 그런 편집이 없으면 에디터 안에서는 고칠 수 없다.

**변환**

- 차트 전체를 편집 한 번으로 바꾼다. Undo 한 번이면 구형 차트로 돌아가고 Redo로 다시 변환 상태가 된다.
- `savedChartJson`은 불러온 구형 차트의 직렬화이므로 변환 뒤 저장 버튼에 미저장 표시가 붙는다. Undo로 구형 차트에 돌아가면 표시가 사라진다.
- 자동 저장은 없다. 사람이 저장하면 일반 저장 게이트(배치 제약 검사)를 거치고, 명시 노트를 담은 main·aux 파일은 v4로 올린다.

**구형 그대로 열기**

- 지금까지처럼 구형·혼합 상태로 연다. 노트·Undo 기록·미저장 표시를 바꾸지 않는다.
- 구형 노트가 남아 있으면 새로 열 때마다 다시 묻는다.

**결과 화면**

- 변환하면 같은 모달이 **변환 완료**로 바뀌어 같은 개수 줄을 보인다.
- 합친 `holdOnly` 연결 수와, 사슬 끝 `holdOnly`가 릴리즈 없는 바디가 되며 뺀 구형 점수 항목 수가 있으면 함께 적는다.
- 아직 저장하지 않았다는 것과 Undo 한 번으로 돌아갈 수 있다는 것을 알린다.
- 검토할 항목이 있으면 **검토 목록 열기**와 **닫기**, 없으면 **닫기**만 있다.

**변환 검토 목록**

보고 항목마다 한 행이고 순서는 레인 → 박이다. 행은 다음을 보인다.

- 레인: 메인은 `레인 1`～`레인 4`, 보조는 에디터의 보조 레인 번호로 `보조 레인 n`이다.
- 위치: `2마디 3박`처럼 적는다. 마디는 타임라인의 마디 번호처럼 1부터 세고, 박은 그 마디 안에서 1부터 센다. 분수 박은 `2마디 1+1/2박`이다. 마디 표시는 지금 차트의 박자표를 따른다.
- 종류 설명: 아래 표를 따른다. 옮기지 못한 구형 점수 항목이 있으면 `옮기지 못한 구형 점수 항목 n개`를 덧붙인다.

| 보고 종류 | 행 설명 |
| --- | --- |
| `holdCountChangeConnection` | `감소 연결 2→1 · 경계 비움`·`증가 연결 1→2 · 경계 비움`. 경계에 head(탭 노트)가 있어 변환 뒤에도 그 탭 노트가 남으면(`hasHead`) `경계 비움` 대신 `경계에 탭 노트 유지`로 적는다. 앞 끝이 `holdOnly`면 ` · 앞 끝 holdOnly`를 덧붙인다 |
| `releaseOmittedTrillBodyEnd` | `트릴 바디 끝 · 릴리즈 없음` |
| `releaseOmittedInTrillZone` | `trillZone 안 바디 끝 · 릴리즈 없음` |
| `releaseOmittedTapAtEnd` | `끝에 탭 노트(o-o) · 릴리즈 없음` |
| `holdOnlyConnectionNotTickable` | `트릴 바디가 낀 holdOnly 연결 · 틱 노트 없음` |
| `auxZeroLengthTrillBody` | `길이 0 트릴 바디 · 릴리즈·틱 노트 없음` |
| `sameHoldCountConnectionWithoutHeadOrHoldOnly` | `head·holdOnly 없는 같은 hold 수 연결` |
| `explicitNoteAtLegacyPosition` | `명시 노트가 이미 있는 위치 · 노트를 더하지 않음` |
| `violationBeforeConversion` | `변환 전 위반: 롱노트 겹침 (longOverlap)`처럼 위반 라벨과 rule id |

- **행을 누르면** 재생 커서를 그 박으로 옮기고, 그 박이 가운데 오게 세로로 스크롤하고, 그 레인이 보이게 가로로 팬한다. 그리고 Select 모드로 바꿔 같은 레인에서 그 박에 놓이거나 그 박에서 끝나는 노트를 선택한다. 노트 index는 편집하면 바뀌므로 레인·박으로 지금 차트에서 다시 찾는다. 그 위치의 노트를 지웠으면 이동만 하고 선택은 빈다.
- 행의 레인이 지금 보조 레인 수(Extra lanes) 밖이라 숨어 있으면 커서 이동과 세로 스크롤만 하고 노트를 선택하지 않는다. 모드와 기존 선택도 그대로 둔다. 보이지 않는 노트가 삭제·이동 대상이 되지 않게 하기 위해서다. 대신 `숨은 보조 레인 n의 항목이라 노트를 선택하지 않았습니다. Extra lanes를 n 이상으로 늘리면 보입니다` 토스트를 띄운다. 보조 레인 수는 차트 자료라 자동으로 늘리지 않는다.
- 붙여넣기 대기나 이동이 진행 중일 때 행을 누르면 툴바의 모드 버튼과 같이 그 편집을 확정한 뒤 이동·선택한다. 취소하지 않는 것은 사용자가 한 붙여넣기를 말없이 버리지 않기 위해서이며, 확정한 편집은 Undo 한 번으로 되돌린다.
- **텍스트로 복사**는 제목 줄 `변환 검토 n건 — 곡명 난이도` 아래에 행마다 `번호. 레인 · 마디 박 (박 곡 시작부터의 박) · 설명`을 한 줄씩 클립보드에 넣는다. 복사하면 토스트로 알린다.
- **위치**: 캔버스를 덮지 않도록 데스크톱은 캔버스 오른쪽 열(300px)에, 좁은 화면(767px 이하)·터치는 캔버스 아래 칸(화면 높이의 38% 이하)에 붙는다. 그만큼 캔버스가 줄어든다.
- **수명**: 닫기(×)로 숨기고 툴바의 **검토 n** 버튼으로 다시 연다. 목록은 이번 세션 동안 남는다. 테스트 플레이에서 돌아와도, Undo로 구형 차트에 돌아가도 남는다. 차트를 새로 불러오면 사라진다.
- 구형 노트라는 이유로 배지·빗금을 붙이지 않는다([RFD 0037 §8](../rfd/0037-explicit-score-notes-and-body.md#8-구형-차트와-과도기)). 이 목록과 툴바 버튼은 승인한 변환 뒤에만 생긴다.

### 명시 차트의 테스트 플레이

main에 명시 노트가 있으면 **처음부터 시작** 또는 **커서부터 시작**으로 새 세션을 연다. 재생 범위를 고르기 전에 전체 문서의 구조·의미와 main의 구형 항목 잔류를 검사한다. 커서 앞의 구형 main이나 aux의 의미 위반도 이 검사에서 숨기지 않는다. aux는 실행에서 제외하되 원본과 배치 진단을 보존한다.

명시 차트의 처음부터·커서부터 테스트 플레이는 별도 카운트다운 없이 음악 준비 3초 뒤 목표 시점에서 시작한다. 커서에 걸친 바디는 남은 부분을 커서 위치에서 일반 시작 판정으로 시작하며 원본 차트와 원본 참조를 보존한다([RFD 0040](../rfd/0040-countdown-and-note-reentry.md)). 전체 문서 검증 후 재생 범위를 선택한다. 커서보다 앞의 점수 항목은 Miss 없이 제외하고 커서와 같은 시각부터 점수·통계·분모에 포함한다. 처음부터 시작은 곡 시간 0에서 자르지 않고 음수 `meta.offsetMs`로 0보다 앞에 놓인 항목도 일반 재생과 똑같이 포함하므로 점수 항목·분모가 일반 재생과 같다(사용자 결정, 2026-10-26). 구형 main만 있는 문서는 기존 테스트 경로를 보존한다.

일시정지 재개는 곡 시간 3초 전으로 되감고 그 뒤 판정·상태를 되돌려 다시 플레이한다([RFD 0040](../rfd/0040-countdown-and-note-reentry.md)). 원래 테스트 시작 시각(처음부터 테스트는 일반 재생과 같은 0)을 하한으로 하며 커서 앞 항목을 새로 포함하거나 분모의 대상 범위를 다시 고르지 않는다.

테스트 결과는 실제 점수·분모·Miss·바디 상태를 보여주고 원래 에디터 문서로 돌아온다. 공식 결과·랭크·기록 정책과 기본 게임 경로 전환은 이 진단 경로와 별도다.

### 이행 검증 기준

구현과 회귀 테스트는 생성 묶음의 취소/Undo, 노트와 바디의 hit 우선순위, 토글 제외 후 실제 집합 복사·이동, 끝 핸들의 미선택/선택 상태와 끝 릴리즈 동반, 삭제/Cut 보호, 우클릭 드래그의 관통 방지·긴 드래그 Undo·Esc 후 재개 금지를 확인한다. 길이 0의 허용/금지 조합, 의미 위반 확정 뒤 선택 교체·수리, 미수정 구형 항목과 일부만 수리한 혼합 차트의 main/aux·메타데이터·dirty 왕복도 함께 검증한다. 이행 상태와 공식 미정은 [PRD §12](../prd.md#12-미정-사항)에서 관리한다.

## 편집기 요구사항

**적용 범위:** 타임라인·뷰포트·이벤트·메타데이터·기존 저장 UI는 공통 요구사항이다. 아래 구형 롱노트·`holdOnly`의 판정·저장 의미는 수리를 위해 보존한다. 생성·선택·삭제 등 조작은 구형 노트의 편집 기록이며, 새 편집 요소에는 위의 채택 계약을 적용한다. 선택 해제 게이트는 제거했다.

### 타임라인

에디터의 그리드는 다음 레인으로 구성된다.

| 레인 종류   | 개수 | 용도                          |
| ----------- | ---- | ----------------------------- |
| 노트 레인   | 4    | L1～L4 노트를 배치하는 레인   |
| BPM 레인    | 1    | `BpmChangeEvent`를 배치하는 보조 레인 |
| 박자 레인   | 1    | `TimeSignatureChangeEvent`를 배치하는 보조 레인 |
| 메시지 레인 | 1    | 메시지를 배치하는 보조 레인. 튜토리얼 등에서 특정 구간에 안내 텍스트를 표시하기 위해 사용한다 |

- **시간 방향**: 타임라인은 **아래에서 위로** 시간이 흐른다. time 0(첫 마디)이 하단, 이후 시간이 위로 올라간다.
- 그리드 배경에 음원 파일의 **파형(waveform)** 을 표시한다.
- 파형 위에 `BpmChangeEvent`·`TimeSignatureChangeEvent`로부터 계산된 **박자 그리드**를 겹쳐 표시한다.
  - 그리드 라인은 마디선과 박자선을 구분할 수 있어야 한다.
  - 오프셋(ms)을 반영하여 그리드와 파형의 정렬을 맞춘다.
  - **마디 번호**: 마디선 옆에 마디 번호를 표시한다.
- 사용자는 파형과 그리드의 정렬을 시각적으로 확인하면서 **오프셋을 조절**할 수 있다.
- **유한 레인 배경**: 레인 배경은 실제 타임라인 구간(첫 마디～끝 마디)만 채운다. 음원이 없으면 기본 16마디, 음원이 있으면 음원 길이 기준으로 마디 수를 계산한다. 타임라인 밖은 검은 배경으로 표시된다.
- **여유 공간(패딩)**: 첫 마디 앞과 끝 마디 뒤에 빈 공간(50px)을 두어 시각적 여유를 제공한다.
- **콘텐츠 정렬**: **마디 번호 레일 + 노트 레인 영역**을 한 덩어리로 묶어 가로 **중앙 정렬**한다. 컨테이너가 콘텐츠 블록보다 넓으면 좌우에 균등한 여백이 생기고, 좁으면 가로 스크롤(팬)로 처리한다. **미니맵은 이 중앙 정렬에서 제외**되어 항상 컨테이너 우측 가장자리에 고정된다(아래 "미니맵" 참고).
- **미니맵**: 컨테이너 우측 가장자리에 고정되어 타임라인 전체를 축소 표시한다. 마우스 휠 스크롤과 동기화된다. 상세는 아래 "미니맵" 참고.

### 미니맵

캔버스 우측에 표시되는 **타임라인 전체의 축소 미리보기**이다. IDE(VS Code 등)의 미니맵과 동일한 개념으로, 차트의 전체 구조를 한눈에 파악하고 빠르게 탐색할 수 있다.

#### 레이아웃

- **위치**: 컨테이너 우측 가장자리에 고정. 기존 스크롤바를 대체한다. 콘텐츠(마디 레일 + 레인)가 중앙 정렬되어도 미니맵은 함께 움직이지 않고 항상 우측 끝에 머문다.
- **너비**: 60px.
- **높이**: 캔버스 높이 전체를 사용한다.
- **배경**: 반투명 어두운 배경(`rgba(0,0,0,0.5)`)으로 타임라인 콘텐츠와 시각적으로 분리한다.

#### 콘텐츠 렌더링

미니맵은 타임라인 전체(첫 마디～끝 마디)를 세로 방향으로 축소하여 표시한다. 축소 비율은 `캔버스 높이 / 전체 타임라인 높이`로 결정된다.

| 요소 | 렌더링 방식 |
|------|------------|
| 노트 레인 영역 | 4개 레인을 미니맵 너비에 비례 축소. 레인 배경색을 표시하여 레인 구분 |
| 싱글 노트 | 해당 레인 위치에 1px 높이의 수평선. 싱글 노트 색상(`#4488ff`) |
| 더블 노트 | 해당 레인 위치에 1px 높이의 수평선. 더블 노트 색상(`#ffcc00`) |
| 트릴 노트 | 해당 레인 위치에 1px 높이의 수평선. 트릴 노트 색상(`#ffffff`) |
| 롱노트 | 시작～끝 구간을 해당 레인에 채움. 해당 롱노트 색상. 50% 불투명도 |
| 마디선 | 전체 너비를 가로지르는 1px 수평선. 흰색 20% 불투명도 |
| 보조 레인(이벤트) | 미니맵에 표시하지 않음. 노트 레인만 표시한다 |
| 위반 지시자 | 위반 노트·`trillZone`·`restZone`·이벤트(RFD 0017 §7)의 시작 beat 위치에 그리는 미니맵 **우측 경계**의 짧은 빨간 가로 막대(해칭 색 `#ff4444`, 90% 불투명도). 종류·레인 무관 단일 채널("이 y에 위반 있음"만 표시)이며, 뷰포트 클리핑 없이 타임라인 전체 범위를 대상으로 그려 **화면 밖 위반을 조기에 경고**한다. 같은 y에 겹치는 위반은 지시자 1개로 합쳐진다 |

#### 뷰포트 인디케이터

현재 화면에 보이는 영역을 미니맵 위에 **반투명 사각형**으로 표시한다.

- 색상: `rgba(255, 255, 255, 0.15)` (반투명 흰색 채움)
- 테두리: `rgba(255, 255, 255, 0.5)` 1px 실선
- 위치와 높이는 현재 `scrollY`와 캔버스 높이에 비례한다

#### 조작

| 입력 | 동작 |
|------|------|
| 미니맵 클릭 | 클릭한 위치를 뷰포트 중심으로 이동 |
| 미니맵 드래그 | 드래그하는 동안 실시간으로 뷰포트 이동 |
| 뷰포트 인디케이터 드래그 | 인디케이터를 잡고 드래그하여 뷰포트 이동 |

미니맵 위에서의 클릭/드래그는 타임라인의 노트 편집 동작과 독립적이다. 미니맵 영역의 입력은 편집 모드(Create/Select/Delete)에 전달되지 않는다.

### 줌

- 타임라인의 픽셀 밀도는 `pixelPerSecond = zoom` 으로 결정된다. zoom 값은 BPM과 무관하다.
- BPM이 변하면 시간축(픽셀)은 그대로이고 **그리드 간격이 달라진다**.
- 사용자는 **zoom** 값을 조절하여 표시되는 노트 밀도를 변경할 수 있다.
- `Ctrl` + 마우스 휠로 줌을 조절한다. 브라우저 기본 줌은 에디터 마운트 중 차단된다.

### 재생

- 음원의 **재생/정지** 기능을 제공한다.
- **재생 중 편집 제한 `[미구현]`**: 에디터 재생 중에는 노트·이벤트의 생성·이동·삭제와 롱노트·구간 이벤트의 길이 조절을 실행할 수 없다. Undo·Redo도 정지 상태에서만 사용할 수 있다. 이 제한은 마우스·터치·키보드 등 입력 방식과 관계없이 적용한다. 결정 근거는 [RFD 0099](../rfd/0099-editor-playback-editing-boundary.md)를 따른다.
- **재생 중 타이밍 값 수정 제한 `[미구현]`**: 오프셋·BPM·박자표 값도 정지 상태에서만 수정할 수 있다. 재생 중 수정 시도는 값과 재생 상태를 바꾸지 않는다.
- **타이밍 값 수정 뒤 커서의 박 유지**: 직접 일시정지한 뒤 타이밍 값을 수정하기 직전 커서의 박 좌표를 유지한다. 수정 전 타이밍에서 현재 커서의 박을 구하고, 수정 후 같은 박에 해당하는 새 음원 시각으로 커서를 갱신한다. 다시 재생하면 그 위치부터 시작한다. 일시정지 후 사용자가 seek했다면 seek한 뒤 수정 직전의 커서 박을 기준으로 한다. 정지 순간의 박을 계속 고정하거나 수정 전 음원 시각을 그대로 유지하는 규칙은 아니다. 박자표는 박과 음원 시각의 변환에 쓰지 않으므로 박자표만 바꾸면 커서가 움직이지 않는다. BPM 변경 이벤트의 생성·이동·삭제와 Undo·Redo처럼 타이밍이 바뀌는 다른 편집에도 같은 규칙을 적용하며, 차트를 새로 불러올 때는 적용하지 않는다. 사용자가 커서를 직접 옮기지 않는 한 커서는 같은 박에 머문다. 그 박이 타임라인(0ms와 0박 중 앞선 시각부터 타임라인 끝까지) 밖으로 나갈 때만 커서를 타임라인 끝으로 옮기며, 이후 타이밍이 Esc·Undo 등으로 되돌아가면 원래 박으로 돌아온다.
- 음원 정렬 오프셋 입력창이 열린 상태에서도 재생·일시정지 조작을 제공한다. 오프셋 값은 정지 상태에서만 수정할 수 있다. 상세 요구는 [곡 타이밍 공유](#곡-타이밍-공유-미구현)의 오프셋 조절 중 재생을 따른다(후속 UI 구현).
- **재생 커서**: 현재 재생 위치를 밝은 초록색 수평선으로 표시한다. 커서 우측에 왼쪽을 향하는 삼각형 핸들이 있으며, 핸들을 드래그하여 재생 위치를 변경(seek)할 수 있다.
- **커서 핸들 드래그**: 타임라인 우측(마디 번호 영역)을 클릭하면 해당 위치로 즉시 이동하며, 드래그하면 실시간으로 재생 위치가 갱신된다.

### 스냅

- **스냅(snap)** 기능으로 그리드 눈금 간격을 조절할 수 있다. 기준 단위는 **박(beat)** 이다 (예: 1/4박, 1/8박, 1/16박, …).
- 노트 배치·이동 시 스냅 설정에 따라 가장 가까운 그리드 눈금에 흡착된다.
- **엔티티 판정(hit test)은 스냅과 무관하게 실제 마우스 위치(raw beat)를 사용한다.** 스냅 1/4 설정에서도 1/16 위치에 배치된 노트를 정확히 hover·클릭·삭제할 수 있다.

### 노트 배치 좌표

노트는 그리드 선을 기준으로 **중앙 정렬**된다. 노트 높이가 `H`이고 그리드 위치가 `P`이면, 노트는 `P − H/2` ～ `P + H/2`에 위치한다.

롱노트의 시작점·끝점도 동일한 규칙을 따른다.

```
시작점 S, 끝점 E, 노트 높이 H 일 때:

  S−H/2 ─┬─ 시작 노트 상단
         │
    S    ─── 시작 그리드 선
         │
  S+H/2 ─┴─ 시작 노트 하단 ─┬─ 바디 시작
                             │  바디 길이 = E − S − H
                             │  (E − S < H 이면 바디 없이 시작·끝 노트가 겹침)
  E−H/2 ─┬─ 끝 노트 상단   ─┘─ 바디 끝
         │
    E    ─── 끝 그리드 선
         │
  E+H/2 ─┴─ 끝 노트 하단

  총 시각적 길이 = (E − S) + H
```

시작점 = 끝점(길이 0)인 롱노트의 시각적 높이는 `H`이다.

**Z-order** (뒤→앞):

| 계층 | 요소 | 비고 |
|------|------|------|
| 1 | 레인 배경 | L1～L4·BPM·박자·메시지 레인의 배경색. 레인 구분을 위해 교대 색상 사용 |
| 2 | 파형 | 음원의 waveform |
| 3 | 마디선 | 마디 경계를 나타내는 굵은 수평선 |
| 4 | 박자선 | 마디 내 박자 경계를 나타내는 수평선. 마디선보다 얇다 |
| 5 | 스냅선 | 스냅 설정에 따른 세분 눈금선. 박자선보다 얇고 연하다 |
| 6 | `trillZone` | 트릴 롱노트의 배경 영역 |
| — | `restZone` | 휴지 구간 밴드 — 레인을 검정 α0.2로 살짝 어둡게 깐 위에 폭 6px 검정 빗금(α0.6)을 긋는다(RFD 0019). 빗금 위상은 구간 시작 박 위치(아래쪽 모서리)에 고정돼 스크롤·이동하면 구간과 함께 움직이고, 끝 캡으로 길이를 바꿔도 미끄러지지 않는다. 위반 표시의 가는 빨간 해칭과 구별된다. 미니맵은 빗금 없이 검정 α0.6 단색이다. 트릴존·노트 아래 z-order |
| 7 | 롱노트 바디 | |
| 8 | 롱노트 끝점 | |
| 9 | 롱노트 시작점(헤드) | |
| 10 | 일반 노트 | 롱노트 헤드보다 위 — 헤드는 바디로 존재를 인지할 수 있지만 일반 노트는 가려지면 알 수 없다 |
| 11 | **선택된** 롱노트 바디 | |
| 12 | **선택된** 롱노트 끝점 | |
| 13 | **선택된** 롱노트 시작점(헤드) | |
| 14 | **선택된** 일반 노트 | |
| 15 | 고스트 프리뷰 | Create 모드에서 배치 예정 위치를 표시하는 반투명 오버레이. 스냅 위치에 기존 노트가 있으면 고스트 대신 hover 아웃라인이 표시된다 |
| 16 | 마디 번호 | 마디선 우측에 표시되는 마디 번호 라벨 |
| 17 | 재생 커서 | 현재 재생 위치의 수평선 + 드래그 핸들 |

`o-o-` 패턴에서 이전 롱노트의 끝점을 조작하려면 해당 롱노트를 먼저 선택하여 z-index를 올린 뒤 리사이즈 핸들을 사용한다.

- **오토스크롤** 토글을 제공한다.
- 활성화 시 재생 중 현재 재생 위치를 따라 타임라인이 자동으로 스크롤된다.

| 모드   | 단축키 | 설명 |
| ------ | ------ | ---- |
| Create | `C`    | 배치할 엔티티 종류(노트 종류·이벤트 종류)를 선택한 뒤 타임라인을 클릭하여 배치한다. 이벤트를 생성하면 직전 이벤트의 값을 복사한 새 이벤트가 생성되며, 더블클릭으로 값을 수정하는 모달이 열린다. 커서 위치에 **고스트 프리뷰**(반투명 흰색)가 표시된다 |

#### Create 모드

|------|------|

| `C` + 마우스 휠 | `C`를 누르고 있는 상태에서 휠을 굴리면 생성할 엔티티 타입을 변경한다. 엔티티 타입 드롭다운이 열린다 |
| 커서 이동 | **빈 셀 위**: 스냅 위치에 **고스트 노트**(반투명 흰색 사각형)가 표시된다. 보조 레인 위에서는 **고스트 이벤트**가 표시된다. **스냅 위치에 기존 노트가 있을 때**: 고스트 대신 해당 노트에 **hover 아웃라인**(흰색 테두리)이 표시된다. **커서가 직접 노트 위에 있을 때**: 스냅과 무관하게 raw beat 기준으로 해당 노트에 hover 아웃라인이 표시되고, 고스트가 숨겨진다. 레인 밖으로 나가거나 다른 모드로 전환하면 고스트가 사라진다 |

| `Shift` + 드래그 | 기존 선택을 유지한 채, 드래그 영역과 겹치는 노트들을 선택에 추가한다 |
| `Alt` + 드래그 | 드래그 영역과 겹치는 노트들을 기존 선택에서 제거한다 |
| 노트 외 영역 클릭 | 선택 해제 (배치 확정 겸용 — 붙여넣기 대기 중이면 확정) |
| `Enter` | 배치 확정 (붙여넣기 대기 중이면 확정). 이동·붙여넣기는 낙관 커밋 — 의미 위반이어도 그대로 반영되고 빨간 해칭으로 표시된다(구조 위반만 거부, RFD 0017) |
| `↑` / `↓` | 선택된 노트의 이동 예정 위치를 한 스냅씩 상/하로 이동 |
| `←` / `→` | 선택된 노트의 레인을 한 칸 좌/우로 이동한다. 메인 레인(1..4)과 보조 레인(5+, 표시상 별도 영역)은 **논리적으로 연속**이라 lane 4에서 `→`면 보조 레인 1로, 보조 레인 1에서 `←`면 lane 4로 **한 칸 이동**한다 — 변환이 아니라 그냥 레인 이동이고 beat는 보존된다. 이동 범위는 `1..(4+보조 레인 수)`로 클램프되며 벗어나면 전체 차단. 트릴 노트 단위 선택은 구간(한 레인)을 벗어날 수 없어 레인 이동이 차단된다 (RFD 0018 ④) |
| `Shift` + `↑` / `↓` | 선택된 롱노트의 끝점을 한 스냅씩 상/하로 이동 (리사이즈). 롱노트가 아닌 노트에는 적용되지 않는다 |
| 선택된 노트 드래그 앤 드롭 | 드래그 중 이동될 위치에 프리뷰를 표시한다(위반 위치도 그대로 표시). 드롭 시 그대로 커밋 — 위반이면 빨간 해칭으로 표시되고 되돌리기는 undo (RFD 0017) |
| 메인↔보조 드래그 | 메인·보조 노트는 한 배열(`chart.notes`)의 lane으로만 구분되므로 드래그가 메인/보조 경계를 넘어도 **변환 없이 그대로 레인이 바뀐다**(메인 4 ↔ 보조 1은 논리적으로 한 칸 연속 — 렌더 x는 시각 경계선을 사이에 둔 별도 영역이라 기하학적으로는 불연속). 이동 범위는 `1..(4+보조 레인 수)`로 클램프되고, 드롭 전 `Esc`는 이동을 취소해 원위치로 되돌린다. 트릴 노트 단위 선택은 구간(한 레인)을 벗어날 수 없어 레인이 고정된 채 beat만 따라온다 (RFD 0018 ④) |
| `Delete` | 선택된 노트를 삭제 |

> **제거한 선택 해제 게이트 (RFD 0017 §3-5, 대조용 기록)**: 새 에디터는 의미 위반 항목도 해제·교체할 수 있다. 제거 전에는 선택 해제(교체·부분 해제·전체 비우기 포함)를 선택 집합 전이로 취급했다 — 해제되는 노트·`trillZone`이 의미 위반에 관여한 채 남으면 그 전이를 거부하고 토스트로 사유를 알렸다(선택 유지). 위반을 해소(재이동)하거나 undo·삭제하면 통과했다.

> **진행 중 조작과 독립 명령**: 붙여넣기 대기·이동 드래그·끝점 리사이즈 중에 `G` 토글·모드 전환·Undo/Redo·다른 편집 같은 독립 명령이 들어오면 진행 중 조작을 **그 시점 결과로 먼저 확정**한 뒤 명령을 실행한다. 확정된 조작은 Undo 한 단위로 남고, 뒤늦은 `Esc`·`Enter`·화살표나 같은 드래그의 후속 이동은 그 조작을 되돌리거나 이어가지 않는다. 우클릭 드래그 삭제도 같은 규칙을 따른다.

> **붙여넣기 보조 레인 자동 확장 (RFD 0018 §8-6 D3)**: 붙여넣은 보조 노트·이벤트가 현재 보조 레인 수를 넘으면(예: 보조 레인 수 1인데 보조 2에 붙여넣기) 그 항목이 숨지 않도록 보조 레인 수를 필요한 만큼 **자동 확장**한다. 이동(레인 클램프)·레인 수 축소(숨김 유지)와 달리 붙여넣기는 새 항목이 보이도록 확장한다. 로드 시 초기 타이밍 설정의 겹침 분리에서도 빈 표시 레인이 부족하면 필요한 만큼 확장한다([RFD 0082](../rfd/0082-initial-timing-events-not-selectable.md), 로드 자동 분리는 후속 구현).

> **이벤트 클립보드 ([RFD 0068](../rfd/0068-common-event-editing.md))**: 명시적으로 선택한 이벤트만 노트·구간과 함께 복사한다. 박자 변경도 포함하며, 복사한 모든 항목의 가장 이른 시작 박을 기준으로 붙여넣는다. 대기 중 위/아래 이동은 박을, 좌/우 이동은 각 항목의 레인을 함께 바꾼다(이벤트는 `editorLane`). Esc는 주입한 이벤트도 복구한다. 의미 위반은 기존 낙관적 편집·저장 검증을 따른다.

##### `trillZone` 선택 모델

`trillZone`과 그 안의 트릴노트는 **두 가지 선택 단위**로 다룬다. **개별 트릴노트 선택**만 배타적이다 — 같은 구간의 트릴노트끼리만 함께 선택되며 일반노트와 섞이지 않는다. **구간 단위 선택(유닛)**은 일반노트 선택과 **공존**한다(RFD 0016·0018). 막히는 선택을 시도하면 **토스트로 이유를 알린다**.

- **구간 단위 선택 (RFD 0016 §6-6)**: `trillZone` **몸통이 노트와 같은 상호작용 규칙**을 따른다 — 별도 이동 핸들은 없다. **미선택 몸통 클릭(움직임 없이 뗌)**하면(또는 박스 선택이 구간을 **완전히 감싸면**) 그 구간이 **유닛으로 선택**되고 — 내부 트릴노트는 선택 집합에 들어가지 않고 이동·삭제·복사 **시점에 파생되어 동반**된다(RFD 0016) — **선택된 몸통을 드래그하면 구간째 이동**한다. 미선택 몸통에서 바로 드래그하면 **박스 선택**이 된다(감쌈 판정은 아래와 동일). `Shift`/토글 클릭은 몸통에서 구간 유닛을 zones에 **토글**한다(기존 선택과 공존). 트릴노트로 꽉 찬 구간(예: 구간과 같은 길이의 trillLong)은 몸통이 노트-히트에 가려지므로 밖에서 감싸는 박스로 유닛 선택한다.
- **노트 단위 선택**: 트릴노트를 클릭하면 그 노트만 선택된다(트릴 헤드와 그 트릴 롱노트는 한 쌍으로 선택된다, 아래 롱노트 "선택" 절). `Shift`/박스 선택으로 추가할 수 있는 대상은 **같은 `trillZone`에 속한 트릴노트로 한정**된다. 일반노트(트릴 이외)와는 함께 선택되지 않는다.
- **박스 선택 — 감쌈(containment) 모델 (RFD 0016 §6-2)**: 박스는 **빈 곳 또는 미선택 `trillZone` 몸통에서 시작**하며(트릴노트 위 드래그는 그 노트 이동), 박스 안 판정은 앵커 없이 매 프레임 순수 기하로 계산된다: `trillZone`을 **완전히 감싸면** 그 구간을 **유닛**으로, 완전히 안 감싸면(통과) 그 구간의 트릴노트 중 **박스 안에 든 것만 개별 선택**, 일반노트는 박스 안이면 선택. 즉 빈 곳에서 트릴노트 주위로 박스를 그리면 그 트릴노트들이 개별 선택되고, 구간 전체를 감싸면 유닛이 된다. 동질성(개별 트릴은 같은 구간끼리만)은 선택 정규화 게이트가 처리한다. 마우스·터치 동일하게 동작한다.

`trillZone`의 **끝(위)**에는 **리사이즈 핸들**(레인 폭을 가로지르는 **풀폭 가로 캡** — 단색 직각 바)이 있다. **캡은 그 구간이 선택됐을 때만 표시·활성**된다(RFD 0016 §6-6) — 미선택 구간에서는 캡이 뜨지 않아 **끝에 놓인 노트를 가리지 않고 그대로 클릭**할 수 있다(리사이즈하려면 먼저 몸통 클릭·박스로 구간을 선택). 끝 가장자리를 드래그하면 `endBeat`가 변경되어 구간 길이가 조절된다(시작점 이상으로 클램프). 선택된 구간에서 끝 리사이즈는 몸통 이동보다 **우선**한다. **리사이즈·이동 드래그 중에는 커서가 구간 밖으로 나가도 핸들이 계속 표시된다.** 캡 위에서는 커서가 `ns-resize`(↕)로, **선택된 구간의 몸통 위**에서는 `move`로 바뀌어 "세로 리사이즈 / 선택 후 양축 이동" 방향을 보강한다. 캡 강조색은 기본 초록(`trillZone` 색), 구간 단위 선택 시 **빨강 + 도형 높이 +1px**(색+형태 이중 채널)이다. 길이 0인 구간(시작==끝)도 리사이즈 캡으로 늘려 실제 길이를 가진 구간으로 만든다.

끝점을 줄여 내부 트릴 노트를 구간 밖으로 내보내는 리사이즈는 마지막 유효 위치를 유지한다(RFD 0017 추가 4, #344에서 구현). 그 뒤에는 트릴 노트를 먼저 옮기거나 삭제한 뒤 축소한다. #344 전의 구현은 이 리사이즈도 낙관 편집으로 확정하고 의미 위반으로 표시했다.

선택 단위별 동작:

| 동작 | 구간 단위 | 트릴 노트 단위 |
|------|-----------|----------------|
| 이동 | 구간 + 안의 노트를 **한 덩어리로 자유 이동**(시간·레인). 선택 후 몸통 드래그와 방향키(`↑`/`↓`/`←`/`→`) 모두 동일하게 동작한다. 타임라인 범위를 벗어나면 차단. 다른 구간과의 겹침(의미 위반)은 낙관 커밋되어 빨간 해칭으로 표시된다(RFD 0017) | **해당 구간 범위 안에서만** 이동(박자 클램프, trillLong은 양끝 모두, **레인 변경 불가**). 드래그는 경계까지 클램프, 방향키는 경계를 벗어나면 차단 |
| 삭제 | 구간 + 안의 노트를 함께 삭제 | 선택된 트릴노트만 삭제(구간은 남는다) |
| 복사/붙여넣기 | 구간 + 안의 노트를 함께 복사하여, 붙여넣을 위치에 구간째 생성(낙관 붙여넣기 — 위반은 빨간 해칭으로 표시) | 복사 시 **구간 단위로 승격**하여 구간 + 선택 노트를 함께 복사 |

선택된 구간(구간 단위 선택)은 선택 강조 테두리로 표시한다.

| `Ctrl` + 마우스 휠 | 타임라인의 zoom 값을 조절한다. 휠 업으로 확대, 휠 다운으로 축소. 브라우저 기본 줌은 차단된다 |

### 모바일 터치 조작

모바일 환경에서는 키보드와 마우스가 없으므로 터치 기반 대체 조작을 제공한다. 모드 전환은 화면 상단 툴바의 버튼으로 수행한다.

| 터치 드래그 | 현재 모드의 드래그 조작을 수행. 브라우저 기본 스크롤/확대 제스처보다 에디터 조작을 우선한다 |

|------|------|
| 노트 터치 | 해당 노트를 삭제 |
| 노트 없는 구간 터치 | 빈 `trillZone`·`restZone`을 삭제한다. 노트가 든 `trillZone`은 지우지 않고 알린다. 삭제가 막힌 노트 아래 구간도 대신 지우지 않는다 |

### 배치 제약 조건

다음 제약 조건은 저장·플레이 진입 게이트가 강제한다. 편집 중에는 낙관적 편집(RFD 0017)에 따라 생성·이동·리사이즈·붙여넣기 모두 의미 위반이어도 그대로 커밋되며(transient 상주), 위반은 빨간 해칭과 미니맵 지시자, 툴바 위반 배지(`⚠ N` + 클릭 시 사유 리스트, §툴바 구성)로 표시된다.

채택한 별도 예외로, `trillZone` 끝을 줄여 내부 트릴 노트를 구간 밖으로 보내는 조작은 마지막 유효 위치에서 멈춘다(#344에서 구현, [RFD 0017 추가 4](../rfd/0017-optimistic-edit-transient-invalid.md#3-4-구조의미-분류-확정-소비자-감사-2026-07-09)). 신형 바디 삭제·축소 보호는 위의 새 계약을 따른다.

1. **동일 위치 중복 금지** — 같은 레인·같은 박자수에 두 개 이상의 노트가 존재할 수 없다.
2. **롱노트 구간 내 겹침 금지** — 롱노트 바디의 시작점과 끝점을 제외한 열린 구간 안에 다른 노트나 롱노트 시작점·끝점이 존재할 수 없다.
3. **`trillZone` 전용** — `trillZone` 안에는 트릴 노트만 존재할 수 있고, 트릴 노트는 `trillZone` 안에만 존재할 수 있다.
4. **`trillZone` 겹침 금지** — 같은 레인에서 `trillZone`끼리 겹칠 수 없다.
5. **이벤트 중복/겹침 금지** — 같은 보조 레인(`editorLane` 생략 시 1)에서는 종류에 관계없이 이벤트의 점·구간이 겹치면 배치 위반이다([RFD 0078](../rfd/0078-event-placement-overlap.md)). 시점 이벤트와 길이 0 구간은 점으로, 양수 길이 구간은 시작을 포함하고 끝을 제외해 검사하며 끝과 다음 시작이 맞닿는 배치는 허용한다. 다른 보조 레인의 동시 배치는 허용하되, 같은 박의 같은 종류 시점 이벤트(BPM, 박자표) 중복과 같은 종류 구간 이벤트(메시지, auto, stop)의 시간 겹침은 기존대로 레인과 관계없이 금지한다. 위반은 편집 중 확정·수리할 수 있지만 저장·플레이를 막으며 일반 이벤트는 자동으로 레인을 옮기지 않는다. 겹친 0박 초기 BPM·박자 설정만 아래 로드 자동 분리 예외를 적용한다([RFD 0082](../rfd/0082-initial-timing-events-not-selectable.md)).
6. **stop 구간 내 노트 금지** — stop 이벤트(§정지 (Stop) 이벤트 참조)가 점유하는 구간 안에 노트를 배치할 수 없다.
7. **길이 0 롱노트 헤드 금지** — 길이 0인 롱노트(시작점 = 끝점)에는 헤드 노트가 존재할 수 없다. 길이가 있는 롱노트(시작점 ≠ 끝점)에만 헤드 노트(싱글/더블/트릴)가 시작점에 배치된다.

의미 위반의 빨간 해칭 표시(RFD 0017)는 노트·`trillZone`뿐 아니라 **이벤트에도 적용**된다 — 위반 이벤트는 자신의 엑스트라 레인 칸(`editorLane`, 기본 1)에 해칭되며, 시점 이벤트(BPM, 박자표)는 포인트로, 구간 이벤트(메시지, auto, stop, tutorial)는 `endBeat`까지의 구간으로 표시된다.

### 롱노트 상호작용

롱노트는 시작점·바디·끝점으로 구성되는 구간 엔티티이다. 다른 노트와 달리 **시작점과 끝점이 분리**되어 있으므로, 생성·선택·리사이즈에 별도의 상호작용 설계가 필요하다. 이 절의 규칙은 싱글 롱노트, 더블 롱노트, 트릴 롱노트 모두에 동일하게 적용된다(다만 트릴 롱노트는 트릴 헤드와 한 쌍으로 선택된다).

#### 위치 겹침 문제

롱노트의 시작점에 헤드 노트(싱글/더블/트릴)가 존재하거나, 끝점 위치에 다른 롱노트의 시작점이 올 수 있다(`o-o-` 패턴). 이처럼 시작점·끝점에 다른 노트가 겹칠 수 있으므로, 리사이즈를 위해 끝점을 드래그하려면 **노트 이동**과 **롱노트 리사이즈** 동작을 구분하는 메커니즘이 필요하다.

#### 생성 (Create 모드) — 통합 입력

롱노트는 **싱글/더블 입력에서 분리된 타입이 아니라, 누르는 길이로 결정**된다. 별도로 "롱노트 타입"을 고를 필요가 없다.

1. 싱글(또는 더블)을 선택한 상태에서 타임라인의 원하는 위치를 누른다.
2. **누르고 바로 떼면**(드래그 0) 그 위치에 단노트(싱글/더블)가 배치된다.
3. **누른 채 드래그하면** 시작 지점이 시작점(헤드), 드래그 끝 지점이 끝점인 롱노트가 된다. 헤드는 싱글→`single`+`long`, 더블→`double`+`doubleLong`로 함께 배치된다.
4. 드래그 중 현재 끝점 위치에 구간 프리뷰가 표시되며, 스냅 설정에 따라 흡착된다.
5. 손을 놓으면 그대로 배치된다(낙관 커밋, RFD 0017) — 배치 결과가 의미 위반(중복·겹침)이어도 커밋되고 빨간 해칭으로 표시된다.

데스크탑(마우스)·모바일(터치) 모두 동일한 모델이다. 모바일에서는 빈 셀을 터치하면 단노트, 길게 눌러 드래그하면 롱노트가 된다.

> 끝점/길이 판정은 **시작 스냅 비트와 끝 스냅 비트가 같으면 길이 0(단노트), 다르면 롱노트**다. 같은 스냅 칸 안의 미세한 드래그는 단노트로 떨어진다.

##### 길이 0 롱노트(헤드 없는 바디) 입력

통합 입력의 "클릭"은 단노트를 만들므로, **헤드 없는 길이 0 롱노트**(바디만, 단노트와 의미가 다른 엔티티)는 통합 입력으로는 만들 수 없다. 이를 위해 툴바의 **`long`/`doubleLong` 엔티티를 유지**한다:

- `long`/`doubleLong`을 선택하고 **클릭(드래그 0)**하면 헤드 없는 **길이 0 롱노트**가 생성된다.
- `long`/`doubleLong`을 선택하고 **드래그**하면 길이가 있는 롱노트(헤드+바디)가 생성된다(싱글/더블 드래그와 동일 결과).

#### 선택 (Select 모드)

롱노트의 **시작점·바디·끝점** 어디를 클릭하든 **롱노트 전체가 하나의 단위로 선택**된다. 롱노트의 구성 요소(시작점, 바디, 끝점)를 개별 선택할 수 없다. 다만 시작점에 헤드 노트가 있으면, 그 위치에서는 롱노트 위에 그려진 헤드 노트가 선택된다. 헤드는 선택돼 있지 않고 롱노트만 선택돼 있으면 선택된 노트가 우선이라, 그 위치에서도 롱노트가 잡힌다(둘 다 선택돼 있으면 헤드가 잡힌다).

**싱글·더블 헤드 노트는 롱노트와 따로 선택된다.** 싱글·더블 헤드는 시작점에 놓인 별개의 노트라([glossary "헤드 노트"](../context/glossary.md#헤드-노트)), 헤드를 클릭하면 헤드만, 바디를 클릭하면 롱노트만 선택된다. 트릴 롱노트는 다르다. 트릴 헤드나 트릴 롱노트를 새로 선택하거나 `Shift`·토글로 더하면 쌍이 함께 선택된다(`withTrillPairs`). 다만 지금은 선택되지 않은 트릴 롱노트의 끝 캡을 잡거나(마우스·터치 공통) 터치로 끝 캡을 길게 누르면(이미 선택돼 있어도) 트릴 롱노트만 선택되고([#329](https://github.com/nanana3679/not4k/issues/329)), `Alt` + 클릭이나 토글로 한쪽을 빼면 누른 노트만 빠져 쌍이 갈라진다. 헤드와 롱노트를 함께 옮기려면 둘 다 선택한다. 헤드를 먼저 고른 뒤 바디를 `Shift` + 클릭하거나, 시작점을 감싸는 박스로 고른다.

> **근거**: 롱노트의 시작점과 끝점은 한 엔티티의 두 값(`beat`·`endBeat`)이라 따로 선택할 수 없다. 싱글·더블 헤드는 시작점에 놓인 별개의 노트라 따로 옮길 수 있다. 헤드가 시작점에서 떨어지면 그 노트는 더 이상 헤드가 아니고, 롱노트는 헤드 없는 롱노트가 된다. 그 결과가 배치 제약을 어기면(예: 같은 unit 수로 맞닿은 경계에는 head 또는 앞 끝의 `holdOnly`가 필요하다, [NJ-C02](note-judgment-cases.md#nj-c02)) 다른 이동처럼 빨간 해칭으로 표시된다(RFD 0017). 메인·보조 레인의 트릴 롱노트는 시작점에 트릴 헤드가 있어야 하므로(`validateTrillLong`), 한쪽만 옮기면 대개 헤드 없는 트릴 롱노트가 되어 위반이 된다. 그래서 쌍으로 묶는다.

#### 리사이즈 (Select 모드)

롱노트의 끝에 **리사이즈 캡**(끝 핸들)이 표시되며, 이를 드래그하여 끝점(`endBeat`)을 변경한다. `trillZone`의 리사이즈 캡과 **같은 도형·커서 언어**를 공유한다.

##### 리사이즈 핸들

| 위치 | 설명 |
|------|------|
| 끝 캡 | 롱노트 끝(위)에 표시되는 **레인 폭을 가로지르는 풀폭 가로 캡**(단색 직각 바). 드래그하면 `endBeat`가 변경되어 길이가 조절된다(시작점 이상으로 클램프) |

- 캡 위에 커서가 올라가면 **수직 리사이즈 커서(`ns-resize`, ↕)**로 변경된다.
- 캡은 롱노트가 **선택된 상태**(모바일·데스크탑 공통)이거나, **select 모드에서 그 노트에 hover**(데스크탑)했을 때 표시된다. 강조색은 hover 시 흰색, 선택 시 빨강이다.
- 캡 색·도형은 `trillZone` 끝 캡과 동일하며, **트릴 롱노트(trillLong)에도 동일하게 캡이 표시**된다(트릴 롱노트도 끝점 리사이즈 대상). `trillZone` 자체의 리사이즈 핸들과는 별개로 동작한다.

##### 한 동작 리사이즈 (미선택 상태)

- 어떤 위치에서 **z-order 최상위**인 롱노트라면, 미리 선택돼 있지 않아도 끝 캡을 잡는 즉시 그 노트를 단독 선택으로 전환하며 리사이즈를 시작한다(별도 선택 단계 불필요).
- 끝점이 다른 노트와 겹치는 `o-o-` 패턴에서는, 그 위치의 최상위 노트가 아닐 경우 캡 리사이즈가 동작을 가로채지 않는다(z-order로 대상 구분). 가려진 롱노트의 끝을 조작하려면 먼저 선택하여 z-index를 올린다.

##### 히트 영역 분리

끝 캡 히트 영역이 바디·헤드와 공간적으로 분리되어, 끝점 리사이즈와 이동을 구분한다:

```
 ┌──────────┐  ← 끝 캡 히트 영역 (드래그 → 끝점 리사이즈)
 │  바 디   │  ← 바디 히트 영역 (드래그 → 롱노트 이동)
 │  바 디   │
 ├──────────┤
 │  헤 드   │  ← 헤드 노트 히트 영역 (드래그 → 헤드 노트 이동)
 └──────────┘
```

> 화면상 시간은 위로 갈수록 증가하므로 **끝점(`endBeat`)이 위, 시작점(헤드)이 아래**에 온다.

- 끝 캡은 끝점(`endBeat`) 위치에 표시되며, 끝점 ± 약 1/16박 범위가 캡 히트 영역이다.
- 시작점(헤드 위치) 리사이즈는 아직 제공하지 않는다. 시작점을 바꾸려면 롱노트를 이동한다(싱글·더블 헤드도 함께 옮기려면 둘 다 선택한다).

##### 드래그 동작

| 드래그 대상 | 동작 |
|-------------|------|
| 헤드 노트 영역 | 롱노트가 선택돼 있지 않으면 헤드를 잡는다. 싱글·더블 헤드는 헤드 노트만 이동하고, 트릴 헤드는 트릴 롱노트와 한 쌍으로 이동한다 |
| 바디 영역 | 롱노트 이동(시작점·끝점 동시 이동) |
| 끝 캡 | 끝점 변경 — 리사이즈 |

- 이미 선택된 노트를 끌면 선택 전체가 이동한다. 그래서 싱글·더블 헤드는 롱노트와 함께 선택돼 있을 때만 바디를 따라간다. 트릴 쌍도 위 "선택"에서 갈라진 경우(끝 캡으로 고름, `Alt` + 클릭·토글)에는 따라가지 않는다.

- 리사이즈는 구조 위반만 거부하고 의미 위반은 드롭 시 낙관적으로 확정해 빨간 해칭으로 표시한다(RFD 0017). 위반을 되돌리려면 Undo한다. 내부 트릴 노트를 내보내는 `trillZone` 축소는 위의 별도 예외다.

##### 방향키 리사이즈

롱노트가 선택된 상태에서 modifier key와 방향키를 조합하여 리사이즈한다:

| 입력 | 동작 |
|------|------|
| `Shift` + `↑` | 끝점을 한 스냅 위로 이동 (롱노트 길이 확대) |
| `Shift` + `↓` | 끝점을 한 스냅 아래로 이동 (롱노트 길이 축소) |

`↑`/`↓` 단독은 기존 동작(롱노트 이동)을 유지한다. `Shift`를 조합하면 끝점만 이동하여 리사이즈한다.

> **시작점은 리사이즈하지 않는다** — 끝점 리사이즈만 캡 드래그와 방향키로 지원하여 조작의 복잡도를 제한한다. 시작점을 바꾸려면 롱노트를 이동한다.

##### 리사이즈 제약

| 제약 | 설명 |
|------|------|
| 최소 길이 | 시작점과 끝점이 같은 위치(길이 0)를 허용한다(startBeat ≤ endBeat). 길이 0인 롱노트는 시각적 높이 `H`로 표시된다 |
| 역전 방지 | 끝 핸들을 시작점 이전으로 드래그할 수 없다. 시작점에서 클램핑된다 |
| 배치 제약 조건 | 구조 위반은 거부하고 의미 위반은 표시한 채 확정한다(RFD 0017). `trillZone` 위반 축소 차단은 별도 보호다(RFD 0017 추가 4, 구현은 #344) |
| 헤드 타입 보존 | 끝점 리사이즈로 별개 헤드 노트의 타입(싱글/더블/트릴)을 변경하지 않는다 |

#### 모바일 터치 조작

Select 모드, 메인 레인(1～4) 롱노트 기준이다. 보조 레인 롱노트의 끝은 아직 끝 캡으로 잡히지 않아 아래 끝 캡 동작이 적용되지 않는다(마우스·터치 공통, [#100](https://github.com/nanana3679/not4k/issues/100)). Create 모드에서는 싱글·더블을 골랐고 그 위치에 노트를 배치할 수 있으면 길게 눌러 새 롱노트를 만든다. 그 밖의 경우 노트 위를 길게 누르면 Select 모드로 바뀌어 아래 롱프레스와 같이 동작한다.

| 입력 | 동작 |
|------|------|
| 끝 캡 롱프레스 후 드래그 | 끝점 리사이즈. 끝 캡을 약 450ms 누르고 있으면 그 롱노트만 선택하고 곧바로 리사이즈를 시작한다. 선택 여부·z-order와 무관하게 끝 캡 히트(`hitTestNoteEnd`)만 보므로(`resolveLongPressAction`), `o-o-` 접점에서는 뒤 노트를 옮기는 대신 앞 롱노트의 끝을 리사이즈한다. 선택 교체는 선택 해제 게이트를 따른다 |
| 끝 캡에서 바로 드래그 | 마우스와 같은 끝점 리사이즈(위 "한 동작 리사이즈"). 선택됐거나 그 위치의 z-order 최상위인 롱노트에만 적용되며, 끝 캡 위에서는 노트 위 바로 드래그보다 우선한다 |
| 바디 롱프레스 후 드래그 | 롱노트 이동(시작점·끝점이 함께 움직인다). 이미 선택된 노트면 선택 전체를 함께 옮긴다. 헤드 노트는 별개 엔티티라 함께 선택돼 있을 때만 따라간다(미선택 트릴 롱노트의 바디를 길게 누르면 트릴 헤드도 함께 선택된다. 끝 캡으로 선택했다면 트릴 롱노트만 선택돼 있어 헤드가 따라가지 않는다) |

리사이즈 캡의 도형과 히트 영역은 데스크탑과 같다(끝점 ± 약 1/16박, 위 "히트 영역 분리"). 지금은 모바일에서도 캡을 크게 그리거나 히트 영역을 넓히지 않는다. 롱노트 끝 캡의 최소 터치 크기를 보장할지는 [PRD §12](../prd.md#12-미정-사항)의 "에디터 모바일 지원 범위"에서 정한다.

### 시각적 피드백

#### 롱노트 끝점
- 끝점은 헤드와 동일한 색상이되, **50% 투명도**로 렌더링되어 시각적으로 구분된다.
- 헤드(시작점)와 바디는 100% 불투명도를 유지한다.

#### 선택된 노트
- 선택된 노트(포인트/롱노트)에는 **밝은 윤곽선**이 표시된다.
- 윤곽선은 노트 영역 **안쪽**(alignment: 0)으로 그려져 인접 노트와 겹치지 않는다.

#### 이벤트 렌더링
- **`BpmChangeEvent`**: 보라색 배경. 이벤트 위에 BPM 값을 11px 크기로 **중앙 정렬** 표시한다.
- **`TimeSignatureChangeEvent`**: 빨간색 배경. 분모가 1이면 분자만 표시하고(예: `4`), 분모가 1이 아니면 분수로 표시한다(예: `7/2`). 11px 크기로 중앙 정렬.
- **`TextEvent`**: 분홍색 배경에 **연분홍 테두리**(안쪽 정렬)가 항상 표시된다. 텍스트는 이벤트 영역 내에서 워드랩되며, 영역을 초과하면 말줄임표(`…`)로 잘린다.

#### 토스트 알림
- 배치 제약 위반, 삭제 불가 등 경고 상황에서 화면 하단 중앙에 **토스트 메시지**가 표시된다.
- 토스트는 일정 시간 후 자동으로 사라진다.

### 이벤트의 선택·공통 편집

> 채택한 편집 계약이다. 이벤트 명칭의 코드 전환은 [PR #368](https://github.com/nanana3679/not4k/pull/368), 공통 편집·배치 겹침 검증·초기 설정 선택 제외는 [PR #369](https://github.com/nanana3679/not4k/pull/369)로 반영했다. 로드 시 초기 설정 자동 분리는 후속 구현이다.

이벤트는 Select 모드에서 일반 노트와 같은 조작을 사용한다([RFD 0068](../rfd/0068-common-event-editing.md)). 저장 배열은 `events`, 선택 인덱스는 `Selection.events`다.

- 클릭은 단독 선택, Shift는 추가, Alt는 해제, 터치 다중선택은 토글이다. 선택된 이벤트에는 선택 윤곽선을 표시한다.
- 박스와 겹친 시점·구간 이벤트를 선택하며 노트·`trillZone`·`restZone`과 함께 선택할 수 있다. 0박 초기 BPM·박자는 클릭·수식자·터치·박스·Ctrl+A를 포함한 모든 선택에서 제외한다([RFD 0082](../rfd/0082-initial-timing-events-not-selectable.md)). 초기 설정 때문에 일반 노트의 혼합 이동이 막히지 않게 한다.
- 선택한 항목은 드래그·위/아래 방향키로 같은 박 오프셋만큼 이동한다. 좌/우 방향키는 이벤트의 `editorLane`을 보조 레인 안에서 이동한다. 혼합 선택에서 한 항목이라도 범위를 벗어나면 전체 이동을 차단한다.
- 구간 이벤트의 끝은 드래그 또는 Shift+위/아래 방향키로 리사이즈한다. 시작 박·종류별 속성은 유지한다.
- 복사·잘라내기·붙여넣기·Delete는 명시적으로 선택한 이벤트에 적용한다. 복사·잘라내기·붙여넣기 토스트는 노트·구간·이벤트를 합친 항목 수를 안내한다. 선택하지 않은 이벤트는 노트의 시간 범위에 겹쳐도 복사하지 않는다. 박자 변경도 선택하면 복사한다.
- 이동·리사이즈·붙여넣기·드래그 삭제는 기존 트랜잭션으로 프리뷰·확정한다. Esc는 시작 전 상태를 복구하고, undo/redo는 확정된 편집을 되돌린다.
- 0박 초기 BPM·박자는 선택할 수 없어 선택 기반 이동·복사·Cut·Delete에 포함되지 않는다. 더블클릭 속성 모달에서 값과 보조 레인(`Editor lane`)을 편집한다. 보조 레인은 현재 보조 레인 수 안의 정수만 허용하며 초기 설정의 종류·0박 위치는 유지한다. Cancel은 값을 적용하지 않고 Save는 Undo 한 단위로 기록한다. 로드 시 겹친 초기 설정만 값·박 위치를 유지해 빈 보조 레인으로 분리하고, 정리 후 상태는 불러온 기본 상태로 삼아 Undo·Redo·별도 미저장 표시에서 제외한다. 이후 보조 레인은 모달에서 수동 편집할 수 있다. 직접 삭제와 시간 이동의 보호도 유지한다.
- BPM·박자 변경 드래그는 down 당시의 시간 투영을 사용하므로 이벤트 이동이 포인터 좌표 해석을 다시 바꾸지 않는다.

### 이벤트 편집 모달

- 이벤트(BPM·박자·메시지)를 **더블클릭**하면 편집 모달이 열린다.
- BPM·박자 모달 제목은 각각 **Edit BPM Change Event**, **Edit Time Signature Change Event**다. 차트 이벤트와 화면 표현을 별도 “마커”로 부르지 않는다([RFD 0067](../rfd/0067-chart-event-names.md)).
- **`BpmChangeEvent`**: BPM 값 입력 필드.
- **`TimeSignatureChangeEvent`**: 분자/분모 입력 필드.
- **메시지**: 텍스트 입력 필드.
- 모달에서 **Save**로 값을 저장하거나 **Delete**로 이벤트를 삭제할 수 있다.
- **beat 0 보호**: 0박에 위치한 `BpmChangeEvent`와 `TimeSignatureChangeEvent`는 초기 설정으로서 삭제할 수 없다(Delete 버튼 비활성화, 안내 **Cannot delete initial event**). 그 밖의 이벤트는 **Delete event**로 안내한다.

### 메타데이터 편집: 현재 모달과 곡 정보 드로어

제목·아티스트·자켓은 곡 공통 정보로 편집하며, 난이도명·Lv. 등 차트별 정보와 구분한다. 같은 곡의 모든 차트가 같은 값을 사용하고, 이 표시 정보만 수정할 때는 기존 기록·랭킹을 유지한다([곡 메타데이터](../context/glossary.md#곡-메타데이터), [RFD 0096](../rfd/0096-song-shared-display-metadata-and-records.md)). 현행 차트 문서에 저장된 사본과 곡이 소유하는 원본 정보의 편집·참조 일치는 후속 구현이다.

**현재 구현**: 툴바의 **Meta** 버튼으로 메타데이터 편집 모달을 연다.

**채택 UI `[미구현]`**: 곡 정보는 왼쪽의 비모달 드로어에서 편집한다. 제목·아티스트·자켓·음원 정렬 오프셋을 표시하고, 드로어가 열려 있어도 타임라인과 재생·일시정지 조작을 사용할 수 있게 하며, 노트·이벤트 편집은 [재생 중 편집 제한](#재생)을 따른다. BPM·박자표는 타임라인의 공통 레인에 유지한다. 곡 저장 버튼은 드로어의 표시 정보·오프셋과 공통 레인의 타이밍 변경을 함께 저장한다([RFD 0098](../rfd/0098-song-info-drawer-and-save-scope.md)).

**드로어 닫기 `[미구현]`**: 곡 정보 드로어에 미저장 곡 정보 변경이 있으면 저장하거나 해당 변경을 취소한 뒤에만 드로어를 닫을 수 있다. 저장을 선택하면 곡 저장이 성공한 뒤 닫으며, 실패하면 드로어와 편집 내용을 유지한다. 변경 취소는 곡 정보의 미저장 변경을 버리고 마지막 저장 상태로 되돌린 뒤 닫는 동작이다. 별도로 편집 중인 차트 변경은 함께 버리지 않는다. 미저장 곡 정보가 없으면 바로 닫을 수 있다.

- 현재 구현의 편집 필드: 곡명, 아티스트명, 난이도명, 난이도 레벨, 오프셋(ms), 오디오 파일, 이미지 파일, 프리뷰 오디오 파일. 음원 정렬용 오프셋과 BPM은 아래 곡 타이밍 공유 규칙으로 전환할 대상이다.
- **Load Audio**: 모달 내에서 오디오 파일을 로드할 수 있다. 파일 선택 시 파형이 타임라인에 반영되고 오디오 파일명이 메타데이터에 기록된다.

### 곡 타이밍 공유 `[미구현]`

같은 곡에 속한 모든 차트는 초기 BPM·곡 중간의 BPM 변경 목록·박자표·변박 정보·음원 정렬용 오프셋을 공통으로 사용한다. 차트 편집에서 이 값을 수정하면 해당 차트만의 시간 기준 변경이 아니라 곡 공통 정보의 수정으로 취급한다. 노트 배치와 난이도는 차트별로 관리한다([곡 타이밍](../context/glossary.md#곡-타이밍), [RFD 0095](../rfd/0095-song-shared-bpm-and-audio-offset.md)).

**공통 영역 구성**: BPM 전용 레인과 박자표 전용 레인을 곡 공통 영역으로 묶는다. 곡 공통 영역은 타임라인 왼쪽에, 4개 노트 레인은 가운데에, 차트별 이벤트 영역은 오른쪽에 배치한다. 모든 레인은 같은 시간축으로 함께 스크롤한다. 음원 정렬 오프셋은 왼쪽 곡 정보 드로어의 숫자 입력으로 둔다. 노트와 차트에 속한 이벤트는 차트별 영역에 표시한다. 곡 공통이라는 표기로 수정 범위를 알리고, 차트를 바꿔도 공통 정보는 같은 값을 표시한다.

**접기와 펼치기**: 곡 공통 영역은 기본으로 펼쳐 둔다. 접으면 BPM·박자표 레인을 숨기고 좁은 펼치기 버튼만 남긴다. 음원 정렬 오프셋은 곡 정보 드로어에서 조절한다. 접기는 표시만 바꾸며 공통 타이밍의 적용과 현재 편집 위치를 유지한다.

**오프셋 조절 중 재생**: 오프셋·BPM·박자표 값은 정지 상태에서만 수정할 수 있다. 재생 중 수정 시도는 값과 재생 상태를 바꾸지 않는다. 직접 일시정지한 뒤 타이밍 값을 수정하기 직전 커서의 박 좌표를 유지한다. 수정 전 타이밍에서 현재 커서의 박을 구하고, 수정 후 같은 박에 해당하는 새 음원 시각으로 커서를 갱신한다. 다시 재생하면 그 위치부터 시작한다. 일시정지 후 사용자가 seek했다면 seek한 뒤 수정 직전의 커서 박을 기준으로 한다. 정지 순간의 박을 계속 고정하거나 수정 전 음원 시각을 그대로 유지하는 규칙은 아니다. 오프셋 입력과 에디터의 재생·일시정지 조작을 함께 사용할 수 있어야 한다. 입력창을 열어 두는 것만으로는 재생을 막지 않으며, 입력창을 열어 둔 채 일시정지해 수정하고 다시 재생할 수 있어야 한다([RFD 0099](../rfd/0099-editor-playback-editing-boundary.md)).

**저장 범위**: **곡 저장**은 제목·아티스트·자켓 등 곡의 표시 정보와 초기 BPM·BPM 변경 목록·박자표·변박 정보·음원 정렬 오프셋 등 공통 타이밍의 변경을 함께 저장한다. **차트 저장**은 해당 차트의 노트·차트별 이벤트·난이도 정보 등 개별 정보만 저장한다. 두 저장이 서로의 범위에 있는 미저장 변경을 함께 확정하지 않는다. 표시 정보만 수정할 때는 기록을 유지하고, 타이밍 수정으로 실제 입력 시각이 달라지는 차트만 기록·랭킹을 새 버전으로 분리한다([RFD 0098](../rfd/0098-song-info-drawer-and-save-scope.md)).

**Undo·Redo 범위**: 곡 정보 변경과 차트 편집은 하나의 Undo·Redo 이력으로 통합한다. 곡 정보·노트·차트별 이벤트의 구분 없이 가장 최근 작업부터 시간순으로 되돌리고 다시 적용한다. 저장 범위는 기존대로 곡 저장과 차트 저장으로 분리한다. Undo·Redo는 정지 상태에서만 사용할 수 있다.

**곡 정보 변경 취소의 이력**: 곡 정보의 변경 취소도 마지막 저장 상태로 되돌리는 한 작업으로 통합 Undo·Redo 이력에 기록한다. Undo하면 취소 직전의 곡 정보 변경을 복원하고, Redo하면 변경 취소를 다시 적용한다. 변경 취소를 Undo해 곡 정보가 복원되면 드로어를 다시 열어 복원된 내용을 보여준다. 이 작업은 별도로 편집한 차트 내용을 바꾸지 않는다.

**차트 저장 전 공통 정보 확인**: 곡 공통 타이밍에 미저장 변경이 있으면 차트 저장을 차단하고 곡 저장을 먼저 실행하도록 안내한다. 곡 저장이 성공하여 타이밍에 미저장 변경이 없어지면 차트 저장을 허용한다. Save Chart와 Save As에 같은 조건을 적용한다.

**기존 차트의 타이밍 이행**: 기존 차트를 곡 공통 타이밍 구조로 옮길 때, 같은 곡의 차트마다 BPM·박자표·음원 정렬 오프셋이 다르면 관리자가 기준으로 삼을 차트 하나를 선택한다. 선택한 차트의 초기 BPM·BPM 변경 목록·박자표·변박 정보·음원 정렬 오프셋을 해당 곡의 공통값으로 적용한다. 곡 공통 타이밍을 적용할 때 기존 노트·차트별 이벤트의 박 위치를 유지한다. 구간 항목의 시작·끝 박도 그대로 두며, 기존 음원 시각을 유지하기 위한 박 좌표 변환은 하지 않는다. 실제 음원상의 입력 시각과 구간 길이는 새 공통 타이밍에 따라 계산한다.

현행 이벤트·메타데이터 편집은 차트별 문서를 수정한다. 곡 단위 저장·반영과 기존 차트의 이행은 후속 구현이며, 세부는 [PRD §12](../prd.md#12-미정-사항)에서 관리한다.

### `trillZone` 삭제 규칙

- `trillZone`은 **내부에 노트가 없을 때만** 삭제할 수 있다.
- `trillZone` 안에 노트가 있는 상태에서 삭제를 시도하면 "Zone contains notes — remove them first" 토스트가 표시된다.
- 우클릭 삭제와 Delete 모드 모두 동일한 규칙을 따른다.

### 롱노트 삭제

- 롱노트를 삭제하면 해당 롱노트에 대응하는 `trillZone`(같은 레인·같은 시작점·끝점)도 함께 삭제된다.

### 저장 및 불러오기

- Supabase Storage에 차트를 **업로드**(저장)할 수 있다. Google OAuth(관리자 전용)로 인증한 뒤 업로드한다.
- 곡의 표시 정보와 공통 타이밍은 **곡 저장**으로 함께 저장하며, 차트 저장과 버튼·범위를 분리한다. 저장 범위는 [곡 타이밍 공유](#곡-타이밍-공유-미구현)를 따른다(후속 UI·저장 구조 구현).
- 서버에 저장된 차트를 **로드**(불러오기)하여 편집을 이어갈 수 있다.

#### 초기 타이밍 설정의 로드 자동 분리 `[미구현]`

차트를 불러올 때 겹친 0박 초기 BPM·박자 설정은 값·박 위치를 유지하고 충돌 없는 보조 레인으로 자동 분리한다. 일반 이벤트는 자동 재배치하지 않으며, 같은 종류의 초기 설정 중복 등 기존 의미 위반은 별도로 유지한다. 초기 설정끼리 또는 다른 이벤트와 겹치면 초기 설정 쪽의 `editorLane`만 옮기며, 빈 표시 레인이 없으면 필요한 만큼 확장한다. 처리 우선순위·빈 레인 탐색 순서는 같은 입력에 같은 결과를 내도록 구현에서 정하고, 이미 분리된 배치를 다시 바꾸지 않는다.

자동 분리 결과와 필요한 보조 레인 수는 불러온 기본 상태로 취급한다. 이 정리는 Undo·Redo 이력에 넣지 않고 별도 미저장 변경 표시도 하지 않는다. 이후 사용자가 저장하면 정리된 레인 배치를 저장하며, 저장 전에는 서버·원본 파일에 자동으로 쓰지 않는다. 정리 이후의 사용자 편집은 일반 미저장 변경·Undo·Redo 규칙을 따른다([RFD 0082](../rfd/0082-initial-timing-events-not-selectable.md)).

#### dirty 상태

- 에디터 store의 `savedChartJson`은 마지막으로 불러오거나 저장한 차트를 Save가 쓰는 방식(메인 `{difficulty}.json`·보조 `{difficulty}.extra.json`)으로 직렬화한 값이다. 불러올 때는 불러온(메인·보조를 합친) 차트를 그때의 보조 레인 수로 직렬화하고, Save Chart·Save As가 성공하면 업로드한 메인·보조 JSON으로 바꾼다.
- `savedChartJson`은 서버에서 받은 파일 텍스트 자체가 아니다. 예를 들어 `.extra.json`도 `extraLaneCount`도 없는 차트는 보조 레인 수 기본값 2로 직렬화하므로 불러온 직후 dirty가 아니지만, Save하면 보조 레인 수 2인 `.extra.json`을 새로 만든다.
- 초기 BPM·박자 설정의 로드 자동 분리가 적용되면 정리 후 문서와 필요한 보조 레인 수를 로드 기준 `savedChartJson`으로 삼는다. 이 정리 자체는 dirty를 만들지 않고 Undo·Redo에서 제외되며, 저장 전 서버·원본 파일도 바꾸지 않는다(후속 구현).
- 현재 차트와 보조 레인 수를 같은 방식(메인/보조 분리)으로 직렬화해 `savedChartJson`과 다르면 dirty다.
- `savedChartJson`은 차트를 새로 불러올 때와 Save Chart·Save As가 성공했을 때만 바뀐다. 편집·Undo·테스트 플레이·실패한 저장은 바꾸지 않는다.
- dirty이면 Save Chart 버튼에 변경 표시가 붙고, Back to Songs는 "Unsaved Changes" 확인을 띄운다. Leave를 누르면 `/game`으로 나가고, Cancel을 누르면 에디터에 남는다.
- 테스트 플레이에서 에디터로 돌아와도 `savedChartJson`은 그대로다. 저장하지 않고 테스트 플레이한 편집은 돌아온 뒤에도 dirty로 남아 나갈 때 확인을 거친다.

#### 저장 중

- Save Chart·Save As가 진행 중이면 Save Chart 버튼은 "Saving chart"로 비활성이고 Save As·Delete Chart도 비활성이다. 테스트 플레이의 처음부터·커서부터 시작도 비활성이며 버튼 title에 "저장 중에는 테스트 플레이를 시작할 수 없습니다"를 보인다.
- 저장 진행 여부(store의 `isSavingChart`)는 페이지가 아니라 에디터 store가 들고 있어 페이지가 다시 마운트돼도 남는다. 진행 중에는 두 번째 저장과 테스트 플레이를 시작하지 않으며, 버튼 밖의 경로로 들어오면 안내 토스트만 띄운다.
- 저장이 실패하면 `savedChartJson`을 바꾸지 않아 편집은 dirty로 남고, 다시 저장할 수 있다.
- 저장이 끝나기 전에 차트를 새로 불러오면, 늦게 끝난 그 저장은 새 차트의 `savedChartJson`과 저장 진행 여부를 바꾸지 않는다.

### 같은 곡의 다른 차트로 전환 `[미구현]`

같은 곡의 다른 차트로 전환할 때도 미저장 곡 정보가 있으면 먼저 곡 저장을 완료하거나 해당 변경을 취소해야 한다. 곡 저장은 성공한 뒤에만 전환하며, 실패하면 현재 차트와 편집 내용을 유지한다. 변경 취소는 곡 정보의 미저장 변경을 마지막 저장 상태로 되돌리는 동작이다. 곡 정보 변경 취소가 현재 차트의 미저장 변경까지 함께 버리는 동작은 아니다. 상세 저장 범위는 [곡 타이밍 공유](#곡-타이밍-공유-미구현), 결정 근거는 [RFD 0098](../rfd/0098-song-info-drawer-and-save-scope.md)을 따른다.

### 곡 이동·에디터 이탈 시 미저장 변경 `[미구현]`

다른 곡으로 이동하거나 에디터를 나가려 할 때 곡 정보 또는 차트에 미저장 변경이 있으면 **저장 후 이동 / 버리고 이동 / 취소**를 선택하게 한다. 저장 후 이동은 변경이 있는 곡 정보·차트를 각 저장 범위에 따라 저장하고 필요한 저장이 모두 성공한 뒤 이동한다. 공통 타이밍 저장이 필요한 경우 곡 저장을 먼저 완료하는 기존 순서를 따른다. 저장 실패 시 이동하지 않고 미저장 변경을 유지한다. 버리고 이동은 미저장 변경을 버리고 이동하며, 취소는 편집 화면과 변경 내용을 유지한다.

곡 저장·차트 저장의 범위는 [곡 타이밍 공유](#곡-타이밍-공유-미구현), 결정 근거는 [RFD 0098](../rfd/0098-song-info-drawer-and-save-scope.md)을 따른다.

### 다른 이름으로 저장 (Save As)

기존 차트를 복제하여 **다른 난이도의 새 차트**를 생성하는 기능이다. 한 곡에 여러 난이도(`LIFTOFF`/`INFILTRATION`/`BREAKTHROUGH`)의 차트를 제작할 때, 기존 차트를 기반으로 수정하여 다른 난이도의 차트를 만드는 워크플로우를 지원한다.

#### 동작

1. 툴바의 **Save As** 버튼을 클릭하면 **Save As 모달**이 열린다.
2. 모달에서 **대상 난이도명**과 **대상 난이도 레벨**을 입력한다.
   - 난이도명 드롭다운: `LIFTOFF`, `INFILTRATION`, `BREAKTHROUGH` 중 선택.
   - 난이도 레벨: 1～15 숫자 입력.
   - 현재 편집 중인 난이도와 동일한 난이도명은 선택할 수 없다(비활성화). 기존 `EASY`/`NORMAL`/`HARD`도 각각 같은 공식 난이도로 취급한다.
3. **Save** 버튼을 누르면:
   - 현재 차트 데이터를 대상 난이도의 경로(`songs/{songId}/{difficulty}.json`)에 새로 저장한다.
   - 보조 레인 노트 데이터도 함께 복제 저장한다.
   - `charts` 테이블에 새 행을 삽입한다(기존 행이 있으면 upsert).
   - 차트의 메타데이터(`difficultyLabel`, `difficultyLevel`)를 대상 값으로 변경하여 저장한다.
   - 자켓 이미지, 프리뷰 음원, 음원 파일은 곡(`songs/{songId}/`) 단위로 공유하므로 복제하지 않는다.
4. 저장 성공 후 **에디터가 새 난이도 차트로 전환**된다. URL 파라미터(`?songId=...&difficulty=...`)가 새 난이도로 갱신되며, 이후 Save Chart 버튼은 새 난이도에 저장한다.

#### 기존 차트 덮어쓰기 경고

대상 난이도에 이미 차트가 존재하는 경우, "이미 {난이도명} 차트가 존재합니다. 덮어쓰시겠습니까?" 확인 다이얼로그를 표시한다. 사용자가 확인하면 기존 차트를 덮어쓰고, 취소하면 모달로 돌아간다.

기존 별칭도 같은 난이도로 조회한다. 예를 들어 `LIFTOFF` 저장 대상에 `easy` 차트가 있으면 확인 후 기존 `easy` 저장 경로를 사용한다. 정확히 일치하는 새 식별자도 있으면 그 식별자를 우선한다. 조회 실패 시 저장하지 않는다. [RFD 0026](../rfd/0026-game-flight-backgrounds.md)을 따른다.

#### 검증

- Save As 실행 전에도 기존 Save Chart과 동일한 **배치 제약 조건 검증**을 수행한다. 검증 실패 시 저장하지 않고 ValidationErrorModal을 표시한다.
- 곡 공통 타이밍에 미저장 변경이 있으면 Save Chart와 Save As 모두 저장을 차단하고 곡 저장을 먼저 안내한다([곡 타이밍 공유](#곡-타이밍-공유-미구현), 후속 구현).
- HARD 전용 패턴(`.-`, `-=`)이 포함된 차트를 EASY 또는 NORMAL로 저장하려 하면 경고를 표시한다. 저장은 허용하되, 사용자가 해당 패턴을 인지하고 수정할 수 있도록 안내한다.

#### 더티 상태

- Save As 성공 후, `savedChartJson`이 새 난이도로 업로드한 메인·보조 JSON으로 갱신되어 더티 상태가 초기화된다.
- 원본 난이도의 차트는 영향을 받지 않는다(Save As 전에 저장하지 않은 변경 사항은 원본에 반영되지 않음).

### 차트 공개/비공개

- 차트는 **공개** 또는 **비공개** 상태를 가진다.
- **공개 차트**: 곡 선택 화면에 표시되며, 모든 유저가 플레이할 수 있다.
- **비공개 차트**: 곡 선택 화면에 표시되지 않으며, 에디터에서만 접근할 수 있다. 제작 중인 차트를 서버에 저장하되 유저에게 노출하지 않기 위한 장치이다.
- 에디터에서 차트를 업로드할 때 공개/비공개를 선택할 수 있다.

| 음원파일   | 곡의 오디오 파일                                    |
| 프리뷰 음원파일 | 곡 선택 화면에서 재생되는 프리뷰 전용 오디오 파일. 본편 음원과 별개의 파일이다 |
| 오프셋     | 현재 파일의 `offsetMs`. 음원 시작에서 0박까지의 시간 차이(ms)이며, 곡 타이밍 공유 규칙에서는 같은 곡의 모든 차트가 공통으로 사용(곡 단위 공유 미구현) |

## 엔티티

차트를 구성하는 배치 가능한 요소. 모든 엔티티는 **위치**를 가진다.

이 절의 노트·시작점/끝점 상호 참조 설명은 **구형 런타임과 과도기 수리 의미**다. 신형 바디·명시 탭/릴리즈/틱 노트는 [새 에디터 채택 계약](#새-에디터-채택-계약)과 glossary를 따르며, 구형 엔티티 구조를 새 저장 형식으로 고정하지 않는다.

### 위치

| 속성   | 설명                                                                 |
| ------ | -------------------------------------------------------------------- |
| 레인   | L1～L4. 노트에는 필수, `TimeSignatureChangeEvent`와 `BpmChangeEvent`에는 없음 (레인에 속하지 않는 전역 엔티티) |
| 박자수 | 곡 시작(0박)으로부터의 경과 박자. **분수**로 표기한다                 |

**박자수의 분수 표기**: 정수 박자는 `0`, `1`, `4`처럼 표기하고, 박자 내 세분 위치는 분수로 표기한다. 예를 들어 8비트의 두 번째 스냅은 `1/2`, 16비트의 세 번째 스냅은 `3/4`. 이를 통해 비트 분할에 독립적인 위치 표현이 가능하다.

---

### 노트

레인 위에 배치되는 입력 대상. 위치의 레인이 필수이다.

| 노트 종류              | 설명                                                                |
| ---------------------- | ------------------------------------------------------------------- |
| 싱글 노트              | 레인에 바인딩된 키 중 하나를 누르는 노트. 롱노트 시작 위치에 배치하면 헤드 역할을 한다 |
| 더블 노트              | 레인에 바인딩된 서로 다른 키 2개를 동시에 누르는 노트. 롱노트 시작 위치에 배치하면 헤드 역할을 한다 |
| 트릴 노트              | 직전 입력과 다른 키를 눌러야 하는 노트. 롱노트 시작 위치에 배치하면 헤드 역할을 한다 |
| 싱글 롱노트 시작  | 싱글 롱노트의 시작점. 대응하는 끝점을 참조한다. 헤드 노트 없이 롱노트만 존재하는 것이 기본 |
| 싱글 롱노트 끝    | 싱글 롱노트의 끝점. 대응하는 시작점을 참조한다         |
| 더블 롱노트 시작  | 더블 롱노트의 시작점. 대응하는 끝점을 참조한다. 헤드 노트 없이 롱노트만 존재하는 것이 기본 |
| 더블 롱노트 끝    | 더블 롱노트의 끝점. 대응하는 시작점을 참조한다         |
| 트릴 롱노트 시작  | 트릴 롱노트의 시작점. 대응하는 끝점을 참조한다. 헤드 노트 없이 롱노트만 존재하는 것이 기본 |
| 트릴 롱노트 끝    | 트릴 롱노트의 끝점. 대응하는 시작점을 참조한다         |

**시작점과 끝점의 상호 참조**: 롱노트의 시작점과 끝점은 반드시 쌍으로 존재하며, 서로를 참조한다. 시작점 없는 끝점, 또는 끝점 없는 시작점은 유효하지 않다.

**헤드 구현**: 롱노트에는 헤드가 내장되어 있지 않다. 롱노트 시작점과 같은 레인·같은 박자수에 일반 노트(싱글/더블/트릴)를 배치하면 해당 노트가 헤드 역할을 한다. 헤드 노트와 롱노트는 별개의 엔티티이며, 판정도 독립적이다.

---

### `trillZone`

트릴 노트가 등장할 수 있는 시각적 영역. 레인 위에 시작점과 끝점을 가진 구간으로 표시된다. `trillZone` 자체는 입력을 요구하지 않는다. 트릴 롱노트 바디와는 별개의 엔티티이다.

| 종류           | 설명                                                        |
| -------------- | ----------------------------------------------------------- |
| `trillZone` 시작 | `trillZone`의 시작점. 대응하는 구간 끝을 참조한다             |
| `trillZone` 끝   | `trillZone`의 끝점. 대응하는 구간 시작을 참조한다             |

**시작과 끝의 상호 참조**: 롱노트와 동일하게, `trillZone` 시작과 끝은 반드시 쌍으로 존재하며 서로를 참조한다.

---

### `TimeSignatureChangeEvent`

한 마디에 몇 박자가 들어가는지(**beatPerMeasure**)를 정의하는 전역 엔티티. 레인에 속하지 않는다. BPM이 한 박자의 시간 간격을 정의하므로, `TimeSignatureChangeEvent`는 한 마디에 필요한 **박자 수만** 정의한다. beatPerMeasure는 정수 또는 분수로 표기하며, 분수는 `7/2`(=3.5박) 등 특수한 박자를 표현하기 위한 장치이다. 이 값을 통해 타임라인의 **마디선 위치가 결정**된다.

- **마디 0에 반드시 존재**한다. 곡의 시작 시점에서 박자가 정의되어야 한다.
- **저장 위치는 `beat`이며, 항상 해당 마디의 첫 박에 위치**한다. 시간 계산용 `TimeSignatureChange`로 추출할 때 마디 번호(`measure`)로 변환한다.
- 다시 등장하면 **해당 시점 이후로 beatPerMeasure가 변경**된다. 다음 `TimeSignatureChangeEvent`가 나올 때까지 유효하다.

예: 마디 0에 beatPerMeasure=`4`, 마디 8에 beatPerMeasure=`3` → 마디 0～7은 4박자 마디, 마디 8 이후는 3박자 마디.

---

### `BpmChangeEvent`

템포를 정의하는 전역 엔티티. 레인에 속하지 않는다.

- **0박에 반드시 존재**한다. 곡의 시작 시점에서 BPM이 정의되어야 한다.
- 다시 등장하면 **해당 시점 이후로 BPM이 변경**된다. 다음 `BpmChangeEvent`가 나올 때까지 유효하다.

예: 0박에 `BPM 150`, 64박에 `BPM 180` → 0～63박은 150 BPM, 64박 이후는 180 BPM.

---

### 메시지

특정 구간에 안내 텍스트를 표시하는 구간 엔티티. 레인에 속하지 않는 전역 엔티티이며, 메시지 레인에 배치한다. 튜토리얼 차트에서 노트 메커니즘이나 판정 규칙을 설명하는 데 사용한다.

| 종류       | 설명                                                    |
| ---------- | ------------------------------------------------------- |
| 메시지 시작 | 메시지 구간의 시작점. 대응하는 메시지 끝을 참조한다     |
| 메시지 끝   | 메시지 구간의 끝점. 대응하는 메시지 시작을 참조한다     |

| 속성   | 설명                                                                 |
| ------ | -------------------------------------------------------------------- |
| 텍스트 | 표시할 안내 문자열                                                   |
| 박자수 | 시작·끝 각각의 위치. 다른 구간 엔티티와 동일하게 분수 박자로 표기한다 |

- **시작과 끝의 상호 참조**: `trillZone`·롱노트와 동일하게, 메시지 시작과 끝은 반드시 쌍으로 존재하며 서로를 참조한다.
- **겹침 금지**: 메시지 구간의 시작점과 끝점을 제외한 열린 구간 안에 다른 메시지의 시작점·끝점이 존재할 수 없다. 단, 메시지 구간의 끝점과 다른 메시지 구간의 시작점은 같은 박자수에 위치할 수 있다 (롱노트의 `o-o-` 패턴과 동일).
- **텍스트 편집**: 메시지 시작 또는 끝을 **더블클릭**하면 텍스트 편집 모달이 열린다. 이벤트 생성과 동일한 방식이다.
- **노트 배치와 독립**: 메시지는 노트 레인에 영향을 주지 않는다. 메시지 구간 안에 어떤 노트든 자유롭게 배치할 수 있다.

### 정지 (Stop) 이벤트

특정 시점에서 노트 스크롤을 일시 정지시키는 이벤트. 시작 박자수와 종료 박자수를 가지는 구간 엔티티이다.

- **stop 구간 동안 노트 스크롤이 멈추며**, 종료 시점에서 다시 재개된다.
- stop 구간 내에는 노트를 배치할 수 없다 (배치 제약 조건 6번).
- 다른 구간 엔티티와 동일하게 시작과 끝이 쌍으로 존재하며 서로를 참조한다.

### ChartEvent 모델

코드상 `BpmChangeEvent`, `TimeSignatureChangeEvent`, 메시지, auto, stop, tutorial input, tutorial diagram 이벤트는 **ChartEvent**라는 디스크리미네이티드 유니온 타입으로 구현되어 있다. 각 이벤트는 `type` 필드로 구분된다.

| type | 종류 | 고유 속성 | 설명 |
|------|------|-----------|------|
| `bpm` | 시점 | `bpm: number` | BPM 변경 |
| `timeSignature` | 시점 | `beatPerMeasure: Beat` | 박자표 변경 |
| `text` | 구간 | `text: string`, `endBeat: Beat` | 메시지 표시 (게임에서 화면 오른쪽에 표시) |
| `auto` | 구간 | `endBeat: Beat` | 자동 연주 구간 (사용자 입력 차단, 노트 자동 Perfect 판정) |
| `stop` | 구간 | `endBeat: Beat` | 정지 구간 (구간 내 노트 배치 금지) |
| `tutorialInput` | 구간 | `endBeat: Beat`, `lane: Lane`, `keyCode: string`, `keyLabel?: string` | 튜토리얼 미리보기/튜토리얼 차트에서 키를 누르고 떼는 시연 입력 |
| `tutorialDiagram` | 구간 | `endBeat: Beat`, `diagramId: TutorialDiagramId` | 튜토리얼 미리보기에서 에디터 노트 렌더러 방식 도식을 표시 |

모든 이벤트는 `beat` (시작 박자수)를 가지며, 구간 이벤트는 추가로 `endBeat` (종료 박자수)를 가진다. 에디터에서는 `editorLane?: number` 필드로 엑스트라 레인 배치 위치를 저장한다 (게임에서 무시).

**에디터에서의 생성**: Create 모드에서 엔티티 타입 드롭다운의 Events 그룹에서 이벤트 종류를 선택한 뒤, 엑스트라 레인을 클릭(시점 이벤트) 또는 드래그(구간 이벤트)하여 생성한다.

**튜토리얼 입력 이벤트 편집**: `tutorialInput` 이벤트는 다른 구간 이벤트처럼 Select 모드에서 끝점을 리사이즈할 수 있고, 속성 모달에서 `lane`, `keyCode`, `keyLabel`을 편집한다. 입력 의미 검증은 같은 `lane + keyCode` 구간의 겹침을 막는다. 다른 키나 다른 입력 레인의 동시 `tutorialInput`은 더블 입력, 롱 유지 중 탭 시연을 위해 허용하되, 에디터 배치는 서로 다른 `editorLane`으로 나누어 같은 보조 레인의 겹침을 피해야 한다([RFD 0078](../rfd/0078-event-placement-overlap.md)).

**튜토리얼 도식 이벤트 편집**: `tutorialDiagram` 이벤트는 다른 구간 이벤트처럼 Select 모드에서 끝점을 리사이즈할 수 있고, 속성 모달에서 `diagramId`를 편집한다. 현재 `connected-switch`, `connected-overlap` 도식을 제공하며, 튜토리얼 미리보기는 해당 구간 동안 축소 재생기 위에 에디터 `NoteRenderer`와 같은 사각 노트/롱노트 gradient 표기법의 패턴을 표시한다.

### 보조 레인의 trillZone

보조 레인도 메인과 동일하게 `trillZone`을 생성·선택·이동·리사이즈·복사·Cut·Delete하고 Esc·Undo/Redo로 복원한다([RFD 0086](../rfd/0086-auxiliary-lane-trill-zones.md)). 노트와 구간은 현재 보이는 레인 범위에서 함께 이동하며, 붙여넣기는 필요한 보조 레인을 확장한다. 보조 레인 수를 줄이면 범위 밖 구간은 숨기되 보존한다. 구간 안에서 탭 도구로 드래그하면 시작 트릴 탭·바디만 만들고 릴리즈는 만들지 않는다. 바디 도구는 기존처럼 바디만 만든다.

트릴 노트·바디는 같은 레인의 한 구간 안에 전체가 포함되어야 하며, 시작 트릴 탭 필수·길이 0 트릴 바디 제한·틱 노트 금지·일반 노트/릴리즈 배타·구간끼리 겹침 금지도 동일하다. 기존 보조 트릴이 구간 밖에 있어도 열어 수리할 수 있지만 저장·플레이는 위반을 해소해야 한다. 자동으로 구간을 만들지 않는다. 구형 변환도 구간·시작 탭 누락을 자동 수리하지 않고 변환 전 위반을 보고한다. 보조 노트·구간은 게임 판정과 렌더링에서 제외한다.
