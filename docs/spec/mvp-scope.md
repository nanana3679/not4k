# not4k — MVP 스코프

> 핵심 질문: **"가변 손배치 4레인 리듬게임이 재미있는가?"**

이 문서는 위 질문에 답하기 위한 최소 기능 범위(Phase A)와, 공개 빌드를 위한 기능 범위(Phase B)를 정의한다. `project-assets.md`의 에셋 단계와 대응하되, **기능적 스코프**에 집중한다.

---

## Phase A: 프로토타입 (핵심 메커니즘 검증)

### 목표

내부 테스터에게 코어 게임플레이를 체험시키고, 다음을 검증한다:

- 트릴/더블 노트가 재미있는가?
- AudioContext 타이밍이 정확한가?
- 가변 손배치가 기존 4키와 체감 차이가 있는가?

### 포함 기능

#### 게임 (`src/game`)

| 카테고리 | 기능 | 근거 |
|---------|------|------|
| **화면** | 타이틀(최소), 프리셋 설정, 튜토리얼, 곡 선택(기본 리스트), 플레이, 결과 | 게임 루프의 최소 단위 |
| **게임플레이** | 4레인 노트 낙하, 싱글/롱/트릴/더블 전 노트 타입, 판정(Perfect～Miss+`goodTrill`) | 모든 노트 타입이 Lv.1부터 등장하므로 전부 필요 (`overview.md`) |
| **오디오** | AudioContext 마스터 클럭, AudioBuffer 전체 로드 | 판정 정확도 검증이 핵심 |
| **키 바인딩** | 프리셋 선택(넘패/TKL) + 레인별 커스텀 바인딩 | 키 바인딩 없으면 플레이 불가 |
| **스크롤 속도** | BPM 독립 절대 속도 조절 | 리듬게임 기본 기능 |
| **리프트/서든** | 서든(상단 커버) + 리프트(판정선 상승) 조합 가능 | 상급 유저 기본 기능 |
| **프레임레이트** | 60/120/144fps/무제한 선택 | 유저 하드웨어 대응 |
| **결과** | 달성률, 랭크(SSS～F), 판정 분포(`goodTrill` 별도 행) | 피드백 루프 필수 |
| **인증** | 비로그인(게스트) 플레이만. 로컬 설정과 튜토리얼 항목 전체 통과 여부, 마지막 선택 탭·항목은 브라우저에 저장. 현재 방법·중간 방법 완료·부분 성공은 저장하지 않으며 재진입은 첫 방법 0회부터 시작 | 진입 장벽 최소화, 인증은 Phase B |
| **콘텐츠** | CC0/CC BY 곡 3～5곡 + 메트로놈에 맞춘 튜토리얼 예제 차트 | 메커니즘 검증에 충분한 최소 곡수 |
| **인프라** | Supabase Storage에서 차트 JSON + 음원 fetch | 온라인 전용 구조 검증 |
| **언어** | 한국어 단일 | i18n 구조만 세팅, 번역은 Phase B |
| **튜토리얼** | Phase 1(연주 방법) + Phase 2(복합 패턴/판정)의 도움말 모달. 입력 학습은 시연 후 직접 연주 항목별 요구 횟수만큼 누적 성공으로 통과한다. 첫 기동 프리셋 설정 뒤 곡 선택 화면 위에 열며 처음부터 바로 닫을 수 있다. 완료·통과를 차트 선택의 선행 조건으로 두지 않는다. "How to Play" 텍스트 안내 포함 | 외부 테스터도 자력으로 게임을 이해할 수 있어야 한다 |
| **일시정지** | 일시정지 기본 구현 (노트 가림 제외) | 게임 루프 필수 기능 |
| **오프셋** | 설정 화면에서 수동 수치 입력 | 전용 캘리브레이션 화면 없이 최소 구현 |

#### 차트 에디터 (`src/editor`)

차트 없이는 게임을 테스트할 수 없으므로, 에디터도 최소 기능이 필요하다.

| 카테고리 | 기능 | 근거 |
|---------|------|------|
| **노트 배치** | Create 모드 — 싱글/롱/트릴/더블 전 타입 | 전 노트 타입이 필요 |
| **노트 편집** | Select 모드(기본 선택 + 이동), Delete 모드(클릭 삭제) | 최소 편집 기능 |
| **이벤트** | `BpmChangeEvent`, `TimeSignatureChangeEvent` 배치 + 값 편집 | 차트 타이밍 정의 필수 |
| **파형** | 음원 파형 기본 표시 | BPM 정렬에 필수 |
| **재생** | 재생/정지 | 배치 확인 |
| **스냅** | 고정 스냅 (1/4, 1/8, 1/16) | 정확한 노트 배치 |
| **줌** | 기본 줌 조절 | 밀집 구간 편집 |
| **배치 제약** | 3가지 제약 조건 실시간 검증 | 유효하지 않은 차트 방지 |
| **배포** | 로컬 실행만 (`pnpm dev` → `/editor` 경로) | 개발자 전용 |

#### 공유 도메인 (`src/shared`)

| 모듈 | 내용 |
|------|------|
| `types/` | ChartData, NoteEntity, ChartEvent, Beat |
| `chart/` | 분수 박자 연산, 차트 유틸리티 |
| `timing/` | beat→time 변환, `BpmChangeEvent` 처리 |
| `validation/` | 배치 제약 조건 검증 |
| `constants/` | 노트 타입 enum, 판정 윈도우 |
| `storage/` | Supabase Storage 접근 유틸리티 |

### 제외 기능 (Phase B로 이동)

| 기능 | 제외 이유 |
|------|----------|
| Google 로그인 | 메커니즘 검증에 인증 불필요. 게스트로 충분 |
| 랭킹 | 내부 테스트 단계에서 경쟁 시스템 불필요 |
| 옵저버 모드 | 고난이도 손배치 계획 도구 — Lv.1～6 테스트 차트에서 불필요 |
| 오프셋 캘리브레이션 전용 화면 | 수동 수치 입력으로 대체 |
| 미러 옵션 | 왼손잡이 지원 — 테스트 단계에서 후순위 |
| 곡 프리뷰 재생 | 3～5곡이면 프리뷰 없이 곡 파악 가능 |
| 일시정지 (노트 가림) | 일시정지 기본 구현은 Phase A에 포함. 노트 가림은 Phase B |
| 스페셜 땡스 | 공개 빌드에서 필요 |
| 일본어/영어 | i18n 구조만 세팅 |
| 에디터 — 멀티 선택/드래그 범위 | 기본 선택으로 충분 |
| 에디터 — 우클릭 삭제/드래그 연속 삭제 | 편의 기능 |
| 에디터 — 오토스크롤 | 수동 스크롤로 대체 |
| 에디터 — Supabase 업로드 | Phase B에서 구현 |
| 에디터 — 모바일 터치 | 개발자 전용 도구, PC로 충분 |

### Phase A 화면 흐름

```
타이틀 → [첫 기동] → 프리셋 설정 → 곡 선택(튜토리얼 모달 자동 열기·바로 닫기 가능)
타이틀 → [이후 기동] → 곡 선택
곡 선택 → 플레이 → 결과 → 곡 선택
곡 선택 → 튜토리얼 도움말 모달 열기 → 닫기
튜토리얼 입력 학습 → 시연 → 직접 연주 → 항목별 요구 횟수만큼 누적 성공 시 통과
곡 선택 → 설정(키 바인딩 + 스크롤 속도 + 리프트/서든 + 프레임레이트 + 오프셋 수치) → 곡 선택
```

첫 기동 튜토리얼은 별도 단계 진행이나 스킵을 요구하지 않는다([RFD 0055](../rfd/0055-first-launch-tutorial-modal.md)). 실습 통과는 차트 선택의 선행 조건으로 사용하지 않는다([RFD 0081](../rfd/0081-tutorial-demonstration-and-three-practice-successes.md)). 현재 도움말 모달은 구현되어 있고 첫 기동 자동 열기·직접 입력 실습·항목별 요구 횟수만큼 누적 성공 통과는 미구현이다.

## Phase B: 알파 (비영리 공개 빌드)

### 목표

외부 유저가 처음 접근해도 게임을 이해하고 플레이할 수 있는 상태. 기록 저장과 경쟁 시스템 도입.

### 추가 기능

#### 게임

| 카테고리 | 기능 |
|---------|------|
| **인증** | Google 로그인 + Anonymous Auth → linkIdentity 업그레이드 |
| **랭킹** | 차트별 달성률 순위 |
| **플레이 기록** | 곡별 최고 기록 저장, 결과 히스토리 |
| **옵저버 모드** | 자유 스크롤 + 재생/일시정지 + 스크롤 바 마커 기반 구간 반복 + 속도 조절 |
| **오프셋** | 전용 캘리브레이션 화면 |
| **미러** | 좌우 반전 옵션 |
| **일시정지** | 노트 가림 포함 완전 구현 |
| **곡 프리뷰** | 곡 선택 시 자동 재생 |
| **i18n** | 일본어 + 영어 추가 |
| **스페셜 땡스** | 크레딧 + 라이선스 표기 |
| **설정 동기화** | 로그인 유저의 설정/오프셋 서버 저장 |
| **튜토리얼 동기화** | 로그인하면 항목 전체 통과 여부만 계정과 동기화. 마지막 선택 탭·항목은 해당 브라우저에만 저장하고 계정과 동기화하지 않음. 게스트 튜토리얼의 항목 전체 통과 기록은 로그인 시 계정당 1회 인계할 수 있다. 이미 인계한 게스트 기록은 다른 계정으로 재인계하지 않는다. 계정에 귀속된 통과 기록은 같은 계정의 여러 기기에서 계속 공유하며, 로컬에 표시된 계정 기록을 게스트 기록으로 재분류하거나 다른 계정으로 인계하지 않는다.  현재 방법·중간 방법 완료·부분 성공은 동기화하지 않으며 재진입은 첫 방법 0회부터 시작 |
| **콘텐츠** | 5～10곡 |

#### 차트 에디터

| 카테고리 | 기능 |
|---------|------|
| **선택** | 멀티 선택, Shift/Alt 조합, 드래그 범위 선택 |
| **삭제** | 우클릭 삭제, 드래그 연속 삭제 |
| **재생** | 오토스크롤, 구간 재생 |
| **스냅** | 자유 스냅 값 |
| **저장** | Supabase Storage 직접 업로드/로드 |

## 리스크와 판단 근거

### Phase A에 전 노트 타입을 포함하는 이유

`overview.md`에 "모든 노트 타입은 Lv.1부터 등장"으로 명시. 싱글만 있는 프로토타입은 not4k의 정체성(트릴/더블)을 검증할 수 없다.

### Phase A에 튜토리얼을 포함하는 이유

외부 테스터도 개발자 브리핑 없이 게임을 이해할 수 있어야 한다. "How to Play" 텍스트 안내와 Phase 1～2 인게임 튜토리얼을 Phase A에 포함하여 자력 학습을 보장한다.

### Phase A에 인증을 제외하는 이유

Supabase Auth 연동은 OAuth 콜백, 세션 관리, RLS 정책 등 부수 작업이 많다. 게스트 플레이만으로 메커니즘 검증이 가능하다.

### Phase B에 옵저버 모드를 포함하는 이유

공개 빌드에서 Lv.7+ 차트를 제공하려면 손배치 계획 도구가 필요하다. `observer-mode.md`의 설계 의도와 일치한다.

```
not4k/
├── src/
│   ├── game/              → 코어 게임플레이

```
