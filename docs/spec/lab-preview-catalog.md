# Lab 미리보기 카탈로그

## 목적

개발용 시연을 날짜나 파일 위치로 기억하지 않고 `/lab`에서 이름과 역할로 다시 찾는다. 카탈로그와 각 시연은 로컬 개발 서버와 Lab 전용 GitHub Pages 정적 사이트에서 제공하며, 메인 게임의 프로덕션 번들에는 포함하지 않는다.

## 등록 규칙

`src/lab/labPreviewCatalog.ts`가 미리보기 목록의 단일 인터페이스다. 새 시연은 중복 없는 `id`, 표시 이름, 한 줄 설명, 분류, `/lab/` 경로를 등록한다. 대표 시연 하나에는 `featured`를 설정할 수 있다.

독립 이미지 HTML 페이지는 `src/lab/labImageGalleryCatalog.ts`에 컬렉션 단위로 등록한다. Lab 홈은 이를 별도 `IMAGE GALLERIES` 그룹에 표시하며, 새 탭의 `/lab/images/<id>/` 정적 페이지로 연다. HTML과 상대 이미지 번들은 `lab/image-galleries/<id>/`에 두고 진입 파일을 `index.html`로 통일한다. 개별 이미지가 아니라 새 HTML 페이지를 만들 때만 항목 하나를 추가한다.

이미지 HTML은 데스크톱의 비교 배열을 유지하되 900px 이하에서는 한 열로 배치한다. 첫 이미지는 즉시 표시하고 나머지 원본 PNG는 viewport에 들어올 때 로드해 모바일 초기 전송과 디코딩을 제한한다.

다른 에이전트가 새 에셋·렌더링·인터랙션 미리보기를 만들어 사용자에게 보여줄 때도 `/lab/<고유-id>`를 기준 경로로 사용한다. 등록 순서와 공개 공유 예외는 [Lab preview workflow](../agents/lab-previews.md)를 따른다.

카탈로그는 다음 분류를 사용한다.

- `Flight`: 난이도명과 비행 연출 비교
- `Rendering`: 배경·투영·오브젝트 렌더 실험
- `Interface`: 기어와 조절 UI 실험
- `Gameplay`: 판정과 튜토리얼 동작 실험

React 기반 시연은 `LabRoutes.tsx`에 라우트를 연결한다. 독립 서버가 필요한 대용량 시연은 구현과 자산을 원래 모듈에 유지하고, 로컬에서는 Vite 개발 서버 adapter를, 공개 사이트에서는 정적 export를 사용해 Lab 화면에 삽입한다. 이 seam 덕분에 Lab 카탈로그는 시연별 파일 제공 방식이나 서버 내부 경로를 알 필요가 없다.

## Flight Background Preview

`/lab/flight-background-preview`는 `/__lab/flight-background-preview/`에 마운트한 독립 공개 미리보기를 iframe으로 연다. Lab 복귀 링크만 바깥에 두며, iframe 안의 `LIFTOFF`, `INFILTRATION`, `BREAKTHROUGH` 탭과 고도 슬라이더는 공개 미리보기와 같은 소스를 사용한다.

정식 공개 진입점은 `https://nanana3679.github.io/not4k/lab/flight-background-preview/`다. Cloudflare Quick Tunnel은 브랜치가 `main`에 반영되기 전 임시 확인용으로만 사용한다.

## Facility Passage Preview

`/lab/facility-passage`는 시설 통과 시연을 고도 0%·정지 상태로 연다. 접근·입구·시설 내부·출구에서 멈추거나 고도를 바꾸고, 같은 화면에서 A~H 건축 비교로 전환할 수 있다. 기존 시연 모듈을 iframe으로 사용하고 Lab 복귀 링크를 제공한다. 고도·진행·모델 선택을 바깥 Lab URL에 동기화하므로 전체 페이지를 새로고침해도 복원한다. 조절 중에는 iframe을 다시 만들지 않는다. 공개 배경 비교의 간소화 스타일을 적용하지 않은 `study.html`을 같은 정적 파일 제공 경로로 내보내므로, 개발 서버와 Pages 모두 전체 조절 화면을 표시한다.

## 노트 에셋 시연실

`Rendering` 분류의 `/lab/note-assets`에서 Classic·Simple 노트, 롱노트, 터미널과 키봄을 실제 튜토리얼 재생기로 비교한다. 기본 시안은 Classic이며 시안 선택과 에셋 랙은 기존 시연실을 그대로 사용한다. 시연실의 `← Lab 목록` 링크는 공통 카탈로그로 돌아온다. 자세한 동작은 [노트 에셋 Lab](note-asset-lab.md)을 따른다.

## Classic Frame Fit

`Interface` 분류의 `/lab/classic-frame-fit`은 승인된 새 Classic 프레임 그림(1024×1536)을 실제 게임 렌더러 안에 얹어 게임 비율에 맞추는 방식과 선명도를 비교한다. 이 미리보기로 정한 배치는 [RFD 0029](../rfd/0029-frame-aspect-fit-narrow-lanes.md)에 기록했다. 게임과 같은 `GameRenderer`(논리 높이 600, 16:9 논리 폭 1067, 레인 영역 400, 판정선 y 440)와 인게임 비행 배경, 흐르는 데모 노트(120 BPM 약 3분)를 그대로 쓰고, 새 프레임은 기어 자리(`gearFrameLayer`)에 놓는다. 프레임을 한 장으로 그리는 방식에서는 승인된 움직임을 Pixi 레이어로 얹는다(아래 `움직임 레이어`). 데모 노트는 입력 없이 정해 둔 판정으로 표시한다. 포인트 노트는 5개마다 1개, 롱노트는 4마디마다 레인 4 롱노트를 놓친다. 맞힌 노트는 판정선에서 키봄·PERFECT와 함께 사라지고(롱노트는 끝에서, 그동안 키빔 유지), 놓친 노트는 머리 120ms 뒤 MISS와 함께 콤보를 끊고 놓친 모양으로 계속 내려간다. 차트가 끝나 처음으로 되감을 때 `setChart`가 노트 표시 상태를 비운다.

- 맞춤 방식: 새 프레임 네 방식은 모두 레인 창(기둥 안쪽 윤곽선 사이) 폭을 렌더러의 레인 영역 400에 맞춘 가로 배율을 쓴다. 레인 폭 맞춤·기둥 잘라 줄이기·세로로 눌러 맞추기는 덱 첫 행(레인 창이 전체 폭을 유지하는 마지막 행의 다음 행)을 판정선에 두고, 가로세로 같이 줄이기는 프레임 아래끝을 화면 아래에 붙여 고정한다.
  - `레인 폭 맞춤 (위 잘림)`(기본): 한 배율로 그려 위가 화면 밖으로 잘린다. 현재 게임 기어와 같은 규칙이다.
  - `기둥 잘라 줄이기`: 기둥 구간에서 가로 행 띠를 지워 프레임 위끝을 화면 위에 붙인다. 지울 행은 이음매 위아래 기둥 행 차이가 가장 작은 곳이며, 이음매는 섞지 않고 그대로 보여 준다.
  - `세로로 눌러 맞추기`: 기둥 구간만 세로로 눌러 화면 위부터 판정선까지 채우고 덱 구간은 가로 배율 그대로 둔다.
  - `가로세로 같이 줄이기`: 프레임을 비율 그대로 줄여 더 많이 보이게 하고, 게임 레인을 프레임 레인 창에 맞춰 좁힌다. `레인 폭` 슬라이더로 16:9 화면(논리 폭 1067)에서의 레인 폭 W를 고른다(기본 250, 지금의 62.5%). 프레임은 아래끝(실루엣 마지막 행의 아래 끝)을 화면 아래 600에 붙여 고정하며, 덱 위끝은 600 − (아래끝 행 − 덱 첫 행) × W ÷ 레인 창 폭이다(W 250이면 429.7). 최소 폭은 위끝이 화면 위에 닿는 폭(600 × 레인 창 폭 ÷ 아래끝 행 ≈ 225.9, 지금의 약 56%)이며, 이때 갑옷 꼭대기부터 하단 바까지 모두 보인다. 게임 코드를 바꾸지 않고 게임 화면 전체를 줌 아웃해 흉내 낸다. 줌 k = 400 ÷ W이고, 렌더러를 논리 크기 1067k×600k, 판정선 오프셋 160k, 해상도 렌더 높이 ÷ 600k, 스크롤 속도 800k로 만든다. 그래서 캔버스 백버퍼 크기와 노트가 화면을 지나는 시간은 그대로다. 화면 전체를 줄이므로 노트 두께, 콤보·정확도 글자, 키봄도 함께 작아진다. 실제 구현은 레인만 좁히고 노트 두께를 유지할 수 있다. 레인 폭 슬라이더를 끄는 동안에는 설명 숫자만 바뀌고, 놓으면(`change`) 0.25초 뒤 렌더러를 다시 만든다.
    - `판정선 높이` 슬라이더는 게임의 Lift 설정과 같은 정수 %(1% = 6 단위, 0~10%, 표시 예: `4% (+24)`)로 판정선만 올린다. 판정선 y = 440 − 6 × %이며 프레임은 움직이지 않는다. 기본 4%(y 416)이고, 슬라이더 최소값은 판정선 아래끝(판정선은 렌더러 단위 ±2 두께라 화면에서 ±2 ÷ k)이 프레임 덱에 가려지지 않는 가장 작은 %다(W 250이면 2%, 270이면 5%). 레인 폭을 바꿔 최소값이 올라가면 판정선 높이도 그 최소값으로 올려 쓴다. 레인 폭이 약 320을 넘으면 10%로도 판정선 아래끝이 덱에 가려지며 설명에 경고가 나온다. 판정선 높이는 렌더러를 다시 만들지 않고 `setLift`로 판정선·콤보/정확도 글자·판정 글자·노트 판정 위치를 옮기며, 렌더러를 다시 만들 때도 같은 높이를 다시 건다.
    - 게임의 판정선 아래 레인 마스크와 40×40 버튼은 끄고, 대신 오버레이가 프레임 아래(같은 색 `0x04060c`)에서 덱 위끝부터 화면 아래까지 레인 영역을 덮는다. 그래서 놓친 포인트 노트는 판정선을 지나 판정선과 덱 사이 틈(W 250·4%면 13.7, 화면 노트 두께의 약 1.1개)을 내려가다 프레임 아래로 사라진다. 실제 게임에 적용하면 레인 마스크가 판정선이 아니라 프레임 덱에서 시작한다는 뜻이다. 롱노트는 게임 렌더러가 머리를 판정선에 붙잡아 두므로 놓쳐도 틈으로 내려가지 않는다(후속 [#214](https://github.com/nanana3679/not4k/issues/214)). 설명에는 판정선 위치, 덱과의 틈, 고정된 프레임 위치(위로 잘리는 행, 아래끝까지 보임), 최소 판정선 높이가 나온다.
  - `현재 게임 기어`: 새 프레임 없이 지금 게임의 기어를 같은 화면에 그린다.
- 움직임 레이어: 승인된 애니메이션 SVG(`54-ambient-motion-v19.svg`, [프레임 움직임](../design/classic-frame-keywords-20260929.md#프레임-움직임))의 네 요소를 SVG 없이 Pixi 레이어로 다시 구성한다. 레인 폭 맞춤과 가로세로 같이 줄이기(프레임 한 장)에서만 프레임 스프라이트 바로 위에 같은 변환으로 얹고, 기둥 잘라 줄이기·세로로 눌러 맞추기(두 조각)와 현재 게임 기어에는 얹지 않는다. 게임 렌더러는 움직임 자료를 기다리지 않고 먼저 뜨며, 자료가 도착하면 렌더러를 다시 만들지 않고 그때 얹는다. 레이어는 프레임 그림 좌표(1024×1536)의 자족 모듈 `classicFrameMotion.ts`가 만들고, 시간 곡선은 SVG CSS 키프레임을 그대로 옮긴 순수 함수(`classicFrameMotionTiming.ts`)가 정한다.
  - `A 큰 광원`: 장갑 영역에서 띠(바깥 1380, 가운데 840, −14°)가 중심 y −841에서 2377까지 60초에 한 번 내려간다. 띠 밖은 #04060a 7%로 어둡게(대비 복사본 조각을 #04060a로 물들여 같은 장갑 알파로 그린다. 단색 #04060a와 1/255 안쪽 차이), 절반 띠는 대비 복사본 128/255, 가운데 띠는 대비 복사본과 흰빛 3%다(흰빛은 가운데 띠 텍스처에 미리 합성해 스프라이트 하나로 그린다). 띠 셋은 Graphics 스텐실 마스크(띠 밖은 `inverse`)이고 매 프레임 위치만 옮긴다. 마스크 사각형은 프레임 안에서 띠가 닿는 만큼(띠 방향 ±702)만 그린다.
  - 알려진 차이(띠 경계 계단): 스텐실 마스크는 픽셀마다 켜고 끄기만 하고 게임 렌더러는 안티앨리어싱(MSAA) 없이 그리므로, 띠 네 경계가 −14° 기울기의 픽셀 계단으로 보이고 띠가 움직일 때 계단이 기어간다. 승인 SVG는 경계를 안티앨리어싱한다. 원본 크기 비교에서 경계 1.5px 안 픽셀의 최대 차이는 12.0/255(15초)·12.7/255(30초)이고 평균은 0.31·0.34다. 비교 Pixi 앱에 MSAA 4×를 켜면 최대 4.7·6.3으로, 띠를 1px 부드러운 알파 마스크로 자르면(`bandEdges: 'soft'`) 2.7~3.0으로 준다. 알파 마스크는 띠마다 마스크 필터 패스가 하나씩 들지만 swiftshader 원본 크기에서는 스텐실보다 빨랐고(264.5 → 212.8ms, MSAA는 323.9ms), 무대는 아직 게임과 같은 스텐실을 쓴다.
  - `B 게이지 액체`: 유리 안쪽 윤곽(스텐실 마스크) 안에서 액체 타일이 10초에 640px 위로 흐르고(불투명도 45%, 좌우 가장자리 흐림은 타일 알파에 구움), 기포 5개와 그 반전이 SVG와 같은 반지름·주기·지연으로 오른다.
  - `C 발광선 호흡`: 파란 발광선과 번짐이 4.4초 주기 ease-in-out으로 0~0.85를 오간다. SVG는 그룹 안에서 발광선을 번짐 위에 겹친 뒤 screen하므로, 번짐 위 발광선(T1)을 불투명도 o로, 발광선 알파 아래 번짐(T2)을 o(1 − o)로 차례로 screen해 같은 결과를 낸다.
  - `D 하단 바 흐름`: 바 마스크 안에서 빛 두 개가 3.2초마다 가운데에서 ±170px 흐른다. 경계가 부드러운 바 마스크만 스프라이트 알파 마스크를 쓰며, 마스크 안에 바 바탕 복사본을 두고 빛을 screen해 SVG의 screen 결과와 같게 한다. 빛이 투명한 동안(주기의 45%)은 그리지 않는다.
  - Pixi는 스프라이트 불투명도를 8비트로 버리므로(17.85 → 17) 0.5/255를 더해 넘겨 브라우저처럼 반올림되게 한다.
  - 장갑·발광선 텍스처는 기둥 사이가 비어 있어 왼쪽 기둥·오른쪽 기둥·아래 띠 두 쪽 조각으로만 그린다(원래 상자의 약 47%). 그려지는 픽셀 수가 줄어 swiftshader에서 움직임이 더하는 프레임 시간이 약 3분의 1로 줄었다. 움직임 텍스처 GPU 메모리는 밉맵 포함 약 16.8MB다.
  - `update`는 매 프레임 새 배열·객체·클로저를 만들지 않는다(옮길 스프라이트 배열과 결과 객체를 만들 때 한 번 준비).
  - 조절: `움직임` 토글, `A 큰 광원`·`B 게이지 액체`·`C 발광선 호흡`·`D 하단 바 흐름` 체크(모두 기본 켬, 승인 SVG 시연과 같은 이름), `처음부터 재생` 버튼과 `움직임 시계` 표시. 움직임 시계는 곡 시간·차트 되감기·렌더러 재생성과 무관한 벽시계(처음부터 재생 이후 경과)라 광원이 끊기지 않고 흐른다. 설정을 바꿔도 렌더러를 다시 만들지 않는다.
  - 움직임 줄이기(`prefers-reduced-motion: reduce`)이면 승인 SVG처럼 움직임 레이어를 모두 숨기고 멈춘다.
  - 무대 data 속성: `data-motion`(`on`·`off`·`reduced`, 지원하지 않는 방식은 `off`), `data-motion-ready`(이 렌더러에 움직임을 얹었는지), `data-motion-armor`·`data-motion-gauge`·`data-motion-accent`·`data-motion-bar`(`on`·`off`), `data-motion-time-ms`(움직임을 그린 마지막 프레임의 움직임 시계, 그리지 않으면 없음).
  - 프레임 간격: 무대 설명에 requestAnimationFrame 간격의 평균과 p95를 움직임 켬·끔 상태별 최근 120프레임으로 따로 보여 주고(1초 넘는 간격은 제외, 렌더러·방식이 바뀌면 다시 모음) `data-frame-time-on`·`data-frame-time-off`(`평균/p95` ms)로 알린다. 움직임 줄이기 상태는 끔으로 센다. 표시는 0.5초마다 이 작은 부분만 다시 그리고 data 속성은 직접 써서, 페이지 전체를 다시 렌더링하지 않는다.
- Pixi ↔ 승인 SVG 비교: 무대 아래 구역에서 프레임만 그린 작은 Pixi 앱(GameRenderer 아님)과 승인 SVG를 같은 CSS 크기·viewBox로 나란히 보여 준다. 두 화면 모두 SVG 안의 같은 바탕 그림(`#fm-base`)을 쓰고, 움직임 텍스처는 무대와 같은 밉맵·삼선형 설정이다. 보기 `전체`(0 0 1024 1536, 기본)·`왼쪽 장갑`(0 420 320 480)·`하단`(300 1240 424 212)은 승인 SVG 시연과 같다. `비교 시각` 슬라이더(0~60초, 0.1초 단위)로 Pixi 움직임 시각을 정하고 SVG의 모든 CSS 애니메이션을 멈춘 채 `currentTime`을 같은 값으로 맞춘다. `재생`은 같은 시계로 양쪽을 함께 움직이고 60초에서 0초로 돌아간다. 이때 주기가 60초를 나누지 않는 발광선(4.4초)·하단 바(3.2초)·일부 기포는 양쪽에서 똑같이 한 번 건너뛰며, 화면 안내에도 적어 둔다. 위의 움직임 요소 체크와 움직임 줄이기는 양쪽에 함께 걸린다. 좁은 화면(720px 이하)에서는 조절과 두 패널이 세로로 쌓인다. 비교 구역은 화면 가까이(600px) 와야 승인 SVG(약 3.8MB)를 읽고 Pixi 앱을 만든다.
  - 띠 가장자리(Pixi 쪽): `가장자리 부드럽게(안티앨리어싱)`를 켜면 비교 Pixi 앱을 MSAA(`antialias: true`)로 다시 만들고, `띠를 알파 마스크로(실험)`를 켜면 광원 띠를 스텐실 대신 1px 부드러운 알파 마스크로 자르는 앱으로 다시 만든다. 둘 다 기본 꺼짐(게임 렌더러와 같음)이고 설명에 실제로 얻은 MSAA 샘플 수를 보여 준다. Pixi 앱은 만들 때마다 새 캔버스를 붙이므로(WebGL 컨텍스트 속성은 캔버스마다 한 번 정해짐) 두 앱이 한 컨텍스트를 함께 쓰는 일이 없다.

- 보기: `화면 맞춤`(기본)은 무대를 화면 폭에 맞춘다. `1:1 픽셀`은 캔버스 1px을 기기 화면 1px로 보여 주며(CSS 크기 = 캔버스 픽셀 ÷ `devicePixelRatio`) 무대 안에서만 스크롤한다. 좁은 화면에서는 조절 패널이 무대 아래로 내려간다.
- 무대 아래 설명은 현재 방식이 원본의 몇 행을 자르거나 누르는지, 화면 아래로 몇 행까지 보이는지, 갑옷 꼭대기·게이지 위끝·하단 바가 보이는지를 보여 준다. `원본 1px → 화면 N px`도 함께 보여 준다. N은 화면 논리 배율 × 렌더 높이 ÷ 600이고, 가로세로 같이 줄이기는 (W ÷ 레인 창 폭) × 렌더 높이 ÷ 600이다. 눌러 맞추기는 기둥 세로 배율도 표시한다.
