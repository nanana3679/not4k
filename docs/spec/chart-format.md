# 차트 문서 저장 포맷

`ChartDocument`는 구형 항목과 새 바디·탭/릴리즈/틱 노트를 함께 저장한다. 항목의 의미는 각 `type`에 있으며 파일 버전 변경으로 구형 배치를 자동 변환하지 않는다. 정식 정의는 [glossary](../context/glossary.md#chartdocument), 과도기 결정은 [RFD 0037 §8](../rfd/0037-explicit-score-notes-and-body.md#8-구형-차트와-과도기)을 따른다.

이 포맷의 공용 입출력(C1)과 실제 에디터의 제작·표시·혼합 저장(E1)을 구현했다([구현 계획](../plans/explicit-score-notes-implementation.md)). 별도 명시 컴파일·실제 코어/세션(M2)과 G2의 별도 게임·에디터 처음부터 재생도 연결했다. I1 전역 통합 검증을 마쳤고 일반 곡 선택·공식 결과의 I2 배선을 구현·검증했다. 공용 문서 왕복 지원을 기존 구형 소비자의 새 의미 지원으로 보지 않는다.

## 문서와 항목

메타데이터·`trillZones`·`restZones`·`events`는 기존 차트 구조를 보존한다. `notes: DocumentNoteEntity[]`에는 구형과 신형 항목을 섞어 저장할 수 있다. 코드의 박은 `Beat`, JSON의 박은 기존과 같은 문자열이다. 박 문자열은 안전 정수 하나(`"7"`) 또는 안전 정수 분자·분모(`"7/2"`)이며 `"1.5"`·`"1oops"`처럼 정수가 아닌 값은 앞부분을 잘라 읽지 않고 형식 오류로 거부한다. 같은 이유로 문서 검증은 정수가 아닌 분자나 양수가 아닌 분모의 `Beat`를 `beatMalformed` 구조 오류로 보고 저장을 막는다. 노트의 배열 상대 순서를 보존하며 맞닿은 바디를 병합하거나 누락된 노트를 자동 생성하지 않는다.

| 타입 | 필수 필드 | 선택 필드와 의미 |
| --- | --- | --- |
| `TapNote` | `type: "tap"`, `kind: "single" \| "double" \| "trill"`, `lane`, `beat` | `grace`는 탭 노트 전체에 적용 |
| `BodyNote` | `type: "body"`, `lane`, `beat`, `endBeat`, `holdCount: 1 \| 2` | `trill: true`는 hold 수 1인 트릴 바디에만 사용. `holdOnly`나 내장 점수 항목 없음 |
| `ReleaseNote` | `type: "release"`, `lane`, `beat`, `count: 1 \| 2` | `grace`는 릴리즈 전체에 적용. 더블 안에 일반/Grace를 섞지 않음 |
| `TickNote` | `type: "tick"`, `lane`, `beat`, `count: 1 \| 2` | `count`는 틱 노트 수량. 바디 소속과 수량 일치 여부는 위치 관계의 의미 검증 소유 |
| 구형 `PointNote` | `type: "single" \| "double" \| "trill"`, `lane`, `beat` | 기존 `grace` 보존 |
| 구형 `RangeNote` | `type: "long" \| "doubleLong" \| "trillLong"`, `lane`, `beat`, `endBeat` | 기존 `holdOnly` 의미 보존 |

`BodyNote.holdCount`와 `ReleaseNote.count`는 독립적이며 저장 과정에서 서로 맞추지 않는다. 틱 노트의 소속 ID는 저장하지 않는다. 명시 타입은 구형 타입으로 이름만 바꿔 내보내지 않는다.

## 버전 읽기와 쓰기

| 문서 | 읽기 | 쓰기 |
| --- | --- | --- |
| 버전 부재·v1 | 기존 `singleLong` 이름과 구형 이벤트의 호환 복원 유지 | 구형 항목만 있으면 기존 정규 v3 출력 |
| v2 | 기존 이벤트 호환 복원, 구형 노트 의미 유지 | 구형 항목만 있으면 정규 v3 출력 |
| v3 | 기존 노트·이벤트·속성 읽기 | 구형 항목만 있으면 기존 정규 v3 출력 |
| v4 | 구형·명시 타입을 항목별로 읽기 | 명시 항목이 있는 신형·혼합 문서는 v4 출력 |

지원하지 않는 버전이나 구형 포맷에 명시 타입을 숨긴 입력을 현재 구형 의미로 추정해 읽지 않는다. v4 안의 구형 항목도 그대로 구형이다. 구형 항목만 남은 문서는 기존 정규 출력으로 돌아갈 수 있으며 이 정규화는 항목의 의미를 바꾸지 않는다.

명시 점수 노트의 저장 이름은 `tap`·`release`·`tick`·`body`다([RFD 0041](../rfd/0041-explicit-score-note-names-tap-tick.md)). 이름 변경 전의 `"point"`·`"sustain"`은 별칭으로 읽지 않고 "지원하지 않는 노트 type"으로 거부한다. 원격 저장소에 그 이름으로 저장된 v4 차트는 없다.

옵션 플래그 `grace`·`holdOnly`는 부재·`true`·명시한 `false`를 보존한다. 바디의 `trill`은 `true`만 쓰고 트릴 바디가 아니면 생략하며, 바디 `trill: false`는 형식 오류다. 기존 메인 codec이 생략하던 명시 `false`도 새 codec에서는 출력될 수 있다. 비교 기준점과 현재 문서는 같은 codec을 사용하고, 한 번 읽어 저장한 뒤의 왕복 표현은 안정적이어야 한다.

`serializeChart`·`chartToJson`은 문서의 지원 항목을 저장한다. `deserializeChartDocument`·`chartDocumentFromJson`은 신형·혼합을 포함하는 문서를 읽는다. 기존 `deserializeChart`·`chartFromJson`은 구형 전용 `Chart` 소비자를 위한 경계이며 명시 항목이 있으면 지원 불가로 거부한다. 새 reader 결과를 구형 타입으로 캐스트해 이 검사를 우회하지 않는다.

미지원 필드는 위치에 따라 다르게 다룬다. 노트 항목은 엄격하게 읽어 미지원 필드(틱 노트의 `grace`, 구형 롱노트의 `holdCount` 등)를 버리지 않고 형식 오류로 거부한다. 최상위·`trillZones`·`restZones`·`events` 항목과 보조 파일 최상위의 미지원 필드는 읽기를 막지 않지만 저장에서 보존하지 않는다. `meta` 객체는 읽은 그대로 저장한다. 박 문자열 오류와 항목 모양 오류를 포함한 읽기 오류는 모두 `ChartFormatError`로 전달하며, 지원하지 않는 명시 내용은 그 하위 클래스 `UnsupportedChartContentError`다.

## 메인과 보조 파일

편집 문서에서는 메인과 보조 노트가 `notes` 안에 함께 있으며 기존 `laneAxis`가 경계를 소유한다. 에셋 저장은 메인 파일과 별도 보조 파일로 나누고 로드는 둘을 합친다. 보조 파일은 기존 `extraLane` 좌표와 `extraLaneCount`를 유지한다. 노트의 `lane`만 `extraLane`으로 바꾸며 종류·일반/Grace·구형 `holdOnly`·신형 수량을 보존한다. 보조 노트의 `extraLane`은 1 이상의 정수여야 하며 0·음수·비정수는 메인 레인이나 성립하지 않는 레인으로 옮기지 않고 형식 오류로 거부한다. 보조 노트 항목에 메인 전용 `lane`이 있으면 `extraLane`으로 덮어쓰지 않고 형식 오류로 거부한다.

에디터가 메인과 보조 자료를 합칠 때는 메인의 보조 레인(5+) 항목만 보조 자료로 교체한다. lane 0·비정수처럼 성립하지 않는 레인의 메인 항목은 걸러내지 않고 그대로 열어 레인 값 오류(`laneMalformed`)로 보인다. 걸러내면 위반 표시 없이 다음 저장에서 지워지기 때문이다.

구형 보조 파일의 기존 표현은 유지하고 명시 항목이 있으면 버전이 있는 새 표현으로 저장한다. `parseExtraNotesDocument`가 전체 지원 항목을 읽고 구형 전용 `parseExtraNotes`는 명시 항목을 구형 타입으로 넘기지 않는다. 별도 보조 파일 부재 시 구형 내장 보조 자료를 읽는 기존 경로도 유지한다.

지원하지 않는 보조 포맷을 빈 보조 배열로 간주하여 열거나 재저장하지 않는다. 지원하지 않는 내용·버전·필드 오류는 호출자에게 전달해 원본이 조용히 유실되지 않게 한다. 현재 에디터는 이 오류를 로드 오류 화면으로 보이고 편집 화면을 열지 않으므로, 빈 보조 자료로 저장해 기존 보조 파일을 지우는 경로가 없다. 별도 보조 파일이 없다는 응답(HTTP 404, 또는 Supabase Storage의 HTTP 400 `NoSuchKey` 본문)만 별도 보조 파일 없음으로 보고 구형 내장 보조 자료 경로로 돌아간다. 권한·서버 오류 응답과 네트워크 오류는 로드 오류다. 성공 응답의 본문이 비었거나 JSON으로 읽히지 않는 손상 보조 파일(업로드가 끊겨 잘린 파일 등)도 별도 보조 파일 없음으로 보지 않고 `ChartFormatError`로 로드를 막는다.

## 수리와 변경 비교

파서는 지원하는 구조를 복원하고 의미 위반 위치도 보존한다. 바디 밖 틱 노트·바디 내부 릴리즈·동일 위치 의미 중첩처럼 수리할 수 있는 배치를 파싱 중 삭제하거나 자동 수정하지 않는다. `trillZone` 안의 명시 릴리즈도 파서는 보존하되 [RFD 0038](../rfd/0038-release-notes-in-trill-zones.md)의 배치 금지는 의미 검증에서 적용한다. C2의 `validateChartDocument`는 구조·의미 오류와 구형 내용의 실행 비호환을 분리한다. `canSave`는 실제 구조·의미 위반만, `canPlayExplicit`는 실행 비호환도 검사한다. 에디터 저장과 새 재생 진입은 이 결과를 소비한다([에디터 계약](chart-editor.md#미리보기확정선택-해제와-검증)).

dirty 비교는 저장과 같은 항목·속성·수량·메타데이터·보조 레인 수를 포함한다. 의미 위반이 있어도 비교 가능한 표현을 만들며, 저장 검증 실패를 이유로 해당 항목을 직렬화나 비교에서 빼지 않는다. 구형만 있는 기존 문서는 정규 출력과 배열 상대 순서를 유지해 의미 없는 dirty 변화를 피한다. 원본 JSON의 공백까지 같은 것은 요구하지 않는다.

혼합 문서에서도 구형 범위가 소유한 배치 제약은 유지한다. 구형 `holdOnly` 끝의 Point 금지, 길이 0 구형 롱노트의 head Point 금지, 같은 unit 수의 구형 연결 경계의 head 필요, 구형 트릴 롱노트의 트릴 head 필요는 탭 노트도 구형 Point로 인식해 검사한다. 구형 범위를 새 바디로, 명시 바디·릴리즈·틱 노트를 구형 항목으로 다시 해석하지는 않는다.

명시 바디 둘이 같은 레인에서 맞닿고(앞 바디 끝 = 뒤 바디 시작) hold 수와 트릴 여부가 같으면(일반 바디 → 일반 바디, 트릴 바디 → 트릴 바디) 화면에서 한 바디와 구별되지 않으므로 경계에 탭 노트나 릴리즈가 있어야 한다. 둘 다 없으면 두 바디를 가리키는 `sameHoldCountConnectionWithoutTapOrRelease` 의미 위반으로 저장을 막는다. 길이 0 뒤 바디와 보조 레인에도 적용하며, 경계의 틱 노트는 경계의 탭·릴리즈로 인정하지 않는다. 메인 레인의 트릴 바디 → 트릴 바디 경계에서 시작 트릴 탭 노트 누락은 `trillLongInvalid`가 보고하므로 이 위반을 겹쳐 내지 않는다.

트릴 바디와 일반 바디는 모양이 달라 맞닿아도 구별되므로 어느 방향이든 이 규칙에서 제외한다. 트릴 바디 → 일반 바디는 사용자 결정(2026-10-27)이고, 일반 바디 → 트릴 바디는 사용자 정정(2026-10-28)이다. 같은 날 앞서 보조 레인의 일반 바디 → 트릴 바디를 막기로 한 답은 질문을 잘못 이해한 것이었다고 사용자가 바로잡았다. 기존 규칙의 적용(사용자 결정이 아님): 메인 레인에서 트릴 바디로 들어가는 경계는 이 제외와 관계없이 기존 `trillLongInvalid`가 시작 트릴 탭 노트를 요구한다. 메인 레인의 트릴 바디 → 일반 바디는 뒤 바디 시작이 `trillZone` 끝에 걸려 `trillExclusive`가 따로 막는다. 그래서 두 방향의 제외가 결과를 바꾸는 곳은 판정하지 않는 보조 레인뿐이다.

경계와 같은 레인·같은 박에 놓인 구형 Point(`single`·`double`·`trill`)도 경계의 탭 노트로 인정한다. 이는 사용자 결정이 아니다. 구형 내용이 있다는 것만으로는 저장을 막지 않는다는 위 `canSave` 계약에 맞춰, 일부만 옮긴 혼합 문서도 저장할 수 있게 한 구현 규칙이다. 메인 레인의 구형 Point는 저장만 허용되고 새 재생은 여전히 `legacyGameContent`가 막는다. 구형 롱노트는 `holdOnly`나 길이 0이어도 경계의 탭 노트로 인정하지 않는다. 구형 롱노트끼리의 경계는 위의 구형 연결 head 제약을 따르고, 구형 롱노트와 명시 바디가 맞닿은 경계는 이 규칙의 대상이 아니다.

## 현재 소비자 경계

`Chart`·`NoteEntity`는 구형 실행 소비자의 타입으로 남기며, 실제 에디터는 `ChartDocument`·문서 검증을 사용한다. 새 명시 컴파일러와 코어/세션은 별도 타입 경로를 사용하고 구형 컴파일러는 명시 항목을 거부한다. 기존 renderer·validator의 `endBeat` 가정이나 타입별 기본 분기로 새 의미를 캐스트해 넘기지 않는다.

명시 컴파일러는 게임 대상 main에 구형 의미가 남으면 거부하며 main의 구형 항목을 걸러내지 않는다. 일반 곡 선택은 메인·별도 보조 파일을 문서 reader로 합치고 전체 검증 뒤 새 세션으로 진입한다. 합칠 때는 메인의 보조 레인 항목만 보조 자료로 교체하며, lane 0·비정수처럼 성립하지 않는 레인의 메인 항목은 걸러내지 않고 검증에 넘겨 재생을 거부한다. 보조 파일 부재(HTTP 404, 또는 Supabase Storage가 없는 객체에 돌려주는 HTTP 400과 본문 `statusCode` "404"·`code` "NoSuchKey")와 권한·네트워크·서버 오류, 손상 JSON을 포함한 형식 오류를 구별한다. 부재만 보조 파일 없음으로 읽고, 형식 오류는 차트 데이터 오류로 알린다. 에디터의 명시 main도 전체 원본 검증 뒤 처음부터/커서부터 새 세션으로 재생하며 커서 범위는 RFD 0040을 따른다. 구형 main만 있는 에디터/Lab의 복귀 경로 테스트와 구형 aux의 게임 제외는 보존한다. 구형·혼합 문서의 읽기·수리·저장은 실행 제한과 별개로 보존한다.
