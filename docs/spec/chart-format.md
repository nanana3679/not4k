# 차트 문서 저장 포맷

`ChartDocument`는 구형 항목과 새 바디·명시 Point/릴리즈/유지를 함께 저장한다. 항목의 의미는 각 `type`에 있으며 파일 버전 변경으로 구형 배치를 자동 변환하지 않는다. 정식 정의는 [glossary](../context/glossary.md#chartdocument), 과도기 결정은 [RFD 0037 §8](../rfd/0037-explicit-score-notes-and-body.md#8-구형-차트와-과도기)을 따른다.

이 단계는 공용 문서 입출력·정적 관계·문서 검증·저장·시간 뷰를 제공한다. 명시 판정 코어, 에디터 제작·표시, 일반 곡 로딩·재생 연결은 후속 단계에서 도입한다. 공용 문서 왕복 지원을 기존 구형 소비자의 새 의미 지원으로 보지 않는다.

## 문서와 항목

메타데이터·`trillZones`·`restZones`·`events`는 기존 차트 구조를 보존한다. `notes: DocumentNoteEntity[]`에는 구형과 신형 항목을 섞어 저장할 수 있다. 코드의 박은 `Beat`, JSON의 박은 기존과 같은 문자열이다. 박 문자열은 안전 정수 하나(`"7"`) 또는 안전 정수 분자·분모(`"7/2"`)이며 `"1.5"`·`"1oops"`처럼 정수가 아닌 값은 앞부분을 잘라 읽지 않고 형식 오류로 거부한다. 같은 이유로 문서 검증은 정수가 아닌 분자나 양수가 아닌 분모의 `Beat`를 `beatMalformed` 구조 오류로 보고 저장을 막는다. 노트의 배열 상대 순서를 보존하며 맞닿은 바디를 병합하거나 누락된 노트를 자동 생성하지 않는다.

| 타입 | 필수 필드 | 선택 필드와 의미 |
| --- | --- | --- |
| `ExplicitPointNote` | `type: "point"`, `kind: "single" \| "double" \| "trill"`, `lane`, `beat` | `grace`는 Point 전체에 적용 |
| `BodyNote` | `type: "body"`, `lane`, `beat`, `endBeat`, `holdCount: 1 \| 2` | `trill: true`는 hold 수 1인 트릴 바디에만 사용. `holdOnly`나 내장 점수 항목 없음 |
| `ReleaseNote` | `type: "release"`, `lane`, `beat`, `count: 1 \| 2` | `grace`는 릴리즈 전체에 적용. 더블 안에 일반/Grace를 섞지 않음 |
| `SustainNote` | `type: "sustain"`, `lane`, `beat`, `count: 1 \| 2` | 명시 표식 수. 바디 소속과 수량 일치 여부는 위치 관계의 의미 검증 소유 |
| 구형 `PointNote` | `type: "single" \| "double" \| "trill"`, `lane`, `beat` | 기존 `grace` 보존 |
| 구형 `RangeNote` | `type: "long" \| "doubleLong" \| "trillLong"`, `lane`, `beat`, `endBeat` | 기존 `holdOnly` 의미 보존 |

`BodyNote.holdCount`와 `ReleaseNote.count`는 독립적이며 저장 과정에서 서로 맞추지 않는다. 유지의 소속 ID는 저장하지 않는다. 명시 타입은 구형 타입으로 이름만 바꿔 내보내지 않는다.

## 버전 읽기와 쓰기

| 문서 | 읽기 | 쓰기 |
| --- | --- | --- |
| 버전 부재·v1 | 기존 `singleLong` 이름과 구형 이벤트의 호환 복원 유지 | 구형 항목만 있으면 기존 정규 v3 출력 |
| v2 | 기존 이벤트 호환 복원, 구형 노트 의미 유지 | 구형 항목만 있으면 정규 v3 출력 |
| v3 | 기존 노트·이벤트·속성 읽기 | 구형 항목만 있으면 기존 정규 v3 출력 |
| v4 | 구형·명시 타입을 항목별로 읽기 | 명시 항목이 있는 신형·혼합 문서는 v4 출력 |

지원하지 않는 버전이나 구형 포맷에 명시 타입을 숨긴 입력을 현재 구형 의미로 추정해 읽지 않는다. v4 안의 구형 항목도 그대로 구형이다. 구형 항목만 남은 문서는 기존 정규 출력으로 돌아갈 수 있으며 이 정규화는 항목의 의미를 바꾸지 않는다.

옵션 플래그 `grace`·`holdOnly`는 부재·`true`·명시한 `false`를 보존한다. 바디의 `trill`은 `true`만 쓰며 트릴 바디가 아니면 생략한다. 명시한 `false`는 형식 오류다. 기존 메인 codec이 생략하던 명시 `false`도 새 codec에서는 출력될 수 있다. 비교 기준점과 현재 문서는 같은 codec을 사용하고, 한 번 읽어 저장한 뒤의 왕복 표현은 안정적이어야 한다.

`serializeChart`·`chartToJson`은 문서의 지원 항목을 저장한다. `deserializeChartDocument`·`chartDocumentFromJson`은 신형·혼합을 포함하는 문서를 읽는다. 기존 `deserializeChart`·`chartFromJson`은 구형 전용 `Chart` 소비자를 위한 경계이며 명시 항목이 있으면 지원 불가로 거부한다. 새 reader 결과를 구형 타입으로 캐스트해 이 검사를 우회하지 않는다.

미지원 필드는 위치에 따라 다르게 다룬다. 노트 항목은 엄격하게 읽어 미지원 필드(유지의 `grace`, 구형 롱노트의 `holdCount` 등)를 버리지 않고 형식 오류로 거부한다. 최상위·`trillZones`·`restZones`·`events` 항목과 보조 파일 최상위의 미지원 필드는 읽기를 막지 않지만 저장에서 보존하지 않는다. `meta` 객체는 읽은 그대로 저장한다. 박 문자열 오류와 항목 모양 오류를 포함한 읽기 오류는 모두 `ChartFormatError`로 전달하며, 지원하지 않는 명시 내용은 그 하위 클래스 `UnsupportedChartContentError`다.

## 메인과 보조 파일

편집 문서에서는 메인과 보조 노트가 `notes` 안에 함께 있으며 기존 `laneAxis`가 경계를 소유한다. 에셋 저장은 메인 파일과 별도 보조 파일로 나누고 로드는 둘을 합친다. 보조 파일은 기존 `extraLane` 좌표와 `extraLaneCount`를 유지한다. 노트의 `lane`만 `extraLane`으로 바꾸며 종류·일반/Grace·구형 `holdOnly`·신형 수량을 보존한다. 보조 노트 항목에 메인 전용 `lane`이 있으면 `extraLane`으로 덮어쓰지 않고 형식 오류로 거부한다.

구형 보조 파일의 기존 표현은 유지하고 명시 항목이 있으면 버전이 있는 새 표현으로 저장한다. `parseExtraNotesDocument`가 전체 지원 항목을 읽고 구형 전용 `parseExtraNotes`는 명시 항목을 구형 타입으로 넘기지 않는다. 별도 보조 파일 부재 시 구형 내장 보조 자료를 읽는 기존 경로도 유지한다.

지원하지 않는 보조 포맷을 빈 보조 배열로 간주하여 열거나 재저장하지 않는다. 지원하지 않는 내용·버전·필드 오류는 호출자에게 전달해 원본이 조용히 유실되지 않게 한다. 현재 에디터는 이 오류를 로드 오류 화면으로 보이고 편집 화면을 열지 않으므로, 빈 보조 자료로 저장해 기존 보조 파일을 지우는 경로가 없다. 별도 보조 파일 요청이 성공하지 못하거나 응답이 JSON으로 읽히지 않으면 기존 동작대로 별도 보조 파일이 없는 것으로 보고 구형 내장 보조 자료 경로로 돌아간다.

## 수리와 변경 비교

파서는 지원하는 구조를 복원하고 의미 위반 위치도 보존한다. 바디 밖 유지·바디 내부 릴리즈·동일 위치 의미 중첩처럼 수리할 수 있는 배치를 파싱 중 삭제하거나 자동 수정하지 않는다. `trillZone` 안의 명시 릴리즈도 파서는 보존하되 [RFD 0038](../rfd/0038-release-notes-in-trill-zones.md)의 배치 금지는 의미 검증에서 적용한다. `validateChartDocument`는 구조·의미 오류와 구형 내용의 실행 비호환을 분리한다. `canSave`는 실제 구조·의미 위반만, `canPlayExplicit`는 실행 비호환도 검사한다. 에디터 저장과 새 재생 진입에서 이 결과를 소비하는 연결은 후속 단계에서 도입한다.

dirty 비교는 저장과 같은 항목·속성·수량·메타데이터·보조 레인 수를 포함한다. 의미 위반이 있어도 비교 가능한 표현을 만들며, 저장 검증 실패를 이유로 해당 항목을 직렬화나 비교에서 빼지 않는다. 구형만 있는 기존 문서는 정규 출력과 배열 상대 순서를 유지해 의미 없는 dirty 변화를 피한다. 원본 JSON의 공백까지 같은 것은 요구하지 않는다.

혼합 문서에서도 구형 범위가 소유한 배치 제약은 유지한다. 구형 `holdOnly` 끝의 Point 금지, 길이 0 구형 롱노트의 head Point 금지, 같은 unit 수의 구형 연결 경계의 head 필요, 구형 트릴 롱노트의 트릴 head 필요는 명시 Point도 Point로 인식해 검사한다. 구형 범위를 새 바디로, 명시 바디·릴리즈·유지를 구형 항목으로 다시 해석하지는 않는다.

## 현재 소비자 경계

`Chart`·`NoteEntity`는 기존 에디터·판정·일반 로딩 소비자의 타입으로 남는다. 문서 reader와 별도로 구형 reader가 명시 항목을 거부하며, 기존 renderer·validator의 `endBeat` 가정이나 타입별 기본 분기로 새 의미를 캐스트해 넘기지 않는다. `ChartTiming`은 문서 항목의 시간을 제공하지만 구형 `judgmentCounts`는 명시 항목을 거부한다.

공용 문서 검증은 게임 대상 main에 구형 의미가 남으면 `canPlayExplicit: false`로 보고하며, 구형 aux는 실행 비호환에서 제외한다. 일반 로딩의 메인·보조 파일 fetch 및 문서 loader 연결은 후속 통합에서 처리한다. 구형·혼합 문서의 공용 읽기·저장은 실행 제한과 별개로 보존한다.
