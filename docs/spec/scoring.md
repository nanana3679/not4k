# not4k — 스코어링 시스템

[RFD 0037](../rfd/0037-explicit-score-notes-and-body.md)의 **채택 계약·구현은 후속 PR**을 반영한다. 정식 정의는 [glossary](../context/glossary.md#점수-항목과-무점수-miss), 설계 기대값은 [명시적 점수 노트 판정 사례](explicit-note-judgment-cases.md)를 따른다. 과도기 구형 점수·입력 설명과 이전 사례 결과는 별도로 보존하며 새 구현의 정답으로 사용하지 않는다. 미정 사항·실제 이행은 [PRD §12](../prd.md#12-미정-사항)에서 추적한다.

## 새 모델의 점수 범위

명시 Point·릴리즈·유지 노트만 점수 항목을 만들고 바디 정상 완료는 무점수다. 바디 실패의 원인 Miss와 연결 항목의 종속 0점은 구별한다. 아래 [명시 점수 항목과 무점수 바디](#명시적-점수-항목과-정산)의 채택 계약을 따른다.

### 핵심 원칙

1. **더블 노트는 가중치를 가진다**: 더블 노트는 독립된 싱글 판정 × 2로 처리되므로, 자연스럽게 싱글 노트의 2배 비중을 차지한다. 별도의 보너스 없이도 더블 노트를 정확하게 입력해야 할 동기가 발생한다.

2. **트릴 노트의 판정은 학습을 돕는 방향으로**: 트릴 노트는 가변 손배치의 학습 장치이므로, 최소한 초급 등급(Lv.4～6)에서는 판정이 관대해야 한다.

3. **입문 등급(Lv.1～3)은 기존 4K와 동일한 스코어링 감각**: 기존 4K 유저가 위화감 없이 진입할 수 있어야 한다.

## 판정 윈도우와 점수

| 등급 | Normal | Easy | 점수 |
|---|---:|---:|---:|
| Perfect | ±41ms | ±50ms | 3 |
| Great | ±82ms | ±100ms | 2 |
| Good | ±120ms | ±150ms | 1 |
| `goodTrill` | Good 안의 교대 실패 | 동일 | 1 |
| Miss | 적격 입력 부재·유지 실패 | 동일 | 0 |

일반 Point와 명시 릴리즈는 누름의 등급별 창을 공유하며 앞뒤 대칭이다. Good 경계값은 포함하고 그 밖 입력은 해당 대상을 소비하지 않는다. Bad 등급과 매칭 구간은 사용하지 않는다. Grace Point·릴리즈는 같은 Good 최대 창 안에서 실제 down/up을 요구하고 타이밍 등급은 Perfect다. 기존 트릴 교대 실패 `goodTrill`은 유지한다. 유지 노트는 바디 상태에 따른 Perfect/종속 0점 정산이며 독립 창·타이밍 등급을 만들지 않는다.

표의 수치는 현행 설정이다. 대표 사례는 Normal과 임시 유지 유예 20ms를 명시해 사용하며 새로운 최종 튜닝 값을 확정하지 않는다. 구형 `holdOnly`의 Perfect/Miss 상태 판정은 아래 과도기 범위에서만 보존한다.

## 명시적 점수 항목과 정산

**채택 계약·구현은 후속 PR.** 명시한 Point·릴리즈·유지 노트가 요구 한 몫당 점수 항목 하나와 이론 가중치 3을 만든다. 더블은 두 항목이다. 바디의 항목 수·가중치는 0이며 정상 유지·종료·경계 자체에 점수·콤보·고도 회복을 만들지 않는다. 새 모델에는 `holdOnly`를 두지 않고 주기적인 자동 유지 점수도 만들지 않는다.

바디 hold 수와 명시 릴리즈 수를 같게 강제하지 않는다. double 바디 끝에 릴리즈 하나만 있으면 그 항목 하나만 분모에 넣는다. single 바디의 double 릴리즈도 수량 차이만으로 금지하거나 자동 보정하지 않는다. 2→1 감소에서 다룬 예시는 싱글 릴리즈 하나이며 감소량에서 숨은 항목을 생성하지 않는다.

같은 더블 릴리즈의 두 항목은 일반/Grace 종류를 공유한다. 일반·Grace를 한 항목씩 섞은 조합은 허용하지 않으며 두 항목의 개별 정산과 노트의 공통 종류를 구별한다.

각 항목은 한 번만 정산한다. 입력 시각·실패 횟수·정산 순서는 전체 이론 가중치를 바꾸지 않는다.

| 결과 | 점수·분모 | 확정 효과 |
| --- | --- | --- |
| 일반 Point·릴리즈 성공 | Perfect 3 / Great 2 / Good 1점, 원래 가중치 3 | 항목별 성공·콤보·고도·타이밍 효과 |
| Grace Point·릴리즈 성공 | 유효 입력의 타이밍 등급 Perfect 3점, 원래 가중치 3 | 실제 down/up 요구, FAST/SLOW·타이밍 오차 없음 |
| 유지 노트 성공 | 표식당 Perfect 3점, 원래 가중치 3 | 콤보 +1·일반 Perfect 고도 기여·Perfect 글자·해당 레인 일반 타격 효과, 타이밍 없음 |
| Point·릴리즈의 일반 실패 | 원래 항목 0점·원래 가중치 | 원인 Miss·콤보 단절·고도 손실 |
| 바디 시작·유지 실패 | 새 항목·분모·직접 감점 없음 | 원인 실패 효과를 한 번만 적용 |
| 실패에 종속된 미처리 릴리즈·유지 항목 | 원래 항목 0점·원래 가중치로 한 번 정산 | 추가 Miss 통계·콤보·고도·판정 글자·성공 타격 효과 없음. 실패 표시는 남음 |

Grace의 타이밍 면제는 기존 트릴 교대 실패 `goodTrill`을 없애지 않는다. 구체적인 고도 회복량과 `flightRule`별 실패 정책은 [PRD §12](../prd.md#12-미정-사항)의 별도 후속 범위다.

### 유지 노트의 정산 시점

유지 노트는 바디와 같은 판정 상태에 정산만 연결한다. 자체 down/up 소비·독립 허용 창·기한은 없다.

- 정상 유지 중이면 표식 시각에 Perfect로 정산한다. 이른 down만으로 미래 표식을 미리 성공시키지 않는다.
- 최초 시작 판단·유지 유예 중이면 바디 결과를 기다린다. 유효한 늦은 시작·회복 뒤 성공하고 확정 실패 뒤 종속 0점으로 정산한다.
- 유효한 이른 정상 종료에서는 그 종료 몫에 속한 남은 표식을 같은 시점에 함께 Perfect로 정산한다. 뒤 바디 소속의 경계 표식을 포함하지 않는다.
- 일반 릴리즈가 Good이어도 유지 성공은 Perfect다. 유지 Good 예외를 만들지 않으며 이미 성공한 표식은 이후 실패로 되돌리지 않는다.

유지 표식만 합법 위치에 추가·제거해도 기존 바디 진행·Point/릴리즈 배정·바디 실패 효과는 같아야 한다. 바뀌는 것은 명시 유지 항목의 정산과 성공 효과다. [ENJ-05～08·18](explicit-note-judgment-cases.md#enj-05)에서 대기·실패·이른 종료·늦은 시작을 대조한다.

### 실패 종속의 범위

실제로 시작하지 않은 바디에 붙은 릴리즈는 끝 창 안 up만으로 성공하지 않는다. 정상 완료한 바디의 릴리즈는 자기 창까지 기다리고, 누락하면 릴리즈만 Miss다. 바디 완료 자체로 성공시키거나 완료한 바디에 새 유지 실패를 더하지 않는다.

double 전체 끝의 릴리즈 두 항목은 바디 한 몫 실패 시 하나만 기회를 잃는다. 전체 끝의 항목이 하나뿐이면 건강한 몫 하나로 기회를 보존한다. 2→1 감소의 싱글 릴리즈는 끝나는 실패 몫에 귀속하고 건강한 몫은 뒤 single로 이어지므로 같은 방식으로 처리하지 않는다. 이미 닫힌 기회는 재누름으로 돌아오지 않는다. [ENJ-09～15](explicit-note-judgment-cases.md#enj-09)와 [RFD 0037 §4](../rfd/0037-explicit-score-notes-and-body.md#4-경계실패-종속)를 따른다.

## 새 모델의 입력과 효과

Point가 가장 이른 적격 down을, 명시 릴리즈가 가장 이른 적격 up을 소비한다. 바디·유지 노트는 입력을 소비하지 않으며 같은 down의 hold도 바디 조건에 참여한다. 숨은 연결 release의 up 자동 소비는 없다. 바디의 실제 시작·종료와 같은 키 재누름 예외는 [게임 코어](game-core.md#새-모델의-입력과-바디-진행)를 따른다.

확정 효과는 항목별로 한 번 적용한다. 현재 콤보는 확정 순서와 같은 timestamp·phase 묶음의 Miss 우선을 유지한다. 같은 확정 시각의 대표 판정 글자는 가장 낮은 등급이며 종속 0점은 후보가 아니다. 대표 등급 안에서 타이밍 표시가 허용된 실제 입력을 우선하고 여러 개면 raw 오차의 절대값이 가장 큰 입력을 사용한다. 유지·Grace에 오차를 만들거나 다른 등급에서 빌리지 않는다. 대표 표시 선택과 각 항목의 점수·통계·콤보·고도·타격 정산은 별개다. [ENJ-07·16·17](explicit-note-judgment-cases.md#enj-16)을 따른다.

## 과도기 구형 점수·입력 계약

아래는 구형 읽기·편집과 현행 런타임/이전 논의를 대조하기 위한 기존 설명이다. 새 모델의 정답으로 적용하지 않으며 구형 항목·기존 사례 결과는 자동 변환하지 않는다. 제거 시점은 [RFD 0037 §8](../rfd/0037-explicit-score-notes-and-body.md#8-구형-차트와-과도기)을 따른다.

### 구형 점수 항목과 정산

차트 컴파일 시 head, 실제 감소·마지막 release, 명시된 `holdOnly`를 점수 항목으로 만들고 각 이론 가중치는 3이다. double head는 두 항목이다. 일반 2→1 감소는 release 한 항목이고 같은 끝에 `holdOnly`가 있으면 앞 double의 상태 항목 두 개다. 일반 connection 성공에는 점수·콤보·고도 회복이 없다.

각 항목은 ID로 한 번만 정산한다. 입력 시각, 실패 횟수, 정산 순서가 전체 이론 가중치를 바꾸지 않는다.

| 결과 | 점수·분모 | 실패·표시 |
|---|---|---|
| head·실제 release·`holdOnly` | 원래 항목을 해당 등급으로 정산 | 해당 판정 효과 |
| 무점수 유지·연결 Miss | 획득 점수 차감과 분모 추가 없음 | Miss 통계·고도 손실·콤보 단절 1회 |
| head Miss 등으로 종속 끝점 실패 | 원래 끝 항목을 0점·원래 가중치로 정산 | 추가 끝 Miss·고도 손실·콤보 이벤트 없음 |

이미 건강하게 승계한 unit은 별도 head Miss 때문에 종속 실패로 정산하지 않는다. 활성화한 unit도 실패 시점과 끝점에서 두 번 패널티를 받지 않는다. 차트·입력별 기대값은 [NJ-S01～S03](note-judgment-cases.md#nj-s01)을 따른다.

### 구형 입력별 판정

Point는 해당 레인에서 Good 창과 물리 키 자격을 충족한 가장 이른 대상이 down을 소비한다. double은 서로 다른 두 물리 키를 요구하고 두 성공을 별도 기록한다. head 없는 미처리 시작은 down을 소비하되 시작 점수는 없다. raw held로 양수 바디를 독립 시작하지 않는다.

실제 release는 준비·창·누름의 권한을 충족한 가장 이른 끝 하나가 up을 소비한다. 일반 여분 up은 소비하지 않는다. 같은 물리 키도 유효한 새 head·미처리 시작으로 새 누름의 권한을 얻으면 남은 release를 처리할 수 있다. 임의 재누름에는 권한이 없다.

연결용 up은 유효한 교대 몫만큼 FIFO로 보정하여 뒤 release에서 제외한다. 모호한 up은 후속 head의 기한까지 보류할 수 있으며, 실제 release로 확정될 때는 원래 up의 시각으로 등급을 계산한다. `holdOnly` 완료는 up을 소비하지 않는다.

트릴 교대 세트에는 head를 소비한 키만 등록한다. 같은 timestamp의 여러 적격 head 중 최고 등급 입력 하나만 교대를 인정하고 나머지는 `goodTrill`이다. 구간 귀속과 실패 초기화는 [트릴 경계 설명](../context/trill-boundary-input.md)을 따른다.

## 현재 콤보와 Full Combo

성공한 점수 판정은 현재 콤보를 1 증가시키고 Miss는 끊는다. `goodTrill`은 Good처럼 콤보를 유지한다. 무점수 connection 성공은 증가시키지 않으며 무점수 유지 Miss도 끊는다. 종속 0점 정산은 별도 콤보 이벤트가 아니다.

보류 판정은 확정 순서로 반영하며 원래 입력 시각으로 소급하지 않는다. 같은 timestamp·phase 확정 묶음에 Miss와 성공이 함께 있으면 Miss 우선으로 현재 콤보는 0이다. 최대 콤보수 통계는 제공하지 않는다.

무점수 유지 실패를 포함해 Miss가 없으면 Full Combo이다. 점수 항목을 모두 Perfect로 처리하고 무점수 연결만 실패한 **100%이지만 Full Combo가 아닌 결과**를 허용한다. 이를 막기 위한 Miss 감점이나 콤보 점수 보너스는 없다.

## FAST/SLOW 표시

raw 입력 오차의 절댓값이 Perfect 창 절반을 넘을 때 음수는 FAST, 양수는 SLOW이다. Normal은 20.5ms, Easy는 25ms가 기준이다.

- 일반 Point와 명시 릴리즈의 원래 입력 시각을 사용한다. 확정을 기다려도 확정 시각으로 타이밍을 바꾸지 않는다.
- 유지 노트, Grace(`goodTrill` 포함), 입력 없는 Miss, 종속 0점 정산에는 FAST/SLOW·타이밍 오차가 없다. 구형 `holdOnly`도 기존대로 제외한다.
- 판정 텍스트 아래 FAST는 파란 계열, SLOW는 빨간 계열로 표시한다. 설정으로 표시를 끌 수 있고 결과 화면에 횟수를 집계한다.

## 달성률과 랭크

### 달성률 (Achievement Rate)

```text
실시간 달성률 = 획득 점수 / 지금까지 정산한 항목의 이론 가중치 × 100%
최종 달성률 = 획득 점수 / 전체 차트 점수 항목의 이론 가중치 × 100%
```

점수 항목이 있는 차트에서 아직 정산한 항목이 없어 실시간 분모가 0이면 실시간 달성률은 0%다. 무점수 Miss는 분모를 늘리지 않는다. 종속 릴리즈·유지 항목의 0점도 원래 항목의 가중치를 정산하며 중복 정산하지 않는다. 종료 시 아직 미정산 항목이 있더라도 최종 분모는 전체 이론치이다.

### 점수 항목이 없는 차트

[RFD 0039](../rfd/0039-unscored-chart-results.md)에 따라 전체 이론 가중치 합이 0인 유효한 차트도 재생을 허용한다. 바디의 실제 시작·유지·완료·실패와 원인 Miss는 그대로 처리하며 자동 점수를 만들지 않는다.

이 차트의 플레이 중 달성률과 결과의 달성률·랭크는 표시하지 않는다. `ScoreManager`의 내부 분모 0 계산값 0·F를 결과로 노출하거나 100%·SSS로 대체하지 않는다. 새 테스트 플레이와 공식 결과 모두 최종 이론 가중치가 0일 때 비율·랭크 영역을 숨긴다. 구현·실행 검증은 후속 PR에서 기록한다.

기준은 전체 이론 가중치이며 아직 정산한 항목이 없어 실시간 분모만 0인 상태와 구별한다. 점수 항목이 있는 차트에서 모든 항목을 놓쳤다면 기존대로 0%·F다. Full Combo의 기존 Miss 기준은 바꾸지 않는다.

### 랭크 (Rank)

| 랭크  | 달성률 기준 |
| ----- | ----------- |
| **SSS** | ≥ 99.5%   |
| **SS**  | ≥ 99.0%   |
| **S**   | ≥ 97.0%   |
| **AAA** | ≥ 95.0%   |
| **AA**  | ≥ 90.0%   |
| **A**   | ≥ 85.0%   |
| **B**   | ≥ 80.0%   |
| **C**   | ≥ 70.0%   |
| **D**   | ≥ 60.0%   |
| **F**   | < 60.0%    |

**10단계 랭크를 채택한 이유**: SSS～F의 10단계는 유저의 성장 과정에서 충분한 중간 목표를 제공한다. SSS(99.5%)는 사실상 올퍼펙에 가까운 달성도이며, F(60% 미만)는 차트를 완주했지만 대부분의 노트를 놓친 상태를 나타낸다. 90%대에 AAA/AA/A 세 단계를 두어, 중급～상급 유저의 미세한 성장도 가시적으로 반영한다.

**랭크 산출은 달성률 단일 기준**: 달성률 하나만으로 랭크가 결정되며, 시스템이 단순하고 직관적이다.

### 달성률·랭크와 `flightRule`의 관계

달성률·랭크와 `flightRule`(클리어/실패)은 **서로 다른 축**이다(RFD 0001).

- **달성률·랭크**: 연주 정확도의 측정. `flightRule`과 무관하게 산출된다.
- **`altitude`·클리어/실패**: `flightRule`의 상태. 달성률이나 랭크를 대체하지 않는다.

`flightRule`의 클리어/실패는 랭크 산출에 영향을 주지 않는다. [RFD 0022](../rfd/0022-flight-difficulty-names-and-visuals.md)의 `Liftoff / Infiltration / Breakthrough` 이름·연출 배치는 점수 가중치를 변경하지 않는다. 종전 `Survival`의 Perfect-only 회복 규칙은 새 단계에 자동 승계하지 않으며, 세부 고도 규칙과 실패 시 기록 정책은 [PRD §12](../prd.md#12-미정-사항)에서 추적한다.
