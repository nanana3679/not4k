# not4k — 노트 시스템

> 판정 규칙은 [RFD 0019](../rfd/0019-note-judgment-units-and-inheritance.md)와 [판정 사례 명세](note-judgment-cases.md)를 우선한다. 현재 채택 모델의 구현·통합 검증은 진행 중이다. 이행 상태는 [PRD §12](../prd.md#12-미정-사항)를 따른다.

## 현재 채택 판정 모델

- 롱노트는 single 1개, double 2개의 `unit`으로 해석하며, unit마다 시작·유지·종료 상태를 독립적으로 추적한다.
- 연결은 같은 레인에서 앞 `endBeat`와 뒤 `beat`가 정확히 같은 경우에만 성립한다. 판정 창, 10ms/1ms 오차, 프레임 시각으로 연결을 추정하지 않는다.
- head, 실제 release, 명시된 `holdOnly`만 score item이며 각각 weight 3이다. 일반 connection 성공은 점수·콤보 항목이 아니다.
- release는 실제 입력 시각에 따라 Perfect/Great/Good/Miss로 판정한다. `holdOnly`는 유지 성공 시 Perfect이며 keyup을 요구하지 않는다.
- 같은 unit 수의 연결 경계에는 head 또는 앞 노트의 `holdOnly`가 필요하다. unit 수가 바뀌는 경계는 둘 없이 허용한다.
- 양수 바디 끝과 별도 길이 0 롱노트의 동시 배치, 길이 0 롱노트의 head, `holdOnly`와 같은 시각의 Point는 금지한다.
- 양수 `trillLong + holdOnly`는 허용하지만 길이 0 `trillLong`은 head 유무와 관계없이 금지한다.

이 문서는 not4k의 각 노트 타입의 메커니즘, 설계 의도, 시각적 요구사항을 정의한다.

> **핵심 원칙: 노트 타입과 입력방식은 다른 개념이다.**
>
> - **노트 타입**: 개념적으로 4종(싱글, 롱, 트릴, 더블)이며, 코드상 포인트 3종(single, double, trill) + 구간 3종(long, doubleLong, trillLong) = **6종**으로 구현. 모든 노트 타입은 Lv.1부터 등장할 수 있다.
> - **입력방식**: 다중키 바인딩 환경에서 노트 배치를 처리하는 방법(홀드 교대, 홀드 중 탭, 릴리즈탭, 홀드 트릴 등). 입력방식을 활용하는 패턴 조각(피스)은 `piece-definition.md`에서 정의한다.

## 1. 싱글 노트

### 메커니즘

- 레인에 바인딩된 키 중 아무 키 하나를 타이밍에 맞춰 누른다.
- 기존 4K 리듬게임의 일반 노트와 동일하다.

### 설계 의도

- 가장 기본적인 입력. 입문 등급(Lv.1~3)에서 게임의 대부분을 구성한다.
- 기존 4K 유저가 추가 학습 없이 즉시 플레이할 수 있는 진입점.

### 시각적 요구사항

- **파란색**(`#4488ff`), 1:5 비율의 옆으로 긴 **직사각형**. 트릴 노트(마름모)와 형태로 구분된다.
- 레인 배경색은 **검은색**.

### 판정

- Good 창 안의 가장 이른 적격 노트에 Perfect/Great/Good을 판정하고, 기한을 넘기면 Miss이다. Normal 창은 ±41/82/120ms, Easy는 ±50/100/150ms이며 Bad는 생성하지 않는다. 창 밖 입력은 그 노트를 소비하지 않는다.

## 2. 롱 노트

### 구조

롱노트는 시작점 S, 바디, 끝점 E를 가진 하나의 구간 엔티티이다. head는 같은 시작에 별도로 놓는 Point이며, single/double head와 single/double 바디를 조합할 수 있다.

바디는 single 1개, double 2개의 `unit`으로 유지·실패를 추적한다. 같은 레인의 바디 열린 구간은 겹치지 않고 내부에 Point를 배치하지 않는다. 이어진 바디 사이의 경계에는 Point를 놓을 수 있다. 판정 창이 겹치면 앞 release 대기와 뒤 시작 준비가 동시에 존재할 수 있다.

### 메커니즘

- 양수 바디는 자기 head·시작 down 또는 정당한 승계로 활성화한다. 임의의 raw held나 다른 독립 Point를 친 down은 시작을 대신하지 않는다.
- head 없는 미처리 시작은 down 하나를 소비하되 시작 점수는 없다. 이미 정당하게 준비한 unit은 새 시작 down을 가져가지 않는다.
- 첫 활성화는 길이와 관계없이 S+Good까지 허용한다. 초단 바디는 E 이후의 첫 활성화도 가능하다.
- 유지 키의 등록과 실제 release 권한을 분리한다. 물리 키를 unit의 고정 owner로 지정하지 않는다.
- 활성화한 unit의 유지 실패는 되돌리지 않는다. 같은 timestamp의 실제 입력 인과관계를 반영한 다음 부족을 확인한다.

### 홀드 교대 (Hold Succession)

정확히 맞닿은 바디에서 유효한 다음 head·미처리 시작을 처리하면 다른 키로 이어갈 수 있다. 동일 키의 유효한 재타격에도 같은 연결 보정을 적용한다. 바디 중간의 임의 재누름은 실패한 unit을 복구하지 않는다.

`o-o-`는 A를 계속 유지하면서 중간 head를 B로 탭하거나, 경계에서 A를 떼고 B로 이어가는 두 방식으로 처리할 수 있다. `d=d=`도 두 키 유지와 별도 head 입력, 두 몫의 교대를 모두 지원한다.

교대에 쓰일 수 있는 up과 뒤 실제 release 창이 겹치면 용도가 확정될 때까지 보류한다. 유효한 교대 몫만큼 적격 up을 발생 순서로 배정하며, 동일 키라는 이유로 후순위 up을 먼저 보정하지 않는다. 교대용 up은 뒤 release에 소비하지 않는다. 구체적인 시각·등급은 [NJ-R04~R14](note-judgment-cases.md#nj-r04)를 따른다.

### 시각적 요구사항

- 싱글 롱노트 바디: **옅은 파란색**(`#88bbff`).
- 더블 롱노트 바디: **옅은 노란색**(`#ffee88`).
- 트릴 롱노트 바디: **옅은 회색**(`#aaaaaa`). 헤드(별도 트릴 노트, 흰 마름모)와 끝(`end cap`)이 모두 **트릴 노트와 같은 마름모** 형태이며, 끝 마름모는 **어두운 색**(`#6a6a6a`)이다. 바디는 끝점 쪽·머리 쪽 양 끝을 각각 **10px씩 줄여**, 두 마름모가 캡처럼 드러나게 한다. 줄여서 바디 높이가 0 이하가 되는 매우 짧은 트릴 롱노트는 바디를 생략하고 끝 마름모만 남긴다.
- 바디 유지 실패 시: 바디가 **회색**(`#555555`)으로 변한다. 이때 헤드(컨테이너), 바디, 터미널 캡, 코어 모두 **무채색 계열**로 전환되어 실패 상태를 명확히 전달한다. 코어는 기존 dimmed(어두운 적갈색)와 구분되는 **무채색 dimmed**(`#1a1a1a` ~ `#3a3a3a`)로 표시된다. 전환은 비가역적이며, 에셋 상세 규칙은 `assets-lab/spec.md`의 "노트 상태별 에셋 규칙 > 롱노트 실패 상태"를 참고한다.
- 바디는 **가로 그라데이션**으로 렌더링한다 — 가장자리가 70% 밝게, 중앙이 원색.
- **유지 중(held) 시각**: 롱노트 머리가 판정선에 닿으면 바디가 held(불 들어온) 표현으로 전환되어 현재 유지 중임을 알린다.
- **이어진 롱노트 전파**: 같은 레인에서 앞 롱노트의 끝과 뒤 롱노트의 시작이 맞닿은 연결(`o-o-`)에서는, 앞 롱노트가 held인 동안 뒤따르는 연결 롱노트도 held로 표시한다 — 연속 홀드를 시각적으로 반영한다. 끝-시작이 벌어진 비연결(`o- o-`)에서는 전파하지 않으며, 앞 롱노트가 유지 실패/Miss이면 연속 홀드가 끊긴 것이므로 전파하지 않는다. 연결의 정의(같은 레인 + 앞 endBeat와 뒤 beat의 정확한 일치)는 판정의 "`connection` 판정"과 동일하다.
- 롱노트의 양 끝은 **캡**으로 마감한다 — 끝점의 `end cap`과 시작점의 `start cap`. 각 캡은 노트 높이의 절반(10px)이며, `start cap`은 `end cap`을 상하반전한 형태다. 이는 롱노트 **자체**의 시작점·끝점 시각 마감으로, 시작점에 별도로 배치하는 **헤드 노트**(일반 노트)와는 다른 요소다.
- 길이 0 등 매우 짧은 롱노트에서는 두 캡이 바디를 거의 다 덮어 가운데 코어(심지)가 가려지므로, 캡 사이에 최소 **5px**의 코어가 보이도록 캡 높이를 줄인다.
- 헤드 노트가 시작점에 배치된 경우, 해당 노트는 자신의 타입(싱글/더블/트릴)에 따른 색상과 형태로 표시된다.

### 시각적 무구분 원칙

롱노트는 **어떤 키에서 시작되었는지를 시각적으로 구분하지 않는다.** 즉, "A로 시작한 롱노트"와 "B로 시작한 롱노트"의 시각적 표현이 동일하다.

이유:

- 홀드 교대를 자연스러운 플레이로 만들기 위해서는, 유저가 "이 롱노트는 A로 시작했으니 A로 유지해야 한다"라는 제약을 인지하지 않아야 한다.
- `A(hold) + B(tap)` 플레이와 `A(release) + B(hold)` 플레이가 모두 유효하고 자연스러워야 하며, 시각적 단서가 한쪽을 유도하지 않아야 한다.
- 예: `-o-` 배치에서, 유저가 `a-`와 `b-`로 홀드를 이어잡았는지(홀드 교대) `a---`를 유지하면서 `..b.`를 탭했는지(홀드 중 탭)를 게임이 시각적으로 구분하지 않는다. 어떤 입력방식을 사용하든 화면에 보이는 결과는 동일하다.
- 유저는 자신의 손가락 상태에 따라 어떤 키로든 롱노트를 유지할 수 있으며, 이것이 "가변 손배치"의 연장선이다.

### 판정

#### head와 활성화

head는 자기 Point 점수 항목을 판정하면서 담당 unit의 시작도 제공한다. double head는 서로 다른 두 물리 키를 요구한다. 두 held가 반드시 겹칠 필요는 없다.

- double head + double 바디는 unit별로 시작한다.
- single head + double 바디는 한 unit의 시작을 제공한다. 다른 unit에는 자기 시작 down 또는 승계가 필요하다.
- double head + single 바디는 첫 성공으로 활성화하고 두 성공 키를 모두 등록한다.
- 이미 건강하게 승계한 바디는 별도 head Miss만으로 실패하지 않는다.
- head Miss로 종속 unit이 시작하지 못하면 해당 끝점의 원래 점수 항목은 0점으로 함께 정산하고, 끝점에서 추가 Miss 효과를 내지 않는다.

#### 유지·끝점·실패

등록된 키 수로 활성 unit의 유지를 충족한다. 부족한 unit만 실패하며 건강한 나머지는 계속 유지할 수 있다. 실패한 같은 unit은 다시 시작하지 않지만, 뒤의 구분되는 새 바디에는 자기 시작 기회가 있다. 실패한 바디를 건너뛰어 오래된 head의 늦은 입력을 전달하지 않는다.

| 일반 경계 | 실제 release 수 | 뒤 시작 |
|---|---:|---|
| single → single | 0 | 정당한 승계 또는 새 head·시작 |
| single → double | 0 | 승계로 채우지 못한 증가분에 시작 필요 |
| double → single | 1 | 남은 몫이 계속 유지 |
| double → double | 0 | 두 몫을 승계하거나 필요한 몫을 새로 시작 |
| 마지막 끝 | 바디 unit 수 | 다음 바디 없음 |

일반 연결 성공에는 점수·콤보·고도 회복이 없다. 명시된 `holdOnly`는 앞 바디 unit 수만큼 상태 판정을 만들므로 double → single에서도 Perfect 두 개가 가능하다.

실제 release는 준비·창·누름의 권한을 충족한 가장 이른 끝 하나에만 소비한다. 일반 여분 up은 소비하지 않으며, 앞에 남은 종료 요구도 여분 계산에 포함한다. 한 up의 권한을 다시 쓰지 않는다. 같은 물리 키라도 유효한 새 head·미처리 시작으로 얻은 새 누름의 권한은 유효하다. 임의 재누름은 새 권한을 만들지 않는다.

#### 키 수 변화와 분할 release

일반 `=-=-`는 감소마다 실제 up 하나를 요구한다. 이른·늦은 정상 실행의 필수 입력 수는 같다([NJ-R01](note-judgment-cases.md#nj-r01)). 감소 `holdOnly`에서는 실제 키 수를 줄이지 않아도 되며, 남은 등록 키를 뒤 증가에 승계할 수 있다.

`o-=`는 single에서 double로 바뀌는 경계에 head가 없는 표현이다. 늘어난 미처리 unit은 별도 시작 down을 요구하되, 앞의 성공한 head나 `holdOnly`로 이미 정당하게 준비한 몫은 승계할 수 있다. raw held 두 개만으로 시작을 생략하지 않는다.

double의 두 실제 release는 각 창 안에서 나누어 처리할 수 있다. 점수 항목 수는 실제 head·감소·마지막 release·명시된 `holdOnly`를 차트에서 계산하며, 모든 연결 끝에 두 점수를 만드는 방식은 사용하지 않는다.

### 설계 의도

- 기존 4K 리듬게임의 롱노트 경험을 유지하면서, 다중키 바인딩 환경에서의 플레이 자유도를 보장한다.
- 홀드 교대는 홀드 중 탭 입력방식의 전제 조건이며, 이것이 없으면 롱노트가 한 손가락을 완전히 묶어버려 같은 레인에서의 추가 입력이 극도로 불편해진다.
- 연결 경계의 Good 창 안에서 유효한 다음 입력과 교대 up을 함께 해석하므로, 두 입력이 완벽하게 동시일 필요는 없다.

## 3. `trillZone`과 트릴 노트

### `trillZone`

`trillZone`은 트릴 노트가 등장할 수 있는 **시각적 영역**이다. 롱노트처럼 레인 위에 시작점과 끝점을 가진 구간으로 표시된다.

- **`trillZone` 자체는 아무 입력을 요구하지 않는다.** 구간이 표시되는 것만으로는 판정이 발생하지 않는다.
- **트릴 노트는 `trillZone` 안에서만 등장할 수 있다.** `trillZone` 밖에 트릴 노트가 단독으로 존재할 수 없다.
- **`trillZone`에는 트릴 노트만 등장할 수 있다.** `trillZone` 안에 싱글 노트나 더블 노트가 배치될 수 없다.
- **빈 틱에서의 입력은 구간 밖과 동일하게 동작한다.** `trillZone` 내 빈 틱(`~`)에서의 입력은 `trillZone` 밖의 빈 틱(`.`)에서의 입력과 결과가 같다. `trillZone`이 있든 없든 차이가 없다.

`trillZone`의 역할:

1. **예고**: `trillZone`이 낙하해오는 것을 보고 유저는 "곧 트릴 입력이 시작된다"는 것을 미리 인지할 수 있다. 트릴 노트가 갑자기 등장하는 것이 아니라, 구간이 먼저 시야에 들어오므로 손배치를 준비할 시간이 생긴다.
2. **시각적 구분**: `trillZone`은 일반 구간과 시각적으로 다르게 표현되므로, 유저가 "이 레인은 지금 트릴 모드다"라는 것을 즉시 인지할 수 있다.
3. **긴장도 유지**: `trillZone`이 지속되는 동안, 트릴 노트가 실제로 등장하지 않더라도 유저는 "언제든 트릴이 올 수 있다"는 긴장 상태를 유지해야 한다. 이것은 트릴 노트의 등장 여부 자체를 읽기의 대상으로 만들며, 입력 없이도 인지적 부하를 생성한다.
4. **시각적 다양성**: 고난이도 차트에서 트릴 노트가 없는 빈 `trillZone`을 배치할 수 있다. 입력을 요구하지 않지만 레인의 시각적 분위기를 변화시켜, 차트의 시각적 표현력을 확장한다.

### 트릴 노트

#### 메커니즘

- `trillZone` 안에 배치되는 노트. **직전에 입력한 키와 다른 키**를 눌러야 한다.
- 바인딩된 키가 2개(A, B)일 때: `A B A B` 또는 `B A B A`로 처리한다.
- 첫 노트는 어떤 키로든 시작할 수 있다. 이후 노트부터 교대가 강제된다.

#### 교대 판정의 세부 규칙

교대 세트에는 해당 `trillZone`에서 head를 소비한 키만 등록한다. raw down, 바디 유지·승계, release 키는 추가하지 않는다. head Miss는 해당 구간의 이전 세트를 비운다. 구간의 귀속은 입력 도착 시각이 아닌 노트의 차트 위치를 따른다.

같은 timestamp의 여러 적격 트릴 head 입력에서는 최고 타이밍 등급 하나만 교대를 인정하고 나머지는 `goodTrill`이다. 하나의 down을 여러 head에 소비하지 않으며 수집 순서에 따라 후속 결과가 달라지지 않아야 한다.

#### 3키 이상 바인딩에서의 트릴

레인에 3개 이상의 키가 바인딩된 경우, 트릴은 2키 교대에 한정되지 않는다. 이것은 차트의 확장성과 입력의 용이함 때문이다.

- **3박자 기반 트릴 (24비트 등)**: 3키 교대(`A → B → C → A → B → C`)가 2키 교대보다 자연스럽다. 2키로 3박자 트릴을 처리하면 강약 패턴이 불균일해지지만, 3키는 각 박에 다른 손가락을 배분할 수 있다.
- **32비트 고속 트릴**: 4키 교대로 처리하면 각 손가락의 부담이 분산되어 물리적 한계가 높아진다.
- **차트 설계의 전제**: 차트 디자이너가 3박자 트릴이나 고속 트릴을 배치하려면, 유저에게 그것을 처리할 수단이 있어야 한다. 3키 이상 바인딩의 허용은 이러한 차트를 제공하기 위한 전제 조건이다.

### 트릴 롱노트

트릴 head와 single 바디를 조합한다. head는 교대를 판정하고 바디는 일반 롱노트의 시작·승계·실제 release 규칙을 따른다. `goodTrill`은 head에만 적용한다.

모든 `trillLong`에는 trill head가 필요하다. 양수 길이 `trillLong + holdOnly`는 허용한다. 길이 0에는 head를 붙이지 않으므로 길이 0 `trillLong`은 금지한다. 바디 유지 키가 바뀌어도 다음 트릴의 교대 기준에는 head를 소비한 키만 반영한다.

### 설계 의도

이 노트 타입의 존재 이유는 **가변 손배치의 점진적 학습**이다.

DJMAX 5B의 핵심 문제는 가변 손배치가 고난이도의 레이저 패턴(중앙 레인 종연타)에서만 강제된다는 것이다. 저난이도 유저는 가변 손배치를 경험할 기회가 없고, 고난이도에 도달했을 때 급격한 난이도 상승을 경험하게 된다.

트릴 노트는 노트 밀도가 낮은 초급 차트에서도 배치할 수 있다. 이를 통해 초급 유저가 "한 레인에서 두 개의 키를 교대로 사용한다"는 가변 손배치의 기본 감각을 자연스럽게 학습한다.

또한 트릴 노트는 인식 난이도 관리의 핵심 장치이기도 하다. "이 구간에서는 키를 교대해야 한다"는 것이 노트 타입 자체에 의해 시각적으로 명시되므로, 유저가 실시간으로 "어떤 키로 칠까"를 판단해야 하는 인지 부하가 줄어든다.

### 시각적 요구사항

`trillZone`과 트릴 노트는 별도의 시각 요소로 표현되어야 한다.

**`trillZone`**:

- **반투명 초록색**(`0x00ff88`, 15% 불투명도) 영역으로 레인 위에 시작~끝 범위를 표시한다. 롱노트와 즉시 구분된다.
- 영역의 세로 범위는 같은 시작/끝 박의 **롱노트 바디와 같은 위치·길이**로 표시한다.
- 빈 `trillZone`(노트 없음)도 시각적으로 존재감이 있어야 한다.

**트릴 노트**:

- 싱글/더블 노트와 동일한 1:5 직사각형에 **내접하는 마름모(◇)** 형태. **흰색**으로 표현한다. 마름모만 그리며, 마름모를 **감싸는 어두운 사각형 배경은 두지 않는다**(투명).
- 교대 실패 시 판정 표기 `goodTrill`의 ◇가 트릴 노트의 형태를 직접 가리키므로, 유저가 "이 Good은 트릴에서 나온 것"임을 시각적으로 연결할 수 있다.

### 판정

Good 창 안에서 교대에 성공하면 Perfect/Great/Good을 판정한다. 교대 실패는 `goodTrill`(1점)이며 독립 표시·집계를 제공한다. head Miss는 해당 구간의 세트를 비운다.

### 다중 레인 트릴의 독립성

교대 상태는 차트상 `trillZone`별로 독립적이다. 이전 구간의 늦은 head는 이전 구간에, 다음 구간의 이른 head는 다음 구간에 기록한다. 새 구간 첫 노트는 이전 구간에서 쓴 키 때문에 `goodTrill`이 되지 않는다. 세부는 [경계 입력 설명](../context/trill-boundary-input.md)을 따른다.

### 더블 트릴 노트가 존재하지 않는 이유

더블 노트(`D`)와 트릴 노트(`t`)를 결합한 "더블 트릴 노트"는 정의하지 않는다.

더블 노트는 한 레인에서 서로 다른 키 2개를 동시에 입력한다. 트릴 노트는 "직전에 입력한 키와 다른 키"를 요구한다. 더블 트릴을 가정하면 **직전 키의 특정이 불가능**하다는 문제가 발생한다.

예시: 키 A, B, C가 바인딩된 레인에서 더블 트릴 `{Dt t}`을 가정한다.

- 유저가 첫 `Dt`에서 A+B를 동시에 누르려 했으나, 미세한 시간차로 A → B 순서로 입력이 들어온 경우
- 시스템은 "직전 키 = B"로 판단하여, 다음 트릴 노트 `t`에서 B를 입력하면 교대 실패로 처리한다
- 그러나 유저는 A+B를 동시에 눌렀다고 인지하므로, 다음 `t`에서 A를 눌러도 B를 눌러도 "교대했다"고 느낀다
- 이러한 입력 순서의 비결정성이 트릴 교대 판정을 신뢰할 수 없게 만든다

레인당 2키 기본 체계에서는 더블 노트가 이미 모든 키를 사용하므로 교대할 키가 남지 않는다는 물리적 제약도 존재한다.

## 4. 더블 노트

### 메커니즘

- 하나의 레인에 바인딩된 **서로 다른 키 2개**를 동시에 누른다.
- 같은 키를 두 번 누르는 더블클릭은 더블 노트로 인정되지 않는다.
- 키 바인딩이 3개 이상인 레인에서는 바인딩된 키 중 **서로 다른 아무 2개**를 사용할 수 있다.
- 4레인 게임이지만 최대 8키의 동시입력이 가능해진다.

### 설계 의도

더블 노트는 두 가지 역할을 수행한다.

**1) 임팩트 노트로서의 역할**: maimai의 Break 노트, 프로젝트 세카이의 임팩트 노트처럼, 리듬의 강조점에서 다른 무게감을 가진 입력을 요구한다. 별도의 노트 타입을 새로 만드는 것이 아니라, "한 레인에 2개의 키를 동시에 누른다"는 기존 메커니즘의 자연스러운 확장으로 구현한다.

**2) 플레이 다양성의 확장**: 기존 4키 게임에서는 동시입력이 최대 4개(4레인 동시치기)였지만, 더블 노트를 통해 최대 8개의 동시입력이 가능해진다. 이는 차트 디자이너에게 새로운 표현 공간을 제공한다.

### 시각적 요구사항

- **노란색**(`#ffcc00`), 싱글 노트와 동일한 1:5 비율의 옆으로 긴 **직사각형**. 색상으로 싱글 노트(파란색)와 즉시 구분된다.
- **부분 입력 피드백**: 더블 노트(및 더블 롱노트 헤드)에서 2개 중 1개만 입력되고 나머지 1개를 기다리거나 놓쳤을 때, 노트가 **50% 불투명도**로 변한다. 유저가 "1개는 눌렀지만 나머지 1개를 놓쳤다"는 것을 즉시 인지할 수 있으며, 2개 모두 성공한 경우의 이펙트와 명확히 구분된다. 처리 완료 후의 노트 숨기기를 포함한 전체 가시성 규칙은 `game-core.md`의 "플레이 중 노트 가시성"을 참고한다.
- **부분 입력 코어 dim**: 50% 불투명도와 함께, 입력을 기다리고 있다는 의미로 **한쪽 코어만 꺼진(dimmed) 상태**로 표시된다. 좌우 대칭 원칙에 따라 레인 1, 2에서는 왼쪽 코어(`dimLeft=true`)가, 레인 3, 4에서는 오른쪽 코어(`dimRight=true`)가 꺼진다. 이는 숏 노트와 롱노트 헤드 모두에 적용된다. 에셋 상세 규칙은 `assets-lab/spec.md`의 "노트 상태별 에셋 규칙 > 더블 노트 부분 입력 상태"를 참고한다.

### 판정

더블 노트는 **독립된 싱글 판정 × 2**로 처리한다. 두 입력은 개별적으로 판정되며, 각각 다른 판정 등급을 받을 수 있다 (예: 첫 번째 입력이 Perfect, 두 번째 입력이 Great).

#### 더블의 미처리 슬롯과 다음 입력

double에 이미 사용한 물리 키는 그 double의 남은 head를 소비할 수 없다. 따라서 `double 1000 → single 1100`에서 A가 앞 double의 첫 슬롯을 처리한 뒤 다시 A를 누르면, 남은 double 슬롯을 건너뛰고 창 안의 다음 적격 대상을 탐색한다. 다른 키 B라면 앞 double의 남은 슬롯이 우선이다.

두 번째 슬롯을 즉시 Miss로 닫지 않는다. 자기 Good 기한까지 서로 다른 키 입력을 받을 수 있다. 일반적으로 앞의 적격 노트가 입력을 먼저 소비하는 원칙은 유지된다.

## 입력방식: 노트 배치의 처리 방법

다중키 바인딩 환경에서 발생하는 고유한 입력 처리 방식이다. 입력방식은 피스(패턴 조각)의 상위 개념이며, 하나의 입력방식이 여러 피스에서 활용된다. 입력방식의 정의는 `glossary.md`를, 이를 활용하는 피스(PP-000 체계)는 `piece-definition.md`를 참고한다. 여기서는 노트 시스템과 직접 관련된 핵심 입력방식의 메커니즘만 서술한다.

### 릴리즈탭 (Release-Tap)

#### 메커니즘

- 한 레인에서 롱노트가 끝날 때, 유지하던 키(A)를 떼면서 같은 레인의 다른 키(B)를 누르는 배치. 키 A, B가 바인딩되어 있을 때: `A(hold) → A(release) + B(press)`로 처리한다.
- 롱노트의 릴리즈 시점에 같은 레인에 싱글 노트가 동시에 등장하는 것으로 표현된다.

#### 설계 의도

릴리즈탭은 **트릴 입문 전 단계의 키 교대 학습 장치**이다.

트릴 노트는 일정한 간격으로 키 교대를 반복해야 하므로, 유저에게 "리듬 유지 + 교대"라는 두 가지 부담을 동시에 준다. 릴리즈탭은 이 중 **교대만을 단 한 번 요구**한다. "다른 키를 사용해야 한다"는 감각을 최소한의 복잡도로 체험시킬 수 있다.

not4k에서만 가능한 입력방식이다. 기존 4키 게임에서는 한 레인에 키가 1개이므로, 롱노트 릴리즈와 동시에 같은 레인에 싱글 노트를 배치하는 것이 불가능하다.

#### 시각적 요구사항 `[미구현]`

- 롱노트 끝과 싱글 노트가 같은 타이밍에 존재한다는 것이 명확해야 한다.
- 롱노트의 실제 release item과 싱글 Point score item은 독립적으로 정산되며, release는 실제 입력 시각 등급을 유지한다.

### 홀드 트릴 (Hold Trill)

#### 메커니즘

- 짧은 롱노트가 빠르게 연속으로 이어지는 배치(`o-o-o-o-`). 경계 head를 별도 탭하거나 유효한 교대로 이어갈 수 있다.
- 홀드 교대(ABAB 교대) 또는 홀드 중 탭으로 처리할 수 있다. 빠른 연속에서는 홀드 교대가 유리하다.

#### 설계 의도

홀드 트릴은 릴리즈탭에서 앵커로 이어지는 중간 단계이다. 릴리즈탭이 "키 교대를 단 한 번 체험"시키는 것이라면, 홀드 트릴은 "키 교대의 연속적 반복"을 요구한다. 트릴 노트와 달리 일반 연결 자체에는 별도 점수가 없지만 바디 유지가 필요하다.

#### 시각적 요구사항 `[미구현]`

- 짧은 롱노트의 연속으로 표현되므로, 롱노트 바디가 충분히 짧아 시각적으로 트릴 느낌이 전달되어야 한다.

### 홀드 중 탭 (Tap-in-Hold)

#### 메커니즘

- 한 레인에 바인딩된 키가 A, B일 때, A로 롱노트를 유지하면서 B로 싱글 노트를 처리한다.
- 같은 레인에서 이어진 바디의 경계에 별도 single head를 배치한다. 하나의 바디 열린 구간 안에 Point를 겹쳐 배치하지 않는다.

홀드 교대(2번 롱노트 참고)에 의해 여러 처리 방식이 가능하다:

```
홀드 중 탭: A(hold 유지) + B(tap)
  → A가 롱노트를 유지한 채, B로 싱글 노트를 처리
  → 가장 직관적인 방식

홀드 교대: A(hold) → A(release) + B(hold) → B(release) + A(hold)
  → 롱노트 유지 중 키를 번갈아 이어받는 방식
  → 유효한 경계 head·시작 입력으로 연결을 성립시킴
  → 두 손가락을 번갈아 사용하여 물리적 부하를 분산
```

어떤 방식으로 처리하든 롱노트는 시각적으로 동일하게 표시되며(시각적 무구분 원칙, 2번 참고), 유저는 자신에게 편한 방식을 선택할 수 있다.

#### 설계 의도

츄니즘에서 한 레인 위에 롱노트가 진행되는 동안 같은 영역에서 싱글 노트를 처리하는 패턴이 가능하다. 이것은 물리적 칸막이가 없는 슬라이더이기에 가능한 것이지만, not4k는 다중키 바인딩과 홀드 교대로 PC 키보드 환경에서 동일한 경험을 제공한다.

이것은 IIDX의 Charge Note가 한 손가락을 묶어두고 나머지로 처리하게 만드는 것의 "레인 내" 버전이다. 기존 4키 게임에서는 불가능했던 레인 내 복합 입력이 가능해지며, 차트 디자이너에게 완전히 새로운 표현 공간을 제공한다.

#### 시각적 요구사항 `[미구현]`

- 롱노트 진행 중에 등장하는 싱글 노트가 별개의 입력임을 명확히 표현해야 한다.
- 츄니즘의 접근 참고: 롱노트 위에 겹쳐서 표시되되, 색상이나 형태로 구분
- 단, 롱노트 자체는 어떤 키에서 시작되었는지 구분하지 않는다(시각적 무구분 원칙)

#### 판정

- 롱노트 유지 중 싱글 노트를 처리하지 못하면: 롱노트 판정에 영향을 주지 않는다 (독립 판정).
- 유지하던 키를 떼면 유효한 경계 교대인지 실제 release인지 구분한다. 두 조건을 충족하지 못한 유지 부족은 해당 unit의 실패이다.
- 홀드 중 탭과 홀드 교대의 판정이 동등해야 한다 (특정 플레이 방식에 유불리가 없어야 함).

### 헤드 없는 롱노트

양수 일반 바디와 `holdOnly`의 독립 시작은 자기 Good 창의 down을 요구한다. 시작 점수는 없으며 정당한 승계가 준비한 unit은 추가 down을 소비하지 않는다. 길이 0 일반 release도 유효한 선행 down으로 준비한 뒤 적격 up을 요구한다. 길이 0 `holdOnly`만 기존 held 상태를 공유한다.

## Grace 플래그

### 정의

Grace는 Point(single/double/trill)에 부여하는 타이밍 면제 플래그이다. Good 창 안의 유효한 입력은 Perfect이며, 기한을 넘기면 Miss이다. FAST/SLOW를 집계하지 않는다.

### 메커니즘

- 다른 Point와 같은 가장 이른 적격 대상 매칭 및 물리 키 조건을 따른다.
- Good 밖의 입력은 해당 head를 소비하지 않는다. Bad 단계는 없다.
- 트릴 교대는 면제하지 않으므로 Grace trill의 교대 실패는 `goodTrill`이다. 이 경우에도 FAST/SLOW는 집계하지 않는다.

### 설계 의도

not4k는 타이밍 정밀도보다 손배치 인식이 핵심 난이도인 게임이다(`overview.md` "난이도 철학" 참고). 손배치 전환이 복잡한 구간에서 타이밍 부담까지 동시에 요구하면 난이도가 불합리하게 치솟는다. Grace 노트는 타이밍 부담을 제거하여, 유저가 "어떤 손으로 칠 것인가"라는 인식 판단에 온전히 집중할 수 있게 하는 균형 도구이다.

### 시각적 요구사항 `[미구현]`

- Grace 플래그가 설정된 노트는 일반 노트와 **색상으로 구분**한다. 기존 노트와 같은 형태(직사각형/마름모)이되, 색상이 다르다.
- maimai의 Break 노트(빨강/노랑)나 츄니즘의 ExTAP(황금색)처럼, 형태가 아닌 색상으로 "이 노트는 특별하다"를 전달하는 접근이다.
- 구체적인 색상은 스킨 시스템 확정 후 결정한다.

### 활용 시나리오

- **곡의 하이라이트 강조**: 클라이맥스에 배치하여 유저가 타이밍 부담 없이 임팩트 순간에 집중할 수 있게 한다.
- **손배치 전환 구간**: 수평 이동, 가변 분할 등 인식 난이도가 높은 구간에서 타이밍 부담을 제거한다.
- **학습 보조**: 새로운 입력방식(트릴, 더블 등)이 처음 등장하는 구간에서 "일단 입력하기만 하면 성공"이라는 경험을 제공한다.

### 상세 리서치

기존 리듬게임의 사례(츄니즘 ExTAP, maimai 슬라이드, osu! 슬라이더 등)와 구현 방안 비교는 `../research/auto-best-judgment-note.md`를 참고한다.

## `holdOnly` 롱노트

`holdOnly`는 끝의 release를 유지 상태 Perfect/Miss로 면제한다. 양수 길이는 정당한 시작·승계와 등록 키 유지가 필요하다. E까지 유지하거나 E−Good부터 유효하게 이른 완료를 하면 Perfect이며, S+Good까지의 늦은 첫 활성화도 허용한다. 상태 완료는 up을 소비하지 않고 FAST/SLOW를 만들지 않는다.

감소하는 double의 `holdOnly`는 두 unit을 각각 판정한다. 두 키를 계속 잡아도 되고, 면제 몫은 뒤 single release의 여분 계산에서 제외한다. 면제 몫을 뒤 double 증가에 사용하면 새 double의 실제 release 두 개가 다시 필요하다. 점수 상태 완료와 종료·승계 배정은 별도이며 고정 owner를 만들지 않는다([NJ-H01~H07](note-judgment-cases.md#nj-h01)).

길이 0 `holdOnly`는 S−Good부터 기존 held를 확인한다. 계속 유지하면 S에 표시하고 유효한 이른 up이면 그 시점에 처리한다. down/up을 소비하거나 독립된 일반 release 권한을 새로 주지 않는다. double은 서로 다른 두 키를 요구하되 두 held가 겹칠 필요는 없다.

같은 레인·시각의 `holdOnly`와 Point는 금지한다. 양수 바디 끝에 별도의 길이 0 range를 붙이지 않는다. 마커는 `*`이며 Grace와 시각 언어를 공유하지만 타이밍 면제와 release 면제는 별개이다.

## 노트 타입의 등장 원칙

**모든 노트 타입은 가장 쉬운 레벨(Lv.1)부터 등장한다.** 난이도에 따라 변하는 것은 등장 여부가 아니라 빈도와 복합도이다.

```
Lv.1~3 (입문):   싱글 90%↑ / 트릴·더블·홀드 교대·홀드 중 탭 극소량으로 존재를 인지
Lv.4~6 (초급):   `trillZone`이 명확해짐 / 더블이 흐름에 삽입 / 홀드 교대·홀드 중 탭 비율 상승
Lv.7~10 (중급):  앵커 본격화 / 홀드 중 탭 비율 본격 상승
Lv.11~13 (상급): 모든 노트 타입과 입력방식이 높은 밀도로 복합 결합
Lv.14~15 (최상급): 기존 4키 게임에 존재하지 않는 차트 공간
```

이 원칙은 DJMAX 5B의 실패("저난이도에서 가변 손배치를 경험할 기회가 없다")를 반복하지 않기 위한 것이다. 가장 쉬운 곡에서도 멀티 바인딩이 필요한 노트(트릴, 더블)와 입력방식(홀드 교대, 홀드 중 탭)이 극소량 등장하여, 유저는 첫 곡부터 "이 게임은 기존 4키와 다르다"는 것을 체감한다. 난이도 상승은 새로운 노트 타입의 등장이 아니라, 인지적 부하(읽기 복잡도, 판단 요소 증가)와 신체적 부하(입력 밀도, 키 교대 빈도 증가)의 **비율 상승**으로 이루어진다.

> **노트 타입 등장과 입력방식 활용의 구분**: 위 표에서 "트릴·더블"은 노트 타입의 단독 등장이고, "홀드 교대·홀드 중 탭"은 입력방식의 극소량 배치이다. 입력방식의 본격 활용은 해당 패턴의 PLv.부터 시작된다. 예: 싱글과 롱노트는 Lv.1부터 등장하지만, 레인 내 분리(홀드 + 탭 공존) 패턴은 PLv.7부터 본격 활용.

자세한 레벨별 노트 구성 비율은 `difficulty-design.md`를 참고한다.
