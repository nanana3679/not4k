# 비행 연출 시연 — 세 난이도 가로 보기와 돌파의 사각뿔

저장 위치 안내 (2026-09-13): 현재 체크아웃에서는 세 난이도 공개 배경 비교와 아래의 돌파 광원+A~H 통합 비교를 실행할 수 있다. 그보다 이전 시연·이미지 탐색의 설명은 보존하고 실행 원본은 로컬 백업에 둔다. [저장한 파일 범위와 실행 방법](../../output/README.md)을 따른다.

2026-09-09. 사용자 피드백을 반영한 별도 시연 35의 현재 명세다. **최신 기본 화면은 원래 비정형 장갑 조각·대각 지지대이며 시점 고도·높이 증가·중앙 접근만 연결한다.** PNG·알파 윤곽·기존 합성 경로를 보존하고 새 구조물이나 렌더러를 추가하지 않는다. 낮은 고도에서 시점이 내려가고 구조물이 높아지며 설치 평면이 중앙에 접근한다. 충돌 판정은 없다. 사용자 선호 크기 10%·속도 1000%·직선, 지표면·천장 이미지 선택, 안쪽 광원, 중앙 레인과 아래 조절을 유지한다. 게임 본편에는 연결하지 않는다. 복원 결정은 [RFD 0025](../rfd/0025-original-obstacle-motion.md), 이전 시점·건축 탐색은 [RFD 0023](../rfd/0023-breakthrough-visual-clearance.md)과 [RFD 0024](../rfd/0024-breakthrough-architectural-modules.md)에 남긴다. 최종 수치와 제품 상태 대응은 [PRD §12](../prd.md#12-미정-사항)에서 추적한다.

## 세 난이도 공개 배경 비교 (2026-09-13)

[독립 공개 미리보기](../../output/prototypes/flight-background-preview-20260913/NOTES.md)는 `LIFTOFF`·`INFILTRATION`·`BREAKTHROUGH`를 한 페이지의 영어 탭으로 전환한다. 각 장면에는 `altitude` 슬라이더 하나만 표시하며 설명·버튼·다른 조절은 숨긴다. 장면을 떠날 때 현재 URL을 기억해 장면별 고도를 유지한다. 게임 본편과 판정·`flightRule`은 변경하지 않는다.

이륙은 오브젝트100%·Secondary15%·속도300%·시작 고도68%, 침투는 같은 오브젝트와 배색에 속도600%·시작 고도23%다. 둘 다 레인을 숨긴다. 침투는 별 없는 먹색·남색 구름층과 청보라 안개의 `sky-infiltration.png`, 이륙은 기존 `sky.png`를 쓴다. 이륙·침투의 잔광은 과거 프레임을 저장하지 않고 현재 절대 고도에만 비례하는 최대160개 절차적 선분이다.

이륙·침투의 수백 개 광원은 CPU의 개별 Canvas 호출 대신 WebGL 동적 정점 한 배치로 그린다. 지표면 원근 무늬도 GPU 삼각형 한 장으로 옮긴다. GPU 경로에서는 보이는 광원의 수와 원래 panel 형태를 유지하고 LOD 개수 제한을 적용하지 않는다. WebGL을 열지 못할 때만 Canvas 2D와 `high → balanced → reduced → minimal` 자동 품질 단계로 폴백한다.

돌파는 기존 Three.js 시연을 재사용한다. 속도1000%·먼 건축 배경의 재귀 확대300%·밝기10%·직선 광원·Secondary15%를 고정한다. F 건물과 구조 연장·입체 주변 건축·레인·가이드는 숨긴다. 배경 확대 속도와 밝기 조절은 표시하지 않지만 고도 슬라이더는 실제 돌파 상태를0~100%로 갱신한다.

서버는 로컬호스트에 바인딩하고 필요할 때 Cloudflare Quick Tunnel로 인터넷에 임시 공개한다. 실행 파일과 PNG만 허용하며 테스트·문서·상위 경로는 제공하지 않는다. 같은 실행 모듈을 Vite 개발 서버의 `/__lab/flight-background-preview/`에 마운트해 [Lab 미리보기 카탈로그](./lab-preview-catalog.md)의 `/lab/flight-background-preview`에서도 다시 찾을 수 있다. 단위201개와 1280×720·390×844 브라우저 검사24개에서 세 장면 전환, 고도 전용 UI, 동일 슬라이더 크기, 돌파 밝기10%·고도 변경, 이륙·침투 고도 렌더와 URL 반영, 장면별 고도 유지, 딥링크 복원, 키보드 조작, 빠른 연속 전환 후 장면 일치, 움직임 줄이기, 장면별 하늘 한 장 로드, 필수 자산 실패 안내, 비정상 요청 격리, 서버 보안 응답, Lab 하위 경로 마운트, 콘솔 오류와 넘침 없음을 확인했다. 자동화 수치는 실물 휴대폰 성능과 미술 최종 승인을 대신하지 않는다.


## 별도 A~H+돌파 절단면 광원 통합 비교 (2026-09-10)

기존 사각뿔 절단면의 삼각형·직선·잔상 연출 안에서 A~H8종을 선택하는 [독립 비교 시연](../../output/prototypes/breakthrough-hangar-integration-20260910/NOTES.md)을 제공한다. E 격납고 하나로 시작한 통합을8종 개별 비교로 확장했다. 위의 원래 기본 시연과 RFD 0025를 교체하지 않는다. 미술 검수는 사용자가 한다.

기존 `worldFaces()`·팔레트·윤곽선·전면 절단·전진 계산을 수정 없이 사용하며, 동일 초점거리·주점·카메라 높이를 Three.js에 맞춘다. E의 배치 중심은 화면상 왼쪽 외곽면의 A→가까운 배치점 경로와 일치하는 원근 경로를 따르며 건물 입체·UV·회전·배율은 고정된다. 광원의 유한한 사각뿔은 유지하고 건물의 출발 깊이는1600으로 연장한다. 화면 밖 통과 중에도 줄어들지 않는다. 기본 속도1000%의 전진량280/초와 광원 위치의 .956배를 건물에도 적용한다. 노트 참고 시간은 속도 배율과 독립이다.

불투명 건물 깊이를 광원·발광·세계 잔상이 함께 검사한다. 뒤의 빛과 잔상은 건물에 가리고 앞의 빛은 보인다. 잔상은 기존 감쇠와 cycle 보호를 사용하며, 수동 시점/도안/진행 변경 시 비우고 정지 시 위치·밝기를 유지한다. 발광은 기존 화면 blur 대신 깊이를 검사하는 약한 가장자리 발광이므로 기존 Canvas 픽셀과 동일하다는 보장은 하지 않는다.

8종은 하나씩 선택하고 현재 고도·거리·속도·광원과 재생 상태를 유지한다. 모델은 기존 원형과 크기를 유지하며100%에서 하단 높이 기준을 맞춘다. E의 기존 경로는 유지한다. `module`을 URL로 복원하며 기본은 E다. `중거리에서 보기`는 깊이160에서 정지해 전체 하단 형태를 비교한다. 저고도 지지부가 끊겨 보이는 사용자 피드백에 따라 E에는 아래의 선택 가능한 공간·하부 연결을 추가했다. 후속 요청으로 나머지7종에도 각 형태에 맞는 고정 연결부를 추가했다. 이어 높이에 용도가 읽히도록8종의 연결부를 실제 방·작업 데크·설비층이 붙는 수직 시설로 재구성했다. 원본 본체와 아래 구조 연장을 함께 표시한다.

기본은 크기10%·속도1000%·직선·잔상120ms, 최신 근접 시점이다. 기본 시작은 깊이1100의 작은 실루엣이며 안개650~1400으로 원거리 모습을 먼저 읽는다. 건물의 전체 반복은1000%에서 약7.47초다. 이전 A 상하 이동도 선택할 수 있다. 먼 곳부터 재생·근거리 정지·건물 표시 비교·고도0/50/100%·진행 정지·건물50~180%·삼각형/직선/혼합·광원0~100%·보조색 빈도·윤곽선·밀도·단면/A 조절·표면 그림·가이드·레인 참고선과 URL 복원을 제공한다. 16:9 화면 아래에 조절하며 움직임 줄이기를 따른다.

바닥/천장 그림·원래 장갑 장애물·8종 동시 혼합·본편 연결은 이 비교에 포함하지 않는다. 8종 선택 추가 후 단위74개·브라우저148개(기존63·원거리10·모델75) 통과, 페이지·콘솔·CSP 오류0개다. 초기 화면상 크기·실제 원거리 가시성·반복 순간을 함께 검증한다. 상세 결과·한계는 시연 기록, 다수 건물 최적화는 [후속 계획](../design/module-integration-plan-20260910.md)에 둔다.


### A~H 구조 연장과 E의 주변 건축 비교

`extensions=1`은 A~H에서 선택한 모델의 구조 연장을 켜고 `extensions=0`은 원래 길이로 비교한다. URL에서 생략하면 기존처럼 꺼진 상태다. `surroundings=1`의 원경과 뒤쪽 큰 골조는 E 전용이며, 다른 모델에서는 이 조절만 비활성화한다. E 복귀 때 선택을 유지한다. 건물 표시를 끄면 선택한 연결부도 숨기되 E 주변 건축은 남긴다.

원경12군락의48개 본체와36개 표시등은 두 인스턴스 메시로 묶고, 상하 몸통을 화면 바깥 방향으로 이어 열린 공극과 큰 스케일을 표현한다. 평면 바닥·천장 이미지를 씌우지 않는다. 뒤 골조는 E 후방에 놓고 연결보로 이어 붙인다. 원래8종 본체의 입체·문·창문은 변형하지 않는다. 외장 표면의 재질과 UV는 아래 공통 외장 기준을 적용한다.

연결부는 각 원본 고정부에서 모델 좌표 y=−640까지 이어진다. 긴 지지 축 주위에 사용 가능한 층을 묶어 배치하며, 같은 창문이나 띠만 반복하는 방식은 쓰지 않는다. 사람용 문 높이2.8과 약6단위 층고로 사람의 크기를 유지하며 H의 화물문은 폭2.8·높이3.4다. 상단 약−10~−150에 사용층을 집중하고 깊은 구간에는 드문 기능층과 긴 여백을 둔다. 창은 일부 방에만 켜며 작은 배관·난간을 촘촘히 추가하지 않는다.

층에는 실제 두께의 바닥과 뒤 벽·측벽을 두고, 열린 작업 공간은 입체적으로 비워 둔다. 층 묶음과 수직 축은 실제로 닿는다. 원래의 중정·갈래 통로·트러스 개구부를 보호한다. 새로운 층도 고정 입체이며 고도에 따라 늘이거나 화면에 맞춰 접지하지 않는다.

연결부8종은 초기 로딩 때 한 번 만들고 선택한 하나만 표시한다. 원래 본체의 치수·위치 기준은 유지하며 연결부가 같은 위치·회전·배율을 따른다. 외장 UV는 생성 시 공통 기준으로 맞춘 뒤 재사용한다. 고도·거리·모델 전환 때 다시 생성하지 않고 숨긴 모델까지 표면 그림 비교를 적용한다. 배경 그림·전진량·광원과 잔상을 초기화하지 않는다. 연결부도 같은 깊이 버퍼와 원경 그림에 맞춘 안개를 사용한다. 유한한 입체 구조를 깊은 공간으로 잇는 시연이며 실제 지표면·충돌·다수 건물 최적화를 구현한 것은 아니다.

최신 검증 결과는 [시연 기록](../../output/prototypes/breakthrough-hangar-integration-20260910/NOTES.md#용도-있는-수직-시설-2026-09-10)을 따른다. 실제 화면에서는8종×고도3단계의 연장 유무, 고도 양끝의 앞뒤 광원·잔상 가림, 최대180% 반복 경계, 모바일 조절과 정지·URL 복원을 확인한다. 새 층의 연결·실제 빈 부피·문 크기·성긴 점등은 단위 테스트로 검사한다.

모든 층은 기존 카메라·전진량과 깊이 검사를 공유한다. 원경은2200, E와 붙인 구조체는2000의 독립 반복 간격을 사용하며, E 재사용 때 원경 시간을 되감지 않는다. 고도와 정지·재생을 바꾸어도 객체를 재생성하지 않는다. 원래8종과의 전환, 원근·가림·순환·원거리 접근 회귀는 유지한다. E 공간 추가 후 단위88개·브라우저184개(기존148·공간36) 통과, 페이지·콘솔·CSP 오류0개다. 상세 미술과 여러 건물 최적화의 완료를 의미하지 않으며, 범위·검증은 [시연 기록](../../output/prototypes/breakthrough-hangar-integration-20260910/NOTES.md)을 따른다.

### 본체와 연결부의 공통 외장

기둥·층 구조와 본체의 재질이 달라 보인다는 사용자 피드백에 따라 `architectural-materials.mjs`가 양쪽의 외장 재질·무늬 크기·시작 위치를 통일한다. A는 기존 장갑판 그림, B~H와 E 뒤 골조는 기존 격납고 외벽 그림을 사용한다. 앞·옆·뒤·윗면의 명암 기준을 공유하고 밑면은 같은 계열의 별도 밑면 그림을 사용한다. 문·창문·승강로 틈·조명은 원래 재질과 UV를 유지한다.

외장 UV는 건물 내부 좌표를 기준으로 맞춘다. 일반 외벽 그림 한 반복은 가로12·세로18, A 장갑판은12×12, 일반 밑면은18×12다. 본체와 기둥의 같은 위치는 같은 UV를 가지며, 긴 기둥에서도 표면 무늬를 세로로 늘이지 않는다. 기존 그림을 거울 반복하므로 새로운 에셋이나 텍스처 복사본을 만들지 않는다. 그림 끄기·켜기와 고도·진행·모델 전환에도 동일 geometry와 재질을 재사용한다. 원본 도안·기본 렌더러 파일은 그대로 보존하고 통합 시연에서 생성한 외장 UV와 재질만 맞춘다.

외장 통일 후 단위191개·브라우저182개(구조146·E 공간36) 통과. 재질 공유·표면 무늬 크기·접합부 위상과 원래 형상·문·창 보존을 검증했다.

### 먼 건축 배경 그림

사용자가 요청한 배경은 검게 비어 있는 부분을 먼 건축물이 그려진 이미지로 채우는 것이다. E 주변의 추가 입체 건축과 구분한다. [배경 그림](../../output/imagegen/distant-architecture-backdrop-20260910/README.md)은 위·아래·양옆의 건축과 공극을 묘사하며 A~H 모두 뒤에서 표시된다.

`backdrop=architecture`로 켜고 `backdropBrightness=0~100`으로 밝기를 조절한다. 기본 밝기는50%이며 기존 URL의 명시값은 유지한다. 기존 URL은 검은 배경을 유지한다. E의 `입체 주변 건축`과 A~H의 `구조 연장`은 별도 선택이다. 배경 그림·밝기는 모델 전환과 새로고침에서 복원하며 광원·시간·카메라를 초기화하지 않는다.

그림 한 장을 무한 원경으로 표시하고, 기준 소실점을 기존 A의 화면 위치에 맞춘다. 전체 고도 범위를 덮는 고정 여백 배율을 사용해 고도 변화에는 그림 위치만 이동한다. 화면비·시점·A 범위 등 투영 조건이 바뀔 때만 여백을 다시 계산한다. 기본 `backdropMotion=recursive`는 동일 그림의 작은 복사본을 안쪽으로 이어4배씩 연속 확대한다. `static`은 이전 고정 그림이다. 별도 벽·바닥·천장 입체 면의 복원을 뜻하지 않는다. 입체 모델의 원거리 안개는 같은 배경 픽셀로 이어져 재사용 시 검은 실루엣이 튀어나오지 않도록 한다. 기존 건물·광원 가림은 유지한다. 배경 추가 후 단위100개·브라우저217개(기존184·배경33) 통과, 페이지·콘솔·CSP 오류0개다.

## 원래 장애물 복원과 세 독립 연동

`wall-armor.png`와 `wall-brace.png`, `wall-contours.mjs`를 수정하지 않고 `structureMeshes`의 앞·뒤 이미지와 원래 윤곽을 따르는 측면을 사용한다. `original-motion.mjs`는 이 경로에 전달할 배치 변환만 계산한다. 아래쪽 윤곽은 지면에 놓으며 높이와 진행 방향 길이를 같은 비율로 확대해 대각선과 빈 공간을 보존한다. 원본의 모양은 유지하지만 원래 무연동 시연의 크기·세로 배치를 그대로 두는 것은 아니다. 새 기초나 연결 부재는 만들지 않는다.

| 하단 조절 | 기본값과 동작 |
| --- | --- |
| 고도 → 시점 높이 | 켜짐. 끄면 고도 50%의 시점과 보조 `A` 흐름에 고정 |
| 저고도 → 장애물 높이 증가 | 켜짐. 끄면 기본 높이만 적용 |
| 기본 높이 | 8~100, 기본 60. 실제 높이는 단면 높이의 70% 이하 |
| 저고도 높이 증가 | 0~100%, 기본 +30%. 대각선 비율을 유지하는 균등 확대 |
| 저고도 → 배치 평면 중앙 접근 | 켜짐. 끄면 기본 벽 이격만 적용 |
| 기본 벽 이격 | 0~24, 기본 0. 벽·광원이 아닌 장애물 평면만 이동 |
| 중앙 접근 강도 | 0~100%, 기본 60%. 중앙선을 넘지 않도록 이격 제한 |

고도 `a`에 대해 `low = 1 − a²(3−2a)`를 사용한다. 기본값의 고도 0→50→100%에서 높이는 78→69→60, 벽 이격은 10.56→5.28→0이다. 시점은 `지면 + 단면 높이 × (0.04 + 0.56 × a²)`로 움직여 지면 여유가 5.76→25.92→86.4가 된다. 원본의 큰 실루엣 위로 올라갈 수 있도록 블록 비교보다 시점 범위를 넓혔다. 수동 극단값에서 고고도 여유까지 보장하는 것은 아니다.

세 연동은 독립적이며 모두 끄면 고도만 바꾸어도 배경·장애물 픽셀이 변하지 않는다. 동일 seed의 타입·좌우·위상·배치 중심·반복 간격은 유지하고 확대는 전진 중심을 기준으로 한다. 실제 벽과 광원 평면은 이동하지 않는다. 정지 상태에서도 높이·이격·증가량·접근 강도를 바꾸면 렌더 캐시를 갱신한다. 기존 간격 4·두께 2·밝기 30%·16:9·레인·전진/노트 시간·이륙/침투는 유지한다.

기본 `obstacleMode=original&clearance=1`. 명시한 `obstacleMode=original`은 예전 URL의 `architecture=1&viewMode=model`보다 우선한다. `originalHeight`, `originalInset`, `originalCameraLinked`, `originalHeightLinked`, `originalApproachLinked`와 기존 `heightBoost`, `approach`를 URL·장면 전환으로 복원한다. 이전 `architecture=0` 또는 `obstacleMode=blocks`는 하단 블록, `architecture=1` 또는 `obstacleMode=architecture`는 건축 9종, `clearance=0`은 원래 무연동 비교다. 건축 조절은 접힌 ‘이전 건축 모듈 비교’에 보존하며 ‘원래 장애물로 보기’와 ‘처음 설정’은 원본 기본 경로로 복귀한다.

## 가로 보기와 세 난이도 전환

사용자 요청으로 모든 장면을 **16:9 가로 화면**에 맞췄다. 같은 비공개 미리보기 안에서 상단의 이륙·침투·돌파 링크로 전환한다. 돌파는 현재 시연 35를 유지하고, 이륙·침투는 기존 시연 20(`cone-controls-study-20260908`)의 실행 모듈과 하늘·지면 이미지를 `approach/`에 복사해 연결했다. 원본 시연 20과 게임 본편은 변경하지 않는다. 아래 배치·조절 명세는 별도 표시가 없으면 돌파에 해당한다.

- 일반 보기에서는 화면 너비에 맞춘 16:9 캔버스를 표시한다. 세로로 든 휴대폰에서도 장면을 세로로 늘이지 않으며, 가로 회전하면 더 넓게 볼 수 있다.
- 조절 패널은 일반 보기에서 **비행 화면 아래에 항상 펼쳐 둔다**. 장면 안의 **조절** 버튼은 아래 패널로 스크롤하며 패널을 접지 않는다. 휴대폰은 세로로 내려 조절하고, 넓은 화면에서는 패널 내용을 여러 열로 배치한다. 캔버스의 16:9 비율과 기존 오브젝트 조절은 유지한다.
- **화면만 보기**는 조절을 접고 화면 전체를 사용하되, 캔버스는 중앙의 16:9 영역에 맞춰 남는 공간을 비운다. 장면을 찌그러뜨리거나 잘라서 채우지 않는다. 세 난이도 링크와 재생·조절 버튼은 계속 보인다. 닫기 또는 Escape로 나가면 일반 보기의 아래 조절 패널이 다시 보인다.
- 이륙의 고정 시선 12도와 침투의 저고도 하향 시선을 유지한다. 돌파의 사각뿔·외곽 2면·간격 4·두께 2·밝기 30% 등 기존 기본값을 바꾸지 않는다.
- 같은 탭에서 난이도를 오가면 장면별 마지막 URL 설정을 `sessionStorage`에서 복원한다. 이륙·침투는 고도와 재생·정지도 URL로 저장하며 새로고침으로 복원한다. 장면별 속도·크기의 기존 URL 단위는 유지하고 서로 덮어쓰지 않는다. 재생 시간 자체는 이동·새로고침 때 처음부터 시작한다.

## 이륙 저고도의 지상 유도등

후속 사용자 요청으로 이륙 저고도에는 활주로처럼 지면에 붙은 가이드 조명을 둔다. 기존 [이륙 저고도 이미지 탐색](../../output/imagegen/liftoff-runway-20260909/README.md)을 참고한 실시간 시연이며, 항공 시설의 실제 규격을 재현하거나 게임의 고도·판정 규칙을 확정하지 않는다.

- 유도등은 같은 지면의 좌우 두 줄에 규칙적으로 배치한다. 모든 꼭짓점의 높이는 0이며 수직 패널·기둥을 만들지 않는다. 시연 세계의 좌우 위치는 ±80, 간격은 36으로 2448 길이에 68쌍을 반복한다. 레인 양옆에서 읽히도록 두 줄 사이에 넓은 빈 공간을 둔다.
- 고도 25%까지는 유도등만 켜고 기존 점·가로·수직 오브젝트 조명은 끈다. 25~65%에서 기존 오브젝트의 밝기를 `smoothstep`으로 0→100% 복원한다. 65% 이상에서는 기존 오브젝트 배치·ID·색·밝기를 유지한다. 경계는 시연용 비교값이다.
- 유도등은 고도가 높아져도 같은 세계 좌표에 남고 투영 크기가 작아진다. 가이드 밝기는 100→35%로 부드럽게 줄인다. 고도별로 배경을 교체하거나 광원을 재추첨하지 않는다. 이륙의 시선 12도·전진 속도·중앙 레인·노트 시간은 유지한다.
- 유도등 본체와 잔광은 모두 **노란색 `#ffdc40` (RGB 255·220·64)**으로 고정한다. 다시 섞기·보조색 등장 비율은 다른 오브젝트에만 적용하며, 유도등의 작은 지상 면 크기도 다른 오브젝트의 크기·선/면 조절과 분리해 유지한다. 고도·거리별 밝기 변화, 광원 끄기와 재생·정지·잔광 조절은 사용할 수 있다.
- 가이드 사이에는 같은 지면에 투영된 어두운 띠를 둔다. 기존 지표 이미지와 하늘 원본은 수정하지 않는다. 고도 조절은 화면 아래에 계속 표시하며 최초 기본 고도 68%와 기존 URL 복원도 유지한다.
- 침투와 돌파에는 이 변경을 적용하지 않는다. 게임 본편과 원본 시연 20도 수정하지 않는다.

`approach/runway.mjs`가 배치·고도별 밝기·지면 투영을 담당한다. `approach/runway.test.ts`는 높이 0·쌍 배치·반복 간격·25/65% 경계의 연속성·작은 화면의 레인 양옆 노출·좌우 배색·고도 및 반복에 대한 배치 보존을 검증한다. `runway-browser-check.cjs`는 네 화면 크기의 저/중/고도·일반 오브젝트 제거와 복원·정지 및 URL 복원·아래 조절·침투/돌파 보존을 검사하고 JSON과 `runway-*.png`로 남긴다.

## 이륙 고도별 하늘 밝기

사용자 요청으로 이륙에서 **지평선 위 배경만 고도가 높을수록 밝아지게** 한다. 기존 밝기가 최대이며 더 밝은 하늘로 바꾸지 않는다. 고도 슬라이더의 최저 3%에서 기존 밝기의 15%, 중간 49%에서 57.5%, 최고 95%에서 100%로 `smoothstep` 보간한다. 하늘과 구름의 원본 이미지·색감은 유지하고 배경 레이어의 지평선 위 영역만 검은색으로 감광한다.

지평선 아래 지표·유도등·일반 광원·레인·조절 UI에는 감광을 적용하지 않는다. 같은 고도에서 이 영역의 픽셀은 변경 전과 같아야 한다. 이륙의 시선·지평선 위치·전진 속도·기존 고도별 오브젝트 조명 전환도 유지한다. 최고 고도에서는 감광 자체를 그리지 않아 변경 전 화면을 그대로 보존한다. 새로고침은 기존 고도 URL에서 밝기를 다시 계산하며, 일시정지 중 고도 조절도 즉시 반영한다. 상승·하강 중에는 목표 슬라이더가 아닌 현재 보간 중인 고도를 사용한다. 침투와 돌파에는 적용하지 않는다.

`approach/sky-lighting.test.ts`에서 상하한·단조 증가·경계 연속성·지평선 영역 제한을 확인한다. `sky-browser-check.cjs --baseline`으로 변경 전 화면의 픽셀 해시를 `sky-before.json`에 기록했으며 해당 증거는 덮어쓰지 않는다. 현재 `sky-browser-check.cjs`는 유도등의 후속 배색 변경과 하늘 감광을 분리하기 위해 테스트용 비교 페이지에서 감광 호출만 제외하고 같은 고도의 지면 픽셀을 비교한다. 최고 고도의 하늘은 원래 기준 해시와도 대조한다. 고도별 실제 하늘 밝기·침투 보존·고도 조절·URL 복원도 검사하며 결과는 `sky-browser-check.json`, 화면은 `sky-altitude-*.png`에 남긴다.

## 돌파 건축 구조물 9종

이 절은 접힌 이전 비교의 명세다. 현재 기본 화면은 위의 원래 장애물 복원이며 건축 모듈은 명시적으로 선택할 때만 사용한다.

[승인한 디자인](../../output/imagegen/base-silhouettes-expanded-20260909/README.md)의 큰 실루엣과 용도·접속·지지를 실제 메시로 구현한다. 이미지를 사각 판에 붙이는 방식이 아니다. ㄱ 배관, ㅣ 설비 기둥, ㅡ 수평 덕트, ㅠ 지면 접속 분배관, ㅓ 정비 통로, ㅜ 설비 지지대, ㅓ 분기 배관, ㅏ 분기 덕트, + 기둥·가로보의 9종이며 큰 실루엣은 8계열이다.

- 원형 관·6구간 엘보·플랜지·밸브, 속이 빈 덕트·그릴·벽 버팀대, 기둥의 패널·세로 보강재·기초, 가로보의 웨브·플랜지·접합판, 정비 통로의 상판·난간·아래 버팀대를 별도 입체 부재로 만든다. ㅓ 정비 통로는 오른쪽 기둥에서 왼쪽으로 뻗는다. 기둥 중간의 가로보가 +, 기둥 꼭대기의 가로보가 ㅜ다.
- ㅠ의 두 다리는 같은 지면의 기초에서 시작한다. 높이는 다리 길이와 상부 관 높이를 바꾸며 발을 공중으로 옮기지 않는다. 벽 이격은 바닥 위 설치 평면을 옮기고 벽 연결부를 연장한다. 구조물의 높이와 벽 이격은 독립적이며, 관 굵기·플랜지·난간 크기는 높이와 함께 늘리지 않는다.
- `비행에서 보기`에서는 종류 선택기의 9종 혼합 또는 단일 종류를 좌우 외곽에 반복 배치한다. 종류를 고른 뒤 보기를 바꿔도 선택을 보존한다. 고도에 따라 타입·ID·전진 위상·색을 재추첨하지 않는다. 좌우의 시작 위상과 타입을 엇갈리고, 깊이에 따라 기존 사각뿔의 `A`로 수렴한다. 출구와 `A` 밖의 삼각형은 수렴 전에 잘라 음수 축척으로 뒤집히지 않게 한다.
- `한 종씩 살펴보기`는 같은 메시를 바닥·벽 연결부와 함께 중립 조명으로 보여 준다. 레인·광원·기존 바닥/천장 이미지는 이 보기에서만 숨기고 설정 자체는 보존한다. 좌우·위아래 관찰 각도를 조절할 수 있다. 종류 선택과 이전/다음 버튼으로 9종을 순환한다. 단독 보기에서 혼합을 선택하면 대표 구조물인 ㅠ 분배관을 보여 주며 이를 수치 표시에도 명시한다.

| 하단 조절 | 범위·기본값·동작 |
| --- | --- |
| 건축 모듈 사용 | 현재 기본 꺼짐. 켜면 이전 9종을 비교하고 끄면 원래 장애물로 복귀 |
| 구조물 높이 | 8~40, 기본 18. 고도 연동 전의 기본 높이 |
| 벽에서 거리 | 0~24, 기본 4. 설치 평면의 기본 이격 |
| 저고도에서 높아지고 중앙으로 접근 | 기본 켜짐. 끄면 수동 높이·거리만 사용 |
| 저고도 높이 증가 | 0~100%, 기본 +30% |
| 중앙 접근 강도 | 0~100%, 기본 60% |
| 좌우에서 보기 | 단독 보기에서 −75~75°, 기본 32° |
| 위·아래에서 보기 | 단독 보기에서 −10~65°, 기본 18° |

고도 `a`를 0~1로 제한하고 `low = 1 − a²(3−2a)`로 보간한다. 연동을 끄면 `low=0`이다. 실제 높이는 `기본 높이 × (1 + low × 높이 증가)`, 추가 이격은 `low × 접근 강도 × 공간 폭 × .2`다. 기본값에서 고도 0→50→100%의 높이는 23.4→20.7→18, 벽 이격은 14.56→9.28→4다. 중앙 침범을 막기 위해 이격을 제한하고, 높이는 공간 높이의 70% 이하로 제한한다. 적용된 실제 수치와 중앙 제한의 안내를 패널 아래에 표시한다. 최고 고도에서의 시점 여유 40.32는 기본 구조물 높이 18보다 크지만 수동 치수를 크게 하면 관계가 달라질 수 있다.

`architecture`, `asset`, `viewMode`, `structureHeight`, `wallDistance`, `architectureLinked`, `heightBoost`, `approach`, `modelYaw`, `modelPitch`를 URL과 장면별 설정에 저장한다. 새로고침·세 장면 전환으로 복원한다. 현재 ‘처음 설정’은 원래 장애물로 돌아간다. 기존 벽면 표시·반복 간격·두께·밝기 조절을 재사용한다. 두께 2가 기본 입체 깊이, 0은 매우 얇은 깊이 비교다. 단독 보기는 형태 확인용 중립 밝기이며 벽면 밝기는 비행에만 적용한다.

`architecture.mjs`는 순수 메시·배치·치수 제작기, `architecture-renderer.mjs`는 WebGL 깊이 버퍼와 관찰 투영을 담당한다. 가까운 관은 12분할, 먼 관은 8분할, 단독 관찰은 24분할하며 먼 거리에서는 일부 작은 부품을 생략한다. 같은 치수의 메시와 정지 렌더를 재사용한다. 건축 메시끼리는 깊이를 비교하지만 기존 바닥·천장·광원과는 합성 순서를 쓰는 시연용 근사다. 사진 수준 마모·투영 그림자·구조 안전·물리 충돌은 구현하지 않는다. WebGL 실패·컨텍스트 소실은 상태 안내로 표시한다.

`architecture.test.ts`는 49개 사례로 9종의 실제 깊이·형태 차이, ㅠ의 두 지면 접점, 덕트 지지대 접속, 독립 조절·고도 연동·한계값·고정 배치·출구 및 사각뿔 내부 제약·단독 투영을 확인한다. `architecture-browser-check.cjs`는 네 화면 크기의 16:9·하단 조절·단독/비행·9종 실제 픽셀·회전·선택 유지·URL 및 장면 복원·재생/정지·기존 비교·비공개 경로를 검사한다. 캡처와 결과는 시연 폴더의 `architecture-*.png`, `architecture-browser-check.json`에 기록한다.

## 돌파 고도별 구조물 근접 연출

사용자가 충돌 판정은 필요 없다고 명시하고 요청한 이전 블록 비교다. 아래 시점 수치는 블록·건축 모듈 비교에만 적용하며 원본 복원 경로는 위의 확장된 시점 범위를 사용한다. **장갑 덩어리의 형태·두께 설명은 명시한 `architecture=0` 또는 `obstacleMode=blocks` 비교에 해당한다.** `clearance=1`이 기본이며 **고도별 구조물 근접 연출** 체크를 끄거나 `clearance=0`으로 접속하면 기존 시연 35를 그대로 비교한다. 전환은 전진 시간·노트 시간을 초기화하지 않으며 URL과 장면별 설정 복원에 포함한다. 고도 슬라이더·하/중/상·상하 반복은 아래 조절에 둔다.

- 가까운 지면과 천장, 좌우 폭·깊이는 유지한다. 시점 높이는 `지면 + 단면 높이 × (0.04 + 0.24 × 고도²)`로 바뀐다. 기본 높이 144에서 고도 0·50·100%의 지면 여유는 5.76·14.4·40.32다. 천장 여유는 최고 고도에도 103.68로 남으며 시점 회전·흔들림은 없다.
- 외곽 좌우에만 바닥 쪽 성긴 장갑 덩어리를 배치한다. 원본 장갑 지표 이미지를 윗면·옆면·끝면의 실제 메시 표면에 적용한다. 구조물 꼭대기는 가까운 지면에서 단면 높이의 14~19.5%이며 seed로 고정한다. 최저 시점보다 높고 최고 시점보다 낮다. 낮으면 옆면과 모서리가 눈높이에 걸리고 높으면 윗면을 아래로 보며 지나간다. 고도에 따라 구조물 수·주기·ID·깊이 위상·색을 재추첨하지 않는다.
- 간격 4·두께 2·밝기 30%를 유지한다. 근접 연출의 두께 2는 바깥 면에서 안쪽으로 뻗는 기본 폭이며 0은 윗면·끝면을 뺀 평면 비교다. 기존 비교에서는 종전 앞뒤 간격의 의미로 돌아간다. 위협 구조물을 천장에 달거나 새로운 기둥·경고·추가 광원을 만들지 않는다.
- `A`는 시점 높이를 따라가되 기존 `A` 높이 조절의 이동량 2.5%를 보조 흐름에 적용한다. `A` 연동을 끄면 전방점은 화면 높이 40%를 유지하지만 **고도에 따른 수직 여유는 계속 바뀐다**. 기본 `A` 이동 5배·단면 높이 144에서 고도 하→상의 전방점 이동은 화면 높이 약 4.8%다. 기존 고정 시점 비교에서는 원래 5배 이동을 그대로 사용한다.
- 기존 광원은 같은 원거리 `A`와 바닥·천장의 평면을 따르며 상단까지 계속 지나간다. 하늘·지평선은 만들지 않는다. 구조물과 단면 사이의 원근·가림은 기존 시연의 근사 합성이며 물리 비행 모델은 아니다. 구조물 안으로 진입하더라도 충돌체·피해·실패·점수·경고 이벤트는 없다.
- 중앙 4레인·판정선·노트 시간·전진 속도·16:9·아래 조절, 이륙·침투의 실행 모듈과 이미지는 유지한다. 최저 구간의 근접감은 연출일 뿐 게임의 저고도 실패 규칙을 확정하지 않는다.

`clearance.mjs`는 시점·원거리 흐름과 하단 메시를 구성한다. `clearance.test.ts`에서 고도별 간격·단조 증가·범위 제한·고정 배치·상하 투영·입체 면·출구 절단·극단 설정·기존 비교 복원을 검증한다. `clearance-browser-check.cjs`는 320·390·844·1440px에서 아래 조절·16:9·낮음/중간/높음·실제 구조물 픽셀·토글·새로고침·재생/정지·상하 반복·장면 이동과 비공개 경로를 검사한다. 결과는 `clearance-browser-check.json`, 비교 화면은 `clearance-low-*.png`, `clearance-high-*.png`, `clearance-mobile-controls.png`다. 실제 휴대폰 성능과 주변시 인지 효과는 이 검사로 확정하지 않는다.

## 기존 고정 시점 비교의 배치와 움직임

이 절과 아래 조절 표의 고정 시점·`A`·벽면 구조물 설명은 **근접 연출을 끈 경우**에 해당한다. 공통 조절은 새 연출에도 적용되며 차이는 위 절을 우선한다.

- 사각뿔의 전방 끝은 `A` 하나다. 벽면 광원은 가까운 쪽 사각 단면의 세로선과 A를 잇는 수직 삼각 단면 안에 놓인다. 지표면·천장 광원은 각각 사각뿔의 아래·위 삼각 면에 눕혀 배치한다. 모든 발광 면은 자신이 속한 평면과 사각뿔 내부를 유지한다.
- 지표면과 천장은 가까운 쪽 아래·위 가로 변과 A를 잇는다. 고도를 바꾸면 가까운 변은 고정된 채 A 쪽 기울기만 변한다. 기본은 장갑 시설 이미지 한 벌이다. 이미지가 켜진 면의 발광 오브젝트는 그리지 않는다. 기존 광원 비교를 선택하면 각 면 112개의 광원을 다시 표시하며 팔레트·형태·윤곽선·크기·잔광 조절을 적용한다. 두 면을 켜고 끄거나 이미지를 바꿔도 기존 벽면 336개의 배치·색·깊이 위상은 재추첨하지 않는다.
- 구조물은 장갑 시설·배관 시설·거대 골조의 3계열로, 각 계열에 지표면·천장 이미지가 하나씩 있다. 원근 없는 2D 표면 이미지에 WebGL 원근 매핑을 적용하고 기존 Canvas 2D 장면에 합성한다. 가로 무늬 좌표는 A에서 가까운 변의 어느 점으로 퍼지는지에 대응하며, 세로 좌표는 광원과 같은 전진량을 사용한다. 긴 방향으로 앞뒤를 번갈아 반복해 이미지 끝의 이음새를 연결하고, 먼 곳은 서서히 어둡게 처리한다. GPU 표면 이미지는 1024×1024로 정규화하고 축소 필터링을 적용한다. 원본 PNG는 변경하지 않는다. 이미지 합성은 화면 가로·세로의 절반 해상도로 처리하고 정지 중에는 같은 이미지를 재사용한다.
- 지표면·천장의 구조물은 그림의 음영으로 깊이를 표현하는 평면 이미지다. 현재 고도 모델에 따라 면 자체가 기울며 이미지도 그 변형을 따른다. 모든 구조물에는 광원 잔상을 적용하지 않는다.
- 가장 바깥 좌우 벽면에는 새로 생성한 [투명 구조물 PNG 2종](../../output/imagegen/sparse-walls-20260909/README.md)을 성기게 배치한다. 단면 수와 무관하게 가장 바깥 좌우 2면에만 어두운 장갑 벽과 장갑 조각·대각 지지대를 함께 배치한다. 기본 안쪽 6면에는 광원만 남긴다. 원본의 완전 투명 비율은 각각 약 94.4%·90.1%이며, 기본 간격 4배에서는 반복 구간의 81.25%를 추가로 비워 둔다. 구조물 높이는 단면 높이의 62% 안에 배치하고 평면별 시작 위치·높이·뒤집힘을 엇갈리게 한다. 배치 추첨은 seed에 고정하며 고도로 재추첨하지 않는다.
- 구조물은 원본 알파 윤곽에서 앞·뒤·옆면을 가진 실제 메시로 만든다. 기본 두께는 가까운 쪽 기준 2이며 0~6으로 조절한다. 0에서는 옆면을 없애 평면 이미지와 비교한다. 두께도 A에서 0으로 모이도록 거리에 비례해 줄고 가까운 출구를 넘어간 부분만 자른다. 옆면은 방향에 따른 명암을 가지며 구조물 내부의 앞뒤 면은 깊이 버퍼로 가린다. 광원·잔광은 해당 단면의 앞쪽 표식으로 합성한다. 바깥 구조물 뒤에 안쪽 단면의 광원·잔광을 차례로 그려 안쪽 빛을 가리지 않는다. 단면 사이 가림은 바깥→안쪽의 순서로 처리하는 시연용 근사이며, 서로 다른 단면의 돌출부와 광원까지 모두 비교하는 전역 3D 깊이·그림자·충돌은 구현하지 않는다. 바닥·천장과 바깥 벽의 바탕은 기존 평면 이미지 방식이다.
- GPU에서 바닥·천장과 바깥 구조물을 두 구역의 이미지 버퍼에 그린 후 한 번만 2D로 읽는다. 안쪽 단면은 구조물 버퍼를 만들지 않고 광원·잔광만 합성한다. 정지 중에는 구조물 버퍼를 재사용하고, 광원의 번짐은 작은 버퍼에서 처리한다.
- 삼각형의 앞 꼭짓점과 선형 광원의 긴 축은 `A`를 향한다. 기본 형태는 직선이며, 삼각형을 고르면 4개의 작은 정삼각형으로 나눈 채움과 팔레트 자동 선택을 사용한다. 가까워질수록 소실점을 향하는 축만 늘려 원근을 강조한다. 먼 쪽 35%까지 추가 변형이 없고 이후 가까운 정도의 제곱으로 강조량을 증가시킨다. 벽면은 위·아래·먼 경계, 지표면·천장은 좌·우·먼 경계에서 강조된 형태를 균일 축소한다. 가까운 끝은 출구로 취급해 전체 도형을 줄이지 않고 z=0을 넘어간 부분만 자른다. 화면 가장자리에 걸친 부분은 캔버스가 자르며 크기를 되돌리지 않는다.
- 윤곽선 도형을 기본 25% 섞는다. 광원 ID·seed로 선택하므로 고도·속도·형태 전환으로 채움 방식이 바뀌지 않는다. 윤곽선은 도형 전체의 바깥둘레만 남기며 내부 칸·색 경계를 그리지 않는다. 삼각형은 채움 마스크와 무관하게 기본 정삼각형 하나의 외곽에 채움 도형과 같은 거리별 길이 강조를 적용한다. 팔레트의 주조·보조 빈도로 오브젝트당 한 색을 고르고, 잔광도 속이 빈 윤곽선을 유지한다. 가까운 끝에서 잘린 윤곽선에는 절단 경계를 잇는 새 선을 그리지 않고 잔광에도 같은 열린 경계를 보존한다.
- 광원 중심은 `A`에서 각 단면의 가까운 목표 위치 쪽으로 이동한다. 가까운 목표 위치·ID·배색·채움·깊이 위상은 고도를 바꾸어도 유지한다. 이는 광원의 흐름을 비교하는 연출 모델이며 카메라의 물리 비행을 재현한 것은 아니다.
- 가까운 단면의 기본 세로 폭은 후속 요청에 따라 72의 2배인 144, 위·아래 끝은 84·−60으로 고정한다. A의 이동 기준 aa′는 높이 72로 유지하며 단면 높이 조절과 분리한다. 고도는 `A`의 높이에만 연결한다. 고도는 `a²(3−2a)`로 보간하고, 두 끝값의 중간을 기준으로 이동량에 배율을 곱한다. 기본 5배 설정에서 고도 0·0.5·1의 `A` 높이는 192·12·−168이다. 1배로 되돌리면 48·12·−24다. 시점 높이 12, 전방 깊이·좌우 폭·속도는 고도 변화로 바꾸지 않는다.
- 화면의 전방점은 이동한 `A`를 실제로 투영한 위치다. 화면 한곳에 되돌리는 보정을 하지 않는다. 확대된 이동 범위에서는 `A`가 화면 밖으로 나갈 수 있으며 화면 경계에 제한하지 않는다. 같은 고도에서는 모든 광원 흐름이 그 한 점을 공유한다. 중앙 4레인·판정선·노트 시간은 고도·배경 속도 변화로 이동하거나 가속하지 않는다. 중앙 레인은 시선 기준용이며 입력·판정 기능이 없다.

### 이전 실험: 거리·고도별 2D 건물 이미지 (2026-09-10)

사용자의 사전 제작 에셋 교체 요청에 따라, A 쐐기형 관제실 한 종류를 **거리 4단계(원거리·중거리·근거리·통과) × 시점 고도 2단계(낮음·높음)**의 PNG 8장으로 제작했다. 구현은 `output/prototypes/wedge-sprite-flight-20260910/`, 에셋은 `output/imagegen/wedge-distance-altitude-assets-20260910/`에 둔다. 기존 원본 장애물·3D 건축 비교 및 본 게임과 독립적인 미술 검증 시연이다.

건물은 Canvas 2D로 이미지 선택·이동·균일 확대만 한다. 이미지마다 alpha 경계와 오른쪽 끝 표시등 기준점을 등록해 교체 시 동일 위치에 놓는다. 낮은 시점은 밑면, 높은 시점은 지붕으로 고도를 표현한다. 고도·거리·건물 크기는 독립이며, 가까운 건물이 화면 밖에 걸쳐도 크기를 줄이지 않는다. 천장·지표면·충돌은 만들지 않는다. 중앙 4레인은 선택 가능한 참고선이다.

기본 속도 1000%는 이 시연에서 한 번 통과 2.4초, 100%는 24초다. 이전 시연의 실제 세계 단위와 같은 속도라는 의미는 아니다. 거리 슬라이더와 네 단계 버튼은 정지 비교, 재생 버튼은 이어서 전진한다. 낮음/높음 버튼·고도 슬라이더·12초 상하 반복, 크기 50~200%, 짧게 섞기/즉시 전환을 제공하고 URL로 복원한다. 움직임 줄이기 환경에서는 명시적 재생 요청이 없으면 정지한다. 에셋 목록에서 PNG 8장을 직접 열 수 있다. 16:9 화면 아래에 조절을 둔다.

생성기가 실제 alpha 대신 체크무늬 RGB를 반환한 뒤, 사용자의 **“배경 제거”** 응답으로 코드 처리가 승인됐다. 흰 단색 배경의 시점 원본을 보존하고 Python + Pillow로 배경·지지대 구멍을 제거했다. 따뜻한 창문·표시등의 흰 중심과 불투명 본체는 보존한다. 실제 RGBA·이미지 기준점·배경 제거·선택·확대·URL의 단위 20개와 별도 브라우저 검사로 검증한다. 테스트 명령, 생성 모드·프롬프트·미술적 한계는 [시연 기록](../../output/prototypes/wedge-sprite-flight-20260910/NOTES.md)과 [에셋 기록](../../output/imagegen/wedge-distance-altitude-assets-20260910/README.md)에 둔다.

그림 사이 세부·원근 차이 때문에 전환 중간에 정지하면 윤곽이 겹친다. 기준점 고정이나 짧은 혼합은 이를 완전히 해결하지 않으며, 동일 3D 모델의 연속 회전과 같다고 해석하지 않는다. 이번 시연만으로 다른 건물 전체의 제작 방식이나 `flightRule`을 확정하지 않는다.
