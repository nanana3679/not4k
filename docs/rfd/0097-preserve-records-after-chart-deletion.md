# RFD 0097: 차트 삭제 후에도 기록을 보관하고 재등록 기록과 분리한다

**Status:** Accepted (2026-10-30) · 용어·컨텍스트·곡 관리·기록·랭킹·PRD 문서 반영 (2026-10-30), 기록 보존·삭제 후 접수의 런타임 반영 미구현

## 기존 결정과 문제의식

[RFD 0085](0085-chart-records-and-detailed-history-visibility.md)는 차트 수정 시 이전 버전의 기록을 보존하도록 정했지만, 차트 자체를 삭제할 때의 기록 처리는 정하지 않았다. 현재 곡·차트 관리 스펙은 콘텐츠의 DB·Storage 삭제 순서를 다룬다. 콘텐츠 삭제가 플레이어의 성과 삭제로 이어지는지, 삭제 뒤 재등록이나 지연 전송된 결과를 어떻게 다루는지 구분할 필요가 있다.

사용자는 삭제 후 기록 보존과 선택·현재 랭킹 제외를 확인하고, 재등록은 새 차트로 취급하며 삭제 전 플레이의 지연 결과도 원래 버전에 접수하도록 확인했다(2026-10-30).

## 검토한 대안과 채택안

차트를 삭제해도 기존 플레이 기록·최고기록·달성 여부는 원래 차트 버전에 보관하고, 삭제된 차트는 곡·차트 선택과 현재 랭킹에서 제외한다. 삭제한 차트를 다시 등록하면 새 차트로 취급해 기록을 새로 쌓으며, 이전 기록은 승계하지 않는다.

삭제 전에 시작한 플레이나 이미 완료된 미전송 결과는 삭제 후에도 원래 차트 버전의 기록으로 접수·보관한다. 이 기록은 현재 랭킹에 반영하거나 재등록된 차트에 연결하지 않는다. 로그인 등 기존 기록 접수 요건과 Quit·Retry 중단 기록 제외는 그대로 적용한다.

기록까지 함께 삭제하는 대안 대신 기존 성과를 보존한다. 재등록을 복구로 간주해 기록을 잇는 대안 대신 새 차트로 분리하여 이전 성과와 섞이지 않게 한다. 삭제 뒤 도착한 결과를 모두 거부하는 대안 대신 삭제 전 플레이의 기록을 원래 버전에 보관한다.

## 현재 구현과 적용 경계

기록 보존은 콘텐츠 파일·음원을 계속 제공하거나 삭제된 차트를 플레이할 수 있게 한다는 뜻이 아니다. 삭제 후 기록의 원래 차트·버전 참조와 접수 요건을 유지해야 하지만, 물리적 삭제·논리적 삭제의 선택이나 보관용 데이터 모델은 이번 결정에서 정하지 않는다. 후속 구현 범위는 [PRD §12](../prd.md#12-미정-사항)에서 단일 관리한다.

이전 버전 기록의 조회 화면·표시 방식은 기존대로 이번 출시 전 설계 범위에서 제외한다. 이번 작업은 문서 반영이며 DB·Storage 데이터나 삭제 런타임을 변경하지 않는다.

## 영향과 검증

[개인 플레이 기록](../context/glossary.md#개인-플레이-기록)과 랭킹 정의, 관련 컨텍스트, [곡 관리](../spec/song-management.md#삭제-규칙)·스코어링·게임 코어 스펙에 정책을 반영한다. 기존 콘텐츠 삭제 순서와 차트가 없는 곡만 삭제할 수 있다는 제약은 유지한다.

후속 구현에서는 차트 삭제 후 기록이 보존되고 선택·현재 랭킹에서 제외되는지, 재등록이 새 기록으로 시작하는지, 삭제 전 시작한 플레이와 완료된 미전송 결과가 원래 버전에만 접수되는지 검증한다. 기존 로그인·정상 종료 요건과 중복 전송 처리도 함께 검증한다.
