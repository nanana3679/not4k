# RFD 0096: 곡의 표시 정보는 모든 차트가 공유하며 수정해도 기록을 유지한다

**Status:** Accepted (2026-10-30) · 용어·컨텍스트·곡 관리·차트 포맷·에디터·기록·PRD 문서 반영 (2026-10-30) · 곡 정보 드로어와 표시 정보·타이밍의 곡 저장을 RFD 0098로 추가 (2026-10-31), 곡 정보 정본의 편집·참조 일치와 기록 보존 정책의 런타임 검증은 후속 작업

## 기존 결정과 문제의식

현재 `songs` 데이터는 제목·아티스트·자켓 참조를 곡 단위로 관리하고 자켓 파일도 곡 경로에 저장한다. 한편 `ChartMeta`에는 `title`·`artist`·`imageFile`이 있어 차트 문서에도 같은 정보를 담는다. 차트에 필드가 있다는 이유로 곡의 표시 정보를 난이도별로 독립 관리하는 것으로 해석해서는 안 된다.

사용자는 제목·아티스트·자켓 같은 표시 정보만 수정했을 때 기존 기록을 유지하고, 이 정보는 같은 곡의 모든 차트가 공유하도록 확인했다(2026-10-30).

## 검토한 대안과 채택안

제목·아티스트·자켓의 논리적 소유자는 곡이다. 같은 곡의 모든 차트는 공통 정보를 사용하며, 차트마다 다른 값을 따로 확정하지 않는다. 난이도명·Lv. 등 차트별 정보와 구별한다. 현재 차트 파일의 필드가 곡 정보의 사본이나 참조를 담는 것과 독립적인 소유권을 갖는 것은 다르다.

이 표시 정보만 수정하면 기존 플레이 기록·최고기록·달성 여부·랭킹을 유지한다. 표시 정보 수정은 기록용 차트 버전의 분리 사유로 삼지 않는다. 노트 배치가 바뀌거나 곡 타이밍 변경으로 실제 입력 시각이 달라질 때 기록을 분리하는 [RFD 0085](https://github.com/nanana3679/not4k/blob/56d6b7100682ad7bb18f597f04699499b533ba0f/docs/rfd/0085-chart-records-and-detailed-history-visibility.md)·[RFD 0095](0095-song-shared-bpm-and-audio-offset.md)의 규칙과 함께 적용한다.

곡의 표시 정보와 플레이 조건을 구별하면 제목 정정이나 자켓 교체 뒤에도 플레이어의 성과를 유지할 수 있다. 편집·저장·표시에서 같은 곡 정보를 소비하여 차트별 사본이 서로 다른 값의 원본으로 굳어지지 않게 해야 한다.

## 현재 구현과 적용 경계

[`DbSong`](../../src/game/screens/songSelect/types.ts)은 곡 단위 제목·아티스트·자켓을 담고, [`ChartMeta`](../../src/shared/types/chart.ts)에도 관련 필드가 있다. 기존 저장 파일과 DB 구조를 이번 문서 작업에서 변환하지 않는다. 곡 단위 저장 경로가 이미 있다는 사실을 모든 편집·표시 경로의 정본 일치나 기록 보존 구현의 완료로 보지 않는다.

기존 사본 정리와 편집·참조 이행의 세부는 [PRD §12](../prd.md#12-미정-사항)에서 단일 관리한다. 저장 UI는 [RFD 0098](0098-song-info-drawer-and-save-scope.md)의 왼쪽 곡 정보 드로어와 곡 저장을 따른다. 곡 저장은 표시 정보와 공통 타이밍을 함께 저장하지만, 기록 버전 분리는 수정한 내용에 따라 판단한다.

## 영향과 검증

[곡 메타데이터](../context/glossary.md#곡-메타데이터)에 소유 범위를 정의하고 차트 메타데이터와 구별한다. 관련 컨텍스트, 곡 관리·차트 포맷·에디터 스펙을 동기화하고 기록·스코어링에는 표시 정보 수정의 기록 유지 규칙을 연결한다.

후속 구현에서는 같은 곡의 차트를 오갈 때 동일한 제목·아티스트·자켓을 참조하는지, 이 정보만 바꾼 뒤 기존 점수·달성 여부·순위와 기록 버전이 유지되는지 검증한다. 이번 작업은 문서 반영이며 런타임·테스트 코드는 변경하지 않는다.
