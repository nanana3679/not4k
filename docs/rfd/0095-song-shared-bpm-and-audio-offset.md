# RFD 0095: 같은 곡의 모든 차트는 BPM·박자표·음원 정렬 오프셋을 공유한다

**Status:** Accepted (2026-10-30) · 용어·컨텍스트·곡 관리·차트 포맷·에디터·게임 코어·기록·PRD 문서 반영 (2026-10-30) · 박자표·변박 공유와 곡 공통 레인 구성 문서 반영 (2026-10-30) · 공통 영역 왼쪽·노트 중앙·차트 이벤트 오른쪽 배치 문서 반영 (2026-10-30) · 공통 영역 기본 펼침·접기와 오프셋 조절 중 재생 문서 반영 (2026-10-30) · 곡 공통 타이밍과 차트의 별도 저장 문서 반영 (2026-10-30) · 공통 타이밍 미저장 시 차트 저장 차단 문서 반영 (2026-10-30) · 곡 정보 드로어·표시 정보와 타이밍의 곡 저장을 RFD 0098로 구체화 (2026-10-31) · 오프셋 값 변경 시 재생 정지로 구체화 (2026-10-31) · 재생 중 편집 제한·타이밍 값 변경 시 정지 및 위치 유지를 RFD 0099로 추가 (2026-10-31) · 기존 타이밍 불일치 시 관리자의 기준 차트 선택 문서 반영 (2026-10-31) · 공통 타이밍 이행 시 기존 박 좌표 유지 문서 반영 (2026-10-31) · PR 이해 확인에서 타이밍 값 변경 시 자동 정지를 재생 중 값 수정 차단으로 대체 (2026-10-31), 곡 타이밍 공유와 기록 버전 분리의 런타임 반영 미구현 · 타이밍 값 수정 직전 커서의 박 좌표 유지·새 음원 시각 계산을 RFD 0099로 변경·문서 반영 (2026-10-31), 커서 기준 전환의 런타임은 후속 구현 · 타이밍 값 수정 뒤 커서의 박 유지 구현 (2026-10-31, PR #392)

## 기존 결정과 문제의식

현재 구현은 BPM 이벤트를 각 차트의 `events`에, 음원 정렬용 오프셋을 각 차트의 `meta.offsetMs`와 `charts.offset_ms`에 저장한다. 같은 곡의 난이도별 차트가 서로 다른 음악 시간 기준을 가질 수 있는 구조다.

[RFD 0085](0085-chart-records-and-detailed-history-visibility.md)는 노트 배치 수정 시 기록을 새 버전으로 분리하도록 정했다. 사용자는 BPM·음원 정렬 오프셋 수정으로 실제 입력 타이밍이 달라질 때도 기록을 분리하는 데 동의했으며, 두 값은 차트마다 달라지지 않고 같은 곡의 모든 차트가 공유해야 한다고 확인했다(2026-10-30).

## 검토한 대안과 채택안

차트별로 시간 기준을 소유하는 방식에서 곡이 공통 시간 기준을 소유하는 방식으로 바꾼다. 같은 곡의 모든 차트는 초기 BPM과 곡 중간의 BPM 변경 목록, 박자표와 변박 정보, 음원 정렬용 오프셋을 공유한다. 음원 정렬용 오프셋은 플레이에 쓰는 음원의 시작점에서 0박까지의 시간 차이다.

논리적인 소유자는 곡이다. 차트 편집에서 이 값을 수정하더라도 같은 곡 전체의 시간 기준을 수정하는 것으로 취급한다. 차트별로 다른 값을 따로 확정하는 기능으로 다루지 않는다. 노트 배치와 난이도는 차트별로 관리한다. 기기별 입력·시각 오프셋은 이 곡 정보와 별개의 보정 설정이다.

에디터에는 BPM 전용 레인과 박자표 전용 레인을 곡 공통 영역으로 묶어 표시한다. 곡 공통 영역은 타임라인 왼쪽에, 4개 노트 레인은 가운데에, 차트별 이벤트 영역은 오른쪽에 배치한다. 모든 레인은 같은 시간축으로 함께 스크롤한다. 음원 정렬 오프셋은 왼쪽 곡 정보 드로어의 숫자 입력으로 제공한다([RFD 0098](0098-song-info-drawer-and-save-scope.md), 2026-10-31 후속 결정). 노트와 차트에 속한 이벤트는 차트별 영역에서 다룬다. 차트를 바꿔도 곡 공통 정보는 같은 값을 표시하고, 곡 공통이라는 표기로 수정 범위를 알린다(사용자 확인, 2026-10-30).

곡 공통 영역은 기본으로 펼쳐 둔다. 접으면 BPM·박자표 레인을 숨기고 좁은 펼치기 버튼만 남긴다. 오프셋 입력은 RFD 0098의 곡 정보 드로어에서 제공한다. 접기는 표시만 바꾸며 공통 타이밍의 적용과 현재 편집 위치를 유지한다.

오프셋 입력과 에디터의 재생·일시정지 조작을 함께 사용할 수 있어야 한다. 입력창을 열어 두는 것만으로는 재생을 막지 않는다. 음원 정렬 오프셋 값은 정지 상태에서만 수정할 수 있으며, 입력창을 열어 둔 채 직접 일시정지하고 수정한 뒤 다시 재생할 수 있어야 한다([RFD 0099](0099-editor-playback-editing-boundary.md), PR 이해 확인에서 수정, 2026-10-31).

재생 중에는 오프셋·BPM·박자표 값을 수정할 수 없으며, 수정 시도는 값과 재생 상태를 바꾸지 않는다. 직접 일시정지한 뒤 값을 수정하며 수정 직전 커서의 박 좌표를 유지한다. 같은 박에 해당하는 수정 후 음원 시각으로 커서를 갱신하고, 다시 재생하면 그 위치부터 시작한다. 재생 중 노트·이벤트 편집과 함께 [RFD 0099](0099-editor-playback-editing-boundary.md)의 제한을 따른다(2026-10-31).

곡 공통 타이밍과 차트의 저장 범위를 분리한다(사용자 확인, 2026-10-30). 후속 [RFD 0098](0098-song-info-drawer-and-save-scope.md)에 따라 곡 저장은 표시 정보와 공통 타이밍을 함께 확정하고, 차트 저장은 노트·차트별 이벤트·난이도 등 개별 정보만 확정한다. 두 저장은 상대 범위의 미저장 변경을 저장하지 않는다(사용자 확인, 2026-10-31).

곡 공통 타이밍에 미저장 변경이 있으면 차트 저장을 차단하고 곡 저장을 먼저 실행하도록 안내한다. 곡 저장이 성공하여 타이밍에 미저장 변경이 없어지면 차트 저장을 허용한다. Save Chart와 Save As에 같은 조건을 적용한다.

공통 BPM·음원 정렬 오프셋을 수정하여 실제 입력 시각이 달라지면, 영향을 받는 각 차트의 기록과 랭킹을 새 버전으로 분리한다. 이전 기록은 보관하고 수정된 버전에 승계하지 않는다. 기록을 구분하는 차트 버전과 JSON 저장 포맷 버전은 구별한다.

같은 곡의 차트들이 음악과의 정렬을 함께 유지할 수 있는 대신, 곡 타이밍의 수정은 해당 곡의 여러 차트에 영향을 줄 수 있다. 저장·편집·재생에서 공통 기준을 일관되게 소비해야 한다.

### 기존 차트 이행 시 기준 차트 선택

기존 차트를 곡 공통 타이밍 구조로 옮길 때, 같은 곡의 차트마다 BPM·박자표·음원 정렬 오프셋이 다르면 관리자가 기준으로 삼을 차트 하나를 선택한다. 선택한 차트의 초기 BPM·BPM 변경 목록·박자표·변박 정보·음원 정렬 오프셋을 해당 곡의 공통값으로 적용한다. 서로 다른 차트의 값을 자동으로 골라 합치기보다 관리자가 기준 차트를 명시하도록 한다(사용자 확인, 2026-10-31).

곡 공통 타이밍을 적용할 때 기존 노트·차트별 이벤트의 박 위치를 유지한다. 구간 항목의 시작·끝 박도 그대로 두며, 기존 음원 시각을 유지하기 위한 박 좌표 변환은 하지 않는다. 실제 음원상의 입력 시각과 구간 길이는 새 공통 타이밍에 따라 계산한다. 입력 시각이 달라지는 차트의 기록 버전은 위의 분리 규칙을 따른다(사용자 확인, 2026-10-31).

## 현재 구현과 적용 경계

현재 [`ChartMeta.offsetMs`](../../src/shared/types/chart.ts)와 [`ChartTiming`](../../src/shared/timing/chartTiming.ts)은 차트별 값을 사용한다. [`charts.offset_ms` 저장 경로](../../src/supabase/songAssets.ts)도 차트 단위다. 이 파일·DB 구조를 곡 공통 소유 모델의 완료된 구현으로 보지 않는다.

현재 [오프셋 도구](../../src/editor/components/EditorToolbar.tsx)는 기본 툴바를 대체해 재생 버튼을 숨긴다. 공통 영역과 재생 조작을 함께 제공하는 UI는 후속 구현이다.

이번 작업은 채택 규칙의 문서 반영이다. 기존 차트 파일·DB·런타임을 변환하지 않는다. 저장 구조, 기존 차트 이행과 편집·저장 반영 절차의 세부는 [PRD §12](../prd.md#12-미정-사항)에서 단일 관리한다.

## 영향과 검증

[glossary의 곡 타이밍](../context/glossary.md#곡-타이밍)에 소유와 공유 범위를 정의하고 관련 컨텍스트를 동기화한다. 곡 관리·차트 포맷·에디터 스펙은 채택한 곡 공통 규칙과 현재 차트별 저장 구조를 구별한다. 게임 코어·스코어링·기록 RFD에는 타이밍 변경의 버전 분리 정책을 연결한다.

후속 구현에서는 같은 곡의 차트를 오갈 때 동일한 초기 BPM·BPM 변경 목록·박자표·변박 정보·음원 정렬 오프셋을 사용하는지, 공통 타이밍 수정이 영향을 받는 차트에 반영되는지, 입력 시각이 바뀐 차트의 새 기록과 이전 기록이 분리되는지 검증한다. 기존 차트들의 타이밍이 다를 때 관리자가 선택한 차트의 타이밍 전체가 곡 공통값으로 적용되고, 노트·차트별 이벤트의 기존 박 좌표는 유지되는지도 확인한다.
