# RFD 0036: 바디 위의 유지 노트와 길이 0 상태 노트의 대체

**Status:** Draft (2026-10-24) · 배치·표현 방향 기록 · 바디 실패 시 유지 노트 기회 소멸 확인(2026-10-24) · 뒤 포인트 성공 시 후속 유지 노트 판정 가능 확인(2026-10-24) · 바디와 같은 유지 조건·항상 Perfect·세 확인 시점 확정(2026-10-24) · 엔진·차트·에디터 구현 전

## 배경

[RFD 0035](0035-release-presence-and-grace.md)는 롱노트의 바디와 명시적인 릴리즈 노트를 분리하고 `holdOnly`를 폐지했다. 바디 자체는 점수 항목·가중치를 만들지 않으며, 일반·그레이스 릴리즈는 모두 실제 뗌을 요구한다. 따라서 기존 길이 0 `holdOnly`의 유지 상태 확인을 그레이스 릴리즈로 바꾸면 없던 뗌 요구가 생긴다.

후속 논의에서 사용자는 기존 길이 0 `holdOnly`를 대체할 노트를 제안하고, 바디 위에 유닛 수만큼 작은 표식을 놓는 방향을 요청했다. 길이 0도 별도의 떠 있는 포인트 노트가 아니라 **길이 0 바디 위에** 표식을 놓는다고 명시했다. 이후 이 개념을 **유지 노트**라고 부르고 문서 PR 작성을 요청했다.

이 문서는 확인된 배치·표현 방향, 유지 조건·확인 시점·점수와 실패 종속 규칙을 기록한다. 남은 판정 창 수치와 이행 세부는 별도로 추적하며, 시각 시안의 존재를 구현 완료로 취급하지 않는다.

## 배치·표현 방향

1. **유지 상태를 명시하는 노트:** 유지 노트는 바디 위 특정 시점의 유지 상태를 확인하기 위한 노트다. 바디 전체의 지속 유지 판정, 별도 누름 노트, 실제 뗌을 요구하는 릴리즈 노트와 구별한다. 용어의 풀 정의는 [glossary](../context/glossary.md#유지-노트)를 따른다.
2. **바디 위에 배치:** 길이가 있는 바디 위에 놓고, 기존 길이 0 상태 노트는 길이 0 바디 위의 유지 노트로 표현한다. 길이 0이라는 이유로 양수 길이 바디나 별도 누름 노트를 만들지 않는다.
3. **유닛 수를 표시:** 싱글은 표식 1개, 더블은 표식 2개로 요구 수를 드러낸다. 유지 조건은 아래와 같이 해당 바디의 hold 수·몫별 상태를 따르며, 표식에 별도의 유지 조건을 만들지 않는다.
4. **시각 방향:** 사용자는 작은 광선 매듭(D)을 선호하고 크기 확대를 요청했다. 더블은 원래 바디의 바깥 면을 유지한 채 중앙 영역을 넓혀 두 광선을 가깝게 놓고, 각 광선에 표식을 하나씩 배치한다. 바디 전체를 가로로 두 번 복제하는 안은 채택하지 않았다. 정확한 크기·재질·실패 표현의 선택과 게임 적용은 별도 작업이다.
5. **명시된 위치를 표현:** 바디 길이나 시간 해상도에 따라 매 틱 자동으로 노트를 생성한다는 결정은 아니다. 논의 중의 이름인 ‘롱노트 틱 노트’ 대신 유지 노트로 설명하며, 차트 시간 단위인 틱과 구분한다.

## 바디와 같은 유지 조건과 Perfect 정산

2026-10-24에 사용자는 ‘유지가 안 되면 바디가 Miss이므로 둘의 조건이 같다’, ‘점수는 무조건 Perfect’, ‘이른 down 또는 그 위치에서 유지 또는 늦은 down’으로 확인한다고 명시했다.

- **유지 조건은 바디와 같다:** 해당 바디의 시작 자격·필요한 hold 수·유지 유예·몫별 실패 상태를 따른다. 바디가 정상인데 유지 노트만 따로 유지 실패하는 조건을 추가하지 않는다. 유지 부족은 바디의 규칙으로 Miss를 확정하며, 유지 노트 위치라는 이유로 유예를 건너뛰고 별도 Miss를 만들지 않는다.
- **확인 시점은 세 가지다:** 허용 범위 안의 **이른 down**, **차트상 해당 위치에서 이미 유지 중인 상태**, **허용 범위 안의 늦은 down**에서 유지 조건 충족을 확인한다. 이미 유지 중이면 새 down을 요구하지 않는다. 세 경로는 같은 유지 노트를 처리하는 대안이며, 한 항목을 중복 정산하지 않는다. 길이 0도 이 상태 확인 방식으로 처리한다.
- **성공은 항상 Perfect다:** 명시된 유지 노트는 점수 항목이며, 이른 입력·유지·늦은 입력의 차이로 Great/Good을 주지 않는다. 기존 공통 점수 규칙대로 항목당 Perfect 3점·이론 가중치 3을 적용한다. 바디 자체는 여전히 점수 항목을 만들지 않는다.
- **확인 기회와 복구는 다르다:** 이른·늦은 down도 해당 바디가 시작·유지될 수 있는 조건을 충족해야 한다. 바디 실패가 이미 확정되어 소멸한 유지 노트 기회를 늦은 down으로 되살리지 않는다. 판정 창 수치와 남은 세부는 [PRD §12](../prd.md#12-미정-사항)에서 추적한다.

## 바디 실패 시 유지 노트 기회 소멸

2026-10-24에 사용자는 바디 실패 후의 유지 노트도 ‘바디 실패하면 릴리즈 못하는 것처럼’ 처리한다고 확인했다.

- **판정 기회 소멸:** 바디 유지에 실패하면 그 바디에 연결된 아직 처리하지 않은 유지 노트의 판정 기회도 사라진다. 노트 없는 재누름만으로 해당 유지 노트를 성공시킬 수 없다. 유지 노트 자체를 실패한 바디의 복구 지점으로 쓰지 않는다. 뒤의 포인트 노트를 유효하게 처리해 그 뒤 바디를 시작하면, 그 바디에 속한 유지 노트는 다시 판정할 수 있다.
- **실패 페널티 중복 없음:** 종속 릴리즈와 같이, 기회가 소멸한 유지 노트 위치에서 추가 Miss·고도 손실·콤보 이벤트를 만들지 않는다. 이미 발생한 바디 유지 실패는 그대로 남는다.
- **종속 0점 정산:** 기회가 소멸한 유지 노트는 종속 릴리즈와 같이 0점·원래 이론 가중치로 정산하며 차트의 분모에서 지우지 않는다. 실패 원인은 바디 Miss이고, 유지 노트마다 별도 실패 이벤트를 추가하지 않는다.

### 뒤 포인트에서 시작하는 바디는 판정 가능

사용자 확인 사례는 `o-+-+-o-+-`이다. 이 예시에서 `o`는 포인트, `+`는 유지 노트, `-`는 바디이며, 포인트와 유지 노트만 순서대로 1～5번으로 센다. `+`는 이 설명의 표기이며 차트 저장 문법이나 전역 표기법을 새로 정한 것은 아니다.

이 사례는 처음에 건강하게 이어받은 바디가 없고 첫 포인트가 시작을 맡는 싱글 배치다. 첫 번째 포인트를 놓치면 그 포인트로 시작할 바디의 두 번째·세 번째 유지 노트는 판정 기회를 잃는다. 이후 네 번째 포인트를 유효하게 누르면 그 포인트부터 뒤 바디를 시작할 수 있고, 유지 조건을 충족한 다섯 번째 유지 노트는 판정할 수 있다. 두 번째·세 번째 유지 노트의 소멸한 기회나 첫 번째 포인트의 Miss를 소급해 복구하지 않는다.

이미 건강하게 이어받은 바디는 별도 head Miss만으로 실패하지 않는다는 기존 규칙([RFD 0032 §5-1](0032-body-held-count.md#5-1-계속-유지한-뒤-바디), [glossary](../context/glossary.md#헤드-노트))을 이 사례로 뒤집지 않는다. 또한 뒤 포인트는 뒤 바디의 시작을 맡는 포인트이며, 같은 레인의 임의 포인트가 모든 실패 바디를 다시 활성화한다는 뜻이 아니다. 더블의 몫별 적용은 [PRD §12](../prd.md#12-미정-사항)에서 추적한다.

따라서 ‘바디 실패 뒤 복구 불가’는 실패한 바디의 미처리 유지 노트에 적용한다. 뒤 포인트가 시작하는 새 바디의 유지 노트까지 실패를 전파하지 않는다. 이 사례는 새 유지 노트의 사용자 확인 기대 동작이며, 아직 해당 노트 타입이 없는 현재 엔진의 실행 결과로 제시하지 않는다.

## 기존 결정과의 관계

- RFD 0035의 **바디 자체는 무점수**라는 결정은 유지한다. 별도로 놓은 유지 노트가 Perfect 점수를 가지며, 바디 자체에 자동 점수를 되돌리지 않는다.
- RFD 0035 결정 6의 ‘독립적인 상태 판정 노트로 유지하지 않는다’에서 후속 검토하는 범위는 **명시적인 유지 노트의 도입과 기존 길이 0 상태 노트의 대체**다. `holdOnly` 속성이나 양수 바디 끝의 자동 상태 완료 점수를 복원하는 결정은 아니다.
- 유지 노트는 그레이스 릴리즈의 다른 이름이 아니다. 그레이스 릴리즈의 실제 뗌 요구는 그대로 유지한다.
- 바디 실패 시 연결된 릴리즈 기회가 소멸한다는 결정도 유지하며, 유지 노트에도 위의 실패 종속 규칙을 적용한다.
- 기존 길이 0 `holdOnly`의 Good 창, 서로 다른 키의 처리, 입력 공유·소비와 배치 제약을 새 유지 노트에 일괄 복사하지 않는다. 위에서 확인한 유지 조건·확인 시점·점수·실패 종속 규칙을 기준으로 데이터 이행을 정한다.

판정 창 수치와 이행의 미정 항목은 [PRD §12의 유지 노트 항목](../prd.md#12-미정-사항)에서만 추적한다. 확인된 유지 조건·확인 시점·Perfect 점수를 다시 미정으로 분류하지 않으며, 배치·표현 방향만으로 나머지 계약을 확정하지 않는다.

## 검토한 대안과 대가

- **기존 길이 0 상태 노트를 없앤다:** 새 노트 개념은 줄지만, 이미 누른 상태를 특정 시점에 확인하는 표현이 사라진다. 사용자가 요청한 대체 방향을 담지 못한다.
- **그레이스 릴리즈로 바꾼다:** 에셋과 기존 명칭을 재사용할 수 있지만 실제 뗌을 새로 요구하므로 같은 의미의 대체가 아니다.
- **별도 누름 노트로 바꾼다:** 새로운 down을 요구하는 노트가 되어 유지 상태 확인과 의미가 달라진다. 길이 0에도 바디 위에 놓으라는 요청과 맞지 않는다.
- **바디 전체에 주기적인 점수 틱을 넣는다:** 긴 바디의 밀도와 점수 비중을 바꾸며 바디의 무점수 결정과 충돌한다. 이번에 요청한 명시적 표식의 범위를 넘는다.
- **바디 위에 유지 노트를 명시한다:** 상태를 확인할 시점과 요구 수를 드러내고 길이 0도 같은 표현을 쓸 수 있다. 바디와 같은 유지 조건으로 성공하면 Perfect 점수를 받는다. 판정 창 수치·저장 표현을 정하고 작은 표식의 가독성을 검증해야 한다. 유지 노트 자체는 바디 실패 이후의 복구 지점이 아니며, 뒤 포인트로 새 바디를 시작하는 것과 구분한다. 이 방향으로 문서와 에셋 시안을 진행한다.
