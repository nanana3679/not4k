# RFD 0036: 바디 위의 유지 노트와 길이 0 상태 노트의 대체

**Status:** Draft (2026-10-24) · 배치·표현 방향 기록 · 판정·점수 계약 검토 중 · 바디 실패 시 유지 노트 기회 소멸 확인(2026-10-24) · 엔진·차트·에디터 구현 전

## 배경

[RFD 0035](0035-release-presence-and-grace.md)는 롱노트의 바디와 명시적인 릴리즈 노트를 분리하고 `holdOnly`를 폐지했다. 바디 자체는 점수 항목·가중치를 만들지 않으며, 일반·그레이스 릴리즈는 모두 실제 뗌을 요구한다. 따라서 기존 길이 0 `holdOnly`의 유지 상태 확인을 그레이스 릴리즈로 바꾸면 없던 뗌 요구가 생긴다.

후속 논의에서 사용자는 기존 길이 0 `holdOnly`를 대체할 노트를 제안하고, 바디 위에 유닛 수만큼 작은 표식을 놓는 방향을 요청했다. 길이 0도 별도의 떠 있는 포인트 노트가 아니라 **길이 0 바디 위에** 표식을 놓는다고 명시했다. 이후 이 개념을 **유지 노트**라고 부르고 문서 PR 작성을 요청했다.

이 문서는 확인된 배치·표현 방향과 실패 종속 규칙, 아직 결정하지 않은 나머지 판정 계약의 경계를 기록한다. 시각 시안의 존재를 판정 모델의 채택이나 구현 완료로 취급하지 않는다.

## 배치·표현 방향

1. **유지 상태를 명시하는 노트:** 유지 노트는 바디 위 특정 시점의 유지 상태를 확인하기 위한 노트다. 바디 전체의 지속 유지 판정, 별도 누름 노트, 실제 뗌을 요구하는 릴리즈 노트와 구별한다. 용어의 풀 정의는 [glossary](../context/glossary.md#유지-노트)를 따른다.
2. **바디 위에 배치:** 길이가 있는 바디 위에 놓고, 기존 길이 0 상태 노트는 길이 0 바디 위의 유지 노트로 표현한다. 길이 0이라는 이유로 양수 길이 바디나 별도 누름 노트를 만들지 않는다.
3. **유닛 수를 표시:** 싱글은 표식 1개, 더블은 표식 2개로 요구 수를 드러낸다. 표식 두 개라는 시각 방향만으로 더블의 동시 held 요구·독립 판정 방식까지 확정하지 않는다.
4. **시각 방향:** 사용자는 작은 광선 매듭(D)을 선호하고 크기 확대를 요청했다. 더블은 원래 바디의 바깥 면을 유지한 채 중앙 영역을 넓혀 두 광선을 가깝게 놓고, 각 광선에 표식을 하나씩 배치한다. 바디 전체를 가로로 두 번 복제하는 안은 채택하지 않았다. 정확한 크기·재질·실패 표현의 선택과 게임 적용은 별도 작업이다.
5. **명시된 위치를 표현:** 바디 길이나 시간 해상도에 따라 매 틱 자동으로 노트를 생성한다는 결정은 아니다. 논의 중의 이름인 ‘롱노트 틱 노트’ 대신 유지 노트로 설명하며, 차트 시간 단위인 틱과 구분한다.

## 바디 실패 시 유지 노트 기회 소멸

2026-10-24에 사용자는 바디 실패 후의 유지 노트도 ‘바디 실패하면 릴리즈 못하는 것처럼’ 처리한다고 확인했다.

- **판정 기회 소멸:** 바디 유지에 실패하면 그 바디에 연결된 아직 처리하지 않은 유지 노트의 판정 기회도 사라진다. 이후에 다시 눌러도 해당 유지 노트를 성공시킬 수 없다. 유지 노트를 실패한 바디의 복구 지점으로 쓰지 않는다.
- **실패 페널티 중복 없음:** 종속 릴리즈와 같이, 기회가 소멸한 유지 노트 위치에서 추가 Miss·고도 손실·콤보 이벤트를 만들지 않는다. 이미 발생한 바디 유지 실패는 그대로 남는다.
- **점수 결정과의 경계:** 유지 노트를 점수 항목으로 채택할 경우, 기회 소멸은 종속 릴리즈와 같이 0점·원래 이론 가중치로 정산하며 차트의 분모에서 지우지 않는다. 이 조건부 정산 규칙이 유지 노트의 점수 여부나 가중치 수치 자체를 확정하는 것은 아니다.

## 기존 결정과의 관계

- RFD 0035의 **바디 자체는 무점수**라는 결정은 유지한다. 별도로 놓은 유지 노트의 점수 여부는 바디에 점수를 되돌리는 문제와 구분해서 결정한다.
- RFD 0035 결정 6의 ‘독립적인 상태 판정 노트로 유지하지 않는다’에서 후속 검토하는 범위는 **명시적인 유지 노트의 도입과 기존 길이 0 상태 노트의 대체**다. `holdOnly` 속성이나 양수 바디 끝의 자동 상태 완료 점수를 복원하는 결정은 아니다.
- 유지 노트는 그레이스 릴리즈의 다른 이름이 아니다. 그레이스 릴리즈의 실제 뗌 요구는 그대로 유지한다.
- 바디 실패 시 연결된 릴리즈 기회가 소멸한다는 결정도 유지하며, 유지 노트에도 위의 실패 종속 규칙을 적용한다.
- 기존 길이 0 `holdOnly`의 Good 창, 서로 다른 키의 처리, 입력 공유·소비, 점수·실패 효과와 배치 제약을 새 유지 노트에 일괄 복사하지 않는다. 판정 계약과 데이터 이행을 먼저 정해야 한다.

판정·점수 계약과 이행의 미정 항목은 [PRD §12의 유지 노트 항목](../prd.md#12-미정-사항)에서만 추적한다. 위에서 확인한 실패 종속 규칙 외의 계약이나 수치를 배치·표현 방향만으로 확정하지 않는다.

## 검토한 대안과 대가

- **기존 길이 0 상태 노트를 없앤다:** 새 노트 개념은 줄지만, 이미 누른 상태를 특정 시점에 확인하는 표현이 사라진다. 사용자가 요청한 대체 방향을 담지 못한다.
- **그레이스 릴리즈로 바꾼다:** 에셋과 기존 명칭을 재사용할 수 있지만 실제 뗌을 새로 요구하므로 같은 의미의 대체가 아니다.
- **별도 누름 노트로 바꾼다:** 새로운 down을 요구하는 노트가 되어 유지 상태 확인과 의미가 달라진다. 길이 0에도 바디 위에 놓으라는 요청과 맞지 않는다.
- **바디 전체에 주기적인 점수 틱을 넣는다:** 긴 바디의 밀도와 점수 비중을 바꾸며 바디의 무점수 결정과 충돌한다. 이번에 요청한 명시적 표식의 범위를 넘는다.
- **바디 위에 유지 노트를 명시한다:** 상태를 확인할 시점과 요구 수를 드러내고 길이 0도 같은 표현을 쓸 수 있다. 대신 판정 창·점수를 별도로 정의하고, 작은 표식의 가독성을 검증해야 한다. 바디 실패 이후의 복구 지점으로는 사용할 수 없다. 이 방향으로 문서와 에셋 시안을 진행한다.
