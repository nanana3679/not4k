# RFD 0082: 초기 BPM·박자 설정은 선택에서 제외하고 불러올 때 겹침을 분리

**Status:** Accepted (2026-10-29) · 선택 정규화·모드·초기 설정 모달 구현, 전체 단위 5,633개·이벤트 E2E 8개 검증 완료 (2026-10-29) · 타입 검사·Lab 빌드 통과 (2026-10-29) · 결정 문서는 [PR #379](https://github.com/nanana3679/not4k/pull/379)로 먼저 main에 반영, 위 구현·검증은 [PR #369](https://github.com/nanana3679/not4k/pull/369)의 작업 (2026-10-31) · 초기 설정 로드 자동 분리·기본 상태·Undo/Redo 제외·미저장 표시 없음 채택·문서 반영 (2026-10-31), 자동 분리 런타임은 후속 구현 · PR #369에 최신 main을 merge하고 main이 새로 들인 보조 레인 `trillZone` 붙여넣기 확장·구형 차트 변환 검토 선택·게임 E2E 픽스처를 이 규칙에 맞춤, 전체 단위 5,997개·타입 검사 통과, E2E 311개 실행에서 부하성 시간 초과는 단독 재실행으로 통과 확인(보조 `trillZone` 저장 E2E 1개는 main에서도 4회 중 1회 실패하는 기존 불안정 테스트) (2026-10-31)

## 기존 결정과 문제의식

[RFD 0068](0068-common-event-editing.md)은 초기 BPM·박자의 개별 선택·가로 이동·복사를 허용하고 시간 이동·삭제·Cut을 보호했다. 이해 확인 중 사용자는 초기 이벤트를 아예 선택하지 못하게 하자고 요청했다. 초기 설정 때문에 노트와 이벤트의 혼합 조작이 달라지는 예외를 줄인다.

사용자는 후속 이해 확인에서 초기 설정이 겹친 차트를 열 때 빈 보조 레인으로 자동 분리하고, 그 결과를 Undo에서 제외한 불러온 기본 상태로 취급하도록 정했다(2026-10-31). 초기 설정의 선택 불가와 더블클릭 수동 편집은 유지한다.

## 검토한 대안

- 개별 선택과 혼합 명령의 예외를 유지한다. 초기 설정을 선택하면 일반 노트의 시간 이동까지 막힌다.
- Ctrl+A에서만 제외한다. 클릭·박스·터치에서 같은 문제가 남는다.
- 초기 설정을 모든 선택에서 제외하고 속성 편집만 허용한다. 공통 조작은 일반 노트와 선택 가능한 이벤트만 대상으로 한다.

로드 시 겹침은 수동 수리만 요구하는 방식, 자동 분리를 미저장 편집·Undo 한 작업으로 처리하는 방식, 자동 분리 후 상태를 로드 기준으로 삼는 방식을 비교했다. 사용자는 세 번째 방식을 선택했다.

## 채택안과 trade-off

- 0박의 `BpmChangeEvent`·`TimeSignatureChangeEvent`는 클릭·Shift·Alt·터치 토글·롱프레스·박스·Ctrl+A 선택에서 제외한다. `SelectionSlice` 정규화도 초기 설정을 제거해 직접 store 쓰기나 선택 복구가 우회하지 못하게 한다. 0박의 다른 종류 이벤트는 선택할 수 있다.
- 초기 설정은 선택에 들어가지 않으므로 선택 기반 이동·복사·Cut·Delete의 대상이 아니다. 기존 직접 삭제·시간 이동 가드는 방어적으로 유지한다.
- 더블클릭 속성 편집은 유지한다. 초기 설정 모달에서 값과 보조 레인(`editorLane`)을 편집할 수 있게 해, [RFD 0078](0078-event-placement-overlap.md)의 기존 파일 겹침을 선택·드래그 없이 수리한다. 레인은 현재 보조 레인 범위의 정수만 허용하며 박 위치와 종류는 바꾸지 않는다. Cancel은 원본을 보존하고 Save는 기존 Undo 경로를 사용한다.
- 차트를 불러올 때 겹친 0박 초기 BPM·박자 설정은 값·박 위치를 유지하고 충돌 없는 보조 레인으로 자동 분리한다. 일반 이벤트는 자동 재배치하지 않으며, 같은 종류의 초기 설정 중복 등 기존 의미 위반은 별도로 유지한다. 초기 설정끼리 또는 다른 이벤트와 배치가 겹치면 초기 설정 쪽의 보조 레인만 옮기며, 노트와 나머지 이벤트의 배치·연주 요구는 바꾸지 않는다.
- 빈 표시 레인이 없으면 필요한 만큼 보조 레인 표시 범위를 확장해 정리 결과를 보이게 한다. 초기 설정의 보존 우선순위·빈 레인 탐색 순서는 구현에서 결정하되 같은 입력에 같은 결과를 내며, 이미 분리된 배치를 다시 바꾸지 않는다.
- 자동 분리 결과와 필요한 보조 레인 수는 불러온 기본 상태로 취급한다. 이 정리는 Undo·Redo 이력에 넣지 않고 별도 미저장 변경 표시도 하지 않는다. 이후 사용자가 저장하면 정리된 레인 배치를 저장하며, 저장 전에는 서버·원본 파일에 자동으로 쓰지 않는다. 이후 사용자가 실행한 편집은 일반적인 미저장 변경·Undo·Redo 규칙을 따른다.

## 영향과 검증

- glossary·에디터 컨텍스트·편집 스펙과 RFD 0068의 후속 결정을 동기화한다.
- `SelectionSlice`·`SelectMode`에서 초기 설정의 선택을 차단하고, 모달·속성 저장에 초기 설정 레인 수리 경로를 연결한다.
- store 정규화·클릭/수식자/박스/터치·혼합 이동·복사·Cut·Delete·Undo의 단위/통합 테스트와 초기 설정 더블클릭·모달 레인 수리·저장 E2E로 검증한다.
- 후속 자동 분리는 초기 설정만의 보조 레인 변경·값과 박 위치 보존·빈 레인 부족 시 표시 확장·반복 로드 안정성·다른 의미 위반 보존으로 검증한다. 정리 직후 dirty가 아니고 Undo·Redo에 정리 작업이 없으며, 저장 전 서버·원본 파일이 그대로이고 명시적 저장 때만 정리 결과가 반영되는지도 확인한다. 이 자동 분리의 구현·검증은 아직 완료하지 않았다.
