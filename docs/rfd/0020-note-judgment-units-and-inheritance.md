# RFD 0020: 롱노트의 unit 활성화, 승계와 release 면제

- 날짜: 2026-09-07
**Status:** 채택 (2026-09-07) · 판정 세션·플레이·자동 입력 연결 구현 (2026-09-08) · Lab 15개 사례와 Advanced 12개 튜토리얼 구현 (2026-09-08) · 늦은 시작 승계 수정과 경계 뒤 교대 up 보강, 경계 뒤 교대 실패를 경계 전과 같게 정리 (2026-10-01, PR #173) · §2.13 head 있는 2→1 감소 release 폐지 채택 (2026-10-01, 구현은 #181 대기) · §2.14 이어지는 바디의 유지 기준과 시작 준비 해제 채택·구현 (2026-10-01, PR #188) · §2.14 double 뒤 바디의 몫별 판정과 같은 키 재누름 결정 반영 (2026-10-01, PR #188) · §2.14 새 down의 몫 배정 순서와 뗀 몫의 인수 기한·더 늦은 Point와의 우선 결정·구현 (2026-10-01, PR #188) · §2.14 결정 ③(뗀 키로 충족할 수 없는 몫의 시작 기한)·④(뒤 바디 끝 head) 확정·구현 (2026-10-01, PR #188) · §2.14 결정 ④의 범위(뗀 키의 up이 가운데 바디를 충족할 때만) 확정·구현 (2026-10-03, PR #188) · §2.14 형제 키를 쥔 채 뗀 몫의 S 이후 인수는 미구현(#198과 함께 수정 예정). 세부 검증 기록은 [PRD §12](../prd.md#12-미정-사항)를 따른다.
- 범위: grill에서 확정한 판정 규칙과 특수 사례의 기대 결과. 엔진 자료구조나 전체 상태 전이표의 검증 완료를 뜻하지 않는다.

## 1. 기존 결정과 문제

[RFD 0015](0015-binary-release-judgment.md)는 release를 Perfect/Miss 이진 판정으로 두고 익명 keyup 하나를 가장 이른 대상에 소비했다. [RFD 0006](0006-earliest-matching-headless-long-note.md)의 시작 입력 매칭과 [RFD 0009](0009-hold-only-long-note.md)의 `holdOnly`는 기존 held로 시작 충족 여부를 판단하는 경로를 포함했다.

새 판정 모델에서는 실제 release의 타이밍 등급, 시작 입력의 필요성, 연결된 바디의 승계를 함께 설명해야 한다. 다음 문제를 입력 사례로 대조했다.

- 이미 준비된 끝점이 새 down을 가져가면 뒤 Point를 치는 데 추가 입력이 필요해진다.
- 단순히 held가 충분하다는 이유로 미처리 시작을 완료하면, 키 두 개를 미리 잡는 플레이가 필수 입력을 대신한다.
- 반대로 모든 바디에 새 down을 강제하면 `o-o-`의 유지와 중간 head 탭을 함께 허용할 수 없다.
- `holdOnly`의 자동 Perfect를 실제 keyup처럼 취급하면 면제한 감소를 다시 요구하거나, 다음 바디의 정상 release를 여분 입력으로 버리게 된다.
- 결과만 적고 차트와 입력 시점을 생략하면, 감소 release와 더 뒤의 이른 마지막 release를 혼동하게 된다.

## 2. 채택안

용어의 풀 정의는 [glossary](../context/glossary.md#롱노트-판정-모델), 입력별 기대 결과는 [판정 사례 명세](../spec/note-judgment-cases.md)에 둔다. 구현 순서와 완료 기준은 [구현·검증 계획](../plans/note-judgment-implementation.md)을 따른다. 현재까지 확인한 사항 중 구현 계획 수립 전에 추가로 답해야 할 제품 질문은 없다. 전체 상태 전이의 일관성은 구현 초기에 사례 재생과 불변식 검사로 검증한다.

### 2.1 활성화와 유지

- 바디는 유지·실패를 추적하는 `unit`으로 나눈다. single은 1개, double은 2개이며, double은 겹친 별도 바디 두 개가 아니다.
- 고정 물리 owner를 두지 않는다. 실제 head·시작 입력·정당한 승계로 등록된 유지 키와, 실제 release를 처리할 권한을 구분한다.
- 양수 길이 바디는 자기 시작 입력 또는 정당한 승계로 활성화한다. head 없는 시작은 keydown을 소비하지만 시작 점수는 발생시키지 않는다.
- 이미 정당한 승계로 준비된 unit은 추가 시작 down을 소비하지 않는다. 실제 head가 있으면 그 head의 별도 입력·판정은 필요하다.
- 일반 바디와 양수 길이 `holdOnly` 모두 임의의 raw held만으로 독립 시작하거나 유지하지 않는다. 다른 독립 노트가 소비한 down도 자기 시작 입력을 대신하지 않는다.
- 첫 활성화 기한은 길이와 무관하게 S+Good이다. 허용된 시작 창 안에서는 E 이후의 첫 활성화도 가능하다.
- S+Good 안의 늦은 첫 활성화도 정당한 시작이다. 시작이 S보다 늦었다는 이유만으로 맞닿은 뒤 바디의 승계나 연결 보정을 막지 않으며, 늦게 시작한 체인도 같은 입력의 정박 시작과 같은 결과를 낸다. 이는 새 규칙이 아니라 위 시작 창의 명확화이며, 실플레이에서 발견한 결함 사례는 [NJ-H08](../spec/note-judgment-cases.md#nj-h08)이다(2026-10-01). 이 수정과 함께 정한 경계 뒤 up의 처리는 §2.12를 따른다.
- 이미 활성화한 unit의 유지 실패는 되돌리지 않는다. 같은 timestamp의 입력을 모두 반영한 뒤 유지 부족을 확인한다. 새 down/up의 실제 인과관계를 지우지 않는다.
- 실패는 해당 unit에 적용한다. 뒤 바디를 한꺼번에 실패시키지 않으며, head·`holdOnly`·unit 수 변화로 구분되는 새 바디에는 자기 시작 기회가 있다.
- 실패한 바디를 건너뛰어 오래된 head의 늦은 성공을 더 뒤의 승계로 전달하지 않는다. 살아 있는 다른 unit의 경로까지 초기화하는 규칙은 아니다.

### 2.2 입력 소비와 실제 release

- keydown은 창과 키 자격을 충족한 가장 이른 Point 또는 실제로 필요한 시작 하나에 소비한다.
- keyup은 창·준비·키 자격을 충족한 가장 이른 실제 release 하나에 소비한다. 가까운 시각 우선이 아니다.
- 실제 release는 Perfect / Great / Good / Miss이며 raw FAST/SLOW를 집계한다. Normal은 ±41/82/120ms, Easy는 ±50/100/150ms이다. Bad는 사용하지 않는다.
- double head 및 double 시작 준비에는 서로 다른 두 물리 키가 필요하다. 실제 release는 각 누름의 권한을 따른다. 같은 물리 키라도 유효한 새 head·미처리 시작을 처리하여 새 권한을 얻으면 같은 double 종료의 남은 release를 처리할 수 있다. 후속 채택 근거는 §2.8을 따른다.
- 이미 release에 사용한 누름의 권한은 남은 release 후보와 여분 키 계산에서 제외한다. 유효한 새 입력으로 얻은 권한까지 물리 키 사용 이력으로 차단하지 않는다.
- 일반 여분 키의 keyup은 실제 release를 소비하지 않는다. keyup은 그 press의 자격을 끝내며, 임의의 재누름으로 자격을 복구하지 않는다.
- 여분 여부는 현재 바디의 unit 수만으로 계산하지 않는다. 앞에 남은 실제 종료 요구도 고려한다.
- 같은 연결 구간의 나중 시작에 등록된 키도 앞의 준비된 실제 release를 처리할 수 있다. 이미 실패한 unit은 부활시키지 않는다.
- 앞 release의 미처리 준비나 Miss로 끝난 몫을 뒤 증가분의 미처리 시작에 중복 배정하지 않는다.
- 유효한 head·시작 입력으로 연결 경계의 교대가 성립한 keyup은 뒤 실제 release에 소비하지 않는다. 교대가 성립할 수 있는 up은 용도를 먼저 확정하며, 그 전에는 뒤 끝의 이른 등급을 확정하지 않는다. 적용 배경과 범위는 §2.6을 따른다.

### 2.3 `holdOnly`

- 양수 길이는 활성화된 바디의 끝에서 release를 면제하고 Perfect/Miss 상태 판정을 한다. 등록된 키로 유지해야 한다.
- E까지 유지하면 Perfect이다. 유효한 이른 완료와 S+Good까지의 늦은 첫 활성화도 허용한다. `holdOnly`에는 FAST/SLOW가 없다.
- 상태 완료는 keyup을 소비하지 않는다. 같은 keyup으로 유효한 `holdOnly` 상태 완료와 실제 release 하나가 함께 성립할 수 있다.
- 2→1의 일반 감소는 실제 release 1개를 판정한다. 경계에 head가 있으면 그 head가 경계의 판정이며 감소 release는 없다(§2.13). 같은 경계에 `holdOnly`가 붙으면 앞 double의 두 unit을 각각 판정한다. 둘 다 성공하면 Perfect 2개이고, 하나는 종료되고 하나는 뒤 바디로 이어진다.
- 사용자 관점에서도 감소 `holdOnly` 경계는 이어지는 쪽에 노트가 하나 더 보이므로 두 판정이 자연스럽다.
- 자동 Perfect와 종료·승계 배정은 분리한다. 늦게 들어온 두 head가 순서대로 종료 쪽과 이어지는 쪽을 충족할 수 있다. 특정 키를 먼저 고정하지 않는다.
- `holdOnly` 감소는 실제 키 수 감소를 요구하지 않는다. 계속 held인 등록 키의 자격은 남으며, 다음 증가에 정당하게 승계할 수 있다.
- **release를 면제받은 몫은 뒤 실제 release를 막는 여분 키 계산에서 제외한다.** double `holdOnly` → single에서 A/B를 유지하다가 마지막에 A만 떼어 실제 release를 완료하고, B는 계속 잡을 수 있다.
- 짧은 감소 구간에서 double의 두 unit을 나눠 시작해 둘째가 바로 이어지는 뒤 바디의 S 이후에 활성화해도, 그 뒤 바디가 아직 진행 중이면 모든 unit의 시작·실패가 정해진 뒤 첫 키를 정박에 쳤는지와 관계없이 같은 면제 몫을 가진다. 위 면제 규칙의 명확화이며 도출한 대조는 [NJ-H03](../spec/note-judgment-cases.md#nj-h03)에 둔다(2026-10-01). 둘째가 그 뒤 바디가 끝난 뒤(예: 다음 증가 구간)에 활성화하는 경우는 정하지 않았으며 [PRD §12](../prd.md#12-미정-사항)에서 추적한다.
- 이 면제는 일반 여분 키 전체에 적용하는 규칙이 아니다. 면제한 몫이 다음 증가의 새 unit으로 이어지면 그 새 unit의 끝 판정을 따른다. 같은 몫을 새 unit의 활성화와 추가 release 면제에 중복 사용하지 않는다.
- 길이 0 `holdOnly`는 기존 held로 통과하는 상태 판정을 유지한다. 독립된 일반 release 권한을 새로 만들지 않는다. 양수 길이에 대한 시작 입력 요구와 구분한다.

### 2.4 점수와 실패

- head, 실제 release, 명시된 `holdOnly`는 점수 항목이다. 일반 `connection` 성공에는 점수·콤보 증가·고도 회복이 없다.
- 일반 연결 바디의 유지 실패는 Miss 표시·통계·고도 손실·콤보 단절에 반영한다. 별도 점수 감점이나 점수 분모 항목을 추가하지 않는다.
- 점수 항목의 이론 가중치는 차트로 고정한다. 실시간 달성률의 분모는 지금까지 처리한 점수 항목의 이론 가중치 합, 최종 분모는 전체 이론 가중치 합이다.
- head Miss로 새 head 종속 unit이 시작할 수 없으면, 종속 끝점은 0점과 원래 가중치를 head Miss와 함께 처리한다. 끝점에서 추가 Miss 표시·고도 손실을 발생시키지 않는다. 이미 건강하게 승계된 바디는 head Miss와 독립적이다.
- 활성화 후 실패한 unit도 한 번만 실패 처리한다. 실패 시점과 끝점에서 중복 패널티를 주지 않는다.
- 100% 달성률이면서 Full Combo가 아닌 결과를 허용한다. 이를 막기 위해 연결 점수, Miss 감점, 콤보 점수 보너스를 추가하지 않는다.

### 2.5 차트 제약

- 같은 레인의 바디 열린 구간은 겹치지 않으며, 그 내부에 Point를 놓지 않는다.
- 차트상 끝과 다음 시작이 맞닿은 경우에 승계한다. 판정 창이 겹친다는 이유만으로 별개 바디를 연결하지 않는다.
- 같은 unit 수의 경계에는 head 또는 `holdOnly`가 있어야 한다. unit 수가 바뀌는 경계에는 둘이 없어도 된다.
- 양수 길이 바디 끝과 같은 시각에 별도의 길이 0 롱노트를 붙이지 않는다. Point는 배치할 수 있으나, `holdOnly`와 Point의 동시 배치는 금지한다.
- head가 있는 길이 0 롱노트는 없다. `trillLong`에는 head가 필요하고, 양수 길이 `trillLong + holdOnly`는 허용하며 길이 0 조합은 금지한다.

### 2.6 교대 keyup과 뒤 release 창이 겹치는 경우 — 후속 채택

`o-o-`에서 앞 키를 995에 떼고 연결 head 1000을 다른 키로 처리해 1100까지 유지했는데, 앞 up이 마지막 1100의 Good으로 먼저 확정되는 결과를 사용자가 재검토했다. 같은 unit 수의 일반 연결 `o-o-`·`d=d=`는 연속 유지와 경계 교대를 모두 지원해야 한다.

**유효한 교대가 성립한 keyup은 뒤 release 판정에 쓰지 않는다.** 사용자는 “교대 시 발생하는 릴리즈를 릴리즈 판정에 안쓰면 되는구나”로 이 원칙을 채택했다. 임의의 raw down이 있었다는 이유로 모든 이전 up을 교대로 처리하지는 않는다.

**동일 키 재타격에도 서로 다른 키로 넘길 때와 같은 release 제외 보정을 적용한다.** 사용자는 설명하기 어려운 동일 키 예외를 재검토한 뒤 “동일 키라도 같은 보정을 적용한다는 말이라면 동의함”이라고 명시했다. 이에 따라 서로 다른 키에만 보정을 적용하던 제한을 정정한다. 유효한 다음 head·시작 입력으로 바디를 이어가는 데 쓰인 up은 키의 동일 여부와 관계없이 뒤 실제 release에 쓰지 않는다. 동일 키라는 이유로 연결 Miss를 추가하지 않는다.

키 교대라는 입력방식은 계속 서로 다른 키 사이의 전환을 뜻한다. 동일 키 재타격에도 같은 연결 보정을 적용한다는 것이며, 키 교대의 용어 정의를 바꾸지 않는다. 임의의 재누름은 유효한 head·시작 입력을 대신하지 않으며, double head의 서로 다른 물리 키 요구는 유지한다. 실제 release 권한의 갱신은 후속 채택 §2.8을 따른다. 보정한 up은 실제 release 사용 이력에 넣지 않는다. 구체적인 짧은 끝·긴 끝의 동일 키 사례는 [NJ-R09](../spec/note-judgment-cases.md#nj-r09), 부분 연결과 동시 입력의 대조는 NJ-R04·NJ-R11을 따른다.

**double의 한 unit만 교대하면 그 몫에만 보정을 적용한다.** A/B 유지 중 A up 995 → C head 1000으로 한 몫을 교대하고 B up 1030 → C up 1100으로 끝 1100을 처리하면, A의 up만 교대로 제외한다. B의 실제 release는 Great(-70), C는 Perfect이며, 나머지 double head의 Miss가 B로 정상 승계된 unit까지 실패시키지 않는다. 하나의 새 head로 두 교대를 성립시키거나 경계 주변의 모든 up을 보정하지 않는다. 사용자 확인 사례는 [NJ-R10](../spec/note-judgment-cases.md#nj-r10)이다.

**적격인 보류 up 중 먼저 발생한 것부터 연결 보정에 배정한다.** double의 A up 1010 → B up 1040 뒤 single head 1000을 C down 1050으로 처리하면, 먼저 발생한 A up을 보정한다. 끝 1100의 실제 release는 B up 1040의 Great(-60), C up 1100의 Perfect이다. 사용자가 이 발생 순서 우선에 동의했으며 [NJ-R12](../spec/note-judgment-cases.md#nj-r12)에 기록했다.

**동일 키 재타격도 보정 후보가 되지만 발생 순서를 앞질러 우선 배정하지 않는다.** C 대신 B down 1050으로 head를 처리해도 먼저 발생한 A up은 연결용, 두 번째 B up 1040은 마지막 `termination`의 Great이다. 사용자는 이 `=o=`의 중간점에 배정할 연결용 up은 한 개이므로 두 번째 up이 terminal에 적용되는 것이 맞다고 명시했다. B의 재타격을 끝까지 성공시키기 위해 두 up의 배정을 바꾸지 않는다. 이후 B up 1100은 §2.8에서 채택한 새 head의 권한으로 두 번째 실제 release Perfect를 처리한다. [NJ-R13](../spec/note-judgment-cases.md#nj-r13)을 따른다.

중간점의 한 몫은 연결 보정에 쓸 수 있는 up의 개수이며, 그 경계에 점수 release를 새로 추가한다는 뜻이 아니다. 기존 유지와 별도 head 탭 방식도 계속 허용한다. 동일 timestamp 후보의 내부 동률 순서는 §2.7의 결과 일관성과 §2.8의 권한 갱신을 만족해야 하며, 사용자에게 별도 키 우선순위를 선택하도록 요구하지 않는다.

교대와 뒤 release 모두에 해당할 수 있는 up은 용도가 결정되기 전까지 잠정 후보로 둔다. 마지막 E 이후에도 연결 head의 Good 창이 남을 수 있으므로 E만으로 확정하지 않는다. 이미 확정한 등급을 되돌리는 방식으로 정의하지 않는다. 이 변경은 교대 up을 뒤 release의 적격 후보에서 제외하며, 남은 실제 release 후보 사이의 가장 이른 대상 우선과 실제 입력 시각의 타이밍 등급은 유지한다.

교대가 실패하여 다음 unit이 시작·승계되지 못하면 그 unit의 실제 release도 성공 판정할 대상이 없다. 보류한 up으로 뒤 끝의 Good을 만드는 이전 설명은 사용자의 “마지막 교대를 실패했다는건 릴리즈 할 대상도 없다는거 아니야?”라는 지적에 따라 정정한다. 종속 끝점은 0점과 원래 가중치로 정리하며, 끝 시점에 추가 Miss 패널티를 주지 않는다. 연결 1000·맨끝 1100에서 A up 995 후 기한까지 새 입력도 유지 키도 없었던 [NJ-R08](../spec/note-judgment-cases.md#nj-r08)에 적용한다.

이 교대 실패 사례에서는 승계 준비만으로 다음 바디를 S 이전에 조기 완료했다고 간주하는 종전 해석을 사용하지 않는다. head만 Miss이고 바디가 기존 키로 정상 승계된 경우와 구분하며, 그 경우에는 해당 바디의 실제 release가 남는다. 정상 승계된 바디의 유효한 이른 release 전체를 금지하는 변경은 아니다.

Trade-off는 모호한 up의 최종 결과가 후속 입력에 따라 늦게 확정될 수 있다는 점이다. 대신 정상 연결이 의도치 않은 이른 끝 판정으로 확정되는 결과를 피한다. 복수 후보의 발생 순서, 같은 키의 새 권한, 동시 후보의 결과 일관성은 이 문서의 채택 규칙이다. 통합 검증과 구현 이행은 [PRD §12](../prd.md#12-미정-사항)에서 추적한다. 서로 다른 키의 정상·늦은 교대는 [NJ-R06](../spec/note-judgment-cases.md#nj-r06)을 따른다.

### 2.7 동일한 플레이의 결과 일관성 — 후속 요구사항

사용자는 “사용자 입장에서 똑같은 플레이를 하면 같은 결과가 나와야” 한다고 명시했다. 같은 차트에서 같은 키·시각의 입력을 했을 때, 서로 다른 키의 동시 up을 내부에서 배정하거나 수신 순번으로 나눈 방식만으로 이후 성공·Miss가 갈리면 안 된다. 같은 timestamp에서 모든 입력을 반영한 뒤 유지 부족을 확인하는 것만으로는 충분하지 않으며, 그 배정이 남긴 release 사용 키 이력까지 후속 결과에 영향을 주지 않아야 한다.

이 요구사항은 채택한다. 수신 순번에 따라 NJ-Q08의 마지막 B up이 성공하거나 막히는 제안은 이 요구를 충족하지 못한다. 후속으로 사용자가 §2.8의 권한 갱신을 채택했다. 동시 up의 내부 배정이 달라도 새 head 뒤 release의 결과가 같은 대조는 [NJ-R14](../spec/note-judgment-cases.md#nj-r14)를 따른다. 전체 상태 전이 검산과 이행 상태는 [PRD §12](../prd.md#12-미정-사항)에서 관리한다.

### 2.8 유효한 새 입력에 따른 release 권한 갱신 — 후속 채택

기존에는 같은 double 끝의 첫 실제 release에 사용한 물리 키를, 새 head가 성공한 뒤에도 남은 release 후보에서 제외했다. NJ-Q08에서 동시 A/B up 중 어느 것을 연결에 배정했는지에 따라 이후 B head → B up의 성공 여부가 달라져 §2.7의 결과 일관성 요구와 충돌했다.

사용자는 **유효한 새 head·미처리 시작을 처리하면 같은 물리 키도 그 새 누름의 release 권한을 얻는다**는 안을 채택했다. 같은 double 끝에서 실제 release에 한 번 쓴 키라는 이유로 새 권한을 차단하지 않는다. 임의의 재누름은 새 권한을 주지 않으며, 등록 대상과 연결 구간, 창·준비·실패 여부 등 기존 적격 조건은 그대로 적용한다. 독립된 다른 Point의 입력이 앞 바디의 권한을 새로 주는 규칙도 아니다.

한 up은 실제 release 하나만 소비한다. 앞 up의 배정·등급을 취소하지 않으며, 첫 up 연결·다음 적격 up terminal이라는 순서를 유지한다. 실패한 unit의 부활과 실패 경로를 건너뛰는 승계는 허용하지 않는다. double head·double 시작의 서로 다른 물리 키 요구도 바꾸지 않는다.

이에 따라 NJ-R13은 A up 1010을 연결, B up 1040을 첫 terminal Great로 처리하고, B head 1050에서 얻은 새 권한으로 B up 1100을 둘째 terminal Perfect로 처리한다. 전체는 Perfect 3개·Great 2개·Miss 없음이다. 동시 up의 두 내부 배정을 대조한 NJ-R14, 아무 새 head·시작 없는 재누름을 대조한 NJ-R15를 함께 기록한다.

Trade-off는 유효한 새 입력을 사이에 두면 같은 double 끝의 두 release를 같은 물리 키로 처리할 수 있다는 점이다. 과거의 무조건적인 물리 키 중복 금지를 유지하는 안이 아니며, 누름별 권한과 유효한 입력 요구로 대체한다. 배정 전체를 가리는 키 차단이나 성공 결과에 맞춘 보정 후보 재배정은 채택하지 않는다.

### 2.9 보류 판정의 콤보는 확정 순서로 반영 — 후속 채택

NJ-Q10에서는 보류한 release가 실제 입력 이후에 확정될 때, 콤보를 원래 입력 시각에 소급하여 계산하는 안을 검토했다. 사용자는 판정이 결정되는 순서로 처리할 것을 제안했다. **현재 콤보는 판정 확정 순서로 반영한다.** 보류 중인 후보는 콤보에 넣지 않으며, 실제 release로 확정된 뒤 반영한다. 이미 지난 Miss 앞에 성공을 소급해서 끼워 넣지 않는다.

타이밍 등급과 raw FAST/SLOW는 계속 실제 up 시각으로 계산한다. 확정이 늦다는 이유로 원래 Great 입력을 늦은 Good이나 Miss로 바꾸지 않는다. 동일 timestamp·phase의 판정은 기존대로 전 레인 묶음으로 처리하고 Miss가 콤보 결과에서 우선한다.

확정 순서는 유효한 입력과 판정 기한 등 게임 규칙에 따른 순서이다. 같은 플레이에서 프레임 호출 간격, 레인 순회, 이벤트 수집 순서 때문에 결과가 달라져도 된다는 뜻은 아니다. 여러 기한을 한 update에서 관측해도 각 기한의 논리적 순서를 보존해야 한다.

확정된 판정을 따라 콤보가 변하도록 하고, 소급 계산을 위해 이미 처리한 콤보 이력을 되돌리는 부담을 없앤다. 채택 결과는 [NJ-S03](../spec/note-judgment-cases.md#nj-s03)을 따른다. 당시 최대 콤보 비교를 포함했던 논의의 범위는 후속 §2.10에 따라 정리한다.

### 2.10 최대 콤보 통계 미제공 — 후속 채택

NJ-Q11에서 같은 확정 묶음의 성공·Miss가 최대 콤보를 갱신하는지 질문했다. 사용자는 최대 콤보수 통계를 제공하지 않을 것이므로 이 논의가 필요 없다고 명시했다. **최대 콤보 통계는 제공하지 않는다.** 해당 질문과 계산 정책의 결정을 철회하고, 판정 사례에서도 최대 콤보를 제품의 기대 결과로 요구하지 않는다.

현재 콤보의 확정 순서와 동일 묶음의 Miss 우선, Full Combo 조건은 기존 채택안을 따른다. 최대 콤보를 별도 성과 지표나 점수 요소로 도입하지 않는다. 기존 구현의 `maxCombo` 필드나 결과 화면 노출이 이 제품 결정을 대신하지 않는다. 결과 화면의 노출 제거는 구현 이행 대상이며, 이번 grill에서 게임 코드는 변경하지 않는다.

Trade-off는 가장 길게 이어 친 구간의 수치를 결과 통계로 제공하지 않는 것이다. 제공하지 않는 통계의 계산 정책을 판정 모델의 미결정 문제로 남기지 않는다. 이행 상태는 [PRD §12](../prd.md#12-미정-사항)에서 관리한다.

### 2.11 함께 적용할 Point·트릴의 기존 채택 규칙

롱노트 이행 과정에서 이미 결정한 입력 규칙을 과거 구현으로 되돌리지 않도록 함께 명시한다.

- Point도 Good 창 안의 가장 이른 적격 대상이 입력을 소비한다. Bad 등급과 Bad 매칭 구간은 사용하지 않는다. double head는 서로 다른 물리 키를 요구하며 두 성공 키의 입력 기록을 모두 보존한다.
- Grace는 Good 창 안의 타이밍 등급을 Perfect로 처리하며 FAST/SLOW를 집계하지 않는다. 트릴 교대 실패에 따른 `goodTrill`은 별도로 적용한다.
- `goodTrill`은 head에만 적용한다. Good과 같은 점수·콤보 취급 및 별도 표시·집계를 가지며 바디의 release 등급을 대신하지 않는다. 일반 `goodTrill`은 raw 타이밍을 사용하고 Grace의 `goodTrill`은 FAST/SLOW에서 제외한다.
- 트릴 교대 세트에는 **head를 소비한 키만 등록**한다. 바디 유지·승계 키나 release만 소비한 키, 임의 raw down을 등록하지 않는다. 과거 handoff의 body owner 등록 설명은 고정 owner 제거 후의 채택안이 아니다.
- 트릴 head 확정 때 이전 세트를 갱신하고, head Miss에서는 이전 세트를 비운다. 교대 세트의 구간은 입력이 도착한 현재 시각이 아니라 해당 노트의 차트상 `trillZone`을 따른다. 이른 입력과 늦은 입력이 인접 구간의 추적을 오염시키지 않아야 한다.
- 같은 timestamp의 복수 적격 트릴 입력에는 최고 등급 입력 선택과 교대 한 번 인정 규칙을 적용한다. 나머지 적격 head 입력은 `goodTrill`이며, 하나의 입력을 여러 head에 중복 소비하지 않는다. 입력 수집 순서만으로 결과가 바뀌지 않는지 통합 검증한다.

이 절은 대화에서 이미 채택한 규칙의 이행 범위 정리이다. 38개 롱노트 사례만으로 Point·트릴의 모든 조합을 검증했다고 주장하지 않으며, 추가 회귀 범위는 구현 계획에 둔다.

### 2.12 경계 뒤 교대 up — 후속 채택

§2.1의 명확화에 따라 늦게 시작한 바디도 경계에서 뒤 바디를 이어받게 되자, 홀드 트릴(PP-010)에서 경계를 조금 지나 앞 키를 떼고 곧바로 연결 head를 치는 입력이 뒤 바디의 유지 Miss가 되었다. 예를 들어 head 0 + `[0,1000]` → head 1000 + `[1000,2000]`에서 A를 1015에 떼고 B로 head를 1020에 치면, 1000에 A로 이어받은 뒤 바디가 1015에 실패했다. 정박 시작에서는 종전부터 같은 결과였고, 늦은 시작은 승계가 막혀 있었기 때문에 우연히 통과했을 뿐이다. §2.6은 경계 전 up만 잠정 후보로 다루었고, 경계 뒤이면서 연결 head의 Good 창 안에 있는 up을 정의한 사례는 없었다.

사용자는 “경계 뒤 up + 창 안의 연결 head를 유효한 교대로 인정할지”라는 질문에 “인정”이라고 답했다(2026-10-01). **연결 경계 뒤에 뗀 up도 연결 head의 Good 창 안이면 경계 전 up과 같은 교대 후보로 보류한다.** 그 창 안에 유효한 연결 head가 오면 이 up은 교대 up이다. 유지 Miss를 만들지 않고, 뒤 실제 release에도 쓰지 않는다.

head가 창 안에 오지 않으면 교대 실패이며, **뒤 바디 길이와 관계없이 경계 전에 뗀 교대 실패(§2.6, [NJ-R08](../spec/note-judgment-cases.md#nj-r08))와 똑같이 처리한다.** 종전 기대값은 head Miss에 이어받은 바디의 유지 Miss를 더해 Miss 2였다. 사용자는 이를 두고 “B가 오지 않으면 포인트+바디 를 같이 미스 처리해야하냐고 묻는거지 한개만 발생”이라고 지적했고, 이를 “경계 뒤 교대가 실패하면(B가 head 창 안에 오지 않으면) 뒤 바디 길이와 상관없이 경계 전에 뗀 경우와 똑같이 처리”로 일반화한 안에 “ㅇㅋ”로 동의했다(2026-10-01). head 기한에 head Miss 하나를 확정하고, 그 보류 up 하나로만 이어지던 뒤 unit은 시작·승계하지 못한 것처럼 끝점을 종속 0점으로 정리한다. 끝 release가 없는 unit은 점수 항목 없이 닫는다. 유지 Miss나 끝 기한의 release Miss를 더하지 않는다. 예를 들어 head 0 + `[0,1000]` → head 1000 + `[1000,2000]`에서 A를 1015에 떼고 head 입력이 없으면 1120에 head Miss와 끝 2000의 종속 0점이며, A를 995에 뗀 경우와 같다. 뒤 바디가 `[1000,1100]`처럼 head 기한 전에 끝나도 같다. 그 뒤에 double `[1100,2000]`이 이어지면 시작하지 못한 double 두 unit만 시작 기한 1220에 Miss이다. 현재 구현에서 이 동치가 아직 성립하지 않는 경우(뒤 바디가 `holdOnly`라 경계 뒤 up이 E−Good 이후의 이른 완료가 되는 경우, 뒤 바디가 head 기한 전에 끝나 다음 head 경계로 넘어간 뒤 뗀 경우)는 [PRD §12](../prd.md#12-미정-사항)에서 추적한다.

- 적용 조건은 §2.6의 연결 보정과 같다. 경계에 head가 있어야 하며, 그 경계에서 허용하는 보정 몫만큼 발생 순서로 배정한다. head 없는 `holdOnly` 경계와 연결 head 창 밖의 up은 보류하지 않고 종전대로 그 시점에 유지 부족을 확인한다. 교대 몫을 넘는 up은 교대로 인정하지 않으므로 그 몫의 unit은 유지 실패한다.
- 경계 뒤의 up이면 뒤 바디는 이미 경계에서 이어받아 시작한 상태다. 그래도 교대가 성립하지 않으면 그 up 하나로만 이어지던 unit은 경계 전 실패와 같이 종속 0점으로 정리하며 유지 Miss를 따로 세지 않는다. 다른 등록 키로 계속 유지 중인 unit은 head Miss와 독립적으로 이어진다(§2.4). 연결 head 창이 지난 뒤의 up은 보류하지 않으므로 그 시점의 유지 실패이며, 교대 실패와 별개의 실패다. 창 밖의 늦은 down은 실패한 바디를 되살리지 않는다.
- 2→1 감소 경계에서도 교대 up은 이어지는 몫 하나만 넘긴다. head가 있는 2→1 경계의 감소 release 항목은 §2.13에 따라 없앤다. 그 구현(#181) 전까지 엔진에 남은 감소 release 항목은 남은 키의 실제 up 또는 끝 기한의 Miss로 정확히 한 번 정산하며, 교대 up으로 대신하거나 정산 없이 닫지 않는다. 짧은 `holdOnly` 뒤 바디처럼 뒤 바디가 연결 head보다 먼저 완료된 경우도 같다. 이는 감소 release의 등급 규칙이 아니라 점수 항목을 빠뜨리지 않는 기준이다.
- head가 먼저 성공한 뒤 경계 뒤에 앞 키를 떼는 입력과 경계 전 교대는 종전 결과를 유지한다.
- 늦게 시작한 체인과 정박 체인은 같은 교대 입력에서 같은 결과를 낸다(§2.7).

Trade-off는 경계 뒤에 뗀 up의 결과가 up 시각이 아니라 연결 head 기한(경계+Good)에 정해진다는 점이다. 교대가 끝내 성립하지 않아도 head Miss 하나로 끝나며, 같은 실패를 head와 바디에 이중으로 세지 않는다. 대신 경계 직후의 자연스러운 교대를 정박·늦은 시작 모두에서 성공으로 처리한다. 사용자 확인 사례와 도출한 대조는 [NJ-R16](../spec/note-judgment-cases.md#nj-r16)을 따른다.

### 2.13 head가 있는 2→1 감소의 release — 후속 채택

§2.3은 2→1 감소에서 실제 release 1개를 판정했다. 감소 경계에 연결 head가 있으면 이 규칙 때문에 같은 감소를 치는 두 입력의 결과가 갈렸다. double head 0 + double `[0,1000]` → single head 1000 + single `[1000,2000]`에서 다음과 같았다.

- ① A·B를 모두 떼고 C로 head를 치는 입력(A up 1015 → C down 1020 → B up 1030)은 B up이 감소 release로 판정됐다.
- ② A를 계속 쥔 채 B만 C로 옮기는 입력(B up 1015 → C down 1020)은 감소 release를 처리할 up이 없어 1120에 release Miss가 됐다.
- ①을 경계 전에 하면(A up 995 → C down 1000 → B up 1030) B up이 이어받은 뒤 바디의 유지 Miss가 되기도 했다(#181).

사용자는 “감소를 치는 방법 2가지인데 ab 둘다떼고 c로 치는 법 b만 c로 옮기는법 둘다 정당한 입력이라”고 했다. 기존 차트의 판정 수가 바뀌는 데 대해서는 “개발중이고 공개를 안해서 기존 판정수 바뀌는건 괜찮아”라며 감소 release를 없애는 안을 골랐다(2026-10-01).

**head가 있는 2→1 감소 경계에서는 그 head가 경계의 판정이며, 감소 release 점수 항목을 두지 않는다.** ①과 ②는 모두 정당한 입력이며 Miss 없이 처리한다. ②처럼 두 키를 쥔 채 이어가도 된다. head 없는 2→1 감소(`D=-`)는 종전대로 실제 release 1개를 판정한다([NJ-R01](../spec/note-judgment-cases.md#nj-r01)·[NJ-R03](../spec/note-judgment-cases.md#nj-r03)).

Trade-off는 이런 경계가 있는 차트의 전체 판정 수(점수 항목 수)와 이론 가중치가 줄어든다는 점이다. 미공개 개발 단계라 기존 차트의 판정 수 변화를 수용한다. 대신 같은 감소를 두 방식 중 어느 쪽으로 쳐도 같은 결과가 나온다(§2.7).

**구현 상태: 후속 PR(#181).** 그 전까지 엔진은 감소 release 항목을 남기고 §2.12의 기준대로 정확히 한 번 정산한다. 입력별 기대 결과는 그 구현과 함께 [NJ-R16](../spec/note-judgment-cases.md#nj-r16)에 정한다.

### 2.14 이어지는 바디의 유지 기준과 시작 준비 해제 — 후속 채택

#180(끝 `holdOnly`의 정산 예외) 수정을 검토하면서, head 없는 경계에서 앞 키를 뒤 바디 시작 전후에 떼는 입력의 결과가 확정 규칙끼리 서로 다르게 읽혔다. Normal(Good 120ms) 기준으로 당시 엔진의 결과는 다음과 같았다.

- head 없는 `[1000,1500]` → head 없는 double `holdOnly [1500,1560]`(1→2 증가)에서 A down 1000 뒤 A만 뗀다. up 1430이면 Miss 3(앞 바디 유지 Miss와 뒤 두 unit), 1455·1500이면 Miss 2(1620에 증가 unit, 1680에 A로 이어진 unit의 상태 Miss), 1520이면 이어진 unit Perfect와 증가 unit Miss였다. 뒤 바디가 `[1500,2000]`이면 1430·1455·1500은 Miss 3, 1520은 Miss 2였다.
- head 없는 double `[1000,1200]` → head 없는 `holdOnly [1200,1260]`(2→1 감소)에서 A·B down 1000 → B up 1160(감소 release Perfect −40) → A up 1170 → D down 1180이면 D down은 어디에도 쓰이지 않고 1380에 `holdOnly` 상태 Miss였다. 뒤 바디가 일반 `[1200,1260]`이어도 1380 release Miss였고, D 없이 A up 1170만 있어도 같았다.
- head 없는 `holdOnly [1000,1500]` → `holdOnly [1500,1560]`에서 A up 1455면 앞 `holdOnly`는 이른 완료 Perfect인데 뒤 `holdOnly`는 1680 상태 Miss였다.
- 같은 up 하나로 짧은 바디 둘 이상을 잇는 체인(예: `[1000,1500]` → double `holdOnly [1500,1560]` → `[1560,1570]`, A up 1455)에서는 판정도 점수 정산도 없이 끝나는 `holdOnly` unit이 있었다.

사용자는 다음을 정했다(2026-10-01).

- 앞 바디의 유지 기준: “1500(-good 윈도우)까지 유지만 하면 됨”
- 짧은 뒤 바디를 앞 키의 유지로 판정하는 선택지 (가): “ㅇㅇ”
- 뗀 키의 준비: “똈으면 예약을 풀어야 겠네 2가 A 1170에서 땠을떄 AB 떼면 뒤 바디를 A 가 이어갈거란 기대 할수없지 d 가 이어가야지”, 이어서 “확정”
- `holdOnly` → `holdOnly` 체인에도 같은 원칙 적용: “확정”
- 뗀 키를 같은 키로 다시 누른 입력도 새 키인지: “응 다시 같은 키 눌러도 새로운 입력”
- 새 down이 이어갈 몫(아래 결정 ①): “그럼 a를 떼도 입력할 기회는 남아있고 입력을 안했을 때만 a 입력을 인정하겠다는 거지 ㅇㅋ”
- 뗀 몫과 더 늦은 Point(아래 결정 ②): “b 990 up 판정은 아무것도 안누를때고, 지금은 c 를 눌렀으니까 b 자리를 c 가 차지해서 뒤에있는 포인트는 미스”, “리듬게임에서는 앞에서부터 입력을 처리하므로 입력 하나가 중간에 덜되면 그 이후 정당하게 입력되도 입력 이벤트가 밀림”, 그리고 “바디가 이미 끝난 뒤(E 이후)에 누른 키는 그 바디를 이어받을 수 없고 다음 노트로 간다”는 정리에 “ㅇㅋ”
- 뗀 키의 up으로 충족할 수 없는 몫(아래 결정 ③): 뗀 키의 up이 그 몫의 E−Good보다 일러 짧은 뒤 바디 규칙으로도 판정할 수 없을 때, E 이후·S+Good 전의 새 down을 (가) 아직 시작하지 않은 바디처럼 그 몫의 시작으로 받을지, (나) 결정 ②대로 다음 노트로 보낼지 묻는 질문(요지)에 “가”
- 뒤 바디 끝의 head(아래 결정 ④): 뗀 키의 up이 짧은 가운데 바디를 충족할 때, 그 바디 끝의 연결 head를 친 새 down을 (가) head에 줄지(옛 키를 떼고 새 키로 연결 head를 치는 §2.6·§2.12의 교대), (나) 결정 ②대로 가운데 바디의 인수에 쓸지 묻는 질문(요지)에 “가”
- 뗀 키의 up이 가운데 바디를 충족하지 못할 때 그 바디 끝의 연결 head를 친 새 down(아래 결정 ④의 범위, 2026-10-03): (가) 엔진처럼 head에 줄지, (나) 가운데 바디의 시작(결정 ③)에 쓸지 묻는 질문(요지)에 “A up하면 n1은 처리가 끝났고 그럼 d가 그다음 노트인 n2를 받는거 아니야?”, 이어서 “원래 a를 1560까지 누르고있어야 하는데 일찍떼서 한번 덜누른게 맞음 a를 일찍떼고 퍼펙트 하려면 d 이후에 한번더 눌러야함”. (나)로 정했다

**이어지는 바디는 자기 E−Good까지만 유지하면 된다.** 자기 release 점수 항목 없이 뒤 바디로 이어지는 바디(증가 앞의 single, 감소 double에서 이어지는 몫 등)는 등록 키를 E−Good 이후에 떼도 그 바디의 실패가 아니다. E−Good 전에 떼면 종전대로 바디 중간의 유지 실패다. 이어가지 못한 결과는 뒤 바디에서 한 번만 센다.

**짧은 뒤 바디는 앞 키를 그 E−Good까지 유지했으면 충족한다.** 뒤 바디의 E−Good이 그 시작 S보다 앞서면, 앞 키를 그 E−Good 이후까지 유지한 것으로 뒤 바디를 판정한다. [NJ-H07](../spec/note-judgment-cases.md#nj-h07)에서 S 전의 up으로 짧은 뒤 바디를 판정한 것과 같은 논리다. 뒤 바디가 `holdOnly`면 이른 완료 Perfect이고, 일반 바디면 그 up이 뒤 바디의 실제 release이며 뒤 E 기준으로 등급을 매긴다. 뒤 E−Good 전에 뗐으면 충족하지 못하므로 새 시작 입력이 없는 뒤 바디는 시작 실패다. 위 첫 차트에서 A up 1455·1500이면 A로 이어진 unit은 Perfect(1455·1500 ≥ 1440)이고, 아무도 누르지 않은 증가 unit만 Miss 1개다. 뒤 바디가 `[1500,2000]`이면 1880 전에 뗀 A로는 충족하지 못해 뒤 두 unit이 Miss 2개다. 어느 경우든 1380 이후에 뗀 앞 바디에는 Miss가 없다. 같은 up이 앞뒤로 이어진 여러 짧은 바디를 차례로 충족할 수 있으며(한 노트의 double 두 몫은 서로 다른 키가 각각 충족한다. 아래 몫별 판정 참조), `holdOnly` 상태 완료는 up을 소비하지 않으므로 같은 up이 뒤 일반 바디의 실제 release 하나도 처리할 수 있다(§2.3).

**키를 떼면 그 키의 시작 준비는 풀린다.** 뗀 키는 뒤 바디를 더 이상 예약하지 않는다. 키를 뗀 뒤 뒤 바디의 인수 기한까지 새로 누른 키가 head 없는 자기 시작으로 뒤 바디를 이어간다. 인수 창은 시작 창(S−Good, [NJ-A01](../spec/note-judgment-cases.md#nj-a01))에서 열리고, 인수 기한은 뒤 바디의 E와 시작 창 끝 S+Good 중 이른 쪽이다(아래 결정 ②). 이때 뗀 키의 up은 뒤 바디 판정에 쓰지 않는다. release로도, `holdOnly` 완료로도 쓰지 않는다. 인수 기한까지 새 키가 오지 않을 때만 뗀 키의 유지로 위 두 규칙을 적용한다. 위 감소 차트에서 A up 1170 → D down 1180이면 D가 뒤 바디를 이어간다. 뒤가 `holdOnly`면 D 유지로 Perfect이고, 일반 바디면 D의 up이 뒤 release다. 새 키가 없으면 뒤 `holdOnly`는 Perfect(1170 ≥ 1140), 일반 뒤 바디는 A up이 release Good(−90)이다.

- 뗀 키의 up은 새 키가 오거나 뒤 바디의 시작 창(S+Good)이 닫힐 때까지 잠정 후보다. 인수 기한이 E로 더 이르더라도 확정은 시작 창이 닫힐 때 한다. 창이 닫히면 그때 확정하고 등급은 실제 up 시각으로 매긴다(§2.6의 잠정 후보, §2.9의 확정 순서). 따라서 [NJ-H07](../spec/note-judgment-cases.md#nj-h07)의 이른 쪽(A up 1050)도 등급은 그대로이고 뒤 release의 확정 시각만 1180이 된다.
- 계속 쥔 키의 준비는 그대로다. [NJ-A04](../spec/note-judgment-cases.md#nj-a04)처럼 준비한 키를 경계까지 쥐고 있으면 S 근처의 새 down은 시작에 쓰지 않는다. 뗀 키의 up 뒤에 누른 새 키만 이어간다. 떼기 전에 눌러 둔 키는 임의의 raw held라 시작하지 않는다(§2.1).
- 같은 키도 떼었다가 다시 누르면 새 키다. 뗀 키가 그 노트에 남긴 등록은 새 down을 막지 않는다. `[1000,1500]` → double `holdOnly [1500,1560]`에서 A up 1455 뒤 A down 1510은 B down 1510과 같다. 새 입력이 아무도 준비하지 않은 증가 unit을 잇고, A로 이어진 unit은 A의 유지로 판정한다.
- double 뒤 바디는 몫(unit)마다 따로 적용한다. 각 몫은 그 몫을 이어받은 키 하나로 판정한다. 형제 몫의 키를 쥐고 있어도 뗀 몫의 준비는 풀리고, 뗀 몫은 자기 키의 up으로만 판정한다. 한 키의 up 하나로 두 몫을 함께 충족하지 않는다. double head 1000 + `[1000,1060]` → double `[1060,1120]`에서 A·B down 1000 뒤 B를 쥔 채 A만 1020에 떼면, 시작 창 안의 C down 1080이 A의 몫을 잇는다. 새 키가 없으면 A의 몫은 B를 언제 떼든 1180에 A up의 release Good(−100)으로 확정한다. double `holdOnly [1000,1500]` → double `holdOnly [1500,1560]`에서 A up 1430·B up 1450이면 B의 몫만 Perfect이고 A의 몫은 1620에 시작 실패다(Miss 1).
- 경계에 head가 있으면 §2.6·§2.12·§2.13과 [NJ-R16](../spec/note-judgment-cases.md#nj-r16)을 그대로 따른다. 그 경계의 새 down은 head의 입력이다(Point 소비 우선).
- 뒤 바디의 끝에 head가 있으면, 뗀 키의 up은 그 head의 교대 up(§2.6) 후보이기도 하다. 그 head가 성공하면 뒤 바디는 그 up으로 이어진 것이다. `holdOnly [1000,1500]` → `[1500,1560]` → head 1560 + `[1560,1760]`에서 A up 1450 뒤 D가 head를 1490에 치면 Full Combo다. D가 head를 먼저 치고 A를 나중에 떼도(D down 1470 → A up 1475) 같다. 이 head는 뒤 바디를 건너뛰는 더 늦은 노트가 아니라 그 바디를 잇는 입력이므로, 그 head를 친 새 down은 결정 ②의 인수에 쓰지 않고 head에 준다(아래 결정 ④). 뗀 키의 up이 뒤 바디를 충족하지 못하면(A up 1430) 뒤 바디는 아직 끝나지 않았으므로 새 down은 뒤 바디를 시작하고, head에는 따로 입력이 필요하다(결정 ④).
- `holdOnly` → `holdOnly` 체인도 같다. head 없는 `holdOnly [1000,1500]` → `holdOnly [1500,1560]`에서 A up 1455면 앞은 이른 완료 Perfect, 뒤는 1455 ≥ 1440이라 Perfect다. 뒤가 `[1500,2000]`이면 새 키가 필요하고 없으면 뒤만 Miss다. 뒤 시작 창 안에 D를 누르면 D가 이어간다.

§2.1의 “이미 정당한 승계로 준비된 unit은 추가 시작 down을 소비하지 않는다”는 준비한 키를 쥐고 있는 동안의 규칙으로 읽는다. §2.12·§2.13은 head가 있는 경계의 규칙이며 바꾸지 않는다. 사용자 확인 사례는 [NJ-A07](../spec/note-judgment-cases.md#nj-a07)이다. 이 규칙만으로 결과가 하나로 정해지지 않던 인접 사례 네 가지(짧은 double 뒤 바디에서 새 down이 이어갈 unit, 더 늦은 Point와 겹치는 시작 창, 뗀 키로 충족할 수 없는 몫의 E 이후 시작, 뒤 바디 끝의 head)는 아래 결정 ①~④로 정했다.

**구현 상태(2026-10-01).** 형제 키를 쥔 채 뗀 몫을 시작 시각 S 이후에 새 키·같은 키 재누름으로 이어받는 경우는 현재 엔진에서 S에 바로 시작 실패한다(#198과 함께 수정 예정). 예: double head 0 + `[0,1000]` → double `[1000,1500]`에서 A·B down 0 → B up 990(또는 200) 뒤 C down 1050(또는 B down 1030)이면 규칙상 새 키가 B의 몫을 이어받아 Full Combo이고, 새 키가 없으면 B의 몫은 1120(S+Good)에 시작 실패해야 하나 엔진은 둘 다 1000에 시작 실패로 처리한다. 뗀 키의 up이 그 몫의 E−Good 이후라 S 전에 승계가 정해지는 짧은 뒤 바디(위 double head 1000 + `[1000,1060]` → double `[1060,1120]` 예)는 구현되어 있다. 추적은 [PRD §12](../prd.md#12-미정-사항)를 따른다.

**결정 ①: 새 down은 아무도 준비하지 않은 몫부터 채운다.** 같은 노트에서 새 down은 먼저 아무도 준비하지 않은 몫(증가로 늘어난 unit 등)을 시작하고, 남은 새 down이 뗀 키의 몫을 이어받는다. 뗀 몫은 새 키가 이어받지 않을 때만 뗀 키의 up으로 판정한다(위 짧은 뒤 바디 규칙). 사용자는 이를 “a를 떼도 입력할 기회는 남아있고 입력을 안했을 때만 a 입력을 인정”으로 정리해 확정했다(2026-10-01). 종전 엔진 동작을 그대로 확정한 것이다. `[1000,1500]` → head 없는 double `[1500,1560]`에서 A down 1000 → A up 1455 뒤 B만 1500에 누르면 B가 증가 unit을 채우고 A의 몫은 A up으로 판정한다. `holdOnly`면 Perfect 2개, 일반 double이면 B up 1560의 release Perfect와 A up의 release Good(−105)로 Miss가 없다. B와 C를 1500에 함께 눌러 1560에 떼면 C가 A의 몫을 이어받아 두 경우 모두 Perfect 2개이며 A up은 쓰지 않는다.

**결정 ②: 뗀 몫의 인수는 더 늦은 Point보다 앞서되, 바디가 끝난 뒤에는 이어받지 않는다.** 준비한 키를 뗀 뒤 그 몫의 인수 기한까지 누른 새 down은, 그 down이 더 늦은 Point의 창 안에 있어도 뗀 몫을 이어받는다. 입력은 앞의 노트부터 처리하므로(§2.2, [가장 이른 노트 매칭](../context/glossary.md#가장-이른-노트-매칭)) 뗀 몫이 더 늦은 Point보다 앞이다. Point는 자기 입력이 따로 필요하고, 없으면 Miss다. 사용자는 이로 인해 뒤 입력이 밀리는 것을 리듬게임의 정상 특성으로 받아들였다([배드말림](../context/glossary.md#배드말림-bad-train)). 인수 기한은 뒤 바디의 E와 S+Good 중 이른 쪽이다. S+Good이 지나면 충족하지 못한 몫은 이미 실패이고, E가 지나면 바디를 유지할 수 없다. 기한 뒤의 down은 그 바디를 이어받지 않고 다음 노트로 간다. 기한까지 새 down이 없으면 뗀 키의 up이 그 몫을 판정한다(결정 ①과 같은 뜻).

- 인수 기한 E는 포함한다. E 시각의 down은 바디를 이어받는다. `holdOnly`는 그 시각에 Perfect이고([NJ-A06](../spec/note-judgment-cases.md#nj-a06)의 E 이후 첫 활성화와 같은 상태 판정), 일반 바디는 새 키의 up을 E 기준으로 판정할 수 있다. 엔진의 다른 창(S+Good, Point의 Good)도 끝 시각을 포함한다.
- [NJ-A04](../spec/note-judgment-cases.md#nj-a04)는 그대로다. 준비한 키를 경계까지 쥐고 있으면 그 몫은 풀린 몫이 아니므로 S 근처의 새 down은 더 늦은 Point로 간다. 결정 ②는 준비한 키를 뗀 몫에만 적용한다.
- 아무도 준비하지 않은 unit(결정 ①의 증가 unit, [NJ-A06](../spec/note-judgment-cases.md#nj-a06)의 독립 바디)은 종전대로 S+Good까지 첫 활성화할 수 있다. E 이후의 금지는 앞 키가 준비했던 몫을 뗀 키의 up이 충족할 때만 적용한다. 뗀 키의 up이 그 몫의 E−Good보다 일러 충족하지 못하는 몫은 결정 ③을 따른다.
- 뗀 키의 up이 그 몫을 충족하면, 그 몫의 끝(E)에 있는 연결 head는 위 bullet처럼 그 바디를 잇는 입력이므로 이 우선의 대상이 아니다(결정 ④).
- 예: NJ-A04 모양 double head 0 + `[0,1000]` → head 없는 double `[1000,1060]` → Point 1100에서 A·B down 0 → B up 990. C down 995 → C up 1000 → A up 1060이면 C가 B의 몫을 이어받아 C up이 그 몫의 release Great(−60), A up은 Perfect, 입력 없는 Point는 1220에 Miss다. C를 1060까지 쥐고 D down 1100이면 모두 Perfect다. C down 1090은 E 1060 뒤라 Point Perfect(−10)이고 B의 몫은 B up의 Great(−70)이다. 종전 엔진은 C down 995를 Point에 주고, 그 뒤 E 이후의 D down 1100이 B의 몫을 이어받아 B의 몫을 쥔 적 없는 D의 up으로 release를 판정했다. 뒤 바디가 `holdOnly`여도, 첫 head를 S+Good 안에서 늦게 쳐도(§2.7) 같다.
- 결정 ②로 [NJ-A07](../spec/note-judgment-cases.md#nj-a07)의 도출 대조 하나를 정정한다. 감소 차트에서 B up 1160 → A up 1170 뒤 E 1260을 지난 D down 1300은 뒤 바디를 이어받지 않는다. 뒤 `holdOnly`는 A로 1320에 Perfect, 일반 뒤 바디는 A up의 release Good(−90)을 1320에 확정한다. 종전 대조는 D가 이어가 `holdOnly`는 1300 Perfect, 일반은 D up 1310의 Great(+50)였다.

**결정 ③: 뗀 키의 up으로 충족할 수 없는 몫은 S+Good까지 새 down으로 시작한다.** 뗀 키의 up이 그 몫의 E−Good보다 일러 짧은 뒤 바디 규칙으로도 그 몫을 판정할 수 없으면, 그 몫은 아직 시작하지 않은 바디와 같다. 바디의 E가 지났어도 S+Good까지의 새 down은 그 몫을 시작한다([NJ-A06](../spec/note-judgment-cases.md#nj-a06)의 E 이후 첫 활성화와 같음). 결정 ②의 E 기한은 뗀 키의 up이 그 몫을 충족해 새 키가 없을 때의 판정이 있는 경우에만 적용한다. 사용자는 이를 “가”로 정했다(2026-10-01).

- 예: head 없는 `holdOnly [1000,1200]` → `[1200,1300]`에서 A down 1000 → A up 1150이면 앞 `holdOnly`는 1150에 이른 완료 Perfect이지만, A up은 뒤 E−Good 1180 전이라 뒤 바디를 충족하지 못한다. E 1300 이후 S+Good 1320까지인 C down 1310 → C up 1330이면 C가 뒤 바디를 시작해 release Perfect(+30, E 기준)이고 Full Combo다. 뒤가 `holdOnly [1200,1300]`이면 C down 1310 시각에 Perfect다. C down 1290(E 전)은 종전과 같고, C down 1321(S+Good 뒤)은 뒤 바디를 시작하지 못해 1320에 시작 실패다. 종전 엔진은 E 이후의 C down을 결정 ②로 막아 1320에 시작 실패했다.
- 앞이 감소 double이어도 같다. double `[1000,1200]` → `[1200,1300]`에서 B up 1100(감소 release Good −100) → A up 1150 → C down 1310이면 C가 뒤 바디를 시작한다.
- 결정 ②의 예는 그대로다. NJ-A04 모양 차트에서 B up 990은 B의 몫(E−Good 940)을 충족하므로 E 1060 뒤의 C down 1090은 Point로 간다.
- (규칙에서 도출) 한 up은 release 하나만 처리하므로, 다른 노트의 뗀 몫이 자기 release로 판정할 up은 이 몫을 충족하지 않는다. double head 1000 + `[1000,1500]` → double `[1500,1560]` → `[1560,1600]`에서 A·B down 1000 → B up 1450 → A up 1485면 A up은 감소 release Great(−75)이고 B up은 끝 E−Good 1480 전이라, 끝 E 1600 이후 S+Good 1680 전의 C down 1610이 끝 바디를 시작한다.
- (규칙에서 도출) 관측이 늦은 up도 raw 시각으로 판단한다. 뒤 S 전에 뗀 up을 S 이후에 관측해 그 몫이 이미 그 키로 승계되었어도, raw up이 E−Good 전이면 충족할 수 없는 몫이다.

**결정 ④: 뒤 바디 끝의 head를 친 새 down은 뗀 키의 up이 그 바디를 충족할 때만 head에 쓴다.** 뗀 키의 up이 짧은 가운데 바디를 충족하면, 그 바디 끝의 연결 head를 친 새 down은 가운데 바디의 인수(결정 ②)가 아니라 head의 입력이다. 옛 키를 떼고 새 키로 연결 head를 치는 §2.6·§2.12의 교대이며, head가 성공하면 가운데 바디는 뗀 키의 up으로 이어진 것이다. 위 bullet의 `holdOnly [1000,1500]` → `[1500,1560]` → head 1560 + `[1560,1760]`에서 A down 1000 → A up 1450 → D down 1490을 1760까지 쥐면 head Great(−70)이고 D가 `[1560,1760]`을 이어 Full Combo다. 사용자는 이를 “가”로 정했다(2026-10-01).

뗀 키의 up이 가운데 바디를 충족하지 못하면(그 바디의 E−Good 전) 새 down은 head가 아니라 가운데 바디를 시작한다(결정 ③). 사용자는 이를 (나)로 정했다(2026-10-03). 원문: “A up하면 n1은 처리가 끝났고 그럼 d가 그다음 노트인 n2를 받는거 아니야?”, “원래 a를 1560까지 누르고있어야 하는데 일찍떼서 한번 덜누른게 맞음 a를 일찍떼고 퍼펙트 하려면 d 이후에 한번더 눌러야함”.

- 두 경우는 한 규칙으로 읽는다. 새 down은 아직 끝나지 않은 가장 이른 노트에 간다(§2.2, [가장 이른 노트 매칭](../context/glossary.md#가장-이른-노트-매칭)). A up 1450은 앞 `holdOnly`와 가운데 바디(짧은 뒤 바디 규칙, 1450 ≥ 1440)를 함께 끝내므로 D down 1490은 다음 노트인 head로 간다. A up 1430은 앞 `holdOnly`만 끝내고, 가운데 바디는 결정 ③대로 S+Good 1620까지 열려 있으므로 D down 1490은 가운데 바디를 시작한다.
- 이때 끝 head는 자기 입력이 따로 필요하다. D를 1760까지 쥐기만 하면 head 1560은 1680에 Miss이고, D가 `[1560,1760]`을 이어 D up 1760이 release Perfect다. Miss 1, 달성률 66.7%다. A를 일찍 떼고도 Full Combo를 하려면 D 뒤에 head를 한 번 더 누른다. 다른 키 E down 1560이면 D의 up(1550, E와 같은 1560, 경계 뒤 1600)은 그 head의 교대 up이다. 같은 키를 다시 누르는 것도 새 입력이다(D up 1550 → D down 1560, 경계 뒤 교대 D up 1575 → D down 1580). 어느 경우든 head Perfect와 끝 release Perfect로 Full Combo다.
- (규칙에서 도출) 충족하지 못한 가운데 바디는 E 1560이 지나도 S+Good 1620까지 새 down으로 시작하므로(결정 ③), 그 사이의 D down 1600·1620도 head가 아니라 가운데 바디로 가고 head는 1680에 Miss다.
- (규칙에서 도출) 관측이 늦은 up도 raw 시각으로 판단한다(결정 ③). A up(raw 1430)을 가운데 S 이후 1502에 관측해 가운데 바디가 이미 A로 승계되었어도 D down 1510은 가운데 바디를 시작한다.
- 종전 엔진은 충족 여부와 관계없이 그 head를 친 새 down을 head에 주었다. A up 1430 → D down 1490이면 head Great(−70)와 가운데 바디의 1620 시작 실패로 달성률이 88.9%였다. Miss 수는 같지만 점수가 달라 결정이 필요한 선택이었다(PR #188 리뷰 5차).

Trade-off는 짧은 뒤 바디의 결과가 뒤 시작 창이 닫힐 때까지 늦게 확정된다는 점, 그리고 새 키로 이어가면 뗀 키만으로 충족했을 결과를 버리므로 새 키를 일찍 떼면 Miss가 될 수 있다는 점이다. 결정 ②에 따라 뗀 몫을 이어받은 새 down은 더 늦은 Point에 쓰이지 않으므로, 그 Point를 노린 입력이 밀려 Point가 Miss가 될 수 있다. 뗀 키의 up이 충족하지 못한 몫의 끝 head도 같다(결정 ④). 대신 두 키를 떼고 새 키로 이어가는 자연스러운 입력을 인정하고, 입력을 앞의 노트부터 처리하며, 바디가 끝난 뒤의 down이 그 바디를 쥔 적 없이 판정하는 일을 막고, 이어가지 못한 한 번의 실패를 앞뒤 바디에 이중으로 세지 않는다.

## 3. 대안과 채택 이유

| 대안 | 처리 |
|---|---|
| unit마다 고정 물리 owner 배정 | 채택하지 않는다. 유지 키 수, 시작 준비, release 권한으로 설명한다. |
| 모든 바디가 새 down을 요구 | 정당한 승계까지 막으므로 채택하지 않는다. 부족한 시작만 입력을 요구한다. |
| 양수 길이 `holdOnly`도 raw held 또는 다른 Point의 down을 공유해 독립 시작 | 채택하지 않는다. 정상적인 앞 노트의 입력이 뒤 바디를 조기 실패시키는 문제와 시작 생략을 막는다. |
| `holdOnly` 자동 완료가 held 키 자격까지 소비 | release 면제 후에도 물리 감소를 요구하므로 채택하지 않는다. |
| 실제 release를 가까운 끝점에 우선 배정 | 채택하지 않는다. 앞의 유효한 미처리 release 우선을 유지한다. |
| 연결 유지 실패를 별도 점수 감점 또는 콤보 점수로 보정 | 채택하지 않는다. 고도·콤보·Miss 기록으로 유지 동기를 둔다. |

폐기안은 배경 기록이다. [사례 명세](../spec/note-judgment-cases.md)의 기대 결과에 대안 결과를 섞지 않는다.

## 4. Trade-off

- 물리 owner를 고정하지 않는 대신, 완료한 점수 항목과 아직 결정할 수 있는 종료·승계 배정을 구분해야 한다.
- `holdOnly`는 의도적으로 release와 후속 재누름 부담을 낮춘다. 임의의 raw held에 같은 효과를 주지 않는다.
- 짧은 double에서 두 키를 겹쳐 누르지 않아도 모든 필수 down/up이 자기 창 안에 있으면 성공할 수 있다.
- 일반 연결 유지 실패에 직접 점수 손실이 없으므로 특이한 플레이가 100% 달성률에 도달할 수 있다. Full Combo와 고도가 이를 별도로 드러낸다.
- 차트 끝점과 길이 0 노트를 중복 인코딩하지 못하게 하여, 같은 끝 표현의 복구 동작이 저장 형태에 따라 달라지는 것을 막는다.

## 5. 사례를 동작 정의와 함께 유지

- 특수 사례에는 안정된 ID, 구체적인 한국어 테스트명, 차트, 초기 held·등록 상태, 시간순 입력, 판정 대상·등급, 후속 unit 상태를 기록한다.
- 같은 물리 입력이 여러 효과를 내면 실제 소비 대상과 상태 완료를 구분한다.
- 일반 여분 키와 `holdOnly` 면제 몫처럼 결과가 다른 인접 사례를 함께 둔다.
- 사용자에게 직접 확인한 사례와 채택 규칙에서 도출한 대조 사례를 구분한다. 기대 결과를 추가로 결정해야 하는 후보는 확정 사례로 쓰지 않는다.
- 사례는 엔진 내부 필드나 구현 함수를 정답으로 삼지 않는다. 구현 시 ID를 테스트명에 남기고, 판정 대상·횟수·등급·부활 여부를 검증한다.
