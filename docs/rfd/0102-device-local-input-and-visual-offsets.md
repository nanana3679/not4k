# RFD 0102: 입력·시각 오프셋과 마스터 볼륨은 기기별로 저장한다

**Status:** Accepted (2026-10-29) · glossary·컨텍스트·게임 코어·PRD·MVP 문서 반영 (2026-10-29), 계정 설정 동기화 미구현 · 마스터 볼륨의 기기별 저장·동기화 제외 문서 반영 (2026-10-29) · 로그아웃 후 게임 설정 유지·비로그인 로컬 저장 문서 반영 (2026-10-30) · 로그인 시 서버 설정 불러오기 실패의 로컬 유지·안내 문서 반영 (2026-10-30) · 설정 서버 저장 실패 시 로컬 변경값 유지·안내 문서 반영 (2026-10-30) · 설정의 로컬 선적용·닉네임과의 확정 시점 구분 문서 정리 (2026-10-30) · 최초 실행·디버그 상태의 기기별 저장 결정 및 계정 설정 동기화 구현·단위 테스트 반영 (2026-10-31) · 새 브라우저의 최초 실행 종료·저장하지 못한 변경의 다음 접속 업로드 결정 및 구현·단위 테스트 반영 (2026-10-31, PR #407) · 저장하지 못한 변경을 키 단위 값으로 기록(`unsyncedAccountSettings`)하도록 재설계·단위 테스트 반영 (2026-10-31, PR #407)

## 기존 결정과 문제의식

기존 게임 코어와 PRD는 입력·시각 오프셋을 계정 설정 동기화에 포함하고, 로그인 시 서버 설정을 우선하도록 정했다. 이 방식은 다른 기기에서 저장한 보정값이 현재 기기의 값을 덮어쓰게 한다.

## 검토한 대안과 채택안

입력 오프셋 `inputOffsetMs`와 시각 오프셋 `visualOffsetMs`는 해당 기기의 브라우저에 로컬 설정으로 저장한다. 계정 설정 동기화 대상에서 제외하며, 로그인 여부와 관계없이 해당 기기의 값을 유지한다(사용자 확인, 2026-10-29).

마스터 볼륨 `masterVolume`도 기기별 브라우저에 저장하고 계정 설정 동기화에서 제외한다. 로그인 여부와 관계없이 해당 기기의 볼륨을 유지한다(사용자 확인, 2026-10-29).

최초 실행 상태 `isFirstLaunch`와 디버그 상태 `debugMode`도 해당 브라우저의 상태이므로 기기별로 저장하고 계정 설정 동기화에서 제외한다. 서버에 값이 있어도 현재 브라우저의 값을 덮어쓰지 않는다(사용자 확인, 2026-10-31).

모든 설정을 계정에 동기화하는 대안 대신, 두 오프셋은 기기마다 조정하는 방식을 택한다. 새 기기에서는 별도로 보정해야 하지만 다른 기기의 보정값으로 현재 값을 덮어쓰지 않는다.

게임 설정의 변경은 현재 브라우저에 먼저 적용하고 저장한 뒤 동기화 대상만 서버에 저장한다. 현재 기기에서 쓸 설정이므로 서버 저장 성공을 적용 조건으로 두지 않는다. 닉네임은 랭킹에 쓰이는 계정 정보로서 서버 저장 성공 후 확정하는 별도 정책을 따른다([RFD 0094](0094-settings-profile-tab.md), 사용자 확인, 2026-10-30).

나머지 계정 설정은 로그인 시 선택창 없이 서버 설정을 우선한다. 서버에 설정이 없으면 동기화 대상인 로컬 설정만 업로드하며, 두 오프셋·마스터 볼륨·최초 실행 상태·디버그 상태는 업로드하지 않는다. 차트 오프셋 `offsetMs`는 이 결정의 대상이 아니다.

로그아웃한 뒤에도 직전에 사용하던 키 바인딩·스크롤 속도 등 게임 설정을 유지한다. 비로그인 상태에서 변경한 설정은 해당 브라우저에 저장한다. 다음 로그인에는 기존의 서버 설정 우선 규칙을 적용하며, 서버 설정이 없을 때만 동기화 대상인 로컬 설정을 업로드한다(사용자 확인, 2026-10-30).

로그인 시 서버 설정을 불러오지 못하면 현재 브라우저 설정으로 계속 진행하고 불러오기 실패 안내를 표시한다. 설정 불러오기 실패를 로그인 실패로 처리하지 않는다. 불러오기 실패는 서버에 설정이 없는 경우와 구별하며, 서버 설정이 없다고 확인되지 않은 상태에서 로컬 설정을 업로드하지 않는다(사용자 확인, 2026-10-30).

로그인 상태에서 변경한 계정 설정을 서버에 저장하지 못해도 변경값은 해당 브라우저에 유지하고 저장 실패 안내를 표시한다(사용자 확인, 2026-10-30).

새 브라우저에서 로그인한 계정의 서버 설정을 불러오면 이 브라우저에서는 첫 기동의 프리셋 선택을 건너뛰고 계정의 키 바인딩을 그대로 쓴다(사용자 확인, 2026-10-31).

로그인 상태에서 서버에 저장하지 못한 계정 설정 변경은 이 브라우저에 표시해 두었다가, 같은 계정의 다음 접속 때 서버 설정 대신 다시 업로드한다(사용자 확인, 2026-10-31).

## 영향과 검증

상세 동작은 [게임 코어의 계정 설정 동기화](../spec/game-core.md#계정-설정-동기화)에 모으고, PRD·MVP에는 요약과 링크를 둔다.

glossary를 먼저 갱신하고 루트·Gameplay·Online services 컨텍스트, 게임 코어, PRD와 MVP 범위를 동기화한다. 기기 전용 다섯 설정을 서버 저장 대상으로 설명한 문구가 남지 않는지, 기존 단위·부호·보정 계산식이 유지되는지 확인한다.

2026-10-31 계정 설정 동기화를 구현했다. 게임 루트에서 인증 상태를 구독하고, `user_settings`의 불러오기·저장을 별도 어댑터로 처리한다. 기기 전용 5개 설정 제외·서버 값 검증·불러오기 실패 후 업로드 차단·저장 지연과 flush·계정 전환 시 오래된 요청 무효화를 단위 테스트로 검증한다. 현재 구현의 재시도·저장 주기는 [게임 코어](../spec/game-core.md#계정-설정-동기화)에 기록한다.

같은 날 리뷰 후속으로 새 브라우저의 최초 실행 종료와 저장하지 못한 변경의 기록(`unsyncedAccountSettings`)을 구현했다. 함께 저장 시 서버 행에서 이 클라이언트가 모르는 키를 보존하고, 숫자 설정을 설정 UI 범위로 제한하고 스킨 목록에 없는 `skinId`를 받지 않으며, 불러오기 실패가 이어지는 동안 실패 안내를 한 번만 표시한다. 로그아웃 전에 대기 저장을 보내지 않는다. 동기화는 세션이 지워진 뒤(`SIGNED_OUT`)에야 로그아웃을 알아 인증된 저장을 보낼 수 없으므로, 버린 대기 저장의 값은 `unsyncedAccountSettings`에 남아 같은 사용자의 다음 접속에서 업로드한다.

구현에서 정한 세부는 다음과 같다. 받을 수 있는 `keyBindings`가 있는 서버 행을 적용할 때 최초 실행을 끝내며, 그때 프리셋 선택 화면이 열려 있으면 프리셋을 고른 뒤 가는 화면으로 넘어간다. 서버에 설정이 없거나 서버 행에 받을 수 있는 `keyBindings`가 없으면 프리셋 선택은 기존과 같다. 최초 실행 상태는 계속 기기별로 저장한다. 최초 실행 중인 브라우저가 행 없음을 확인하면 아직 고르지 않은 기본 `keyBindings`·`preset`도 포함한 동기화 대상 설정 전체를 최초 업로드한다. 그래서 최초 실행 중 로그인해 프리셋을 고르기 전에 떠나면 기본 키 바인딩이 계정의 키 바인딩이 되고, 다른 새 브라우저는 그 행으로 프리셋 선택을 건너뛴다(알려진 동작). 두 키를 빼고 최초 업로드하던 앞선 구현은 기본값과 같은 TKL 선택을 끝내 업로드하지 못하고 삽입·불러오기 중의 선택을 놓쳐 되돌렸다.

서버에 저장하지 못한 변경은 `unsyncedAccountSettings`(localStorage `not4k-account-settings-unsynced`)에 사용자 id별로, 바꾼 계정 설정 키와 바꿀 때의 값으로 기록한다. 로그인 상태에서 계정 설정을 바꿀 때마다 기록하며 불러오기 중이나 불러오기 실패 뒤의 변경도 기록한다. 로그아웃 상태의 변경은 기록하지 않는다. 최초 실행 중의 변경(첫 기동 프리셋 선택)은 계정 행을 아직 모를 때(불러오는 중·불러오기 실패 뒤)만 기록하지 않아 다음 불러오기에서 계정의 키 바인딩을 덮지 않으며, 계정 행의 유무를 확인한 뒤(행을 찾아 적용했거나 행이 없어 최초 삽입을 시작한 뒤)의 프리셋 선택은 최초 삽입 중이어도 기록해 그 저장이 실패해도 다음 접속에서 업로드한다. 최초 업로드 실패는 기록하지 않는다. 같은 사용자의 다음 접속에서 불러오기에 성공하면 서버 행을 적용하고 그 사용자의 기록을 위에 얹어 적용한 뒤 업로드한다. 서버 행에 없거나 서버 행에서 받지 않은 키는 이 탭의 메모리 값으로 채운다. 서버에 설정이 없으면 기록을 로컬 위에 얹어 기존처럼 덮어쓰지 않는 최초 업로드를 한다. 업로드에 성공하면 업로드한 값과 아직 같은 기록만 지워 그 사이 다른 탭이 기록한 더 새 값은 남긴다. 다만 localStorage에는 탭 사이 잠금이 없어, 기록을 지우려고 읽고 다시 쓰는 사이에 다른 탭이 기록한 더 새 값은 잃을 수 있다. 기록을 읽어 서버 행 위에 얹는 것은 불러오기 직후의 업로드뿐이며, 그 뒤의 일반 저장은 이 탭의 메모리 설정을 업로드하고 탭 사이에서는 마지막 저장이 이긴다. 다른 사용자의 기록은 그 사용자 자신의 값이라 그대로 둔다. 페이지를 닫을 때 보내지 못한 저장은 이 기록으로 다음 접속에서 이어 보내므로 페이지 종료 시의 keepalive 저장은 두지 않는다. 앞선 구현은 사용자 id 하나만 표시하고 탭의 메모리 설정 전체를 업로드해, 오래된 탭이 다른 계정이나 옛 값을 업로드하고 불러오기 실패 중의 프리셋 선택이 계정의 키 바인딩을 덮어쓸 수 있어 이렇게 바꿨다.

서버의 `playSpeed`는 슬라이더 최솟값 이상, `renderHeight`는 설정 UI 선택지 값만 받는다. 로컬 복원은 개발·E2E가 쓰는 값 때문에 두 설정에 UI 최솟값을 적용하지 않는다. 설정 UI 범위는 설정 패널과 복원 정규화가 같은 상수를 쓴다. 세부는 [게임 코어](../spec/game-core.md#계정-설정-동기화)에 기록한다.
