# RFD 0037: 명시적 점수 노트와 무점수 바디

**Status:** Accepted (2026-10-25) · 2026-10-24～2026-10-25 제품 논의 §1～104 통합 · 공식 문서·대표 사례 반영 · RFD 0039·0040 후속 결정 동기화 (2026-10-26) · 런타임 구현은 후속 PR

이 문서는 새 판정 모델의 채택 계약이다. 기존 엔진의 실행 결과나 구현 완료 보고가 아니다. 과도기의 구형 의미는 §8에 따라 보존한다. 이 문서와 충돌하는 RFD 0020·0032의 연결 up 소비·자동 끝 점수·`holdOnly` 규칙은 새 모델에 적용하지 않는다. 충돌하지 않는 입력 시간·실패 비중복·트릴 규칙과 기존 실행 기록은 보존한다. 미정 사항과 구현 이행은 [PRD §12](../prd.md#12-미정-사항)에서 추적한다.

## 1. 기존 결정과 문제

구형 모델은 바디 끝에서 release 또는 `holdOnly` 점수를 만들고, 연결 Point의 교대 up에도 별도 소비 의미를 부여한다. 이는 바디 유지, 실제 누름·뗌 요구, 점수 항목을 한 구조에서 추론하게 한다. 릴리즈를 차트에 명시하기로 한 이상, 명시하지 않은 끝에 입력이나 점수를 자동 생성하면 그 의미가 다시 모호해진다.

[RFD 0035](https://github.com/nanana3679/not4k/blob/30ef57ffc35599b165f859361372d7258d500857/docs/rfd/0035-release-presence-and-grace.md)의 릴리즈 유무·Grace 분리와 [PR #338](https://github.com/nanana3679/not4k/pull/338)의 유지 노트 제안을 검토한 뒤 후속 논의를 반영했다. **PR #338의 구형 제안은 이 RFD의 채택 계약으로 철회·대체한다.** 일반 릴리즈의 별도 창 확대는 철회했고, 유지 노트의 독립 창·이른 down 선판정·Good 예외도 폐지했다. 일반 릴리즈는 누름과 같은 창을 쓰고 유지 노트는 바디 상태만 따른다. 이 문서는 #338을 수정·닫기·병합하는 작업을 포함하지 않는다. 구형 차트 자동 변환 대신 사람이 수정하는 과도기를 둔다.

연결 바디에서 의미 없는 콤보 증가가 없어지는 것은 이 분리에서 따라오는 부가 효과다. 결정의 근거는 명시한 입력·점수 요구를 차트 그대로 읽을 수 있게 하는 것이다.

## 2. 구성과 점수 의미

- 바디는 같은 레인에서 필요한 hold 수를 요구하는 구간이다. 점수 항목·이론 가중치는 0이며 down·up을 소비하지 않는다. 양수 길이와 길이 0을 허용한다.
- Point는 누름 점수 노트이며 down 하나를 소비한다. 같은 down의 hold가 바디 조건도 충족할 수 있다.
- 릴리즈는 뗌 점수 노트이며 실제 up 하나를 소비한다. 바디 끝 또는 바디 밖 단독 위치에 명시한다. 바디나 감소량에서 자동 생성하지 않는다.
- 유지 노트는 소속 바디의 상태로 확인하는 명시적 점수 표식이다. 자체 입력을 소비하거나 바디 경계를 만들지 않는다.
- Point·릴리즈·유지 노트는 요구 한 몫당 점수 항목 하나와 이론 가중치 3을 만든다. 더블은 두 항목이며, 편집에서는 하나의 노트다. 바디 hold 수와 끝 릴리즈 수를 같게 강제하지 않는다.
- 새 모델에는 `holdOnly`를 두지 않는다. 릴리즈 없는 바디의 정상 종료에 자동 Perfect·점수·콤보를 만들지 않는다.
- 일반 Point·릴리즈는 기존 누름의 Perfect·Great·Good 창을 공유하며 등급별 앞뒤 폭이 같다. Grace Point·릴리즈는 같은 Good 최대 창 안에서 실제 입력을 요구하고 타이밍 등급은 항상 Perfect다. 다만 기존 트릴 교대 실패 `goodTrill`(화면 GOOD◇)은 Grace 트릴 Point에도 그대로 적용하므로, Grace라도 교대에 실패하면 Good◇다. Grace의 타이밍 오차·FAST/SLOW는 표시·집계하지 않는다.
- 하나의 더블 릴리즈는 두 항목의 일반/Grace 종류를 통일한다. 일반 한 항목과 Grace 한 항목을 섞은 더블 릴리즈는 허용하지 않는다. 저장 왕복과 편집의 종류 변경에서도 이 구분을 보존한다.

정식 용어 정의는 [glossary](../context/glossary.md), 저장 필드·배열·ID·API 이름은 공용 모델 구현이 소유한다. 이 문서의 의미 구분을 구형 `holdOnly` 속성 하나로 위장하지 않는다.

## 3. 바디 시작·유지·끝과 릴리즈 자격

### 3-1. 시작 시각과 유지

시작 창 전부터 누른 키로는 창이 열릴 때 미리 시작하지 않는다. 차트상 바디 시작 시각에 필요한 hold가 충족되면 시작한다. 시작 창 안의 유효한 새 down은 그 시각부터 충족하는 몫을 시작하며 down을 소비하지 않는다. head 없는 1→2 증가의 추가 몫에도 같은 규칙을 적용한다.

실제 바디 경계는 새 시작 판단 지점이다. 이어진 바디를 앞 종료·뒤 시작으로 나누어 읽는 연주도 허용한다. 다만 이미 실패한 구간의 실패 공유·승계 규칙은 §4를 따른다. 정상 승계된 키가 계속 눌려 있으면 뒤 바디는 차트상 시작 시각에 시작한다. 짧은 뒤 바디의 시작 Point가 미처리라는 이유로 이 건강한 승계를 미시작으로 바꾸지 않는다.

Point가 맡는 몫과 다른 몫의 시작·실패를 구별한다. single Point가 있는 double에서 Point를 놓쳐도 다른 한 몫은 자기 조건으로 시작할 수 있다. 건강한 승계가 없는 첫 Point 실패의 종속 규칙을 미리 누름 규칙만으로 없애지 않는다. Point 담당 몫의 유지 실패 대기와 유효한 실제 Point down 기준은 RFD 0032 §4-3·§5-2～5-4의 충돌하지 않는 계약을 보존한다. 이미 확정한 실패나 정상 완료를 뒤 Point 입력으로 되돌리지는 않는다.

**double Point로 시작하는 single 바디(사용자 결정, 2026-10-26):** 바디는 두 Point 몫 중 어느 쪽이든 먼저 성공한 Point down의 시각에 시작하고 그 키를 유지 키로 등록한다. 바디의 Point Miss 실패는 Point의 모든 몫이 Miss일 때만 생기며, 한 몫만 Miss면 그 Point 항목만 Miss다. 구형의 [head와 unit](../context/glossary.md#롱노트-판정-모델) 규칙과 같다. 구현은 #342다.

같은 시각의 입력을 반영한 뒤 hold 부족을 판단한다. 유지 유예와 head 없는 시작 직후의 기존 재충전은 보존한다. Point가 있는 double의 비담당 몫에도 시작 창 끝까지 재충전을 새로 넓히는 안은 채택하지 않았다. 이미 시작한 해당 몫에는 기존 유지 유예를 적용한다. 유지 유예 20ms는 사례에서 쓰는 임시 값이며 최종 튜닝 값의 확정이 아니다.

### 3-2. 짧은 바디와 이른 정상 종료

릴리즈가 바디에 연결되면 그 바디가 실제로 시작한 것이 판정의 전제다. 끝 창에 들어왔다는 이유만으로 미시작 바디를 릴리즈하지 못한다. 짧은 바디도 새 down은 시작 창 안에서 해야 하며 끝 창을 시작 허용 범위로 덧붙이지 않는다.

실제 시작한 바디는 자기 끝의 Good 이른 폭 안에서 일찍 정상 종료할 수 있다. 일반 릴리즈가 있으면 그 up의 등급을 별도로 판단한다. 릴리즈 없는 바디에도 같은 이른 종료 허용 폭을 쓰되 늦은 뗌 요구를 추가하지 않는다. 바디 정상 완료와 명시 릴리즈의 남은 판정 기회는 별도 상태다.

**이른 종료 창 직전의 유지 부족(사용자 결정, 2026-10-26):** hold 부족이 이른 종료 창(E − Good) 직전에 시작했다면 그 유지 유예 20ms가 창 안에서 끝나도 유지 실패다. 유지 유예는 이른 종료 창(Good 120ms)을 넓히지 않는다. 예를 들어 끝 E가 2000ms인 single 바디를 1875ms에 떼고 다시 누르지 않으면 1895ms에 바디 유지 실패 Miss이고, 끝 릴리즈는 종속 0점이다. 릴리즈 없는 바디도 같은 유지 실패 Miss다. 현재 엔진 동작이며 회귀 테스트는 #342에서 고정한다.

single 바디의 차트상 끝이 지났어도 시작 창 안인 유효한 첫 down이면 실제 시작 → 즉시 유지 완료 → 명시 릴리즈 대기로 처리한다. 추가 유지 시간·바디 점수·자동 릴리즈 성공을 만들지 않는다. 더블의 유지에는 서로 다른 두 물리 키가 필요하며 시작·끝 창이 겹쳐도 한 키를 두 번 눌러 두 유지 몫을 완료할 수 없다.

### 3-3. up 배정과 같은 키 재누름

명시된 릴리즈의 창·시작·실패 자격을 충족한 up을 차트상 가장 이른 적격 릴리즈 하나에 배정한다. 같은 레인이라도 한 up으로 두 점수 항목을 처리하지 않는다. 유지 키와 고정 물리 소유권을 같은 개념으로 두지 않는다.

같은 더블 릴리즈의 두 up은 서로 다른 키를 요구한다. 예외는 같은 키를 다시 눌러 **해당 바디의 시작 Point를 실제로 처리한 경우**다. 그 누름의 up은 같은 더블 릴리즈의 남은 항목을 처리할 수 있다. 이 예외는 싱글 바디에 붙은 더블 릴리즈에도 적용한다. 임의의 재누름·다른 바디의 Point로 확대하거나 double 바디의 두 키 유지 요구를 바꾸지 않는다. 이미 정상 완료한 바디를 다시 활성화하지도 않는다.

연결 Point의 탭·교대에서 생긴 up을 숨은 연결 release로 자동 소비하는 규칙은 제거한다. 적격 up이 뒤 명시 릴리즈를 일찍 처리할 수 있다는 결과를 받아들인다. 바디 시작 누름이 뒤 Point를 의도치 않게 처리하는 배치는 제작 지침으로 피하며, Point 후보를 엔진에서 숨기지 않는다.

같은 관측 묶음의 동일 raw 시각 up은 가능한 배정을 함께 대조해 서로 다른 키의 수신 순서로 결과가 달라지지 않게 한다. 서로 다른 raw 시각 순서·같은 키의 down/up 인과관계·가장 이른 적격 대상·확정 판정 불번복은 유지한다.

## 4. 경계·실패 종속

다음은 입력 사례 표가 아니라 경계 관계의 분류다. 저장과 컴파일에서 실제 앞뒤 바디를 합쳐 없애지 않는다.

| 경계 | 새 시작과 실패 전파 |
| --- | --- |
| 같은 hold 수, Point·릴리즈 없음 | 실제 경계·정상 분리 연주·앞 끝/뒤 시작 창은 보존하되 확정 탈락을 공유한다. 뒤 재누름으로 실패를 복구하지 않는다 |
| Point 없는 1→1, 릴리즈 있음 | 앞 실패·종속 0점과 별개로 뒤 바디가 자기 조건으로 새로 시작한다 |
| Point 없는 2→2, 릴리즈 하나 있음 | 뒤 두 몫 모두 자기 조건으로 새 시작 가능하며 릴리즈 수로 새 시작 가능 몫 수를 제한하지 않는다 |
| single Point가 있는 2→2 | 앞의 전체 탈락과 별개로 뒤 두 몫이 각각 시작 가능하다. Point 하나가 두 몫의 hold를 자동 충족시키지는 않는다 |
| Point 없는 1→2 | 앞 탈락과 별개로 뒤 두 몫 모두 새 시작 가능하다. 각 몫의 조건은 따로 충족해야 한다 |
| Point 없는 2→1 | 건강한 몫을 뒤 single로 승계한다. 앞 두 몫 모두 탈락했으면 뒤 single도 탈락을 유지한다 |

double 전체 끝에 릴리즈 두 몫이면 바디 한 몫의 유지 실패는 그 몫의 릴리즈 하나만 소멸시킨다. 전체 끝의 릴리즈가 하나뿐이면 정상 유지한 몫 하나로 그 기회를 보존한다. 두 몫 모두 실패하면 기회가 없다.

2→1 감소의 싱글 릴리즈는 끝나는 몫에 대응한다. 한 몫 실패 시 건강한 몫은 뒤 single로 이어지고 감소 릴리즈는 실패한 몫에 종속된 0점이다. 전체 끝의 단일 릴리즈와 귀속이 다르다. 바디/릴리즈 수량 차이 자체를 금지하거나 자동 보정하는 규칙은 만들지 않는다.

**2→1 경계의 더블 릴리즈(사용자 결정, 2026-10-26):** 2→1 경계에 더블 릴리즈를 두는 것도 허용하며 현재 검증기·엔진 동작을 유지한다. 감소를 치는 방법은 두 키를 모두 떼고 뒤 single을 새 키로 잡는 `ab-c-`와 a·b 중 하나만 떼는 `ab-` 두 가지다. 경계의 더블 릴리즈는 그중 `ab-c-` 연주를 요구할 뿐이다. 사용자: “놔도돼 감소를 치는방법 ab-c-랑 ab- 에서 하나만떼기 두방법있는데 한쪽을 ab-c-를 요구하는것뿐임”.

확정 실패는 같은 바디의 hold를 다시 채워도 복구되지 않는다. 기회를 잃은 릴리즈·유지 항목은 원래 이론 가중치를 유지한 0점으로 정확히 한 번 정산한다. 원인 실패의 Miss·콤보 단절·고도 효과만 적용하고 종속 항목에 추가 실패 효과를 만들지 않는다. 이미 성공한 항목을 소급해서 실패로 바꾸지 않는다.

## 5. 유지 노트

유지 노트는 바디와 같은 시작·hold 수·유지 유예·몫별 실패를 따르고 명시된 점수 정산만 더한다. 독립 허용 창·기한·입력 배정·이른 down에 의한 미래 표식 선판정은 없다.

- 정상 유지 중이면 표식 시각에 성공한다.
- 바디의 최초 시작 판단·회복 유예 중이면 결과를 기다린다. 유효한 늦은 시작·회복이면 보류한 항목을 성공 처리하고 실패 확정이면 종속 0점이다.
- 유효한 이른 정상 종료에서는 **그 종료 몫에 속한** 남은 미처리 표식을 함께 성공 처리한다. 뒤 새 바디 소속의 경계 표식까지 가져오지 않는다.
- 성공은 표식 하나당 Perfect 3점·이론 가중치 3·콤보 +1·일반 Perfect 고도 기여다. 일반 릴리즈가 Good이어도 유지 성공은 Perfect이며 Good 예외를 만들지 않는다.
- 유지 성공에는 타이밍 오차·FAST/SLOW를 표시·집계하지 않는다. 이미 정산한 표식은 다시 정산하지 않으며 표식 없는 바디에 자동 주기 점수를 만들지 않는다.

유지 노트를 추가·제거해도 같은 바디·Point·릴리즈와 같은 입력의 진행·배정·기존 판정·실패 효과는 같아야 한다. 바뀌는 것은 명시 유지 항목의 정산과 성공 효과다.

## 6. 위치 관계와 편집

### 6-1. 배치와 소속

같은 레인·같은 시각에 Point+릴리즈, Point+유지, 릴리즈+유지처럼 서로 다른 점수 의미를 겹치지 않는다. 같은 의미의 수량인 더블과 허용된 바디 위 노트는 이 금지와 구별한다.

유지 노트는 같은 레인 바디의 시작·끝을 포함한 구간에 있어야 하며 명시적 소속 ID를 요구하지 않는다. 공유 경계에서는 뒤 바디에만 속한다. 같은 hold 수의 연결점과 트릴 바디에는 유지 노트를 놓지 않는다. 한 바디 내부·독립 길이 0·1→2·2→1 위치는 허용하고, 증가 위치는 뒤 double의 두 표식, 감소 위치는 뒤 single의 한 표식을 쓴다.

릴리즈는 앞 바디 끝점 또는 바디 밖의 단독 위치에 둔다. 바디 내부의 끝점 아닌 위치는 의미 위반이다. 길이 0 바디와 같은 위치의 Point·릴리즈 조합도 시각적으로 표현할 수 없어 금지한다. 길이 0 바디+유지 표식과 표식 없는 길이 0 바디는 허용한다.

현재 `trillZone` 안에는 바디 끝을 포함해 명시 릴리즈를 도입하지 않는다. 트릴 Point·바디의 기존 제약을 유지하고 트릴 생성 조작에서는 끝 릴리즈를 만들지 않는다([후속 RFD 0038](0038-release-notes-in-trill-zones.md)).

### 6-2. 생성·선택·이동

일반 Point 입력 상태의 드래그는 시작 Point·바디·끝 릴리즈를 한 생성/취소/Undo 조작으로 만든다. 싱글·더블 수량을 맞춰 기본 생성하며 Grace 모드는 시작 Point와 릴리즈를 모두 Grace로 만든다. [RFD 0038](0038-release-notes-in-trill-zones.md)에 따라 트릴 드래그는 Point·바디만 만들고 끝 릴리즈는 만들지 않는다. 컴파일러의 자동 릴리즈 생성과 구별한다. 더블 Point·릴리즈는 전체가 하나의 편집·삭제 단위이며 한 번 삭제로 싱글로 줄이지 않는다.

바디 위 유지 노트는 바디 hold 수에 맞는 표식 1개·2개를 한 번에 배치한다. 다른 바디로 이동하면 새 바디에 맞춰 수량과 이론 항목 수를 바꾼다. 빈 위치의 새 유지는 길이 0 싱글 바디와 함께 생성하고, 유지 배치 상태에서 그 길이 0 싱글을 다시 클릭하면 더블로 변경한다. 더블 재클릭의 싱글 토글은 없다. 바디 밖으로 이동·붙여넣은 표식에는 바디를 자동 생성하지 않는다.

바디 클릭·박스에 바디 일부 포함·미선택 바디 끝 핸들 잡기는 시작 Point·소속 유지·끝 릴리즈를 함께 선택한다. 중간 Point는 포함하지 않는다. 미선택 개별 노트 직접 클릭은 그 노트만 선택하고 노트 hit가 바디보다 우선한다. 이미 선택된 노트를 누르면 현재 선택을 유지하고 끌면 선택 전체를 이동한다(구형 노트와 같음, 사용자 결정 2026-10-26). 박스에 표식·릴리즈만 있으면 해당 항목만 선택한다. 토글로 개별 제외할 수 있고 바디를 제외해도 나머지 선택은 남는다.

복사·이동은 실제 선택 집합을 따른다. 실행 시 제외한 항목을 다시 추가하지 않는다. 선택된 끝 릴리즈만 끝 resize를 따라가며 내부 표식·시작 Point를 비례 이동시키지 않는다. 유지 표식을 밖으로 내보내는 바디 축소와 트릴 노트를 밖으로 내보내는 `trillZone` 축소는 막는다.

### 6-3. 삭제·취소·수리

바디와 소속 유지 표식을 모두 삭제할 수 있으면 한 편집에서 표식을 먼저 지우고 바디를 지운다. 소속 유지가 삭제 집합에서 빠졌다면 바디 삭제·Cut을 막는다. Cut은 삭제 가능성을 먼저 검사하고 거부 시 클립보드도 보존한다. 복사는 허용한다. 표식만 삭제한 길이 0 바디는 남긴다.

미선택 바디 직접 삭제는 시작 Point·유지·끝 릴리즈를 함께 지운다. 선택된 바디 우클릭은 클릭한 바디 쪽에서 현재 선택에 남은 관련 항목만 지우고 다른 선택 바디나 제외한 항목은 남긴다. Delete 키는 선택 전체를 지운다. 개별 노트 직접 삭제는 해당 노트만 지운다.

같은 우클릭 드래그에서 노트 삭제로 드러난 바디를 관통해 추가 삭제하지 않는다. 버튼을 떼고 새 조작을 해야 한다. 연속 삭제 한 드래그는 길이에 관계없이 Undo 한 번이며 별개 드래그·다른 편집과 시간으로 병합하지 않는다. 도중 Esc는 그 드래그의 삭제만 복구·취소하고 새 Undo 기록을 만들지 않는다. 버튼을 떼기 전 후속 이동으로 다시 삭제하지 않는다.

이동·붙여넣기 등의 의미 위반은 미리보기부터 빗금으로 보이고 위반 상태로도 확정할 수 있다. 새 에디터는 위반 항목의 선택 해제·다른 선택도 허용한다. 이는 RFD 0017 §3-5의 선택 해제 게이트를 대체한다. 구조 오류 거부, 위의 바디 삭제·축소 보호, 실제 의미 위반의 저장·플레이 차단은 유지한다.

## 7. 표시와 확정 효과

- 유지 성공은 표식을 즉시 숨기고 Perfect 글자와 해당 레인의 일반 타격 이펙트를 낸다. 회복 뒤 성공·이른 종료 일괄 성공도 포함한다. 미확정 상태에서 미리 숨기거나 효과를 내지 않는다.
- 바디 정상 완료는 이른 종료·연결 여부와 관계없이 즉시 숨긴다. 대기 중인 명시 릴리즈는 별도로 남는다. 실패 바디·릴리즈와 종속 0점인 유지 표식은 실패색으로 원래 위치에서 스크롤하여 화면 밖까지 남긴다.
- 더블의 일부 실패는 실패한 절반을 실패색으로, 일부 성공은 전체 alpha 0.7로 표시하며 두 축을 합성한다. 한쪽 성공·한쪽 실패인 릴리즈는 부분 실패 도안 전체를 alpha 0.7로 남긴다. 두 쪽 모두 성공/정상 완료하면 숨긴다.
- 더블 바디는 실제 시작한 몫 중 하나라도 살아 있으면(유지 중 또는 회복 유예 중) 판정선 고정을 유지하고 실패한 절반만 실패 도안으로 그린다. 모든 몫이 실패해야 고정을 풀고 원래 차트 위치에서 스크롤한다(사용자 결정, 2026-10-26). 구현은 #343이다.
- 유지 노트는 표식 수로 요구 수를 나타내므로 일부 성공 alpha 0.7의 예외다. 성공한 표식만 숨기고 나머지 위치·크기·밝기를 유지하며 실패한 표식은 실패색으로 남긴다.
- Grace 릴리즈의 흰 외곽은 본체가 보이는 동안 실패를 포함해 전체 원래 밝기를 유지한다. 본체 alpha와 분리하고 본체가 사라질 때 함께 숨긴다.
- 별도 바디 시작·끝 마감 에셋을 두지 않는다. 릴리즈 없는 끝에 끝 노트를 덧그리거나 릴리즈와 중복 합성하지 않는다.

같은 확정 시각에는 표시 대상 중 가장 낮은 등급을 대표 판정 글자로 고른다. 종속 0점은 표시 후보가 아니다. 같은 대표 등급에서는 표시 가능한 타이밍을 가진 실제 입력을 우선하고, 여러 개면 raw 오차 절대값이 가장 큰 입력의 FAST/SLOW·타이밍 수치를 쓴다. 유지/Grace에 타이밍을 새로 만들거나 다른 등급에서 빌려 오지 않는다. 기존 표시 임계값·설정은 유지한다. 동일 절대 오차의 안정 동률 선택은 구현 사항이다.

대표 글자를 고르는 것과 각 항목의 점수·통계·콤보·고도·타격 효과 정산은 별개다. 서로 다른 확정 시각을 프레임이나 새 허용 폭으로 묶지 않는다. 같은 시각 후보의 수신·호출 분할 순서로 대표 등급이 달라지지 않아야 한다. 현재 콤보는 기존 확정 순서와 같은 timestamp·phase의 Miss 우선을 유지한다. 상태 재조회·튜토리얼 반복·렌더러 재부착으로 이미 처리한 효과를 재실행하지 않는다.

## 8. 구형 차트와 과도기

구형 차트는 사람이 수정할 수 있도록 읽기·표시·선택·속성·편집·Undo 의미를 보존한다. 전체 문서의 버전 하나만으로 미수정 구형 항목을 새 의미로 바꾸지 않는다. 자동 배치 변환·일괄 재구성·`holdOnly`의 조용한 릴리즈/유지 변환은 하지 않는다.

일부만 수리한 구형·신형 혼합 차트도 저장·재불러오기를 허용한다. 양쪽 의미와 main/aux 자료·메타데이터·dirty 비교를 손실 없이 보존한다. 실제 의미 위반은 저장·플레이를 막지만 구형 항목의 존재 자체는 혼합 저장을 막지 않는다. 구형이라는 이유만으로 별도 배지·라벨·강조·빗금을 추가하지 않는다.

새 compiler와 인게임은 구형 의미가 하나라도 남은 게임 차트의 재생을 차단한다. 구형 읽기·수리 지원과 새 의미의 재생 허용을 분리한다. 저장소가 관리하는 차트의 수리를 완료한 뒤 **사용자가 종료 시점을 알릴 때** 구형 스펙 제거를 진행한다. 과도기 종료 뒤 저장소 밖의 구형 차트까지 에디터 지원을 보장할 필요는 없다.

**일반 재생 전환 뒤의 공백(사용자 결정, 2026-10-26):** #347 머지 뒤 일반 곡 선택은 명시 판정만 실행한다. 현재 운영 차트(노트가 있는 구형 v3 차트 8개와 aux 없는 빈 차트 2개)는 사람이 새 계약으로 다시 제작하기 전까지 곡 선택에서 플레이할 수 없다. 게임이 아직 출시 전이라 사용자는 이 공백을 감수하기로 했다. 다시 제작하는 작업과 과도기 종료는 [PRD §12](../prd.md#12-미정-사항)에서 추적한다.

## 9. 구현 경계·단계와 검증

저장/편집 문서 → 정적 관계·진단 → 컴파일된 명시 점수 항목·바디 몫 → 세션의 현재 snapshot·불변 확정 사실 → 표시 어댑터로 구분한다. 정적 관계는 lane·Beat 배치로 도출하고 원본 참조·점수 항목 참조·바디 몫·반복 표시 인스턴스를 구분한다. API나 저장 ID 선택은 이 의미를 보존하는 구현 사항이다. 에디터·인게임의 표시와 입력 소비자는 판정 규칙을 재구현하지 않고 공용 모델과 세션이 낸 관계·상태·확정 효과를 소비한다.

준비 중인 새 경로를 구형 코어에 조용히 연결하거나 실제 플레이 기본값을 미리 전환하지 않는다. 기존 사례 결과는 보존하고 새 표현/규칙으로의 대응을 기록한다.

작업 순서·담당 경계·단계별 완료 기준은 [명시적 점수 노트 구현 계획](../plans/explicit-score-notes-implementation.md)을 따른다. 이 계획 작성은 런타임 구현 완료나 실제 기본 경로 전환이 아니다.

[대표 판정 사례 18건](../spec/explicit-note-judgment-cases.md)과 [기존 RFD 0032 테스트 81건의 이전 대응표](../spec/judgment-case-migration.md)를 문서로 고정했다. 이 입력·기대값과 그림은 정적 검토한 설계 계약이며 새 엔진 실행 결과가 아니다. 81건 중 37건은 차트 표현을 옮겨 적용하고 44건은 승인된 규칙 변경에 따라 기대값을 대체한다. 원본 테스트와 당시 기대값은 보존한다.

검증은 명시 항목의 정확히 한 번 정산·분모, 실제 시작과 끝 자격, 실패 비중복, 유지 추가/제거의 바디/입력 불변, 같은 raw 시각의 순서 독립, 지연 입력의 인과관계·확정 사실 보존, 혼합 저장 왕복, 편집 보호와 취소/Undo, 몫별 표시와 일회성 효과, 합법 AutoPlayer 입력·튜토리얼 반복을 포함한다. 그림의 설계 기대값을 엔진 실행 결과로 표시하지 않는다.

중간 재생은 [RFD 0040](0040-countdown-and-note-reentry.md)의 곡 시간 고정 3초 되감기·상태 복원과 실제 시간 3초 음악 준비를 따른다. 새 테스트의 커서 앞 점수 항목은 Miss 없이 제외하며 원본은 보존한다. 일반 첫 재생·Retry는 음악 준비 없이 즉시 시작한다. 무점수 차트의 재생 허용·달성률/랭크 숨김은 [RFD 0039](0039-unscored-chart-results.md)로 확정했다. 기존 튜토리얼 목록 개편과 아직 미구현인 기록 저장·랭킹·모델 간 호환은 이번 전환에서 제외하고 후속 작업으로 둔다. 입력 손실·`flightRule` 세부·유지 유예 최종 튜닝 등 미정 사항은 [PRD §12](../prd.md#12-미정-사항)에서만 추적한다.

## 10. 대안과 영향

채택하지 않은 안은 바디 시작 down 선점, 숨은 연결 up 소비 유지, 일반 릴리즈 창 확대, 유지 노트의 독립 창/선판정/Good 예외, 시각 표현 없는 길이 0 바디+Point/릴리즈 허용, 구형 차트 자동 변환, 의미 위반 선택 해제 차단 유지다. 입력 혼선을 제작 지침으로 피하고 명시 요구와 입력 소비를 단순하게 유지하는 대신, 창 겹침에 따른 이른 릴리즈·미수정 구형 차트의 재생 제한·수동 수리 부담을 받아들인다.

영향 문서는 glossary·term-map·루트/공유/게임/에디터 CONTEXT, 게임 코어·점수·에디터 스펙, 제작 지침, 판정 사례와 PRD다. 향후 구현은 `src/shared`의 차트/검증/I/O, `src/game/judgment`와 scoring, editor 명령/선택/history/I/O, 게임 렌더러/스킨·입력·AutoPlayer·튜토리얼 소비자를 함께 다룬다. 이번 반영은 문서와 사례 기준이며 이 코드들의 새 동작을 구현한 것이 아니다.
