# RFD 0027: 하나의 분출구와 색으로 구분하는 추진부 입력 표현

**Status:** Accepted (2026-09-29) · 사용자 방향 분출을 반영한 외형 3종·Lab 비교 교체 및 모바일·데스크톱 E2E 검증 (2026-09-29) · 저장소 반영, 이전 탐색 보관 페이지는 용량 때문에 제외 (2026-10-04, PR #210) · 게임 기어 버튼 누름·싱글 연파랑·더블 금색 규칙 적용 (2026-10-14, PR #277)

**구현 기록:** 2026-10-13 Classic 기어의 키 덱 네 버튼이 레인 키를 누르는 동안 눌려 빛나도록 게임에 적용했다([게임 코어 명세](../spec/game-core.md#플레이-화면-배치)). 버튼은 같은 형상으로 눌리고 싱글 연파랑·더블 금색 레이어를 모두 갖추며, 누를 때마다 색을 중간 단계 없이 정한다. 이 RFD가 정하지 않은 "어떤 누름을 더블로 보는가"는 처음에는 모든 누름을 싱글로 두었다가 2026-10-14 사용자가 정해 아래 [게임 적용](#게임-적용-2026-10-14)에 적었다.

## 기존 결정과 문제

추진부 아이디어는 입력하면 추진부가 활성화되어 빛이 분출되는 방향으로 선택했다. 초기 정지 시안은 싱글의 한 줄과 더블의 두 줄, 서로 다른 셔터 열림 정도나 두 원형 분출구로 상태를 구분했다.

사용자는 싱글과 더블이 계속 빠르게 반복되어 기구가 서로 전환할 시간이 없음을 지적했다. 분출구가 한 개에서 두 개로 바뀌는 표현은 이 사용 장면에 맞지 않는다.

## 검토한 대안

- 하나와 두 개의 분출구·빛줄기를 상태별로 전환한다: 정지 도안에서는 읽히지만 전환 동작과 별도 형상을 요구한다.
- 두 분출구를 고정하고 빛을 합치거나 나눈다: 구멍 수를 바꾸지는 않지만 싱글·더블을 구분하는 합치기·갈라지기 시간이 남는다.
- 하나의 분출구를 공유하고 이펙트 색만 전환한다: 같은 형상을 유지한 채 입력 상태를 즉시 표현할 수 있다. 이 안을 채택한다.

## 채택한 표시 규칙

- 각 버튼에는 연속된 구멍 하나만 둔다. 내부 칸막이·두 코어·두 출구로 한 개와 두 개를 세어 구분하게 만들지 않는다.
- 싱글과 더블은 같은 위치·크기·형상의 분출구를 사용한다. 셔터·조리개·입력면의 활성 상태 형상도 동일하다.
- 이펙트는 하나의 같은 분출 형상이며, 싱글은 연파랑, 더블은 금색 계열로 구분한다. 두 갈래 광선이나 출구 추가로 더블을 표현하지 않는다.
- 분출은 **화면 앞의 사용자를 향한다**. 사용자는 단일 분출구 비교의 3번에서 방향만 선택했으며, 원형 구멍과 버튼 외형은 마음에 들지 않는다고 명시했다. 아래로 흐르는 분출로 되돌리지 않고, 정면을 향한 출구·가까워지는 빛을 다른 외형으로 탐색한다. 원형 구멍은 채택 조건이 아니다.
- 싱글↔더블은 현재 이펙트 색만 즉시 바꾼다. 중간 대기·닫힘·재개방, 기구 이동 완료 대기, 빛의 합치기·갈라지기 단계를 넣지 않는다.
- 입력으로 추진부가 활성화된다는 아이디어를 유지한다. 구체적인 외형과 대기↔활성 모션 등 남은 선택은 [PRD §12](../prd.md#12-미정-사항)에서 관리한다.

색만으로 상태를 구분하므로 색각 차이에 따른 구분력은 별도 접근성 정책의 검토 대상이다. 이번 작업에서 다른 판정·입력·비행 규칙을 추가하지 않는다.

## 영향 범위

- [노트 에셋 Lab 명세](../spec/note-asset-lab.md#추진부-아이디어-확정)와 PRD의 추진부 디자인 항목을 현재 결정으로 갱신한다.
- `/lab/images/thrust-button-study-20260929/`의 최신 시안을 하나의 분출구 기준으로 교체한다. 후속 시안은 사용자 방향 분출을 공통으로 유지하면서 버튼·출구 외형을 새로 비교한다.
- 이전 셔터·덮개·두 분출구 도안과 단일 분출구의 초기 3개 도안은 저장소 반영 시 이미지와 보관 페이지를 제외하고, 실제 생성 요청 JSON만 `assets-lab/classic/revisions/thrust-button-study-20260929/`에 남긴다.
- Lab 카탈로그의 이름·설명과 해당 미리보기의 E2E 검증을 갱신한다.
- 이번 반영은 미술 시안과 비교 페이지까지다. 실제 게임의 런타임 버튼 에셋·입력 처리 적용은 포함하지 않는다.

## 게임 적용 (2026-10-14)

사용자가 게임 기어 버튼에서 더블 금색을 쓰는 누름을 정했다. 표시만 정하며 판정·점수·입력 규칙은 바꾸지 않는다.

- **노트를 친 누름**(keydown이 Point head나 롱노트 시작에 소비됨): 그 노트가 더블(`double`·`doubleLong`)이면 금색, 아니면 연파랑이다. 그 레인에 누르고 있는 키 수와 관계없다.
- **[공입력](../context/glossary.md#공입력)**(어떤 노트에도 소비되지 않은 keydown): 그 순간 그 레인에 누르고 있는 키가 이 키를 포함해 둘 이상이면 금색, 하나면 연파랑이다.
- `AutoPlayer`의 합성 누름도 같은 규칙이다. 버튼 색은 그 레인에서 마지막으로 누른 키의 색이고, 색 전환은 이 RFD대로 중간 단계 없이 바로 일어난다.
- 누름이 노트를 쳤는지는 게임 루프가 그 렌더 프레임에서 입력을 판정할 때 정해진다. 판정 core가 keydown을 노트에 소비한 순간을 알리고(`onDownConsumed`), 플레이 화면이 렌더 프레임을 그리기 직전에 그 색으로 고쳐 누름이 처음 보이는 프레임부터 맞는 색이다. 자세한 동작은 [게임 코어 명세](../spec/game-core.md#플레이-화면-배치)를 따른다.
- 이 규칙에 RFD를 따로 두지 않았다. 표시 색만 정하고 되돌리기 쉬우며, 이 RFD의 "싱글 연파랑·더블 금색, 즉시 전환"을 게임 입력에 대응시킨 것이기 때문이다.
