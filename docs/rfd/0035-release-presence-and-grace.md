# RFD 0035: 롱노트와 릴리즈 노트의 분리, Grace의 타이밍 등급 면제

**Status:** Accepted (2026-10-23) · 용어와 동작 구분 채택 · 바디·릴리즈 노트 분리와 바디의 점수 제외 확인(2026-10-23) · 엔진·차트·에디터·에셋 이행 전

## 배경

기존 `holdOnly`는 롱노트 끝의 뗌을 면제하고 유지 상태로 Perfect/Miss를 판정했다. Grace 포인트 노트와 시각 언어를 공유했지만, Grace 포인트는 누름을 요구하면서 타이밍 등급만 면제하므로 같은 표시가 서로 다른 의미를 가졌다.

롱노트 시인성 논의에서는 릴리즈의 유무를 표시하고, 실제 release를 요구하는 곳의 판정 창을 넓히는 방향을 검토했다. `o-o` 끝의 누름 노트와 릴리즈 노트를 같은 위치에 겹치는 방식은 시인성 목표에 맞지 않는다고 사용자가 지적했다. 이 자리에서 릴리즈를 생략해 교대의 뗌을 강제하지 않는 방향도 검토 중이다. 표시 생략을 숨겨진 뗌 요구로 해석하지 않는다.

사용자는 2026-10-23에 기존 `holdOnly`는 논의에서 폐지되었음을 재확인하고, 그레이스 릴리즈는 타이밍 등급 면제로 정리했다. 이 결정은 RFD 0009·0020·0032의 `holdOnly`를 새 설계에 그대로 유지하거나 단순히 이름만 바꾸는 안을 대체한다.

같은 날 사용자는 기존 일반 롱노트가 **유지를 담당하는 롱노트와 명시적인 릴리즈 노트의 조합**으로 바뀐다고 설명했다. 롱노트 자체가 release를 내장하던 이전 모델에서는 바디 끝에 별도 길이 0 릴리즈를 붙이면 요구가 중복되었지만, 새 롱노트는 release를 함유하지 않는다. 따라서 그 조합에 기존 중복 금지를 유지하는 해석은 잘못이며, 새 모델에서 바디 끝에 릴리즈 노트를 명시하는 배치를 허용한다.

## 결정

1. **롱노트와 릴리즈 노트의 분리:** 롱노트는 바디의 유지를 담당하고 release를 내장하지 않는다. 뗌을 요구할 때는 별도의 릴리즈 노트를 명시한다. 기존 일반 롱노트의 유지와 끝 뗌은 새 모델에서 바디와 릴리즈 노트의 조합으로 표현한다. 같은 레인·시각의 바디 끝과 릴리즈 노트는 이 조합으로 허용하며, 이전 모델의 「양수 바디 끝 + 별도 길이 0 롱노트 금지」를 이 조합에 적용하지 않는다. 도메인상의 분리이며 저장 포맷과 코드 필드 구조는 이 결정으로 확정하지 않는다.
2. **릴리즈 없음:** 릴리즈 노트를 두지 않은 바디 끝에서는 뗌을 요구하지 않는다. 바디의 유지 요구는 남으며, 그 끝을 지나 계속 눌러도 뗌 누락으로 실패하지 않는다. 이를 Grace라고 부르지 않는다.
3. **일반 릴리즈 노트:** 실제 뗌을 요구하고, 유효한 입력의 타이밍에 따라 Perfect/Great/Good을 판정한다. 유효한 뗌을 놓치면 Miss다. 판정 창을 누름보다 관대하게 넓히는 방향은 유지한다.
4. **그레이스 릴리즈:** 실제 뗌을 요구하되 허용 창 안의 유효한 입력은 항상 Perfect다. 유효한 뗌을 놓치면 Miss이며, 계속 유지하는 것으로 대신할 수 없다. Grace 포인트와 마찬가지로 FAST/SLOW를 집계하지 않는다.
5. **Grace의 공통 의미:** 해당 노트가 요구하는 동작은 유지하고 타이밍 등급만 면제한다. 누름 노트의 Grace와 릴리즈 노트의 Grace는 각각 자기 입력에 적용한다.
6. **`holdOnly` 폐지:** 새 설계에서 독립적인 상태 판정 노트로 유지하지 않는다. 기존 양수 길이 `holdOnly`의 뗌 요구 없음은 릴리즈 노트를 두지 않는 구성에 대응한다. 기존 구현·차트의 `holdOnly`는 이행 전 자료이며 그레이스 릴리즈의 동의어가 아니다. 기존 데이터를 단순히 그레이스 릴리즈로 치환하면 없던 뗌 요구가 생기므로 자동으로 같은 의미라고 취급하지 않는다.
7. **바디는 점수에서 제외:** 바디 자체는 점수 항목을 만들지 않고 획득 점수와 달성률의 이론 가중치에 포함하지 않는다. 바디의 유지 판정은 콤보와 고도에만 관여한다. 기존 유지 실패의 콤보 단절·고도 손실을 기준으로 하며, 폐지한 `holdOnly`의 상태 완료 점수를 바디에 남기지 않는다. 별도 누름·릴리즈 노트의 점수 판정과 구분한다.
8. **바디 실패 시 연결된 릴리즈 기회 소멸:** 바디 유지에 실패하면 그 바디에 연결된 릴리즈 노트를 판정받을 기회를 잃는다. 이후에 다시 누르고 떼어 그 릴리즈를 성공시킬 수 없으며, 일반·그레이스 릴리즈에 똑같이 적용한다. 노트를 별도로 명시한다는 것은 바디 실패와 무관하게 독립 판정한다는 뜻이 아니다. 바디 자체에는 점수가 없지만 연결된 릴리즈의 득점 기회는 바디 유지에 달려 있다. 기회 소멸로 차트의 이론 가중치를 지우지 않으며, 기존 종속 끝점처럼 해당 릴리즈는 0점·원래 가중치로 정산하고 추가 끝 Miss·고도 손실·콤보 이벤트는 만들지 않는다.

사용자에게는 **릴리즈 노트**, **그레이스 릴리즈**, **릴리즈 없음**으로 설명한다. `hasRelease` 같은 내부 식별자를 사용자 용어로 쓰지 않는다. 릴리즈 노트는 바디 끝에 조합하거나 바디 없이 단독으로 배치하는 뗌 노트이며, 롱노트의 내장 끝 표시로 한정하지 않는다.

## 대안과 대가

- 기존 `holdOnly`와 그레이스 릴리즈를 같은 뜻으로 유지하면 Grace가 동작 면제인지 타이밍 등급 면제인지 표시만으로 구별하기 어렵다. 채택하지 않는다.
- 모든 릴리즈를 Perfect/Miss로 통일하면 일반 릴리즈의 타이밍 등급까지 사라진다. 이번 결정은 그레이스 릴리즈에만 등급 면제를 적용한다.
- 릴리즈 없음은 실제로 계속 누르는 연주도 허용한다. 대부분의 롱노트에서 익힌 뗌을 해당 자리에서도 자연스럽게 할 것이라는 기대와 판정상 강제는 구분한다.
- 기존 `holdOnly`의 점수 항목·입력 소비·길이 0 상태 확인을 그대로 승계할 수 없으므로, 새 모델에 맞춘 이행이 필요하다. 나머지 결정과 구현 과제는 [PRD §12](../prd.md#12-미정-사항)에서 관리한다.
- 바디 끝과 명시적 릴리즈의 조합을 허용하는 것은 동일 릴리즈를 중복 배치하거나 누름 노트와 같은 위치에 합성하는 규칙을 확정하는 것이 아니다. 기존 내장 release에 새 release를 더해 이중 요구로 구현하지 않는다.

## 영향

- [glossary](../context/glossary.md)의 Grace·릴리즈 노트·`holdOnly` 정의와 [term-map](../context/term-map.md), 루트 및 Gameplay·Chart editor·Shared chart model의 `CONTEXT.md`를 동기화한다.
- 판정 엔진의 실제 release와 상태 완료, 바디를 제외한 점수 항목·가중치 집계와 유지 실패의 콤보·고도 효과, FAST/SLOW, 차트 데이터·검증, 에디터의 바디·릴리즈 조합과 Grace 조작, 튜토리얼·AutoPlayer가 이행 대상이다. [NJ-C01](../spec/note-judgment-cases.md#nj-c01)의 중복 금지는 이전 엔진의 사례로 보존하고 새 바디·릴리즈 조합의 금지 근거로 쓰지 않는다.
- 표시에서는 릴리즈가 없는 끝에 릴리즈 노트를 그리지 않으며, 일반 릴리즈와 그레이스 릴리즈를 구분해야 한다. 구체적인 에셋·크기·글로우 조합은 이 결정으로 확정하지 않는다.
- 이번 기록은 도메인 결정이다. 현재 엔진과 차트 포맷은 여전히 기존 `holdOnly`를 사용하며, 구현 완료로 취급하지 않는다.
