## 기존 결정과 문제

[RFD 0019](0019-rest-zone-lane-guidance.md)는 게임에서 `restZone`이 덮은 레인 구간을 검정 α0.6 띠로 어둡게(dim) 보여 주기로 했다. 띠는 차트에 붙어 노트와 함께 흘러온다. 에디터 타임라인은 PR #283에서 검정 빗금으로 바꿨고, 게임은 아직 dim이다.

2026-10-14～15에 Lab `restZone Lane`(#282)으로 다른 연출을 시안했다. `restZone` 동안 레인 판넬이 판정선을 경첩 삼아 뒤로 꺼졌다가, 다음 노트가 오기 전에 올라온다. 이때 정한 것은 다음과 같다(2026-10-15 사용자 결정).

- 판넬은 `restZone`이 시작된 직후 꺼지고, 끝보다 **추정 녹숫**만큼 앞서 다 올라온다. 시작 직전이 아니라 직후에 꺼지는 것은 시작 박에 붙은 노트(배치 제약 위반이 아니다)가 꺼지는 판넬 위에 얹히지 않게 하기 위해서다.
- 사용자 설정(스크롤 속도·리프트·서든)은 전환 시각을 바꾸지 않는다. 모든 사용자가 같은 시각에 같은 연출을 본다.
- 추정 녹숫은 차트 Lv.로 정한다.

판넬을 게임에 넣으면 RFD 0019의 시각 결정이 바뀌므로 RFD가 필요했다. Lv.별 추정 녹숫 값, 테두리, 애니메이션 길이, 짧은 `restZone` 처리는 [PRD §12](../prd.md#12-미정-사항)에서 미정으로 관리했다.

## 결정

1. **게임의 `restZone` 표시를 dim에서 레인 판넬로 바꾸고 dim은 없앤다.** 짧은 `restZone`에만 dim을 남기는 방식도 쓰지 않는다. 판넬은 판정선부터 노트가 보이는 레인 위끝까지 덮고(게임에 서든 커버가 생기면 그 아래끝까지. 지금 `GameRenderer.setSudden`은 TODO다), 판정선을 경첩 삼아 뒤로 꺼진다. 꺼진 판넬은 레인색과 검은 빗금이 섞인 사다리꼴로 원근 투영하고, 판넬이 꺼지며 드러난 뒷배경은 검정이다. 판정선 아래 레인(키 윗면까지)은 그대로 둔다.
2. **전환 시각은 Lab 시안과 같다.** 판넬은 `restZone` 시작 시각부터 애니메이션 길이 동안 꺼지고, (끝 − 추정 녹숫)에 다 올라온다(`restPanelTiming`). 꺼짐·올라옴 곡선도 Lab과 같다(`restPanelState`: 꺼짐은 진행 비율의 제곱, 올라옴은 남은 비율의 제곱). 사용자 설정은 전환 시각을 바꾸지 않는다. 다음 두 가지는 에이전트가 정한 기본값이다(사용자 확인 대기).
   - 시각은 노트와 같은 곡 시간(`GameClock` 시각 시간)으로 계산한다. 재생 배속을 바꿔도 판넬과 노트의 관계가 배속 1과 같고, 애니메이션의 실제 길이만 배속에 반비례한다. Lab도 곡 시간으로 재생한다.
   - 같은 레인에서 앞 `restZone`의 끝과 뒤 `restZone`의 시작이 맞닿으면 하나로 이어 본다. 검증은 맞닿음을 허용하므로, 따로 계산하면 이어진 쉼 한가운데서 판넬이 올라왔다가 다시 꺼진다.
3. **추정 녹숫은 Lv.1 3000ms부터 Lv.15 500ms까지 선형으로 줄인다.** Lv.n의 추정 녹숫은 3000 − (n − 1) × 2500 / 14 ms다(1단계마다 약 178.6ms, Lv.8은 1750ms). Lv.15보다 높으면 500ms, Lv.1보다 낮으면 3000ms다. 사용자 대부분의 녹숫보다 넉넉하게(길게) 잡은 값이라, 대부분의 사용자는 판넬이 다 올라온 뒤에 다음 노트를 본다. 입력 범위는 에이전트가 정한 기본값이다(사용자 확인 대기). `difficultyLevel`을 1～15로 자른 뒤 같은 식에 넣으므로 소수 Lv.도 선형으로 구하고, 숫자가 아니면(`NaN`, 옛 JSON의 빈 값) Lv.1로 본다.
4. **판넬 시각 값은 Lab 기본값으로 정하고, 테두리만 밝은 레인색 둘레로 한다.**

   | 항목 | 값 |
   | --- | --- |
   | 테두리 | 밝은 레인색 둘레(레인색을 밝힌 선, Lab `rim`) |
   | 꺼지는 각도 | 60° |
   | 원근 거리 | 판넬 높이의 1.5배 |
   | 눈높이 | 경첩 위로 판넬 높이의 0.5배(Lab 고정값) |
   | 애니메이션 길이 | 300ms(꺼짐·올라옴 각각) |
   | 빗금 밝기·간격 | 100%·8 |
   | 어둠 시작 위치·윗변 남는 밝기 | 40%·0 |
   | 인접 레인 묶기·레인 사이 틈 메우기 | 켬·켬 |

5. **짧은 `restZone`은 따로 처리하지 않는다.** `restZone`이 추정 녹숫 이하이면 판넬이 꺼지지 않는다. 그보다 길고 추정 녹숫 + 애니메이션 2번(Lv.1 3.6초, Lv.8 2.35초, Lv.15 1.1초)보다 짧으면 덜 꺼지며, 가장 많이 꺼질 때의 진행도는 ((길이 − 추정 녹숫) / 600ms)²다. 차트가 아래 최소 길이 지침을 지킨다고 가정하고, 지키지 않은 구간에 dim 같은 다른 표시를 더하지 않는다. [차트 디자인 9항](../context/chart-design.md#9-restzone은-판넬-연출이-들어갈-만큼-길게-잡는다)의 최소 길이 지침을 "검토 중"에서 확정 지침으로 올린다. 에디터는 이 지침을 검사하지 않고, 이후 에이전트·스크립트 차트 리뷰 기능에서 확인한다(2026-10-15 결정 유지).
6. **바꾸지 않는 것:** `restZone`의 데이터 모양과 배치 제약, 판정 불개입([RFD 0019 §3-3](0019-rest-zone-lane-guidance.md#3-3-기각향후에도-계획-없음-세이프존--휴지-구간에서-입력-판정-면제)), 에디터 타임라인의 검정 빗금과 미니맵 단색, 전역 레인 base 밝기([RFD 0019 §4-3](0019-rest-zone-lane-guidance.md#4-3-시각-결과--레인-base-밝기-상향전역)).

## 검토한 대안

- **dim 유지(기각):** dim 띠는 노트와 함께 흘러와 쉬는 구간이 시작되기 전부터 보인다. 하지만 띠의 끝과 다음 노트가 같은 속도로 흘러오므로, 다음 노트가 구간 끝에 붙어 있으면 레인이 돌아온다는 신호가 다음 노트보다 먼저 오지 않는다. 판넬은 (끝 − 추정 녹숫)에 다 올라와, 녹숫이 추정 이하인 사용자에게 레인 복귀를 다음 노트보다 먼저 알린다.
- **판넬 + 판넬이 꺼지지 않는 짧은 구간에만 dim(기각):** 짧은 구간의 정보는 남지만 같은 뜻을 두 방식(흘러오는 띠, 제자리에서 꺼지는 판넬)으로 보여 주게 되어, 사용자가 둘의 차이를 따로 배워야 한다. 짧은 구간은 차트 제작 단계에서 막는다.
- **사용자 녹숫으로 전환 시각 맞추기(기각, 2026-10-15):** 사용자마다 연출 시각이 달라진다. 추정 녹숫으로 정하면 모든 사용자가 같은 시각에 같은 연출을 본다.

## Trade-off

- 판넬은 `restZone`이 시작된 뒤에 꺼지므로, dim처럼 구간이 오기 전에 미리 보이지 않는다. 사용자는 쉬는 구간을 시작될 때 안다.
- 추정 녹숫을 넉넉하게 잡아 최소 길이 지침이 길어진다(120 BPM에서 Lv.1 7.2박, Lv.15 2.2박). 지침보다 짧은 `restZone`은 판넬이 덜 꺼지거나 아무 표시 없이 지나간다.
- 녹숫이 추정보다 긴(스크롤이 느린) 사용자는 그 차이만큼 판넬이 다 올라오기 전에 다음 노트를 본다. 기본 설정의 녹숫(약 0.54초)도 Lv.15 추정 녹숫 500ms보다 길어, Lv.15에서는 기본 설정이면 다음 노트가 약 40ms 먼저 보인다.
- 판넬마다 원근 메시(Pixi `PerspectiveMesh`)와 텍스처가 든다. 렌더 프레임마다 새 객체를 만들지 않도록 렌더러 준비 단계에서 만들어 두고 다시 쓴다(GC 끊김 #227의 교훈).

## 영향

구현은 작은 PR로 나눈다.

1. **결정 기록(이 RFD):** RFD 0019 Status 이정표, [PRD §12](../prd.md#12-미정-사항)의 `restZone` 판넬 연출 행(모두 결정되어 뺀다), glossary 추정 녹숫 값, [차트 디자인 9항](../context/chart-design.md#9-restzone은-판넬-연출이-들어갈-만큼-길게-잡는다), [Lab `restZone Lane`](../spec/lab-preview-catalog.md#restzone-lane)의 게임 적용 문장
2. **판넬 계산을 게임 모듈로 옮김:** `src/lab/restZonePanel.ts`·`restZonePanelTexture.ts`의 전환 시각·투영·판넬 묶기·텍스처를 게임 렌더러 쪽 모듈로 옮기고 Lab이 그것을 쓴다. 함께 할 일은 다음과 같다.
   - Lv.에서 추정 녹숫을 구하는 함수, 맞닿은 같은 레인 `restZone`을 잇는 계산과 단위 테스트
   - 3개 이상 붙어 접히는 판넬의 진행도가 서로 다르면 맞닿은 변이 몇 px 벌어지는 알려진 한계(`sharedCameraLane` 주석, Lab은 많아야 2개라 생기지 않음): 이음새마다 카메라를 따로 두거나, 벌어짐을 받아들이기로 정한다
   - Lab `restZone Lane`이 게임 값을 보여 주도록 추정 녹숫 슬라이더(지금 300～2500ms)를 500～3000ms로 넓히거나 Lv. 선택으로 바꾸고, 테두리 기본값을 `밝은 레인색 둘레`로 바꾼다
3. **게임 렌더러 적용:** `GameRenderer`의 `restZone` dim 띠(`COLORS.REST_ZONE_DIM`·`REST_ZONE_ALPHA`)를 판넬로 바꾼다. 추정 녹숫은 차트 메타의 `difficultyLevel`에서 구한다. 같은 렌더러를 쓰는 튜토리얼 미리보기도 판넬로 바뀐다. glossary `restZone` 기능 (1)의 "게임은 dim"과 `src/shared/CONTEXT.md` 요약, [게임 코어](../spec/game-core.md)의 레인 끝 문장, 관련 E2E를 함께 고친다.
