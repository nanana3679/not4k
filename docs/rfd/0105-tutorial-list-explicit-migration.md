# RFD 0105: 튜토리얼 목록을 명시 노트 엔진으로 옮기고 실습 판정 기준을 정한다

**Status:** Accepted (2026-10-31) · PRD 반영 (2026-10-31) · 성공 조건을 Great 이하 판정 수로 바꾸고 트릴 롱노트 Miss 0회 조건·통과 기록 계정 동기화 세부 추가 (2026-10-31) · 실습 토글 양방향 즉시 전환 추가 (2026-11-01) · 모든 항목의 마지막 판정 뒤 2초 여백 추가 (2026-11-01) · 목록 이행·실습 판정 기준 미구현

## 기존 결정과 문제의식

일반 플레이는 명시 노트 엔진(`ExplicitJudgmentSession`)으로 판정하지만, 곡 선택의 튜토리얼 도움말은 구형 차트와 구형 세션(`NoteJudgmentSession`)으로 재생한다. 공개 목록에는 새 모델에서 폐지한 `holdOnly`를 설명하는 항목도 남아 있다. [PRD §12](../prd.md#12-미정-사항)의 "튜토리얼 목록 이행"은 내용·범위를 후속 착수 때 정하도록 남겨 두었다(2026-10-26).

[RFD 0081](0081-tutorial-demonstration-and-three-practice-successes.md)로 튜토리얼을 시연 뒤 직접 입력 실습으로 통과하는 방식으로 바꾸면서, 실습 통과가 실제 플레이와 다른 엔진으로 판정되면 튜토리얼에서 익힌 연주가 곡에서 다르게 판정될 수 있다. 항목별 성공 조건의 구체값도 PRD §12에 미정으로 남아 있었다.

## 검토한 대안과 채택안

튜토리얼의 시연과 실습을 모두 명시 노트 엔진으로 옮긴다. 구형 엔진 위에 실습을 먼저 붙이는 안과 비교해 사용자가 전부 명시 노트 엔진으로 옮기기로 했다(사용자 확인, 2026-10-31). 검토 때 든 근거는 구형 엔진 위의 실습은 나중에 다시 옮겨야 하고, 그동안 실습 판정이 실제 플레이와 어긋난다는 점이었다.

공개 목록의 기존 학습 주제는 유지하고 새 모델에 맞게 예제와 설명을 고친다. 항목별로 다음과 같이 이행한다(사용자 확인, 2026-10-31).

- **grace 롱노트(Basic 12)**: 끝에 릴리즈가 없는 바디로 바꾼다. 끝에서 떼지 않아도 되는 롱노트로 설명하고, 제목도 바디 용어로 바꾼다.
- **길이 0 grace 롱노트(Basic 13)**: 길이 0 바디와 틱 노트로 바꾼다. 그 순간 누르고 있으면 되는 노트로 설명하고, 제목도 바디·틱 노트 용어로 바꾼다.

위 두 항목의 옛 제목은 대응 확인을 위해 적었다. glossary의 Grace는 바디·틱 노트의 속성이 아니므로 새 제목에 grace를 쓰지 않는다.
- **길이 0 롱노트(Basic 10)**: 단독 릴리즈 노트가 되며, 떼는 순간만 판정하는 노트를 설명하는 항목으로 유지한다.
- **트릴 롱노트 끝(Basic 4·8)**: 새 모델에서 트릴 바디 끝에는 릴리즈가 없다. 이를 그대로 받아들이고 설명만 고친다.
- **감소(`advanced-decrease`)**: 감소 지점에 릴리즈를 명시해, 두 키를 그대로 쥐면 실패한다는 원래 레슨을 유지한다.
- **`holdOnly` 전용 Advanced 4개**(`advanced-holdonly-decrease`·`advanced-independent-holdonly`·`advanced-short-holdonly`·`advanced-zero-holdonly`): 목록에서 뺀다. 새 모델 고유 규칙을 다루는 항목은 별도로 정한다.
- **나머지 Advanced**: 새 엔진의 판정 결과로 기대값을 다시 맞추고, 설명의 근거를 명시 노트 모델로 바꾼다.

시연과 실습의 판정 기준은 실제 플레이와 맞춘다(사용자 확인, 2026-10-31).

- **판정 창**: 튜토리얼 고정값(Normal) 대신 플레이어 설정의 판정 모드(`judgmentMode`)를 따른다.
- **입력 오프셋**: 직접 입력 실습의 판정에 플레이어의 입력 오프셋(`inputOffsetMs`)을 적용한다.

항목별 성공 조건의 기본값을 정한다(사용자 확인, 2026-10-31). 요구 성공 횟수는 3회다. 트릴 교대를 배우는 항목에만 `goodTrill` 0회 조건을 더한다. 개발자는 [RFD 0081](0081-tutorial-demonstration-and-three-practice-successes.md)대로 항목별로 다른 값을 정할 수 있다.

실습 1회 성공은 목표 달성률 대신 **Great 이하 판정이 X개 이하**인지로 판단한다(사용자 확인, 2026-10-31). Great 이하 판정은 Perfect가 아닌 판정(Great·Good·`goodTrill`·Miss)이며, 바디 유지 실패의 무점수 Miss도 센다. 점수 항목이 적은 짧은 패턴에서 달성률 90%는 Great 하나만 나와도 미달이 되어 사실상 전부 Perfect를 요구했기 때문이다. 이는 RFD 0081의 "목표 달성률과 추가 조건"에서 목표 달성률 자리를 대신한다. X의 기본값은 1개다(사용자 확인, 2026-10-31). 사용자가 실제로 쳐 보며 조정할 예정이다.

트릴 롱노트를 유지하는 항목(`long-note`, `connected-trill-long`)에는 Miss 0회 조건을 더한다(사용자 확인, 2026-10-31). 트릴 바디에는 틱 노트를 둘 수 없어, 바디를 일찍 떼는 실패를 점수 항목으로 잡을 수 없기 때문이다.

통과 기록의 계정 동기화 세부를 정한다(사용자 확인, 2026-10-31).

- **인계 방식**: 로그인할 때 이 브라우저에 게스트 통과 기록이 있으면 자동으로 계정에 넘긴다. 기록을 합치기만 하므로 잃는 기록은 없다.
- **기회 소진**: 계정당 1회인 인계 기회는 실제로 넘긴 게스트 기록이 있을 때만 소진한다. 게스트 기록 없이 로그인하면 소진하지 않는다.
- **로그아웃 뒤 표시**: 로그아웃하면 계정 기록은 숨기고, 인계하지 않은 게스트 기록만 다시 보여 준다. 이미 인계한 게스트 기록은 다른 계정으로 다시 인계하지 않는다.

실습 중 `직접 입력 / 시연` 토글은 어느 방향으로 바꾸든 현재 재생 위치에서 즉시 적용한다(사용자 확인, 2026-11-01). [RFD 0081](0081-tutorial-demonstration-and-three-practice-successes.md)은 직접 입력에서 시연으로 바꿀 때 패턴이 재생 중이면 다음 패턴 시작부터 적용하도록 정했다. 그러면 시연을 고른 뒤 반복이 끝날 때까지 기다려야 하므로, 시연에서 직접 입력으로 바꿀 때와 같이 즉시 적용으로 바꾼다. 패턴 재생 도중 전환한 그 패턴은 방향과 관계없이 성공 집계에서 제외하고, 다음 패턴부터 직접 입력으로 연주한 패턴을 집계한다.

모든 튜토리얼 항목은 한 반복의 마지막 판정 대상(노트·릴리즈) 시각 뒤에 최소 2초의 여백을 둔다(사용자 확인, 2026-11-01). 여백은 박이 아니라 시간으로 정한다. 플레이어가 판정 결과와 조건 표시를 확인하고 실패 이유를 알아챌 시간을 주기 위해서다. 지금까지는 Advanced만 마지막 판정 기한 뒤 여백을 두었고, Basic에는 마지막 판정이 반복 끝과 겹치는 항목이 있었다. 2초는 잠정값이며 실제 플레이 뒤 조정한다.

## 영향과 검증

- PRD §12의 "튜토리얼 목록 이행"과 "튜토리얼" 행에서 정한 항목을 지우고 이 RFD를 링크한다.
- 튜토리얼 스펙의 Basic·Advanced 표와 기대값, glossary·컨텍스트의 튜토리얼 설명은 목록을 실제로 옮기는 구현과 함께 갱신한다. 이 문서 반영에서는 런타임을 바꾸지 않는다.
- 구현 방식(이 RFD의 결정이 아닌 구현 제안): [RFD 0037 §8](0037-explicit-score-notes-and-body.md#8-구형-차트와-과도기)이 구형 차트의 실행 중 변환을 허용하지 않으므로, 튜토리얼 차트는 명시 노트 차트로 저작해 저장소에 둔다.
- 여백 규칙은 튜토리얼 스펙의 Advanced 전용 문장을 모든 항목의 규칙으로 바꾸고, Basic 항목의 반복 길이를 늘린다. 메트로놈 박자가 반복 경계에서 어긋나지 않도록 반복 길이를 박 단위로 맞추는 것은 구현 방식이다.
- 토글 전환 규칙은 RFD 0081·glossary·튜토리얼 스펙·PRD의 해당 문장을 현재 규칙으로 고치고, 실습 진행 코어와 실습 화면에서 시연 예약 전환을 없앤다.
- 구현에서는 옮긴 항목마다 명시 엔진의 실제 판정 결과를 테스트로 고정하고, 실습 판정이 플레이어의 판정 모드와 입력 오프셋을 쓰는지 확인한다.
