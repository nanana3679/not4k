# RFD 0100: 비행 배경의 움직임을 별도 설정으로 끌 수 있게 한다

**Status:** Accepted (2026-10-31) · 용어·컨텍스트·게임 코어·RFD 0030·PRD 문서 반영 (2026-10-31) · 기본 켬·일반 플레이와 옵저버 공통 적용 문서 반영 (2026-10-31), 플레이어 설정과 고정 배경 전환의 런타임 반영 미구현 · 플레이어 설정과 고정 배경 전환 구현: `Settings → Gameplay → Display`의 `Background Motion`(`flightBackgroundMotion`, 기본 켬)을 일반 플레이·테스트 재생 렌더러의 `showFlightBackground`에 연결 (2026-10-31, PR #399). 남은 항목: 옵저버는 미구현이며 구현할 때 같은 설정을 쓴다

## 기존 결정과 문제의식

[RFD 0030](0030-ignore-os-reduced-motion.md)은 운영체제의 모션 감소 설정을 읽지 않고 게임 내 설정을 따르도록 정했다. 기어 모션은 `Gear Motion`으로 끌 수 있지만, 당시 결정에서는 비행 배경을 항상 움직이게 하고 배경 끄기는 후속 검토로 남겼다.

사용자는 비행 배경의 움직임을 끄는 별도 설정을 제공하고, 끄면 어두운 고정 배경에 노트·기어·고도 게이지를 그대로 표시하도록 확인했다(2026-10-31).

## 검토한 대안과 채택안

비행 배경의 움직임은 기어 모션과 별도의 게임 내 설정으로 끌 수 있게 한다. 끄면 어두운 고정 배경으로 바꾸고, 노트·기어·고도 게이지는 그대로 표시한다. 이 설정으로 노트 진행·입력 판정·고도 계산을 멈추지 않는다.

설정의 기본값은 켬이며, 일반 플레이와 옵저버가 같은 설정을 사용한다. 모드마다 별도 값을 두지 않는다(사용자 확인, 2026-10-31).

기어 모션은 기존 `Gear Motion` 설정을 독립적으로 따른다. 비행 배경의 설정이 기어 모션을 함께 끄지 않는다. 운영체제의 `prefers-reduced-motion`을 자동으로 따르지 않는 기존 원칙도 유지한다.

항상 움직이는 배경만 제공하는 대안 대신 플레이어가 배경 움직임을 선택할 수 있게 한다. 기어·노트까지 한꺼번에 끄는 설정이나 비행 배경의 한 프레임을 그대로 고정하는 대안 대신 어두운 고정 배경을 표시한다. 비행 배경을 끄더라도 고도 게이지를 통해 고도 상태를 확인할 수 있어야 한다.

## 현재 구현과 적용 경계

게임 설정 `flightBackgroundMotion`(설정 화면 `Settings → Gameplay → Display`의 `Background Motion`, 기본 켬)을 두었다. 저장된 설정에 이 값이 없으면 켬으로 복원한다. 일반 플레이·명시 테스트 재생(`ExplicitPlayRuntime`)과 구형 에디터 테스트 재생(`PlayScreen`)이 이 값을 렌더러 옵션 `showFlightBackground`로 넘긴다. 설정은 곡을 시작할 때 읽으며, `gearMotion`과 독립이라 한쪽을 바꿔도 다른 쪽은 그대로다.

끄면 렌더러는 비행 배경(`FlightBackground`)을 만들지 않고 Pixi 캔버스를 스킨 테마 바탕색 `bg`로 불투명하게 칠한다. 지금 스킨의 `bg`는 모두 어두운 색이다(Classic·Note Asset Lab `0x05080d`, Crystal `0x06070c`, Prism `0x06040e`, Simple `0x0a0a14`, 보관한 Classic 버전도 `0x05080d`). 렌더러는 기어 게이지가 있으면 비행 배경이 없어도 프레임마다 고도를 계산해 게이지에 주므로, 고도 게이지와 판정에 따른 고도 변화는 그대로다. 튜토리얼 재생기처럼 원래 비행 배경을 그리지 않는 렌더러는 이 설정과 관계없이 그리지 않는다. 옵저버는 아직 구현되지 않았으며, 구현할 때 같은 설정을 쓴다.

단위 테스트는 기본값과 저장 복원(`gameStore.test.ts`), 두 재생 경로가 `Gear Motion`과 반대 값을 조합해도 각 설정을 렌더러 옵션으로 그대로 넘기는지(`ExplicitPlayRuntime.test.ts`·`PlayScreen.flightBackgroundMotion.test.ts`), 끈 렌더러가 테마 바탕색으로 불투명하게 초기화되고 게이지가 고도를 따르는지(`GameRenderer.gearGauge.test.ts`)를 확인한다. 설정 화면 토글의 저장은 `e2e/game/settings.spec.ts`가 확인한다.

## 영향과 검증

[비행 배경](../context/glossary.md#비행-배경)의 정의와 관련 컨텍스트·게임 코어·PRD를 동기화한다. RFD 0030의 항상 움직이는 비행 배경 결정은 이 RFD의 별도 설정으로 갱신한다.

구현(PR #399)의 검증 항목은 다음 테스트가 확인한다. 기본 켬과 저장 복원은 `gameStore.test.ts`와 `e2e/game/settings.spec.ts`, 기어 모션 설정과의 독립 조합과 일반 플레이·테스트 재생 적용은 `ExplicitPlayRuntime.test.ts`·`PlayScreen.flightBackgroundMotion.test.ts`, 끈 렌더러가 테마 바탕색으로 불투명하게 칠하고 게이지가 고도를 따르는지는 `GameRenderer.gearGauge.test.ts`, 운영체제 모션 감소 설정을 읽지 않는지는 `FlightBackground.test.ts`가 맡는다. `e2e/game/gear-motion.spec.ts`는 끈 채 실제 플레이를 시작하면 비행 배경과 그 에셋 요청이 없고, 고도 게이지는 남아 Miss 판정에 따라 내려가는지 확인한다. 남은 확인은 두 가지다. 끈 상태에서 어두운 고정 배경 위에 노트·기어·고도 게이지가 제대로 보이는지는 자동 테스트가 화면을 비교하지 않으므로 눈으로 확인한다. 옵저버는 구현할 때 같은 설정이 적용되는지 확인한다.
