## 기존 결정과 문제의식

현재 공개 튜토리얼은 자동 시연을 보는 도움말이며, 본 항목 체크를 저장한다. 직접 따라 치는 실습과 통과 기준은 미정이었다. PRD에는 레벨별 튜토리얼 선행 조건도 검토 대상으로 남아 있었다.

사용자는 리듬세상처럼 시연을 본 뒤 실제로 입력을 3번 해 통과하는 학습 흐름으로 바꾸고, 차트 선택의 선행 조건은 일단 빼기로 했다. 이후 요구 성공 횟수를 실습항목별로 설정하도록 변경했으며, 처음의 3회는 기본값으로 유지한다(사용자 확인, 2026-10-31).

## 검토한 대안과 채택안

요구 성공 횟수는 실습항목별로 개발자가 양의 정수로 설정하며 기본값은 3회다. 플레이어가 목표 횟수를 바꾸는 설정 UI는 추가하지 않는다. 여러 연주 방법을 실습하는 항목은 각 방법에서 해당 항목의 목표를 따로 달성해야 한다. 구체적인 항목별 수치는 [PRD §12](../prd.md#12-미정-사항)에서 관리한다(사용자 확인, 2026-10-31).

`AutoEvent`는 튜토리얼 시연용으로만 다룬다. 일반 차트의 연출용 자동연주 기능으로 확대하지 않는다. 새 `직접 입력 / 시연` 토글과 기존 이벤트를 연결하는 구현 방식은 [PRD §12](../prd.md#12-미정-사항)에서 관리한다(사용자 확인, 2026-10-29).

자동 시연만 열람하는 방식 대신, 입력을 배우는 항목은 시연을 본 뒤 제시된 동작이나 짧은 패턴을 직접 연주하고 항목별 요구 횟수만큼 누적 성공하면 통과하는 방식으로 바꾼다. 단순히 항목을 보았다는 사실과 실제 실습 통과를 구별한다. 성공 횟수는 누적하며 실습 중 실패해도 줄이거나 초기화하지 않는다.

처음 실습에 들어갈 때부터 `직접 입력 / 시연` 토글을 사용한다. 플레이어가 직접 입력을 선택하면 실습으로 넘어가며, 시연 종료만으로 자동 전환하지 않는다. 처음 검토한 별도 실습 시작 버튼은 토글로 통일한다(사용자 확인, 2026-10-29).

실습에 필요한 키가 현재 바인딩에 부족하면 먼저 키 설정을 수정하도록 안내한다. 현재 키 설정으로 실습할 수 없어도 시연은 이용할 수 있다. `직접 입력 / 시연` 토글의 직접 입력 옵션을 비활성화하고 키가 부족한 이유와 실제 키 설정을 수정하는 경로를 안내한다. 실제 설정이 요구를 충족하면 직접 입력 옵션을 활성화하지만 자동으로 실습에 전환하지 않으며, 플레이어가 직접 선택해야 한다. 별도 실습 시작 버튼이나 임시 키 자동 배정은 추가하지 않는다. 시연용 표시 키 보충은 실제 실습의 키 요건을 충족한 것으로 취급하지 않는다. 실제 설정이 해당 실습의 요구를 충족한 뒤 실습을 시작하며, 실습 중에만 쓸 임시 키를 자동 배정하지 않는다. 기존 자동 시연 프리뷰의 표시용 키 보충과 직접 입력 실습의 요구를 구별한다(사용자 확인, 2026-10-29).

실습에서는 플레이어가 노트를 보고 직접 사용할 키를 판단한다. 다음에 눌러야 할 키를 미리 알려주는 가이드는 표시하지 않는다. 시연의 입력 안내와 실습 중 실제 누른 키의 표시를 구별하며, 노트와 `trillZone` 등 입력 요구를 알리는 시각 표시는 유지한다(사용자 확인, 2026-10-29).

튜토리얼의 노트 낙하 속도는 플레이어의 본 플레이 설정에 연동하지 않고 튜토리얼용 고정값을 사용한다. 본 플레이의 설정값은 변경하지 않는다. 구체적인 고정값은 [PRD §12](../prd.md#12-미정-사항)에서 관리한다(사용자 확인, 2026-10-29).

실습을 시작한 뒤에는 성공·실패마다 버튼을 다시 누르지 않고 같은 실습을 자동 반복한다. 실패해도 성공 횟수는 유지하며, 항목별 요구 횟수만큼 누적 성공하면 반복을 마치고 통과 처리한다. 이미 통과한 항목을 다시 실습해도 새 실습에서 항목별 요구 횟수만큼 누적 성공하면 반복을 종료하며, 기존 통과 기록은 유지한다. 플레이어는 통과 전에도 모달을 닫을 수 있다(사용자 확인, 2026-10-29).

항목 전체를 통과한 뒤에는 현재 항목에 머물며 `다음` 버튼을 누르면 다음 항목으로 이동한다. 통과만으로 자동 이동하지 않는다(사용자 확인, 2026-10-29).

실습 중 시연을 다시 확인할 때는 별도 다시 보기 버튼 대신 `직접 입력 / 시연` 토글로 두 상태를 오간다. 토글로 시연에 다녀와도 이미 쌓인 성공 횟수는 유지하고, 시연의 자동 입력은 성공 횟수에 포함하지 않는다. 직접 입력에서 시연으로 바꿀 때 이미 패턴이 재생 중이면 다음 패턴 시작부터 적용하며, 재생 중이 아니면 바로 적용한다. 시연에서 직접 입력으로 바꿀 때는 현재 재생 위치에서 즉시 적용한다. 시연 도중 직접 입력으로 바꾼 현재 패턴은 성공 집계에서 제외하고, 다음 패턴부터 성공 횟수를 집계한다. 항목별 목표 수치 등 남은 세부는 [PRD §12](../prd.md#12-미정-사항)에서 관리한다(사용자 확인, 2026-10-29). 이 전환 규칙은 튜토리얼에 적용하며 옵저버의 Auto 전환 규칙과 구별한다.

1회 성공 여부는 튜토리얼 항목마다 정한 목표 달성률과 추가 조건으로 판단하며, 이 조건들을 해당 튜토리얼에 표시한다. 실습 한 차례의 결과가 모든 조건을 만족하면 성공 횟수를 1회 더한다. 해당 항목의 요구 성공 횟수에 도달하면 통과한다.

각 통과 조건은 콤보 아래에 줄을 나눠 하나씩 표시한다. 충족한 조건에는 초록 체크 아이콘을, 실패한 조건에는 빨강 X 아이콘을 표시하며 중립 상태는 흰색 글씨로 표시한다(사용자 확인, 2026-10-29). 조건 상태는 연주 도중 실시간으로 갱신한다. 조건 목록 바로 아래에는 성공 횟수 진행도를 `현재 성공 횟수/해당 항목의 요구 성공 횟수`로 표시한다(기본값 3회인 항목의 예: `1/3`). 성공 횟수는 패턴 결과가 확정될 때 집계하며, 성공이 확정되면 진행도도 즉시 갱신한다.

일반 Good은 달성률 계산에 반영하며 발생 자체만으로 실패 처리하지 않는다. 트릴 교대 학습에는 `goodTrill` 0회 조건을 두어 교대 실패를 성공으로 집계하지 않는다. 항목별 구체적인 목표 수치와 추가 조건은 [PRD §12](../prd.md#12-미정-사항)에서 관리한다.

실습 과제는 올바른 연주 방법을 익히는 내용으로만 구성한다. 판정의 실패 사례는 시연으로 설명하고, 실패 동작을 직접 재현해야 통과하는 과제는 두지 않는다. 실습에서 실제로 발생한 실패는 일반 규칙대로 판정하며, 기존의 항목별 달성률·추가 조건으로 성공 여부를 판단한다(사용자 확인, 2026-10-29).

롱노트 중 탭은 한 항목 안에서 기존 키를 유지하는 방법을 먼저 시연·실습하고, 그 방법의 목표를 달성한 뒤 유지 키를 교대하는 방법을 시연·실습한다. 첫 방법의 목표를 달성하면 반복을 멈추고 현재 단계에 머물며, `다음` 버튼으로 두 번째 방법으로 이동한다. 자동으로 다음 방법으로 전환하지 않는다. 두 방법 모두 목표를 달성해야 항목 전체를 통과한다. 두 방법을 자유롭게 번갈아 선택하는 방식으로 만들거나 전체 튜토리얼 항목의 순서를 잠그는 것으로 확대하지 않는다. 각 방법에서 해당 항목의 요구 횟수만큼 성공을 누적한다. 성공 횟수를 방법별로 집계하며 서로 합산하지 않는다. 한 방법의 성공으로 다른 방법의 실습을 대신하지 않는다(사용자 확인, 2026-10-29).

실습 기록으로는 항목 전체 통과 여부만 로그인 여부와 관계없이 브라우저에 저장한다. 로그인하면 항목 전체 통과 여부를 계정과 동기화해 다른 기기에서도 같은 통과 표시를 확인할 수 있게 한다. 게스트 튜토리얼의 항목 전체 통과 기록은 로그인 시 계정당 1회 인계할 수 있다. 이미 인계한 게스트 기록은 다른 계정으로 재인계하지 않는다. 계정에 귀속된 통과 기록은 같은 계정의 여러 기기에서 계속 공유하며, 로컬에 표시된 계정 기록을 게스트 기록으로 재분류하거나 다른 계정으로 인계하지 않는다.  현재 방법·부분 성공 횟수·중간 방법 완료 여부는 현재 실습 세션에서만 유지하고 영구 저장·계정 동기화하지 않는다. 미완료 항목을 닫았다 다시 열거나 다른 항목에서 돌아오거나 게임을 재시작하면 첫 번째 방법의 성공 횟수 0회부터 시작한다. 이미 전체 통과한 항목의 재실습도 첫 번째 방법 0회부터 새로 진행하되 과거 항목 통과 기록은 지우지 않는다. 같은 항목 안에서 시연/직접 입력을 토글할 때는 현재 방법과 누적 성공 횟수를 유지하며 기존 전환·집계 규칙을 따른다. 같은 계정으로 다른 기기에 접속해도 통과 여부를 확인할 수 있게 한다(사용자 확인, 2026-10-30). 비로그인 플레이어도 통과한 항목을 다시 확인할 수 있게 한다(사용자 확인, 2026-10-30). 튜토리얼을 닫았다 다시 열면 미완료 실습의 성공 횟수는 0회부터 시작하며, 누적 성공 1회·2회 같은 중간 진행도는 복원하지 않는다. 이미 전체 통과한 항목의 기록은 유지한다. 실습 도중 실패해도 횟수를 유지하는 규칙과 닫은 뒤 재진입하는 초기화를 구별한다(사용자 확인, 2026-10-29). 다른 튜토리얼 항목으로 이동했다 돌아오는 경우에도 미완료 실습의 성공 횟수는 0회로 초기화한다. 같은 항목에서 직접 입력/시연을 토글할 때는 성공 횟수를 유지한다.

튜토리얼 목록에서 통과한 항목에 체크 표시를 붙인다. 시연만 본 항목에는 통과 체크를 붙이지 않으며, 별도의 열람 표시도 두지 않는다. 여러 연주 방법을 각각 실습하는 항목은 필요한 모든 방법을 통과해야 항목 전체를 통과로 표시한다(사용자 확인, 2026-10-30).

튜토리얼을 닫았다 다시 열면 마지막으로 선택한 탭과 항목을 연다. 마지막으로 선택한 탭과 항목은 해당 기기의 브라우저에만 저장해 게임을 껐다 켜도 복원하며 계정과 동기화하지 않는다. 선택 이력이 없는 최초 진입은 `Basic` 첫 항목에서 시작한다. 항목 위치 복원과 미완료 실습의 성공 횟수 복원은 구별한다. 현재 공개 도움말이 다시 열 때 `Basic` 첫 항목으로 돌아가는 동작을 변경한다(사용자 확인, 2026-10-30).

튜토리얼 완료·통과를 차트 선택의 선행 조건으로 두지 않는다. [RFD 0055](0055-first-launch-tutorial-modal.md)의 처음부터 바로 닫을 수 있는 모달과 수동 재진입 원칙도 유지한다. 실습의 통과 조건과 일반 차트의 이용 조건은 구별한다.

직접 입력을 통해 동작을 익혔는지 확인할 수 있으나, 시연만 보는 방식보다 입력 전환·반복·실패 처리를 설계해야 한다. 기존 열람 체크를 실습 통과로 간주하지 않는다.

## 영향과 검증

glossary, 루트·게임 컨텍스트, 튜토리얼·게임 코어·MVP 스펙과 PRD를 동기화한다. PRD의 미정 사항에서 레벨별 튜토리얼 선행 조건을 제거하고 남은 실습 세부만 관리한다. 기존 공개 튜토리얼과 새 목표를 구별하며 런타임 코드는 변경하지 않는다. 향후 구현에서는 시연·직접 입력 전환, 항목별 요구 횟수만큼 누적 성공 집계, 열람·통과의 구분과 자유로운 종료·차트 선택을 검증한다.
