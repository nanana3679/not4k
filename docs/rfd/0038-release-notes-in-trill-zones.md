# RFD 0038: trillZone 안의 명시 릴리즈 배치

**Status:** Accepted (2026-10-25) · 현재 제품 범위는 trillZone 안의 명시 릴리즈 미도입 · 구현은 #341(검증)·#342(컴파일)·#344(에디터 생성) · 트릴 안 명시 릴리즈의 배치 검증·에디터 저장·실행 차단 구현 (2026-10-26)

**이름 변경:** 노트 이름은 [RFD 0041](0041-explicit-score-note-names-tap-tick.md)에서 tap·tick으로 바꿨다(포인트 노트(Point)·`point`→탭 노트·`tap`, 유지 노트·유지 표식·`sustain`→틱 노트·`tick`). 이 문서의 본문은 결정 당시의 이름을 그대로 둔다.

**보조 레인 확장:** [RFD 0086](0086-auxiliary-lane-trill-zones.md)에서 메인/보조의 구간 귀속·릴리즈 배타를 같은 범위로 확장했다. 이 문서의 릴리즈 미도입 원칙은 보조 구간에도 적용한다.

## 배경

[RFD 0037](0037-explicit-score-notes-and-body.md)은 바디와 명시 릴리즈를 분리한다. 새 명시 릴리즈에는 별도 트릴 종류가 없으며 실제 up 하나를 소비한다. 기존 `trillZone` 배타 검증은 `trill`·`trillLong` 이외의 노트를 구간 안에서 금지하므로 이를 새 타입에 그대로 적용하면 트릴 바디 끝의 명시 릴리즈까지 막힌다.

트릴 바디 끝의 릴리즈도 새 조합으로 제공할 것이라는 전제로 바디 끝·단독 허용안을 검토했으나, 사용자는 “트릴 구간 안에서는 릴리즈 노트 도입할 생각 지금은 없음”이라고 답했다(2026-10-25). 따라서 현재 제품 범위는 끝점과 단독을 구별하여 허용하는 것이 아니라 구간 안의 명시 릴리즈 자체를 도입하지 않는 것이다.

## 결정

1. 같은 레인의 `trillZone` 시작·끝을 포함한 구간 안에는 명시 릴리즈를 배치하지 않는다. 바디 끝/단독, 싱글/더블, 일반/Grace에 따른 예외를 두지 않는다. 메인/보조 레인과 구간 귀속의 기존 범위는 유지한다.
2. 구간 안의 트릴 Point·바디 생성 조작은 Point와 바디만 만든다. 일반 Point 드래그의 기본 끝 릴리즈 생성을 이 조작에 적용하지 않는다.
3. 트릴 Point·바디의 기존 구간 배타·바디 전체 동일 구간 포함·시작 트릴 Point 필수·길이 0 트릴 바디 금지를 유지한다. 유지 노트의 트릴 바디 금지도 바꾸지 않는다.
4. 새 바디의 무점수·입력 미소비와 명시 항목만 점수로 만드는 RFD 0037을 유지한다. 구간 안 릴리즈 미도입을 이유로 자동 끝 점수·숨은 뗌 소비·`holdOnly`를 복원하지 않는다.
5. 구형 `trillLong`의 읽기·수리·편집 의미와 당시 실행 기록은 과도기 계약으로 보존한다. 저장 버전 변경으로 새 트릴 바디로 자동 변환하지 않는다.

이는 현재 범위의 결정이다. 이후 트릴 구간에 명시 릴리즈를 도입할 때는 별도 논의와 문서 변경으로 다룬다. 구현 진척과 후속 사항은 [PRD §12](../prd.md#12-미정-사항)에서 관리한다.

## 검토한 대안

| 안 | 동작 | 영향 |
| --- | --- | --- |
| 릴리즈의 바디 끝·단독 모두 허용 | 릴리즈에는 `trillZone`의 일반 Point/바디 배타를 적용하지 않는다 | 릴리즈는 위치에 관계없이 같은 up 의미를 사용하며 단독 뗌도 구간 안에 명시할 수 있다 |
| 트릴 바디 끝에 붙은 릴리즈만 허용 | 트릴 바디의 끝점에서만 구간 안 릴리즈를 허용하고 단독은 금지한다 | 기존 트릴 구성의 분리는 가능하지만 단독 릴리즈에는 추가 위치 제약이 생긴다 |

두 안 모두 현재 범위를 넘는 명시 릴리즈 도입이므로 채택하지 않았다. 트릴 교대 세트는 기존대로 Point down으로 갱신하며 릴리즈를 통해 교대 세트를 갱신하는 새 의미를 만들지 않는다.

## 유지할 규칙

바디 끝점 또는 단독 위치, 다른 점수 의미와 동일 위치 금지, 길이 0 바디와 조합 금지, 실제 시작·실패 종속·한 up당 한 항목·같은 키 예외는 RFD 0037을 따른다. 릴리즈의 일반/Grace와 수량을 구간 때문에 바꾸지 않는다. 이 결정으로 Point·바디의 트릴 교대나 유지 노트의 트릴 바디 금지를 바꾸지 않는다.

## 영향

glossary·관련 CONTEXT·에디터 스펙과 C2 문서 검증을 맞춘다. 새 릴리즈의 구간 배타는 붙은 끝/단독, 일반/Grace·싱글/더블, 양쪽 경계와 레인 차이를 정적 테스트로 검증한다. 트릴 생성에서 끝 릴리즈를 만들지 않는 조작과 새 트릴 바디의 무점수를 후속 E1/M2에서 확인한다. 구형 validator·보관 사례의 당시 기대값과 별도 정적 에셋 계약은 보존한다.
