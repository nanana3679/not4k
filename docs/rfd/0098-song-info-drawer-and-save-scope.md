# RFD 0098: 곡 정보는 왼쪽 드로어에서 편집하고 곡 저장으로 함께 확정한다

**Status:** Accepted (2026-10-31) · 용어·에디터 컨텍스트·편집 및 곡 관리 스펙·PRD 문서 반영 (2026-10-31) · 곡 이동·에디터 이탈 시 미저장 변경 선택 문서 반영 (2026-10-31) · 드로어 닫기 전 곡 정보 저장·변경 취소 문서 반영 (2026-10-31) · 같은 곡의 차트 전환 전 곡 정보 저장·변경 취소 문서 반영 (2026-10-31) · 오프셋 값 변경 시 재생 정지 문서 반영 (2026-10-31) · 재생 중 편집 제한·타이밍 값 변경 시 정지 및 위치 유지를 RFD 0099로 추가 (2026-10-31) · 곡 정보와 차트 편집의 시간순 Undo·Redo 통합 문서 반영 (2026-10-31) · 곡 정보 변경 취소의 이력 처리·Undo 복원 시 드로어 열기 문서 반영 (2026-10-31) · PR 이해 확인에서 타이밍 값 변경 시 자동 정지를 재생 중 값 수정 차단으로 대체 (2026-10-31), 드로어·곡 및 차트 저장 분리·이탈 확인 런타임 미구현 · 타이밍 값 수정 후 커서는 수정 직전 박을 유지하도록 RFD 0099의 후속 결정 연결 (2026-10-31), 커서 기준 전환의 런타임은 후속 구현 · 타이밍 값 수정 뒤 커서의 박 유지 구현 (2026-10-31, PR #392)

## 기존 결정과 문제의식

[RFD 0095](0095-song-shared-bpm-and-audio-offset.md)는 공통 타이밍과 차트의 저장을 분리하고 오프셋 조절 중에도 에디터 재생을 사용할 수 있도록 정했다. [RFD 0096](0096-song-shared-display-metadata-and-records.md)은 제목·아티스트·자켓도 곡이 소유하도록 정했다. 기존 Meta 모달과 오프셋 툴바는 곡 정보 편집과 타임라인 조작을 함께 사용하기 어렵다.

사용자는 왼쪽 드로어에 제목·아티스트·자켓·오프셋을 두고 타임라인 편집·재생을 유지하며, 곡 저장에서 표시 정보와 공통 타이밍을 함께 저장하는 방향을 확인했다(2026-10-31).

## 검토한 대안과 채택안

곡 정보는 왼쪽의 비모달 드로어에서 편집한다. 드로어가 열려 있어도 타임라인을 볼 수 있고, 편집은 재생 상태에 따른 제한을 따르며, 에디터의 재생·일시정지를 사용할 수 있어야 한다. 오프셋 입력을 열어 둔 정지 상태에서도 재생을 시작할 수 있다. 제목·아티스트·자켓·음원 정렬 오프셋은 드로어에 두고, BPM·박자표는 타임라인의 곡 공통 레인에 유지한다.

**곡 저장**은 제목·아티스트·자켓 등 곡의 표시 정보와 초기 BPM·BPM 변경 목록·박자표·변박 정보·음원 정렬 오프셋 등 공통 타이밍의 변경을 함께 저장한다. **차트 저장**은 해당 차트의 노트·차트별 이벤트·난이도 정보 등 개별 정보만 저장한다. 두 저장이 서로의 범위에 있는 미저장 변경을 함께 확정하지 않는다.

공통 타이밍에 미저장 변경이 있으면 Save Chart와 Save As를 차단하는 기존 규칙을 유지하되, 먼저 실행할 저장은 곡 저장으로 한다. 곡 저장이 성공하고 타이밍에 미저장 변경이 남아 있지 않으면 차트 저장을 허용한다. 표시 정보만 바꾼 경우까지 이 차단 조건을 확대하는 결정은 아니다.

모달로 편집 중 타임라인 조작을 막는 대안 대신 곡 정보와 편집 화면을 함께 사용한다. 표시 정보와 타이밍에 각각 저장 버튼을 두는 대안 대신 곡 단위 저장 하나로 묶는다. 곡 저장은 해당 곡 전체에 영향을 주므로 차트 저장과 구분해 표시해야 한다.

공통 레인의 접기·펼치기는 BPM·박자표 레인의 표시를 조절한다. 음원 정렬 오프셋 입력의 위치는 기존 공통 영역에서 곡 정보 드로어로 옮긴다. 접기로 공통 타이밍의 적용이나 현재 편집 위치를 바꾸지 않는다.

### 곡 정보와 차트 편집의 Undo·Redo

곡 정보 변경과 차트 편집은 하나의 Undo·Redo 이력으로 통합한다. 곡 정보·노트·차트별 이벤트의 구분 없이 가장 최근 작업부터 시간순으로 되돌리고 다시 적용한다. 저장 범위는 기존대로 곡 저장과 차트 저장으로 분리한다. Undo·Redo는 정지 상태에서만 사용할 수 있다. 저장 범위마다 별도 이력을 두는 대안 대신 편집한 순서에 따라 통합해 되돌리는 방식을 채택한다(사용자 확인, 2026-10-31).

곡 정보의 변경 취소도 마지막 저장 상태로 되돌리는 한 작업으로 통합 Undo·Redo 이력에 기록한다. Undo하면 취소 직전의 곡 정보 변경을 복원하고, Redo하면 변경 취소를 다시 적용한다. 변경 취소를 Undo해 곡 정보가 복원되면 드로어를 다시 열어 복원된 내용을 보여준다. 이 작업은 별도로 편집한 차트 내용을 바꾸지 않는다. 취소한 곡 정보 변경을 Undo 대상에서 별도로 제외하는 대안보다 일반 편집과 같은 이력 규칙을 따른다(사용자 확인, 2026-10-31).

예를 들어 BPM 수정 → 노트 배치 → 곡 정보 변경 취소 순서로 작업했다면 첫 Undo는 취소 직전의 BPM을 복원하고, 두 번째 Undo는 노트 배치를 되돌린다.

### 오프셋 변경 시 재생

오프셋 입력과 에디터의 재생·일시정지 조작을 함께 사용할 수 있어야 한다. 입력창을 열어 두는 것만으로는 재생을 막지 않는다. 음원 정렬 오프셋 값은 정지 상태에서만 수정할 수 있으며, 입력창을 열어 둔 채 직접 일시정지하고 수정한 뒤 다시 재생할 수 있어야 한다. 재생 중 수정 시도는 값과 재생 상태를 바꾸지 않는다([RFD 0099](0099-editor-playback-editing-boundary.md), PR 이해 확인에서 수정, 2026-10-31).

오프셋·BPM·박자표 값 수정은 정지 상태에서만 허용한다. 직접 일시정지한 뒤 값을 수정하며 수정 직전 커서의 박 좌표를 유지한다. 수정 후 같은 박에 해당하는 새 음원 시각으로 커서를 갱신하고, 다시 재생하면 그 위치부터 시작한다. 에디터 재생 중에는 노트·이벤트의 생성·이동·삭제와 롱노트·구간 이벤트의 길이 조절을 실행할 수 없다. Undo·Redo도 정지 상태에서만 사용할 수 있다. 이 제한은 마우스·터치·키보드 등 입력 방식과 관계없이 적용한다. 상세는 [RFD 0099](0099-editor-playback-editing-boundary.md)를 따른다.

### 드로어 닫기

곡 정보 드로어에 미저장 곡 정보 변경이 있으면 저장하거나 해당 변경을 취소한 뒤에만 드로어를 닫을 수 있다. 저장을 선택하면 곡 저장이 성공한 뒤 닫으며, 실패하면 드로어와 편집 내용을 유지한다. 변경 취소는 곡 정보의 미저장 변경을 버리고 마지막 저장 상태로 되돌린 뒤 닫는 동작이다. 별도로 편집 중인 차트 변경은 함께 버리지 않는다. 미저장 곡 정보가 없으면 바로 닫을 수 있다. 미저장 곡 정보를 유지한 채 드로어만 닫는 대안은 채택하지 않는다(사용자 확인, 2026-10-31).

### 같은 곡의 다른 차트로 전환

같은 곡의 다른 차트로 전환할 때도 미저장 곡 정보가 있으면 먼저 곡 저장을 완료하거나 해당 변경을 취소해야 한다. 곡 저장은 성공한 뒤에만 전환하며, 실패하면 현재 차트와 편집 내용을 유지한다. 변경 취소는 곡 정보의 미저장 변경을 마지막 저장 상태로 되돌리는 동작이다. 곡 정보 변경 취소가 현재 차트의 미저장 변경까지 함께 버리는 동작은 아니다. 미저장 공통 초안을 유지한 채 다른 차트로 전환하는 대안 대신, 저장하거나 변경을 취소해 곡 정보를 확정한 뒤 전환한다(사용자 확인, 2026-10-31).

### 곡 이동·에디터 이탈 시 미저장 변경

다른 곡으로 이동하거나 에디터를 나가려 할 때 곡 정보 또는 차트에 미저장 변경이 있으면 **저장 후 이동 / 버리고 이동 / 취소**를 선택하게 한다. 저장 후 이동은 변경이 있는 곡 정보·차트를 각 저장 범위에 따라 저장하고 필요한 저장이 모두 성공한 뒤 이동한다. 공통 타이밍 저장이 필요한 경우 곡 저장을 먼저 완료하는 기존 순서를 따른다. 저장 실패 시 이동하지 않고 미저장 변경을 유지한다. 버리고 이동은 미저장 변경을 버리고 이동하며, 취소는 편집 화면과 변경 내용을 유지한다.

미저장 변경을 알리지 않고 이동하는 대신 저장·폐기·이동 취소를 선택할 수 있게 한다(사용자 확인, 2026-10-31).

## 현재 구현과 적용 경계

현재 Meta 모달·오프셋 툴바와 차트 저장 경로를 이번 작업에서 변경하지 않는다. 저장 구조와 기존 사본 이행 등 남은 절차는 [PRD §12](../prd.md#12-미정-사항)에서 단일 관리한다.

곡 저장 버튼으로 표시 정보와 타이밍을 함께 저장하더라도 기록 버전 분리의 판단 기준은 변경 내용이다. 표시 정보만 수정하면 기록을 유지하고, 공통 타이밍 수정으로 실제 입력 시각이 달라진 차트는 기존 결정대로 기록·랭킹을 새 버전으로 분리한다.

## 영향과 검증

[곡 저장](../context/glossary.md#곡-저장)의 범위를 정의하고 에디터 컨텍스트, [에디터 스펙](../spec/chart-editor.md#곡-타이밍-공유-미구현), 곡 관리·PRD를 동기화한다. RFD 0095·0096에는 후속 UI·저장 결정을 연결한다.

후속 구현에서는 드로어가 열린 상태에서 타임라인 편집과 재생 시작·일시정지를 할 수 있는지, 표시 정보와 공통 레인 수정이 곡 저장에 함께 포함되는지, 곡·차트 저장이 상대 범위의 변경을 저장하지 않는지 검증한다. 곡 정보와 차트를 번갈아 편집한 뒤 Undo·Redo가 통합된 작업 순서를 따르는지도 확인한다. 곡 정보 변경 취소의 Undo·Redo, 복원 시 드로어 열기와 차트 내용 보존도 검증한다. 재생 중 오프셋·BPM·박자표 값 수정이 실행되지 않고 값과 재생 상태를 유지하는지, 입력창을 열어 둔 채 직접 일시정지해 수정하고 다시 재생할 수 있는지도 확인한다. 공통 타이밍이 미저장 상태이거나 저장에 실패하면 차트 저장이 계속 차단되는지도 확인한다. 드로어가 미저장 변경을 남긴 채 닫히지 않는지, 변경 취소가 차트 변경에 영향을 주지 않는지, 같은 곡의 다른 차트로 전환하기 전 곡 정보 저장·변경 취소의 처리, 곡 이동·에디터 이탈에서 세 선택의 결과와 저장 실패 시 편집 유지도 검증한다. 이번 작업은 문서 변경이다.
