# RFD 0029: 새 기어 프레임을 비율 그대로 배치하고 레인을 좁힌다

**Status:** Accepted (2026-10-04, 사용자 결정) · 결정 근거가 된 Pixi 미리보기 `/lab/classic-frame-fit` (2026-10-04, PR #215) · 실제 게임 적용 미구현

## 기존 결정과 문제

게임은 논리 높이 600 화면 가운데에 폭 400의 레인 영역을 두고, 판정선을 y 440(아래에서 160)에 그린다. 기어 프레임(스킨 공통 에셋 `public/gear/gear-frame.png`)은 안쪽 창의 폭을 레인 영역 400에 맞춰 같은 배율로 그린다. 이 배율에서는 프레임 위쪽 약 332 논리 단위가 화면 밖으로 잘린다. 판정선 아래 레인은 불투명 가림막이 판정선 바로 밑부터 덮어서, 판정선을 지난 노트는 곧바로 보이지 않는다.

[RFD 0027](0027-single-aperture-thrust-feedback.md)의 추진부 디자인을 이어 만든 새 Classic 프레임(대기 바탕 `press-idle-deck-v17-input.png`, 1024×1536)은 사용자가 [움직임 애니메이션까지 수용](../design/classic-frame-keywords-20260929.md#프레임-움직임)했다. 이를 게임에 넣으려 할 때 두 가지 문제가 있었다.

- **비율:** 그림 속 레인 칸은 552×1090px(x 236–787, 덱 첫 행 1090)로 폭 대 높이가 약 1:2다. 게임 레인 영역은 판정선 위가 400×440으로 약 1:1.1이다. 레인 폭을 지금처럼 400에 맞추면 프레임 위쪽 483행이 잘리고 하단 바는 화면 밖으로 나간다.
- **화질:** 같은 배율에서 원본 1px이 렌더 높이 1080 기준 화면 1.30px로 확대되어 흐려진다(1440이면 1.74px). SVG로 넣으면 Pixi가 정지 비트맵으로 구워 CSS 애니메이션도 사라진다.

처음에는 기둥과 덱을 부분 에셋으로 나눠 배치하는 방향을 검토했고, 맞춤 방식은 Pixi 안에서 실제 게임 비율로 보여 주는 미리보기를 보고 정하기로 했다.

## 검토한 대안

[Classic Frame Fit 미리보기](../spec/lab-preview-catalog.md#classic-frame-fit)에서 실제 `GameRenderer`, 인게임 비행 배경, 흐르는 노트 위에 프레임을 얹어 비교했다.

- **레인 폭 맞춤(위 잘림):** 지금 기어와 같은 규칙이다. 위쪽 483행(게이지 윗부분·장갑 머리)이 잘리고, 하단 바가 보이지 않으며, 원본이 확대되어 흐리다.
- **기둥 잘라 줄이기:** 기둥에서 483행을 지워 위끝을 화면 위에 맞춘다. 가장 덜 티 나는 위치를 골라도 이음매의 행 차이가 보통 인접 행 차이의 약 14배라 이음매가 보인다.
- **세로로 눌러 맞추기:** 기둥 구간만 세로로 56%로 누른다. 그림이 왜곡된다.
- **부분 에셋으로 나눠 배치하거나 다시 생성:** 기둥과 덱을 따로 놓는다. 게임 레인 영역의 비율이 그대로라 기둥을 늘이거나 줄이는 문제가 남고, 다시 생성하면 수용한 외형이 바뀔 수 있다.
- **가로세로 같이 줄이고 레인을 좁힌다:** 프레임을 비율 그대로 줄이고 게임 레인을 그림 속 레인 칸에 맞춰 좁힌다. 이 안을 채택한다.

## 채택안

- **프레임은 이미지 한 장을 비율 그대로 줄여 놓는다.** 그림 속 레인 칸(x 236–787)을 게임 레인 영역에 정확히 맞춘다. 배치를 위해 그림을 부분으로 나누지 않는다. 키 누름·게이지·광원 같은 [부분별 발광 레이어](../design/classic-frame-keywords-20260929.md#버튼-누름-애니메이션-1단계)는 같은 바탕 좌표 위에 측정 마스크로 겹친다.
- **레인 영역 폭은 높이 600 화면 기준 약 250**이다(지금 400의 62.5%). 이때 프레임 배율은 약 0.45다. 원본 1px이 렌더 높이 1080에서 화면 0.82px, 1440에서 1.09px로 그려져 흐려지지 않는다. 축소할 때 테두리 계단이 생기지 않도록 프레임 텍스처는 밉맵으로 거른다.
- **프레임은 아래끝을 화면 아래에 고정한다.** 레인 폭 250에서 위쪽 장갑 머리 약 141행만 잘리고, 게이지·덱·하단 바는 모두 보인다.
- **판정선 기본 위치는 프레임 덱 위끝보다 노트 두께 약 1배 위다.** 미리보기 기준으로 y 416이고, 지금 리프트 설정으로 치면 4%다. 덱 위끝은 y 429.7이며 판정선과 덱 사이 틈은 13.7(노트 두께의 약 1.1배)이다.
- **리프트는 프레임을 움직이지 않고 판정선만 올린다.** 판정선은 선 두께까지 프레임 덱에 가려지지 않아야 한다.
- **레인 가림막은 판정선이 아니라 프레임 덱 위끝부터 덮는다.** 맞힌 노트는 지금처럼 판정선에서 사라진다. 놓친 노트는 판정선을 지나 판정선과 덱 사이 틈을 통과한 뒤 덱 밑으로 사라진다. 놓친 롱노트는 지금 렌더러가 판정선에 고정하므로 [#214](https://github.com/nanana3679/not4k/issues/214)에서 같은 동작으로 바꾼다.
- **움직임은 Pixi 안에서 다시 구성한다.** 애니메이션 SVG를 그대로 넣지 않고, 같은 바탕과 측정 마스크로 큰 광원·게이지 액체·발광선·하단 바를 Pixi 레이어로 만든다.

## Trade-off

- 레인과 노트가 좁아져 화면에서 차지하는 폭이 줄어든다(16:9 기준 화면 폭의 약 37%에서 23%). 대신 프레임 전체가 보이고 원본보다 작게 그려져 선명하다.
- 미리보기는 레인을 좁히는 대신 게임 화면 전체를 줌아웃해 흉내 냈다. 그래서 노트 두께, 콤보·정확도 글자, 키봄도 함께 작아졌다. 실제 적용에서 이 크기들을 레인 폭과 함께 줄일지 따로 정할지는 아직 정하지 않았다.
- 판정선 기본 위치가 덱 위로 올라가면서 리프트 0%의 위치가 지금과 달라진다. 리프트 설정값의 의미(기본 위치에서 판정선만 올린다)는 유지한다.
- 놓친 노트가 판정선 아래 틈에서 잠깐 더 보인다. 판정 결과는 바뀌지 않으며 화면 표시만 바뀐다.

## 영향 범위

이 RFD는 결정만 기록한다. 아래 항목은 실제 게임에 적용할 때 바꾼다.

- **렌더러 배치:** `src/game/renderer/constants.ts`의 `LANE_AREA_WIDTH`·`LANE_WIDTH`·`NOTE_WIDTH`, 판정선 위치(`JUDGMENT_LINE_OFFSET`과 `setLift`), 판정선 아래 가림막(`drawMask`), 기어 프레임 배치(`GameRenderer`의 `GEAR_INNER_*`와 `updateGearFrameTransform`), 기존 40×40 버튼 그림.
- **에셋:** 기어 프레임과 양옆 게이지(`public/gear/`, `gearGaugeMetadata.json`)를 새 프레임 바탕과 측정 마스크로 바꾼다. 기어 프레임은 지금처럼 스킨 공통 에셋이다.
- **노트 표시:** 놓친 노트를 덱까지 그리고, 놓친 롱노트의 판정선 고정을 푼다(#214).
- **문서:** [게임 코어 명세](../spec/game-core.md)의 리프트 기본 위치와 레인·판정선 배치, [PRD §12](../prd.md#12-미정-사항)의 `Classic 추진부 디자인` 행.
- **튜토리얼·노트 에셋 재생기:** 자체 레인 배치(폭 400, 판정선 오프셋 80, 기어 없음)를 쓰므로 새 레인 폭을 따를지 함께 정한다.
- 남은 선택(노트 두께·글자·키봄 크기, 정확한 틈 높이, 움직임 레이어의 Pixi 구성)은 [PRD §12](../prd.md#12-미정-사항)에서 관리한다.
