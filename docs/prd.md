# not4k — Product Requirements Document (PRD)

> 4레인 노트낙하형 가변 손배치 PC 리듬게임

---

## 1. 문제 정의

PC 노트낙하형 고정키 리듬게임은 세 가지 구조적 한계를 공유한다.

| # | 문제 | 근본 원인 | 영향 |
|---|------|-----------|------|
| A | **연타의 물리적 고통** | 한 키에 한 손가락이 고정되어 반복 충격이 집중 | 건초염·손목 터널 증후군, 고난이도 패턴 단순화 |
| B | **키 수 간 난이도 단절** | 4B→5B→6B→8B 전환 시 레인 구조가 변경 | 키 수마다 사실상 다른 게임, 통합 성장 경로 부재 |
| C | **고정 손배치의 해부학적으로 불리한 패턴** | 레인-키 1:1 고정으로 해부학적 한계에 충돌. 키 수가 늘수록(5B·7+1) 심화 | IIDX 4756 문제, 랜덤 의존, 실력이 아닌 운에 의한 클리어 |

아케이드 리듬게임(SDVX, 츄니즘, maimai)은 물리적 인터페이스 특성으로 이 문제를 부분적으로 해결하지만, PC 키보드 환경으로 이식할 수 없다.

**근거 문서**: `docs/context/rationale.md`, `docs/research/` (6개 역기획 보고서)

## 2. 해법

### 핵심 메커니즘: 4레인 + 레인당 다중키 바인딩

- 화면에는 항상 4개의 레인이 존재한다.
- 유저는 각 레인에 **2개 이상의 키**를 바인딩한다.
- 같은 레인의 노트는 바인딩된 키 중 아무 키로든 처리할 수 있다.

| 기존 문제 | 해법 | 효과 |
|-----------|------|------|
| 연타의 고통 | 연타를 트릴(키 교대)로 처리 가능 | 반복 충격 분산, 패턴 다양성 확보 |
| 키 수 단절 | 레인 수 불변, 키 수만 유저가 확장 | 4키→16키가 하나의 연속된 성장 경로 |
| 해부학적으로 불리한 패턴 | 어떤 키 조합을 쓸지 유저가 선택 | 해부학적 한계가 시스템에 의해 강제되지 않음 |

**트레이드오프**: 입력 난이도 감소 대신 인식 난이도(어떤 키로 처리할지의 실시간 판단) 증가. 트릴 노트와 난이도 계단으로 관리.

## 3. 타겟 유저

### 1차 타깃: 기존 노트낙하형 리듬게임 유저 중 신체적 부하와 물리적 한계로 흥미를 잃은 유저

osu!mania, DJMAX 등 4키+ 리듬게임 경험자 중 고난이도에서 **신체적 부하와 물리적 한계**로 흥미를 잃은 유저.

| 기존 4키의 문제 | not4k의 해법 |
|---------------|-------------|
| 물리적 속도·지구력이 난이도 천장 | 신체 부하 대신 **인식 부하**(손배치 전환 판단)로 난이도 상승 |
| 특정 손가락에 부하 집중 (약지·소지) | 8키 분산 → 손가락 사용이 **균등하게 분산** |
| 배치가 불편해도 강제 | 원하는 손가락을 선택 가능 → **배치 스트레스 없음** |

### 2차 타깃: 리듬게임 입문자

리듬게임을 처음 접하는 유저도 not4k로 시작할 수 있도록 **진입 장벽을 낮추는 장치**를 마련한다:

- 튜토리얼 (Phase B): 연주 방법 → 복합 패턴 단계적 학습
- Lv.1～3: 전 노트 타입이 등장하지만, 패턴 밀도와 조합이 단순
- 옵저버 모드 (Phase B): 어려운 구간을 미리 연습 가능

단, **메인 타깃은 신체적 부하와 물리적 한계로 기존 리듬게임에서 흥미를 잃은 유저**이다. 입문자는 "이 게임으로도 시작할 수 있다"는 접근성을 보장하되, 게임 설계의 핵심 의사결정은 1차 타깃 기준으로 내린다.

### 3차 타깃: 상급 유저

고난이도 도전과 랭킹 경쟁을 원하는 유저. 기존 게임에 없는 차트 공간(홀드 중 탭, 수평 이동 등)이 동기 부여.

### 지역 타깃

한국 → 일본 → 글로벌 순. 다국어(ko/ja/en) 확정.

로그인한 플레이어의 완주 기록뿐 아니라 `flightRule`에 따라 곡 도중 실패로 종료된 기록도 점수 기록과 랭킹 반영 대상에 포함한다. 곡 도중 실패로 종료되면 그때까지 얻은 점수를 반영한다. 더 높은 점수라면 최고기록을 갱신하며, 해당 플레이의 클리어 여부는 점수와 별도로 판정한다. 기존에 달성한 클리어 기록은 유지한다. 플레이어가 직접 중단한 Quit·Retry 경로는 기록을 남기지 않는다.

현재 차트 버전의 최고기록·클리어 여부·풀콤보 여부는 곡·차트 선택에서 바로 표시한다. 차트 선택에서 해당 차트의 플레이 기록이 없으면 클리어 상태 표시를 비워둔다. 0점이더라도 실패 기록이 있으면 실패를 표시한다. 차트 선택에서는 올퍼펙트를 달성한 경우 풀콤보 표시 대신 올퍼펙트를 표시한다. 최고 점수가 갱신되지 않는 동점 플레이에서 새로 달성한 올퍼펙트도 표시에 반영한다. 최고기록은 최고 점수이며 더 높은 점수를 얻으면 갱신한다. 플레이 횟수는 통계창에서 확인한다. 첫 클리어 시점 등 다른 상세 기록은 예시이며 저장 항목으로 확정하지 않는다. 타인에게 기본 공개하지 않는 원칙은 유지한다([RFD 0085](rfd/0085-chart-records-and-detailed-history-visibility.md)). 집계·저장·상세 화면은 §12에서 관리하며, 이번 결정은 표시·독립 보존 정책의 문서 반영이다. 최고기록·클리어 여부·풀콤보 여부는 서로 다른 플레이에서 달성해도 각각 보존한다. 최고기록 갱신 여부와 관계없이 새 클리어·풀콤보를 보존하고, 새 최고기록을 세운 플레이에서 달성하지 못해도 기존 달성 여부는 유지한다. Normal과 Easy의 최고 점수·클리어 여부·풀콤보 여부는 판정 설정별로 분리해 보존한다. 한 설정에서 달성한 기록으로 다른 설정의 기록을 갱신하지 않는다. 같은 판정 설정 안에서는 미러 사용 여부와 관계없이 같은 차트의 기록으로 합쳐 보존하며 두 경우 모두 같은 최고기록의 갱신 대상이다. 곡·차트 선택과 랭킹에는 현재 차트 버전의 새 기록만 표시한다. 이전 버전 기록의 조회 화면과 표시 방식은 이번 출시 전 설계 범위에서 제외한다. 차트 삭제 후에도 원래 버전의 기록은 보관하며 선택·현재 랭킹에서는 제외한다. 재등록은 새 차트로 취급하고, 삭제 전 플레이의 지연 전송 결과도 원래 버전에 보관한다([RFD 0097](rfd/0097-preserve-records-after-chart-deletion.md)).

### 4.4 백엔드 (Supabase — 별도 서버 없음)

별도의 커스텀 백엔드 서버를 두지 않고, **Supabase**의 Auth·Database·Storage·Edge Functions를 직접 사용한다. 클라이언트가 Supabase SDK를 통해 직접 접근하며, Supabase 클라이언트 설정은 `src/supabase/`에 위치한다.

| ID | 기능 | Supabase 기능 | 상세 | 상태 |
|----|------|--------------|------|------|
| B-01 | **인증** | Auth | Google OAuth + Anonymous Auth. 비로그인 플레이 허용(기록 미저장). 타이틀·곡 선택 화면에 로그인 버튼 제공. admin 권한은 `profiles.is_admin` 플래그로 관리(개발자가 Supabase 콘솔에서 직접 변경). admin 유저는 곡 선택에서 비공개 곡 접근·Edit 버튼 표시·에디터 진입 가능 | 부분 구현 — 에디터에서만 Google OAuth·admin 검증 구현, 게임 클라이언트 로그인·admin 분기 미구현 |
| B-02 | **차트 제공** | Storage | 차트 JSON + 음원 파일을 Storage에서 fetch. OGG→MP3 폴백 지원. 오프라인 미지원 | 차트·음원 제공 구현, 곡 타이밍 공유 미구현 |
| B-03 | **랭킹** | Database | 차트(곡 + 난이도)의 버전별 점수 순위. 기록 수치는 점수만 표시하고 달성률은 표시하지 않음. Normal/Easy 모두 제공하며 판정 설정별로 따로 집계. 동점은 해당 점수를 먼저 달성한 순서([RFD 0085](rfd/0085-chart-records-and-detailed-history-visibility.md)) 점수와 독립 보존한 풀콤보·올퍼펙트 배지 표시(AP 우선). 일반 성공·실패는 미표시. 배지는 점수 순위·동점 최초 달성 시각에 영향 없음. 같은 점수의 새 AP도 배지만 갱신하고 점수 갱신 안내 없음. 상위 목록 밖에 있는 본인의 순위·점수도 별도로 표시. 랭킹 창을 열 때 최신 기록을 불러오며 열어둔 동안에는 자동 갱신하지 않음. 조회 실패 시 랭킹 창 안에 오류 안내·재시도 버튼 표시. 플레이어 이름은 현재 닉네임으로 표시. 기존 랭킹 이름도 조회 시 현재 닉네임으로 표시 | 미구현 |
| B-04 | **기록** | Database | 로그인 유저 플레이 기록 저장 (차트 버전·Normal/Easy별 최고 점수·클리어·풀콤보 독립 보존). 완주 시 클리어 실패와 `flightRule`에 따른 곡 도중 실패 종료 모두 획득 점수를 기록·랭킹 반영 대상에 포함. 직접 중단한 Quit·Retry는 제외. 전송 실패 시 결과 화면에 실패 안내·전송 재시도 버튼 제공. 결과 화면을 나가도 미전송 기록을 해당 계정과 연결해 브라우저에 보관하고 다음 접속 때 원래 계정으로 로그인되어 있으면 자동 재전송 | 미구현 |
| B-05 | **설정 동기화** | Database | 키 바인딩, 오프셋 등 유저 설정의 서버 저장 | 미구현 |
| B-06 | **튜토리얼 동기화** | Database | 로그인하면 항목 전체 통과 여부와 마지막 선택 탭·항목을 계정과 동기화. 열람 위치가 다르면 실제로 가장 최근에 선택한 위치를 사용. 브라우저·계정 중 어느 쪽에서든 통과한 항목은 합쳐 보존. 현재 방법·중간 방법 완료·부분 성공은 동기화하지 않고 재진입 시 첫 방법 0회부터 시작([RFD 0081](rfd/0081-tutorial-demonstration-and-three-practice-successes.md)) | 미구현 |

## 5. 노트 시스템

### 5.1 노트 타입

모든 노트 타입은 **Lv.1부터 등장**. 난이도에 따라 변하는 것은 빈도와 복합도.

아래 표는 과도기 구형 엔진의 노트 타입과 판정 구성을 설명한다. [RFD 0035](rfd/0035-release-presence-and-grace.md)의 새 롱노트는 release를 내장하지 않으며 바디와 별도 릴리즈 노트를 조합한다. 바디는 점수 항목·가중치에서 제외하고 콤보와 고도에만 관여한다.

개념적으로 4종(싱글, 롱, 트릴, 더블)이며, 코드상 포인트 3종 + 구간 3종 = **6종**으로 구현:

| 노트 타입 | 코드명 | 메커니즘 | 요구 키 수 | 판정 | 형상 | 색상 |
|-----------|--------|----------|------------|------|------|------|
| **싱글** | single | 레인 내 아무 키 1개 | 1+ | 1회 | 직사각형 | #4488ff |
| **더블** | double | 서로 다른 키 **2개 동시** | 2+ | 독립 싱글 판정 × 2 | 직사각형 | #ffcc00 |
| **트릴** | trill | 직전 키와 **다른 키**. `trillZone` 내에서만 등장 | 2+ | 1회 (교대 실패 시 `goodTrill`) | 다이아몬드 | #ffffff |
| **싱글롱** | long | 키 누르기 → 유지 → 떼기. 시작점·바디·끝점 구조 | 1+ | 최대 2회 (헤드+릴리즈) | 직사각형 | #88bbff |
| **더블롱** | doubleLong | 2키 동시 홀드 | 2+ | 헤드+릴리즈 각각 더블 판정 | 직사각형 | #ffee88 |
| **트릴롱** | trillLong | `trillZone` 내 롱노트 | 2+ | 헤드+릴리즈 (교대 실패 시 `goodTrill`) | 다이아몬드 | #aaaaaa |

### 5.2 특수 메커니즘

| 메커니즘 | 설명 |
|----------|------|
| **홀드 교대** | 같은 레인의 hold 수로 연결 경계의 유지를 이어받음. 이미 확정된 실패는 새 입력으로 복구하지 않음. 구형 엔진은 등록된 유지 키와 연결 경계의 유효 판정 창으로 교대 |
| **끝점 판정** | 일반 릴리즈는 Perfect/Great/Good/Miss. 그레이스 릴리즈도 실제 뗌은 필수이며 Good 창 안이면 Perfect. 릴리즈 없음은 뗌을 요구하지 않음. 일반 승계 성공에는 점수·콤보 없음([RFD 0035](rfd/0035-release-presence-and-grace.md)·[RFD 0037 §2](rfd/0037-explicit-score-notes-and-body.md#2-구성과-점수-의미), 명시 판정 구현) |

| **바디 구간 독립성** | `o-o-`의 각 바디 구간은 독립 판정 |
| **`trillZone`** | 시각적 예고 영역. 입력 불요구. 긴장도 유지·시각적 다양성 역할 |

| 롱노트 끝 탭 | 4 | 롱노트 끝에서 다른 키로 탭하는 배치. 트릴 연결은 선택적 |
| 싱글→더블 전환 | 4 | 싱글 노트 흐름이 더블 노트로 전환되는 배치 |

## 7. 스코어링

아래는 [RFD 0020](rfd/0020-note-judgment-units-and-inheritance.md)의 채택 규칙이다. 구현 이행 상태는 [§12](#12-미정-사항)를 따른다.

| 항목 | 규격 |
|------|------|
| **달성률** | (획득 점수 / 차트 점수 항목의 이론 가중치 합) × 100%. 실시간 분모에는 지금까지 처리한 점수 항목의 가중치를 반영. 무점수 유지 Miss는 분모를 늘리지 않음 |
| **점수** | Perfect=3, Great=2, Good=1, `goodTrill`=1, Miss=0. Miss 자체의 별도 감점 없음 |
| **콤보 유지** | Perfect, Great, Good, `goodTrill` |
| **콤보 파괴** | Miss — 무점수 유지 실패도 포함 |
| **풀콤보** | 곡 완주 + Miss=0 (`goodTrill`은 영향 없음). 미완주 시에는 인정하지 않음. 달성률 100%이면서 Full Combo가 아닌 결과 허용 |
| **올퍼펙트** | 곡 완주 + 모든 점수 노트 Perfect + 무점수 바디 실패를 포함한 Miss=0. 점수 노트를 모두 Perfect로 처리했어도 바디 Miss가 있으면 인정하지 않음 |
| **랭크** | SSS(≥99.5%) / SS(≥99.0%) / S(≥97.0%) / AAA(≥95.0%) / AA(≥90.0%) / A(≥85.0%) / B(≥80.0%) / C(≥70.0%) / D(≥60.0%) / F(<60%) |
| **`flightRule`과 난이도명** | `Liftoff → Infiltration → Breakthrough` 순서로 차트 난이도명과 비행 시나리오를 연결한다. 연출은 각각 각도 유지·하향 회전·전방을 보는 지속 저공비행이다. `Liftoff`의 관대한 역할과 곡 중 게임 오버 없음은 유지하고 Miss 없는 완주가 클리어 조건을 충족하도록 게이지 상승량을 설정하며, 새 단계의 세부 규칙은 §12에서 추적한다. 실패 조건 없는 완주·학습은 옵저버 모드가 담당한다. 이름·배치는 [RFD 0022](rfd/0022-flight-difficulty-names-and-visuals.md)에서 확정했고 [RFD 0026](rfd/0026-game-flight-backgrounds.md)으로 표시·배경 연결을 구현했다. 비행 규칙은 미구현이다. |

### 8.3 키 규칙

- 레인당 2키 이상 바인딩 필수 (최소 8키). 기본 프리셋은 레인당 4키 (총 16키)
- 바인딩된 키는 시스템상 모두 동등. 주키/보조키는 유저의 운용 개념 — 기본 손 위치의 주키 4개와, 손 옮기기 등 특정 패턴에서만 쓰는 보조키로 나뉜다
- 16키 프리셋도 **동시 사용은 최대 8키 수준**. 패턴마다 유도되는 보조키가 달라져 차트 전체에서 최대 16키가 활용된다 (`docs/spec/keybinding.md`의 "주키와 보조키")
- 하나의 물리 키는 하나의 레인에만 바인딩 (충돌 불가)

## 9. 튜토리얼

시연과 직접 입력 실습은 메트로놈의 박자 소리에 맞춰 진행한다. 처음 재생을 시작할 때만 첫 입력 전에 메트로놈을 4박 들려주는 준비 구간을 둔다. 반복 예제의 구간 자체에 다음 입력을 준비할 여유를 포함한다. 별도의 4박 준비 구간은 첫 재생 앞에만 두며, 이후 패턴을 반복할 때는 다시 추가하지 않는다. 예제 차트의 박자·노트·판정 시간과 소리를 맞추며 튜토리얼 전용 음악은 요구하지 않는다([RFD 0083](rfd/0083-tutorial-metronome.md)). 메트로놈을 사용하는 새 학습 흐름은 미구현이다.

노트 연주법과 판정 규칙을 소개하는 4단계 내용 구성이다. 키 추가·손배치 발견을 단계적으로 체험하는 튜토리얼 과정은 별도로도, 노트 학습에 통합해서도 두지 않는다. 실습에 필요한 실제 키 설정은 먼저 갖추도록 안내한다([RFD 0104](rfd/0104-no-keybinding-discovery-tutorial.md)).

입력을 배우는 항목은 **시연 → 직접 입력 실습 → 항목별 요구 횟수만큼 누적 성공 시 통과**로 바꾼다. 단순 열람과 실습 통과는 구별한다. 튜토리얼 완료·통과를 차트 선택의 선행 조건으로 두지 않으며, 처음부터 모달을 바로 닫고 차트를 선택할 수 있다([RFD 0081](rfd/0081-tutorial-demonstration-and-three-practice-successes.md)). 현재 공개 튜토리얼은 시연 중심이며 직접 입력·통과 기능은 미구현이다.

피스 이름은 플레이어에게 튜토리얼 제목 정도에만 사용한다. 본문은 실제 입력 동작과 연주 방법을 설명하며, 이름 암기를 요구하지 않는다([RFD 0080](rfd/0080-piece-names-in-tutorial-titles.md)).

실패 사례는 시연으로 설명하고 직접 입력 실습은 올바른 연주 방법을 익히는 과제로만 구성한다. 실패 동작을 직접 재현해야 통과하는 과제는 두지 않는다. 실제 발생한 실패의 판정과 항목별 성공 조건은 그대로 적용한다.

요구 성공 횟수는 개발자가 실습항목별로 정하는 양의 정수이며 기본값은 3회다. 플레이어가 목표 횟수를 바꾸는 설정 UI는 두지 않는다. 각 항목에 목표 달성률과 추가 조건을 표시한다. 실습 한 차례에서 모든 조건을 충족하면 1회 성공으로 세고, 항목별 요구 횟수만큼 누적 성공으로 통과한다. 일반 Good은 달성률에 반영하며 발생 자체만으로 실패 처리하지 않고, 트릴 교대 학습은 `goodTrill` 0회 조건을 둔다.

튜토리얼을 닫았다 다시 열면 마지막으로 선택한 탭과 항목을 연다. 마지막으로 선택한 탭과 항목을 브라우저에 저장해 게임을 껐다 켜도 복원한다. 로그인하면 마지막으로 선택한 탭과 항목도 계정과 동기화해 다른 기기에서 같은 위치를 이어 볼 수 있게 한다. 기기마다 마지막 열람 위치가 다르면 실제로 가장 최근에 선택한 탭과 항목을 사용한다. 동기화 요청이 나중에 도착했다는 이유로 더 오래된 선택 위치가 최신 위치를 덮어쓰지 않는다. 선택 이력이 없는 최초 진입은 `Basic` 첫 항목에서 시작한다. 항목 위치 복원과 미완료 실습의 성공 횟수 복원은 구별한다. 실습 기록으로는 항목 전체 통과 여부만 로그인 여부와 관계없이 브라우저에 저장한다. 로그인하면 항목 전체 통과 여부를 계정과 동기화해 다른 기기에서도 같은 통과 표시를 확인할 수 있게 한다. 브라우저와 계정 중 어느 쪽에서든 전체 통과한 항목은 합쳐 보존한다. 현재 방법·부분 성공 횟수·중간 방법 완료 여부는 현재 실습 세션에서만 유지하고 영구 저장·계정 동기화하지 않는다. 미완료 항목을 닫았다 다시 열거나 다른 항목에서 돌아오거나 게임을 재시작하면 첫 번째 방법의 성공 횟수 0회부터 시작한다. 이미 전체 통과한 항목의 재실습도 첫 번째 방법 0회부터 새로 진행하되 과거 항목 통과 기록은 지우지 않는다. 같은 항목 안에서 시연/직접 입력을 토글할 때는 현재 방법과 누적 성공 횟수를 유지하며 기존 전환·집계 규칙을 따른다. 튜토리얼 목록에서 통과한 항목에 체크 표시를 붙인다. 시연만 본 항목에는 통과 체크를 붙이지 않으며, 별도의 열람 표시도 두지 않는다. 여러 연주 방법을 각각 실습하는 항목은 필요한 모든 방법을 통과해야 항목 전체를 통과로 표시한다. 튜토리얼을 닫았다 다시 열면 미완료 실습은 0회부터 시작한다. 중간 진행도는 복원하지 않고 이미 전체 통과한 항목의 기록은 유지한다. 다른 튜토리얼 항목으로 이동했다 돌아오는 경우에도 미완료 실습의 성공 횟수는 0회로 초기화한다. 같은 항목에서 직접 입력/시연을 토글할 때는 성공 횟수를 유지한다.

처음 실습에 들어갈 때부터 `직접 입력 / 시연` 토글을 사용한다. 플레이어가 직접 입력을 선택하면 실습으로 넘어가며, 시연 종료만으로 자동 전환하지 않는다. 별도의 실습 시작 버튼은 두지 않는다.

실습에 필요한 키가 부족하면 먼저 키 설정을 수정하도록 안내한다. 현재 키 설정으로 실습할 수 없어도 시연은 이용할 수 있다. `직접 입력 / 시연` 토글의 직접 입력 옵션을 비활성화하고 키가 부족한 이유와 실제 키 설정을 수정하는 경로를 안내한다. 실제 설정이 요구를 충족하면 직접 입력 옵션을 활성화하지만 자동으로 실습에 전환하지 않으며, 플레이어가 직접 선택해야 한다. 별도 실습 시작 버튼이나 임시 키 자동 배정은 추가하지 않는다. 시연용 표시 키 보충은 실제 실습의 키 요건을 충족한 것으로 취급하지 않는다. 실제 설정이 요구를 충족한 뒤 실습을 시작하며, 실습 중에만 쓸 임시 키를 자동 배정하지 않는다.

실습 시작 후에는 성공·실패마다 버튼을 다시 누르지 않고 자동 반복한다. 실패해도 성공 횟수는 유지하며, 항목별 요구 횟수만큼 누적 성공하면 반복을 마치고 통과 처리한다. 이미 통과한 항목을 다시 실습해도 새 실습에서 항목별 요구 횟수만큼 누적 성공하면 반복을 종료하며, 기존 통과 기록은 유지한다. 통과 전에도 모달을 닫을 수 있다.

항목 전체를 통과한 뒤에는 현재 항목에 머물며 `다음` 버튼을 누르면 다음 항목으로 이동한다. 통과만으로 자동 이동하지 않는다.

실습 중에는 `직접 입력 / 시연` 토글로 두 상태를 오가며 연주 방법을 다시 확인한다. 시연에 다녀와도 성공 횟수는 유지하고 시연의 자동 입력은 성공 횟수에 포함하지 않는다. 재생 중 직접 입력→시연 전환은 다음 패턴 시작부터 적용하며, 재생 중이 아니면 바로 적용한다. 시연→직접 입력 전환은 현재 재생 위치에서 즉시 적용한다. 시연 도중 직접 입력으로 바꾼 현재 패턴은 성공 집계에서 제외하고, 다음 패턴부터 성공 횟수를 집계한다. 이 규칙은 튜토리얼에 적용한다.

각 통과 조건은 콤보 아래에 한 줄씩 표시한다. 충족은 초록 체크 아이콘, 실패는 빨강 X 아이콘으로 표시하며 중립 상태는 흰색 글씨로 표시한다. 조건 상태는 연주 도중 실시간으로 갱신한다. 조건 목록 바로 아래에는 성공 횟수 진행도를 `현재 성공 횟수/해당 항목의 요구 성공 횟수`로 표시한다(기본값 3회인 항목의 예: `1/3`). 성공 횟수는 패턴 결과가 확정될 때 집계하며, 성공이 확정되면 진행도도 즉시 갱신한다.

실습에서는 노트를 보고 직접 사용할 키를 판단한다. 다음에 눌러야 할 키를 미리 알려주는 가이드는 표시하지 않으며, 실제 누른 키와 노트·`trillZone` 등 입력 요구의 시각 표시는 유지한다.

노트 낙하 속도는 튜토리얼용 고정값을 사용하며, 플레이어의 본 플레이 설정에 연동하거나 본 플레이의 설정값을 변경하지 않는다. 구체적인 값은 §12에서 관리한다.

롱노트 중 탭은 한 항목 안에서 기존 키를 유지하는 방법을 먼저 시연·실습하고, 그 방법의 목표를 달성한 뒤 유지 키를 교대하는 방법을 시연·실습한다. 첫 방법의 목표를 달성하면 반복을 멈추고 현재 단계에 머물며, `다음` 버튼으로 두 번째 방법으로 이동한다. 자동으로 다음 방법으로 전환하지 않는다. 두 방법 모두 목표를 달성해야 항목 전체를 통과한다. 두 방법을 자유롭게 번갈아 선택하는 방식으로 만들거나 전체 튜토리얼 항목의 순서를 잠그는 것으로 확대하지 않는다. 두 방법을 각각 실습하여 각각 항목별 요구 횟수만큼 누적 성공해야 하며, 성공 횟수를 서로 합산하지 않는다([튜토리얼 Phase 3](spec/tutorial.md#phase-3-홀드-교대와-헤드-없는-롱노트--홀드의-확장)).

| Phase | 목표 | 소개하는 것 | 소개하지 않는 것 |
|-------|------|-------------|------------------|
| 1 | 모든 노트 타입을 처리할 수 있다 | 싱글, 롱, 트릴, 더블의 기본 입력 | 판정 세부 규칙 |
| 2 | 판정 결과를 이해하고 개선 방향을 안다 | `termination` vs `connection` 판정, `goodTrill`, 분할 릴리즈 | — |
| 3 | 롱노트 중 유지·탭과 키 교대를 이해 | 같은 배치의 두 연주 방법, 홀드 교대, 유예 시간 | — |
| 4 | 16키 바인딩의 이점 이해 | 3～4키 트릴, 더블홀드+트릴 처리 | — |

### 10.3 오프셋

| 오프셋 | 용도 |
|--------|------|
| **입력 오프셋** (`inputOffsetMs`, Input Offset) | 입력 장치 지연·개인 체감 보정. SLOW면 음수 |
| **시각 오프셋** (`visualOffsetMs`, Visual Offset) | 화면 표시 지연 보정. 화면이 소리보다 늦으면 양수 |

[RFD 0031](rfd/0031-audio-first-timing-model.md) PR 1 계산식·설정·곡 끝 처리를 구현했다. 출력 장치 지연은 재생 전 running AudioContext에서 안정된 값을 읽어 곡마다 고정한 L₀로 자동 보정한다. J = P − L₀·r, V = J + visualOffsetMs·r, 입력 = J − handlerDelay·r + inputOffsetMs·r이다. 두 오프셋은 기본 0의 실제 시간 ms이며, 입력 지연·체감과 화면 표시 지연을 독립적으로 보정한다. 오디오 오프셋은 제거했고 옛 설정 키는 이전하지 않고 버린다. 차트 오프셋은 유지한다.

오디오 끝 뒤에도 시계를 진행하며 J가 재생 끝에 도달하고 판정 진행 상한이 마지막 Good 기한을 지난 뒤 결과로 넘어간다. 이 대기 중 pause/resume은 진행만 멈췄다 잇고 끝난 음원은 다시 재생하지 않는다. 현재는 두 오프셋을 숫자로 직접 입력하며 Calibrate 진입은 숨긴다. 입력·시각 캘리브레이션은 PR 2·3, auto 키빔·키봄의 V 적용은 #245 후속이다.

### 10.4 에러 처리

| 시나리오 | 동작 |
|----------|------|
| 플레이 중 네트워크 단절 | 음원/차트는 사전 로드 완료이므로 플레이 계속. 결과 전송은 복구 후 재시도. 로그인한 플레이의 기록 전송 실패 시 결과 화면에 실패 안내와 전송 재시도 버튼 표시. 결과 화면을 나가도 미전송 기록을 브라우저에 보관하고 다음 접속 때 원래 계정으로 로그인되어 있으면 자동 재전송([RFD 0085](rfd/0085-chart-records-and-detailed-history-visibility.md)) |

## 11. 에셋 전략

### 왜 무료로 시작하는가

초기 자본이 없으므로 음원을 구매할 수 없다. 대신 동인(BMS) 작곡가들이 **비상업 목적 사용을 허가**한 곡을 활용하여 게임을 공개한다. 비상업 단계에서 재미를 검증하고 유저를 확보한 뒤, 수요가 확인되면 이미 커넥션이 형성된 작곡가들과 **상업 라이선스 계약으로 전환**한다. 비상업 단계의 협력 관계가 상업화 전환 비용을 낮추는 핵심 자산이다.

### 단계별 계획

| 단계 | 목표 곡수 | 에셋 수급 | 비용 |
|------|----------|-----------|------|
| **Phase A: 프로토타입** | 3～5곡 | 플레이스홀더(단순 도형), CC0 효과음, Noto Sans CJK | 0원 |
| **Phase B: 알파 (비영리 공개)** | 5～10곡 | 노트 타입별 디자인 자체 제작, BMS 작가 비상업 허가 교섭, Freesound 가공 | 0～30만원 |
| **Phase C: 베타** | 10곡+ | 최종 노트 스킨 커미션, 로고, 자켓 의뢰 | 10～100만원 |
| **Phase D: 상업화 (선택)** | — | 기존 BMS 작가와 상업 라이선스 계약 전환, CC-NC 곡 교체, 오리지널 곡 커미션, 법률 검토 | 별도 |

**음원 확보**: BMS 작가 비상업 허가(핵심), CC 라이선스 곡, Newgrounds/SoundCloud CC 필터, 자체 작곡, 작곡 콘테스트.

**라이선스 원칙**: 모든 외부 에셋 출처·조건 기록, CC-NC 에셋에 `non-commercial-only` 태그, BMS 작가 허가 서면 보존.

**근거 문서**: `docs/spec/project-assets.md`

Auto는 현재 재생 위치에서 즉시 전환하며 구간을 다시 시작하지 않고 같은 반복 안의 수동 집계도 유지한다. Auto 중에는 판정만 보여주고 콤보·달성률은 숨기며, Auto 노트의 점수·이론 가중치는 집계에서 제외한다. 수동 집계는 반복 구간 종료 시 초기화한다([RFD 0075](rfd/0075-observer-manual-only-statistics.md)). 옵저버 진입·재진입 시 재생 속도를 1.0x로 초기화하고 Auto로 바로 재생한다. 감속 재생에서도 원곡의 음높이를 유지하며, 재생 중 속도 변경은 현재 곡 위치에서 즉시 적용하고 수동 집계를 초기화하지 않는다([RFD 0076](rfd/0076-observer-slowdown-preserves-pitch.md)). 처리 방식과 음질·지연·동기화 검증은 구현 단계에서 정한다. 미니맵의 시작·끝 핸들은 구간 길이를 조절하고 몸통은 길이를 유지해 위치를 옮긴다. 구간의 시간 위치는 자유롭게 지정하며 박자 스냅을 적용하지 않는다. 드래그 중에는 정지하고 놓으면 확정 구간의 앞 페이드 구간부터 다시 재생하며 새 시도로 집계한다. 시작 경계에서 잘려 헤드가 없는 바디는 일반적인 헤드 없는 바디의 시작 허용 범위에 따라 미리 누른 키와 구간 시작에 누른 키 모두 허용한다([RFD 0063](rfd/0063-observer-range-note-clipping.md)). Auto를 끄면 진행 중인 바디도 즉시 직접 이어받고, 실제로 누르고 있는 키로 유지 여부를 판단한다. Auto 전환의 입력 이벤트 처리와 전환 경계에 걸친 입력·판정의 귀속, 반복 경계의 키·바디 상태 처리는 미정이며 런타임은 미구현이다. |
