# 노트 판정 상태 전이 검산

2026-09-07. [RFD 0020](../rfd/0020-note-judgment-units-and-inheritance.md)와 [27개 판정 사례](../spec/note-judgment-cases.md)를 대조한 첫 검산 기록이다. 게임 엔진 구현이나 전체 상태 전이표의 검증 완료를 뜻하지 않는다. 추가 결정과 후속 작업의 상태는 [PRD §12](../prd.md#12-미정-사항)에서 단일 추적한다.

후속 grill의 현재 사례는 38개이며, 사용자가 RFD와 구현·테스트·검증 계획 작성으로 전환했다. [구현 계획](../plans/note-judgment-implementation.md)에 따라 단일 상태 모형의 검증을 진행한다. 이 기록의 과거 질문들을 미결정 목록으로 다시 사용하지 않는다.

**최신 채택은 §15의 release 권한 갱신과 §16의 확정 순서에 따른 현재 콤보 반영을 포함한다. §17의 최대 콤보 질문은 통계 미제공으로 철회했다.** §13의 첫 up 연결·다음 적격 up terminal 순서는 유지하고, 새 head 뒤에도 같은 물리 키를 차단하던 제한은 §15로 대체한다. §4~14에는 변경·철회 과정을 포함하므로 당시의 동일 키 보정 제외, NJ-R04/R09/R11 보류, NJ-R13 마지막 실패를 현재 규칙으로 사용하지 않는다. 현재 기대값은 사례 명세를 따른다.

## 1. 함께 추적해야 하는 상태

아래는 검산에 필요한 관측 항목이다. 새 엔진의 자료구조나 필드명을 지정하지 않는다.

| 관측 항목 | 구분해야 하는 상태 | 근거 사례 |
|---|---|---|
| 물리 입력 | 눌린 키와 그 press를 끝내는 실제 up | NJ-A03, NJ-R04 |
| 유지 자격 | 등록된 held / 미등록 raw held | NJ-A02, NJ-A03 |
| unit 시작 | 미처리 / 정당하게 준비됨 / 활성화됨 | NJ-A04, NJ-A06, NJ-R03 |
| unit 유지 | 유지 중 / 유효한 끝 처리로 종료 / 회복 불가능한 실패 | NJ-A05, NJ-F03 |
| 점수 항목 | 미처리 / 성공 등급 확정 / 0점 확정 | NJ-S01, NJ-S02 |
| 경계 배정 | 앞에서 끝나는 몫 / 뒤로 이어지는 몫 / 아직 배정 가능한 상태 | NJ-H05, NJ-H06 |
| 실제 release | 준비 여부, 판정 창, 각 누름의 권한과 유효한 새 입력에 따른 갱신 | NJ-R01, NJ-R02, NJ-R13~R15 |
| 면제된 몫 | held 자격은 남지만 뒤 release의 여분 계산에서 제외되는 몫 | NJ-H02, NJ-H03 |

`holdOnly` Perfect 확정만으로 경계 배정까지 완료했다고 보면 NJ-H05가 성립하지 않는다. 현재 바디의 unit 수만으로 여분 키를 계산하면 NJ-R02가 성립하지 않는다. 등록 키 수만으로 새 시작을 완료하면 NJ-R03이 성립하지 않는다.

## 2. 채택 규칙에서 확보한 부분 전이표

| 계기와 조건 | 상태 변화 | 점수·실패 효과 |
|---|---|---|
| 적격 head가 down을 소비 | 해당 head 처리, 담당 시작 또는 등록 키 반영. 바디 등록 조건을 충족하면 새 누름의 release 권한 부여. 실패한 바디는 부활시키지 않음 | head 등급 1개 |
| 적격한 미처리 headless 시작이 down을 소비 | 해당 unit의 시작 준비·활성화, 새 누름의 release 권한 반영 | 시작 점수 없음 |
| 정당한 승계 준비로 시작이 이미 충족 | 추가 시작 down을 소비하지 않음. 별도 head의 입력 요구는 유지 | 일반 승계 성공 점수 없음 |
| 아무 head·시작도 소비하지 않은 down | raw held만 변함 | 양수 바디의 유지 자격을 새로 주지 않음 |
| 적격 실제 release가 up을 소비 | 실제 release 한 개 완료, 해당 누름의 권한 종료. 같은 물리 키의 미래 유효 입력까지 차단하지 않음 | 해당 끝의 타이밍 등급 1개 |
| 일반 여분 up | press의 유지 자격 종료, 실제 release는 미처리로 남음 | 실제 release 점수 없음 |
| 유효한 head·시작 입력으로 다음 바디 연결이 성립 | 같은 키 재타격과 서로 다른 키 교대 모두 보류 up을 뒤 실제 release 후보와 그 끝의 사용 키 이력에서 제외 | 앞 up의 이른 끝 등급 없음. 키 동일 여부의 추가 연결 Miss 없음 |
| 교대 실패로 다음 unit의 시작·승계가 불가능해짐 | 보류 up으로 실패한 unit의 끝을 성공 처리하지 않음 | 종속 끝점 0점·가중치 반영, 끝에서 추가 Miss 패널티 없음 |
| 활성화된 `holdOnly`가 유효하게 완료 | 상태 Perfect 확정. 물리 up 없이 held 자격과 경계 배정이 남을 수 있음 | unit별 Perfect. FAST/SLOW 없음 |
| `holdOnly` 면제 몫을 뒤 증가에 승계 | 새 unit의 시작 충족. 그 새 unit의 끝은 자기 속성을 따름 | 새 일반 끝의 release까지 면제하지 않음 |
| E를 지났지만 S+Good 이내이고 아직 첫 시작 전 | 첫 활성화 기회 유지 | E만으로 미시작 실패를 확정하지 않음 |
| head 시작 기한 초과로 종속 unit을 시작할 수 없음 | head와 종속 점수 항목을 함께 처리 | 종속 끝점 0점·가중치 반영, 추가 Miss 표시 없음 |
| 유효한 경계 기회가 없고 timestamp 입력 후 유지 부족 | 해당 활성 unit 실패를 확정 | 1회 실패. 끝에서 중복 실패하거나 같은 바디를 재활성화하지 않음 |
| 실패한 경로를 뒤늦은 앞 head 성공이 통과하려 함 | 경로의 실패 상태 보존 | 건강한 다른 경로까지 초기화하지 않음 |

이 표는 단일 계기의 효과를 정리한 것이다. 아래 반례의 같은 물리 키 차단은 §15의 권한 갱신으로 대체되었으며, 현재 동시 up 대조는 NJ-R14에 기록했다. 전체 상태 전이표의 검증 완료를 뜻하지 않는다.

## 4. 반례 NJ-Q01: 동시에 뗀 두 키 중 소비한 키에 따라 뒤 등급이 달라짐

**아래 표는 교대 보정 전의 역사적 검산 반례이다.** 교대 up을 뒤 release에서 제외하는 후속 원칙이 채택되기 전의 순차 해석 두 가지를 비교한다. 이후 같은 키와 부분 교대를 적용한 재대조도 아래에 보존하되, 동일 키 보정이 다시 정정되어 [NJ-R11](../spec/note-judgment-cases.md#nj-r11)은 재검산 대상으로 돌아갔다. 이전 어느 결과도 현재 테스트 정답으로 사용하지 않는다. 후속 상태는 [PRD §12](../prd.md#12-미정-사항)를 따른다.

Normal: Perfect ±41, Great ±82, Good ±120ms. 같은 레인의 서로 다른 물리 키 A/B/C를 사용한다.

차트:

| 바디 | 구간 | head | 끝 |
|---|---|---|---|
| 앞 double | `[0,1000]` | double head 0 | 1000에서 같은 unit 수로 연결, release 없음 |
| 뒤 double | `[1000,1100]` | double head 1000 | 실제 release 2개, `holdOnly` 없음 |

입력:

| 시각 | 입력 | 두 해석의 공통 상태 |
|---:|---|---|
| 0 | A/B down | 앞 double head 두 개 성공, 유지 |
| 1000 | C down | 뒤 double head의 첫 입력 Perfect. 뒤 바디는 승계됐고 등록 held는 A/B/C 세 개 |
| 1080 | A/B up, **같은 timestamp** | 일반 여분 하나와 첫 실제 release 하나로 처리하면 남은 held는 C, 남은 release는 하나 |
| 1100 | A down | 뒤 double head의 둘째 입력 Good(+100). 이 head에서는 C와 다른 물리 키이므로 적격 |
| 1105 | C up | 두 해석의 결과가 갈림 |
| 1150 | A up | 두 해석의 결과가 갈림 |

순차 해석:

| 단계 | 1080에서 A up → B up 순으로 처리 | 1080에서 B up → A up 순으로 처리 |
|---|---|---|
| 1080의 첫 up | A는 여분이라 실제 release 무소비 | B는 여분이라 실제 release 무소비 |
| 1080의 둘째 up | B로 첫 release Perfect(-20) | A로 첫 release Perfect(-20) |
| 1100의 A 재등록 | 같은 끝의 사용 키는 B이므로 A는 남은 후보에 포함 | 같은 끝의 사용 키는 A이므로 A는 남은 후보·여분 계산에서 제외 |
| C up 1105 | A가 남으므로 여분 up. 실제 release 무소비 | C로 둘째 release Perfect(+5) |
| A up 1150 | 둘째 release Great(+50) | 해당 끝의 추가 판정 없음 |

head 등급, 입력 시각, 물리 held 변화가 같아도 실제 release 결과가 **Perfect + Great**와 **Perfect + Perfect**로 갈린다. 두 해석 모두 1080의 입력을 모두 처리한 뒤에는 유지 부족이 없다. 따라서 유지 부족 확인을 배치 끝으로 미루는 것만으로 해결되지 않는다.

재현은 `/tmp/not4k-release-batch-audit.py`에서 두 순서를 열거했다. 이 국소 모형은 head 매칭·승계가 위 표처럼 성립한 상태를 주입하고, 일반 여분 up과 같은 double 끝의 사용 키 제외 규칙만 계산한다. 게임 엔진의 현재 버그를 실행 재현한 것은 아니다.

대처안 비교에서는 같은 timestamp의 A/B 묶음 전체를 그 double 끝의 남은 후보에서 제외하면 두 순서 모두 C up 1105가 둘째 Perfect가 됐다. **이 대처안은 철회한다.** 실제 release를 소비하지 않은 여분 키까지, 새 head 성공 후에도 제한하는 추가 규칙이기 때문이다. 단지 두 실행의 결과가 같아진다는 이유로 기존 권한 획득 규칙을 확대 제한하지 않는다.

### head 성공과 같은 끝의 재사용 제한

사용자가 “헤드를 누른 시점에 릴리즈 권한을 얻는 것 아닌가”라고 확인했다. 현재 채택안에서 유효한 새 head 성공은 키 등록과 release 권한을 제공한다. [NJ-R04](../spec/note-judgment-cases.md#nj-r04)의 같은 double 끝 재사용 제한은 별도 조건이다.

- A의 앞 up이 여분으로 무소비였다면, 새 head로 등록된 A를 그 끝의 남은 후보에서 일괄 제외할 근거가 없다.
- A의 앞 up이 그 double 끝의 첫 실제 release를 소비했다면, 새 head는 별도로 성공해도 동일한 물리 키로 그 끝의 둘째 release까지 처리하지 못한다.
- 실제 release로 분류된 up에만 같은 끝의 사용 키 제한을 적용한다. 새 head의 권한 획득을 없애거나, 여분 up까지 소비한 키처럼 취급하지 않는다.

### 부분 교대 채택 후의 재대조

동일 키 보정이 허용되던 시점에는 NJ-Q04의 부분 교대까지 반영해 C head 1000과 A head 1100으로 두 몫의 교대가 성립한다고 도출했다. 당시에는 1080의 A/B up을 C/A에 어느 방식으로 대응시키든 두 up 모두 뒤 실제 release에서 제외됐다. 그 기대값은 C up 1105가 첫 실제 release Perfect, A up 1150이 둘째 Great이며, 전체 Perfect 4개·Good 1개·Great 1개였다.

동일 키 보정 정정 후에는 A→C·B→A의 대응만 두 몫 모두 서로 다른 키이며, B→C·A→A는 마지막 몫이 보정 대상이 아니다. 따라서 앞 C에 대한 동률 배정과 후속 A 입력의 관계를 다시 확인해야 한다. [NJ-R11](../spec/note-judgment-cases.md#nj-r11)의 이전 기대값을 현재 정답으로 쓰지 않는다. 이 국소 대조는 엔진 실행이나 전체 배정 모형의 검증 완료를 뜻하지 않는다.

## 5. 연결 교대와 뒤 바디의 마지막 release 창

사용자는 `o-o-`의 연속 유지·중간 head 탭 방식과 경계 교대 방식이 `d=d=`에도 성립해야 한다고 짚었다. 아래는 **교대 up 보정 전의 해석 기록**이다. 정상 교대 up을 뒤 release에서 제외하는 후속 채택안은 [RFD 0020 §2.6](../rfd/0020-note-judgment-units-and-inheritance.md#26-교대-keyup과-뒤-release-창이-겹치는-경우--후속-채택)을 따른다.

같은 unit 수로 이어지는 경계에는 별도의 점수 release가 없다. 경계 교대에 물리 up이 쓰일 수 있고, 기존 키의 release 권한은 정당한 승계로 뒤 실제 끝에도 적용된다. 이 up이 뒤 끝의 창에 들어오면 “교대하려던 입력”이라는 의도로 실제 release 후보에서 빼지 않는다. 일반 여분 키의 up 무소비 조건은 그대로 적용한다. 기존 근거는 [NJ-R04](../spec/note-judgment-cases.md#nj-r04)의 이른 맨끝 release와 뒤늦은 중간 head 처리이다.

single `[0,1000]` → single `[1000,1100]`, 두 시작에 single head, `holdOnly` 없음. A down 0으로 시작한다. Normal의 마지막 release 창은 980~1220ms이다.

| 독립 실행 | 입력 | 교대 up 보정 전의 결과 |
|---|---|---|
| 기존 키 유지 + 중간 head 탭 | B down 1000 / B up 1005 / A up 1100 | B head Perfect. B up은 A가 유지하므로 여분. A up이 마지막 Perfect |
| 먼저 떼고 뒤 head 처리 | A up 995 / B down 1000 / B up 1100 | A up이 승계 준비된 마지막 release의 Good(-105). B head는 Perfect. 마지막 release는 이미 끝났으므로 다시 판정하지 않음 |
| 뒤 head를 먼저 치고 교대 | B down 995 / A up 1000 / B up 1100 | B head Perfect. A up은 B가 유지하므로 여분. B up이 마지막 Perfect |

`d=d=`에서 기존 A/B를 유지하고 새 C/D로 중간 double head만 탭할 때도 같은 계산을 두 unit에 적용한다. 기존 A/B를 먼저 떼는 교대가 마지막 release 창 안에 있으면, 그 두 up으로 마지막 두 release를 먼저 처리할 수 있고 뒤 double head는 별도로 남는다. 마지막 release가 이미 끝났다는 이유로 뒤 head의 입력 요구를 없애지 않는다.

이 설명으로 NJ-Q01의 다중 up 소비 키 배정까지 해결되는 것은 아니다. 교대 up의 실제 release 적격 여부를 포함한 뒤에도, 등록 키가 세 개인 부분 입력 상태의 동시 up에는 앞 절의 배정 문제가 남는다.

## 6. NJ-Q02: E까지의 보류만으로는 늦은 교대를 구분하지 못함

사용자는 정상 교대의 up이 뒤 끝의 이른 release로 처리되는 결과를 우려하며, 이른 `connection`이 있는 경우의 보정과 끝 E까지의 판정 보류를 명시적으로 재검토했다. 아래 대조 후 “교대 시 발생하는 릴리즈를 릴리즈 판정에 안쓰면 되는구나”로 교대 up 제외 원칙을 채택했다. 후속 결정 상태는 [PRD §12](../prd.md#12-미정-사항)에서 추적한다.

범위는 먼저 같은 unit 수의 일반 연결 `o-o-`·`d=d=`이다. 다음 single 사례에서 연결 시각을 C=1000, 마지막 끝을 E=1100으로 둔다. 두 시작에 head가 있고 A down 0으로 앞 바디를 시작한다. Good=120ms이다.

| 시각 | 입력·관측 | 의미 |
|---:|---|---|
| 995 | A up | C의 교대 창과 E의 release 창에 모두 포함. 보정 전 규칙은 E의 Good(-105)을 즉시 확정 |
| 1100 | E 도달, 새 head 입력은 아직 없음 | C의 head 기한 1120이 남아 있으므로 교대가 안 올 것이라고 확정할 수 없음 |
| 1110 | B down | C의 늦은 head Good(+110)으로 유효 |
| 1115 | B up | E의 release 창에서 Perfect(+15)에 해당하는 시각 |

“A up을 교대에 사용하고 B up을 맨끝에 사용한다”는 해석을 지원하려면 E 이후의 유효한 head까지 고려해야 한다. 같은 head를 1000에 정상 입력하는 대조 실행에서는 교대를 E 전에 확인할 수 있다. 따라서 단순히 모든 이른 release를 E에 확정하는 고정 시각만으로 두 실행을 함께 설명할 수 없다.

채택한 방향은 앞 경계의 교대에도 사용할 수 있는 이른 up의 용도를 잠정 보류하고, 적격 head·시작 입력으로 교대가 확인되면 그 up을 뒤 끝의 실제 release로 쓰지 않는 것이다. 정상·늦은 교대는 [NJ-R06](../spec/note-judgment-cases.md#nj-r06), 실제 승계 실패로 마지막 release를 성공 처리할 수 없는 정정 사례는 [NJ-R08](../spec/note-judgment-cases.md#nj-r08)에 반영했다.

판정 표시만 E까지 늦추면서 A up을 이미 E의 release로 소비한 상태로 두는 것은 입력 귀속을 바꾸지 않으므로 사용자가 지적한 결과를 해결하지 못한다. 잠정 후보를 두는 변경은 이미 확정한 성공·실패를 나중에 취소하는 방식과 구분해서 검토한다.

### NJ-R08의 release 대상 성립 전제

사용자는 후속으로 “마지막 교대를 실패했다는건 릴리즈 할 대상도 없다는거 아니야?”라고 지적했다. **실제로 다음 unit이 시작·승계되지 못하거나 이미 실패했다면, 보류한 up이 있다는 이유만으로 그 끝의 성공 판정을 만들 수 없다.** 반면 head Miss만으로 건강하게 승계된 unit의 release가 사라지지는 않는다.

이전 NJ-R08의 Good 기대값은 “정당한 승계 준비를 충족한 unit은 S 전에도 마지막 release를 받을 수 있다”는 규칙을 적용한 해석이었다. A up 995가 뒤 unit을 조기 완료한 것으로 간주하면서 이를 “교대 실패”라고 설명한 것이 문제였다. 사용자의 지적 후 실제 승계 실패에서는 보류 up으로 마지막 Good을 만들지 않고, 종속 끝점을 0점으로 정리하며 끝에서 추가 Miss 패널티를 주지 않는 것으로 설명을 정정했다.

현재 NJ-R08은 A up 995 후 기한까지 새 입력도 유지 키도 없어 다음 unit이 시작·승계되지 못하는 사례로 기록한다. 이 실패한 교대 후보를 승계 준비만으로 조기 완료한 끝으로 바꾸지 않는다. 정상 승계된 unit의 이른 release 전체를 금지한 것은 아니다. head만 Miss인 경우와 실제 바디 실패를 구분해야 하며, 그 차이를 아래 double 부분 교대에서 대조한다. 결정 상태는 [PRD §12](../prd.md#12-미정-사항)에서 관리한다.

## 7. NJ-R04의 보정 전 기대값 보존

이 절은 교대 up 보정 전의 역사적 기대값이다. 현재 자동 테스트의 정답으로 사용하지 않는다. 같은 double 끝의 두 실제 release는 서로 다른 물리 키를 요구한다는 원칙은 유지하지만, 먼저 그 up이 실제 release인지 교대인지 분류해야 한다.

차트: double head 0 + double `[0,1000]` → single head 1000 + double `[1000,1060]`. A/B는 0의 head를 성공하고 유지한다.

| 입력 | 보정 전 기대값 |
|---|---|
| A up 1020 | 맨끝 1060의 첫 release Perfect |
| A down 1030 | head Perfect. A는 같은 끝의 남은 후보·여분 계산에서 제외 |
| B up 1035 | 맨끝 1060의 둘째 release Perfect |
| A up 1040 | 추가 release 없음 |

같은 키 보정이 허용되던 다음 단계에는 A up 1020을 교대로 제외하고, B up 1035와 A up 1040을 두 실제 release Perfect로 처리한다고 도출했다. 이 시기의 전체 기대값도 Perfect 5개·유지 Miss 없음이었다. 그러나 동일 키 보정이 다시 정정되어 A up 1020과 A down 1030을 그렇게 묶을 수 없다. B up과 A head의 서로 다른 키 교대 가능성, 같은 double 끝의 사용 키 제한을 함께 재대조해야 하므로 [NJ-R04](../spec/note-judgment-cases.md#nj-r04)의 이전 두 기대값 모두 현재 정답으로 사용하지 않는다.

## 8. NJ-Q03: 같은 키로 다음 head를 다시 치는 경우

사용자는 처음 “같은 키에도 보정을 적용할게”로 이 사례를 허용했으나, `=o=`의 정상 플레이를 설명한 뒤 **동일 키 재타격에는 키 교대의 release 제외 보정을 주지 않는 것으로 정정하는 데 동의했다.** 아래는 이전 입력과 기대값의 역사적 기록이다. [NJ-R09](../spec/note-judgment-cases.md#nj-r09)는 재검산 대상으로 표시하며, 후속 상태는 [PRD §12](../prd.md#12-미정-사항)를 따른다.

차트는 일반 single head 0 + single `[0,1000]` → 일반 single head 1000 + single `[1000,1100]`이다. `holdOnly`와 `trillZone`은 없다.

| 입력 | 대조할 의미 |
|---|---|
| A down 0 | 첫 head 성공 |
| A up 995 | 연결 경계와 마지막 release의 창에 모두 해당 |
| A down 1000 | 같은 물리 키로 별개의 다음 head를 성공. 해당 single head의 유효한 새 입력 |
| A up 1100 | 마지막 release 시각의 up |

NJ-R06과의 차이는 뒤 head를 B 대신 A로 친 것뿐이다. 이전 동일 키 보정에서는 995의 up을 뒤 release에서 제외하고 1100의 up으로 Perfect 처리하여, 두 head와 마지막 release 모두 Perfect·유지 Miss 없음으로 기록했다. 이 기대값은 동일 키 보정 정정으로 더 이상 현재 정답이 아니다.

이 정정으로 일반 head 자체를 같은 키라는 이유만으로 무효화하지 않는다. 실제 바디 연결과 새 시작 효과를 먼저 구분한 뒤 짧은 끝의 release 창을 다시 대조한다. 서로 다른 두 물리 키를 요구하는 double head·double 끝의 규칙은 그대로 유지한다.

## 9. NJ-Q04: double에서 한 unit만 교대하고 다른 unit은 이르게 종료하는 경우

사용자는 이 부분 교대의 처리에 동의했다. 기대값은 [NJ-R10](../spec/note-judgment-cases.md#nj-r10)에 반영했으며, 후속 상태는 [PRD §12](../prd.md#12-미정-사항)에서 추적한다.

차트: double head 0 + double `[0,1000]` → double head 1000 + double `[1000,1100]`. `holdOnly`와 `trillZone` 없음. Normal의 마지막 release 창은 980~1220ms이다.

| 입력·진행 | 대조할 의미 |
|---|---|
| A/B down 0 | 앞 double head 성공 후 유지 |
| A up 995 | 교대 후보. B는 계속 유지 |
| C down 1000 | 뒤 double head 중 하나만 Perfect. A가 놓은 한 몫을 C로 교대하고 B는 기존 held로 승계 |
| B up 1030 | 경계 뒤까지 정상 유지한 B의 up. 마지막 release 기준 -70ms로 Great 창 안 |
| C up 1100 | 마지막 release 정박 입력 |
| 1121까지 추가 입력 없음 | 뒤 double head의 나머지 하나는 Miss |

성립한 한 몫의 교대에만 보정을 적용한다. A up 995는 뒤 release에서 제외하고, B up 1030은 첫 실제 release Great, C up 1100은 둘째 실제 release Perfect로 처리한다. 뒤 head 하나의 Miss가 B로 정상 승계된 바디까지 실패시키지는 않는다. 모든 up을 한꺼번에 교대로 제외하거나, 하나의 새 head로 두 교대를 성립시킨 것으로 보지 않는다. 이 범위를 반영한 NJ-R04와 NJ-Q01의 재대조 결과는 각각 §7, §4에 기록했다.

## 10. NJ-Q05: 두 보류 up 중 하나만 교대할 때의 배정

사용자는 적격 보류 up을 발생 순서로 교대에 배정하는 데 동의했다. 현재 기대값은 [NJ-R12](../spec/note-judgment-cases.md#nj-r12)에 반영했으며, 후속 상태는 [PRD §12](../prd.md#12-미정-사항)에서 추적한다.

차트: double head 0 + double `[0,1000]` → **single head 1000** + double `[1000,1100]`. `holdOnly`와 `trillZone` 없음. A/B로 처음 두 head를 성공하고 1000까지 유지하여 뒤 double을 승계한다.

| 입력 | 가능한 용도 |
|---|---|
| A up 1010 | 교대 후보 또는 마지막 release Good(-90) |
| B up 1040 | 교대 후보 또는 마지막 release Great(-60) |
| C down 1050 | 뒤 single head Great(+50). 두 보류 up 중 한 몫의 교대만 성립시킬 수 있음 |
| C up 1100 | 마지막 release Perfect |

결정 전에는 한 보류 up을 교대로 쓰고 다른 up을 실제 release로 쓰는 두 해석이 가능했다. A up을 교대로 쓰면 실제 release는 B의 Great와 C의 Perfect, B up을 교대로 쓰면 A의 Good과 C의 Perfect이다. 두 실제 release는 어느 해석에서도 서로 다른 키이며, 양쪽 모두 바디는 경계에서 정상 승계되어 있다. 같은 키 제한이나 NJ-R08의 미승계 실패 규칙만으로는 배정이 정해지지 않아 발생 순서 우선을 채택했다.

현재 규칙은 해당 경계에서 적격인 보류 up 중 먼저 발생한 것을 교대에 배정하는 것이다. 이 입력에서는 A up 1010을 교대로, B up 1040을 실제 release Great로 처리한다. 타이밍 등급을 보고 후보를 선택하는 대신 실제 발생 순서로 정한다. 같은 timestamp에서 일부 후보만 교대로 쓰는 동률 배정까지 이 사례로 확정하지 않는다. 다음 대조에서는 C 대신 B로 새 head를 처리했을 때의 키 자격 문제를 먼저 확인한다.

## 11. NJ-Q06: 발생 순서와 같은 키 교대가 충돌하는 경우

이 절은 NJ-Q05에서 채택한 발생 순서와 같은 키 교대의 우선 관계를 검토하기 위한 대조이며 확정 테스트 기대값이 아니다. 상태는 [PRD §12](../prd.md#12-미정-사항)에서 추적한다.

차트는 NJ-R12와 같다. double head 0 + double `[0,1000]` → single head 1000 + double `[1000,1100]`. A/B로 첫 두 head를 성공하고 1000까지 유지한다. `holdOnly`와 `trillZone` 없음. 입력의 차이는 새 head와 마지막 up을 C 대신 B로 처리한 것뿐이다.

| 입력 | 발생 순서를 우선 적용한 결과 |
|---|---|
| A up 1010 | 첫 교대 후보로 보류 |
| B up 1040 | 둘째 교대 후보로 보류 |
| B down 1050 | 뒤 single head Great(+50). 가장 이른 A up을 교대로 쓰면 B up 1040이 첫 실제 release Great(-60)를 소비 |
| B up 1100 | 같은 끝에서 이미 첫 release를 소비한 B이므로 둘째 실제 release를 성공 처리할 수 없음 |

유효한 새 head로 B를 등록해도 같은 double 끝의 두 실제 release는 서로 다른 물리 키를 요구한다. 발생 순서만 우선하면 이 입력은 마지막 release를 완료할 수 없다. 물리 held와 타이밍이 NJ-R12와 같아도 새 head의 키가 바뀌면서 완료 여부가 달라지는 대조다.

이 입력도 끝까지 성공시켜야 한다는 전제로, 새 head와 같은 키의 보류 up을 우선 교대로 배정하는 안을 제안했다. 그 안에서는 B up 1040을 B down 1050의 교대로, A up 1010을 실제 release Good(-90), B up 1100을 둘째 Perfect로 처리한다. **이 우선순위 제안은 채택되지 않았으며 아래 사용자 지적에 따라 철회한다.** 정상적으로 지원해야 할 키 교대인지 확인하기 전에 동일 키 재타격의 끝 성공을 보장하려 했기 때문이다.

### 사용자가 밝힌 =o=의 정상 입력

사용자는 `=o=`의 정당한 처리로 `ab== + .c.`와 `a-- + b-c-`를 들었다. 첫 방식은 A/B로 double을 계속 유지하면서 C로 중간 head만 탭한다. 둘째 방식은 A를 계속 유지하고 나머지 한 몫을 B에서 C로 넘긴다. 실제 키 교대는 첫 방식에 없고 둘째 방식에 B→C 한 번이며, 같은 키의 재타격을 뜻하지 않는다.

이는 glossary의 키 교대·홀드 교대 정의가 서로 다른 키 사이의 전환을 가리키는 것과 일치한다. 사용자는 이후 이전 동일 키 보정을 정정하는 데 동의했다. NJ-Q06에서 B up을 B의 새 head와 묶는 우선 보정은 적용하지 않는다. 일반 head 자체를 같은 키라는 이유만으로 무효화하는 결정은 아니며, 영향 받는 바디 전이는 다음 절에서 대조한다. 결정 상태는 [PRD §12](../prd.md#12-미정-사항)에서 관리한다.

## 12. NJ-Q07: 동일 키 재타격의 연결과 새 바디 시작

동일 키 재타격에 release 제외 보정을 적용하지 않는다는 결정과, 그 입력의 바디 연결 성공 여부를 구분하기 위한 대조다. 이 절의 추천은 확정 테스트 기대값이 아니며, 상태는 [PRD §12](../prd.md#12-미정-사항)에서 추적한다.

차트: single head 0 + single `[0,1000]` → single head 1000 + single `[1000,2000]`. `holdOnly`와 `trillZone` 없음. 마지막 끝을 2000으로 두어 경계와 마지막 release 창이 겹치지 않게 한다.

| 입력 | 확인할 의미 |
|---|---|
| A down 0 | 첫 head Perfect, 앞 바디 활성화 |
| A up 995 | 연결 경계의 Good 창 안이지만 마지막 끝 2000의 release 창 밖 |
| A down 1000 | 같은 키로 별개의 일반 head를 정박 입력. 키 교대의 release 제외 보정은 없음 |
| A up 2000 | 마지막 끝의 정박 입력 |

처음에는 동일 키라는 이유로 앞 connection에 유지 Miss를 주고, 뒤 head와 새 바디의 마지막 release는 Perfect로 처리하는 안을 추천했다. **이 추가 Miss 제안은 채택되지 않았으며 철회한다.** 동일 키 재타격의 release 제외 보정을 제거한 결정만으로 연결 실패 조건까지 추가할 근거가 없기 때문이다.

사용자는 이 규칙을 유저에게 설명하기 어렵다고 지적하고, 같은 키를 다시 누르려면 한 번은 뗀 것이 확실하므로 보정이 없다고 설명해야 하는지 물었다. 물리 keyup은 다른 키로 넘길 때도 존재하므로, 실제로 키를 뗐다는 사실만으로 두 입력의 차이를 설명할 수 없다. 현재 제품 규칙은 서로 다른 키로 넘기는 동작에 한해 release 제외 보정을 적용한다는 것이다. 이를 같은 키 재타격의 자동 연결 Miss나 일반 head의 무효화와 혼동하지 않는다.

현재 추천은 동일 키 자체를 별도 Miss 조건으로 추가하지 않고, 해당 up의 release 적격성과 기존 유지·경계 조건, 새 down의 head·시작 판정을 각각 적용하는 것이다. 이 추천이 모든 재타격의 성공이나 동일 키 release 제외 보정의 복원을 뜻하지는 않는다. 이 처리 방향을 확인한 뒤 NJ-R09의 짧은 마지막 release 창과 NJ-R04의 double 끝으로 돌아간다.

## 13. 최신 채택: 동일 키 재타격에도 같은 연결 보정 적용

이 절의 연결 보정·발생 순서는 유지한다. 아래 NJ-R13의 마지막 실패는 이후 §15에서 권한 갱신을 채택하면서 성공으로 정정한 역사적 결과다.

사용자는 “동일 키라도 같은 보정을 적용한다는 말이라면 동의함”이라고 명시했다. 따라서 같은 키에 대해서도 release 제외 보정을 실제로 적용한다. 단순히 추가 Miss만 없애고 동일 키 보정은 계속 제외하는 해석을 사용하지 않는다.

유효한 다음 head·시작 입력으로 바디를 이어가는 데 쓰인 up은 물리 키의 동일 여부와 관계없이 뒤 실제 release에 쓰지 않는다. 키 교대라는 용어는 서로 다른 키 전환을 가리키되, 동일 키 재타격도 연결 보정에서는 똑같이 처리한다. 일반 head·시작 입력의 적격성, 한 입력의 소비 범위, double의 서로 다른 키 요구는 유지한다.

이 결정으로 NJ-Q07의 단일 동일 키 재타격은 앞 연결 Miss 없이 다음 head와 마지막 release를 처리한다. NJ-R09에 E=1100의 짧은 끝과 E=2000의 긴 끝을 함께 기록했으며 두 실행 모두 Perfect 3개·유지 Miss 없음이다. 같은 보정을 전제로 NJ-R04는 A up 1020을 보정하고 B up 1035와 A up 1040을 두 실제 release Perfect로, NJ-R11은 두 동시 up을 보정하고 C up 1105와 A up 1150을 각각 Perfect·Great로 대조했다. 이 세 사례의 현재 기대값은 더 이상 보류 상태가 아니다.

사용자는 후속으로 “이 패턴에서 중간점에 차트가 기대하는 릴리즈는 1개이므로 두번째 릴리즈가 터미널에 적용되는게 맞아”라고 명시했다. NJ-Q06은 발생 순서를 유지하는 결과로 정리한다. A up 1010은 중간 연결에 배정하고, B up 1040은 끝 1100의 첫 실제 release Great이다. 뒤 B head가 성공해도 B up을 우선 보정하도록 배정을 바꾸지 않는다. 따라서 B up 1100은 같은 double 끝의 둘째 실제 release를 소비하지 못하며, 추가 입력이 없으면 남은 끝은 실패한다. [NJ-R13](../spec/note-judgment-cases.md#nj-r13)에 기록했다.

동일 키 재타격도 보정 후보가 될 수 있다는 것은 동일 키 후보를 먼저 선택하거나 모든 재타격의 마지막 성공을 보장한다는 뜻이 아니다. 연결에 배정할 몫과 입력 발생 순서를 유지하며, 실제 release에는 같은 double 끝의 서로 다른 키 요구를 적용한다. 중간 연결의 한 몫을 새 점수 release로 추가한 것도 아니다. 후속 상태는 [PRD §12](../prd.md#12-미정-사항)에서만 관리한다.

## 14. NJ-Q08: 같은 timestamp의 두 up 중 하나만 연결에 배정하는 경우

이 절은 권한 갱신 전의 모순을 드러낸 역사적 대조다. §15에서 해결 방향을 채택했으며 현재 기대값은 NJ-R14를 따른다. 상태는 [PRD §12](../prd.md#12-미정-사항)에서 추적한다.

차트는 NJ-R13과 같다. A/B로 첫 double을 정상 처리하고 1000까지 유지한 뒤, **A/B up을 모두 1040에 입력**하고 B head 1050 → B up 1100을 입력한다. 중간 연결에 배정할 up은 하나이다.

| 동률에서 먼저 배정한 up | 연결 보정 | 첫 실제 release | B up 1100 |
|---|---|---|---|
| A up | A | B up 1040, Great(-60) | 같은 끝에서 B를 이미 사용하여 두 번째 release 무소비 |
| B up | B | A up 1040, Great(-60) | 다른 키의 두 번째 release Perfect |

timestamp만으로는 두 up의 발생 순서가 구분되지 않는다. 입력 수신 순번을 보존해 그 순서로 배정하는 안을 제안했으나, 사용자는 동일한 플레이의 결과가 같아야 한다고 명시했다. **수신 순번 때문에 후속 성공·Miss가 달라지는 제안은 철회한다.** 수신 순번의 기록 자체와 그것이 사용자 판정 결과를 바꾸는 규칙은 구분한다. 같은 timestamp의 유지 부족 판정은 기존대로 모든 입력 반영 후 수행한다.

사용자가 요구한 것은 단순한 테스트 재현성이 아니라 내부 동률 배정에 영향을 받지 않는 플레이 결과이다. 이 요구를 [RFD 0020 §2.7](../rfd/0020-note-judgment-units-and-inheritance.md#27-동일한-플레이의-결과-일관성--후속-요구사항)에 기록했다. 같은 double 끝의 물리 키 사용 이력이 다음 head의 새 입력까지 제한하는 부분을 다음 절에서 검토한다.

## 15. NJ-Q09: 유효한 새 입력에 따른 release 권한 갱신

사용자가 “그게 좋을거같음”으로 이 권한 갱신을 채택했다. 근거는 [RFD 0020 §2.8](../rfd/0020-note-judgment-units-and-inheritance.md#28-유효한-새-입력에-따른-release-권한-갱신--후속-채택), 현재 기대값은 NJ-R13~R15를 따른다. 전체 검산과 이행 상태는 [PRD §12](../prd.md#12-미정-사항)에서 관리한다.

채택 규칙은 **실제 release로 사용한 물리 키라도, 유효한 새 head·미처리 시작 입력을 처리하면 새 누름의 release 권한을 얻는 것**이다. 물리 키 자체를 같은 double 끝에서 끝까지 차단하던 제한을 이 경우에 완화한다. 한 up으로 실제 release 하나만 처리하며, 앞 up의 소비를 취소하거나 보정 대상을 뒤바꾸지 않는다. 임의의 재누름은 새 권한을 주지 않고, 실패한 unit을 되살리거나 건너뛰는 승계도 허용하지 않는다.

NJ-R13의 서로 다른 시각 대조에 이 규칙을 적용하면 다음 결과가 된다.

| 입력 | 채택 결과 |
|---|---|
| A up 1010 | 중간 연결에 배정할 첫 up |
| B up 1040 | terminal의 첫 실제 release Great(-60)로 배정 |
| B head 1050 | head Great(+50). 유효한 새 press에 release 권한 부여. 앞 두 up의 배정 순서는 유지 |
| B up 1100 | 새 press의 권한으로 두 번째 실제 release Perfect |

NJ-Q08처럼 A/B up이 모두 1040이라면, 앞 terminal을 A가 처리했든 B가 처리했든 유효한 B head 뒤에는 B의 새 누름이 남는다. 두 배정 모두 terminal Great + Perfect이며 내부에서 첫 terminal에 어느 물리 키를 사용했는지가 후속 결과를 갈라놓지 않는다. NJ-R14에 규칙에서 도출한 대조로 기록했다. 전체 상태 전이 모형의 검증 완료를 뜻하지 않는다.

대조할 실패 사례: double head 0 + 일반 double `[0,1000]`, 다른 head·시작 없음. A/B로 시작한 뒤 A up 1000으로 첫 release를 처리하고 A down 1005 → A up 1010을 입력한다. 그 down은 아무 새 head·미처리 시작도 소비하지 않으므로 A의 새 release 권한은 없으며, 두 번째 끝을 처리하지 못한다. B를 계속 유지해 1121까지 가면 남은 release는 Miss이다.

Trade-off는 같은 double terminal의 두 실제 release가 유효한 새 입력을 사이에 두고 같은 물리 키로 처리될 수 있다는 점이다. 기존의 서로 다른 물리 키 요구를 전부 보존하는 안이라고 설명하지 않는다. double head 자체의 서로 다른 키 요구는 유지한다. release에 사용하지 않은 여분 키까지 한꺼번에 차단하거나, 어느 up을 연결에 사용할지 성공 결과에 맞춰 재배정하지 않는다. NJ-R13의 마지막 실패 기대값은 이번 채택으로 성공으로 바뀌었으며, 임의 재누름 실패 대조는 NJ-R15에 기록했다.

## 16. NJ-Q10: 보류 release와 다른 레인 Miss의 콤보 순서

사용자는 판정이 결정되는 순서로 처리할 것을 제안했다. 현재 콤보는 확정 순서로 반영하고 실제 up 시각으로 소급하지 않는다. 원래 up 시각으로 타이밍 등급을 계산하는 규칙은 유지한다. 최대 콤보 통계 미제공의 후속 범위 정리는 §17을 따른다. 채택 근거는 [RFD 0020 §2.9](../rfd/0020-note-judgment-units-and-inheritance.md#29-보류-판정의-콤보는-확정-순서로-반영--후속-채택), 이행 상태는 [PRD §12](../prd.md#12-미정-사항)에서 관리한다.

L1은 NJ-R10과 같다. double head 0 + double `[0,1000]` → double head 1000 + double `[1000,1100]`. A/B down 0, A up 995, C down 1000, B up 1030, C up 1100으로 처리하고 나머지 head는 입력하지 않는다. L2에는 Point 930 하나를 놓고 아무 입력 없이 Good 기한 1050을 넘겨 1051에 Miss를 관측한다. 콤보는 0에서 시작한다. `holdOnly`와 `trillZone`은 없다.

| 시각 | 판정에 필요한 사실 |
|---|---|
| 0 | L1 앞 double head Perfect 2개 |
| 1000 | L1 뒤 head 하나 Perfect. 누적 성공 3개 |
| 1030 | L1 B up. 남은 head의 연결 후보가 될 수 있어 용도 보류 |
| 1051 | L2 Point의 기한 초과 Miss. 콤보 단절 |
| 1100 | L1 C up. 마지막 release Perfect |
| 1121 | L1 남은 head Miss. 보류한 B up은 실제 release Great(-70)로 분류 |

처음에는 B의 release를 실제 up 시각인 1030에 소급하여 최대 콤보를 4로 계산하는 안을 추천했다. **이 추천은 철회한다.** 확정 순서의 최대 콤보 3과 다른 것은 두 정책의 차이이며, 그 자체로 동일 플레이의 결과 일관성을 어기는 증거가 아니다. 이후 사용자는 최대 콤보 통계를 제공하지 않는다고 명시했다. 이 숫자 비교는 당시 논의의 기록일 뿐, 현재 검산의 기대 결과나 결정 요구가 아니다.

채택한 확정 순서에서는 1030에 보류 중인 B up을 콤보에 넣지 않는다. 1051의 Miss 전 성공은 3개이고, 1100의 C release로 콤보 1이 된다. 1121에 B Great와 head Miss를 같은 기한 처리 묶음으로 확정하며 기존의 동일 timestamp·phase에서 Miss 우선 규칙을 적용하면 최종 콤보 0이다. [NJ-S03](../spec/note-judgment-cases.md#nj-s03)에 기록했다.

현재 `JudgmentEngine`은 `incrementCombo`·`breakCombo` 호출 시점에 콤보를 갱신하고, `ScoreManager`는 점수·판정 수를 기록한다. 새 연결 보류 모델의 통합 구현은 아직 없다. 채택한 확정 순서는 입력·기한에 따른 논리적 순서이며, 현재 코드의 임의 호출 순서를 그대로 제품 규칙으로 삼는 것이 아니다. 같은 플레이는 프레임 간격이나 레인 순회와 관계없이 같은 확정 순서·콤보 결과를 가져야 한다. 콤보를 최종 점수에 추가하는 변경은 없다.

## 17. NJ-Q11: 성공과 Miss가 같은 묶음에서 확정될 때 최대 콤보

**질문 철회.** 사용자는 “최대 콤보수라는 통계를 제공하지 않을거라 이 논의가 필요없어”라고 명시했다. 제공하지 않는 통계의 계산 방식을 판정 모델의 미결정 문제로 올린 것이므로, 99 유지와 100 기록 중 어느 쪽도 채택하지 않고 질문 자체를 제거한다.

현재 콤보의 확정 순서와 동일 묶음 Miss 우선은 유지한다. NJ-S03은 현재 콤보 전이·판정 등급만 검산하도록 정리했으며, 최대 콤보 기대값은 제거했다. 기존 코드에 `maxCombo`가 있다는 사실만으로 제품의 통계 요구를 추론하지 않는다. 최대 콤보 통계 미제공은 [RFD 0020 §2.10](../rfd/0020-note-judgment-units-and-inheritance.md#210-최대-콤보-통계-미제공--후속-채택), 결과 화면 노출의 구현 이행은 [PRD §12](../prd.md#12-미정-사항)를 따른다.
