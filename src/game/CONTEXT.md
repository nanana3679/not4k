# Gameplay

Gameplay 컨텍스트는 유저가 차트를 선택해 플레이하고, 입력이 판정과 결과로 이어지는 경험을 다룬다.
노트 타입, 피스, 난이도 용어는 먼저 루트 `CONTEXT.md`의 Core domain을 따른다.

일시정지 재개는 곡 시간 고정 3초 되감기와 이후 상태 복원을 따른다. 일반 첫 재생·Retry는 즉시 시작하며 테스트·재개의 준비와 커서 범위는 [glossary](../../docs/context/glossary.md#일시정지-후-재개)에 정의한다.

## 판정 모델의 전제

[RFD 0037](../../docs/rfd/0037-explicit-score-notes-and-body.md)의 **채택 계약·일반 기본 경로 구현·검증**이다. 정식 정의는 glossary, 실행 전 기대값은 [명시적 점수 노트 판정 사례](../../docs/spec/explicit-note-judgment-cases.md)를 따른다.

- 바디는 hold 수를 요구하는 무점수 구간이고 탭 노트·릴리즈 노트·틱 노트만 명시 점수 항목을 만든다. [바디](../../docs/context/glossary.md#바디)·[점수 항목](../../docs/context/glossary.md#점수-항목과-무점수-miss)을 따른다.
- 전체 이론 가중치가 0인 유효한 차트도 재생하고 달성률·랭크는 표시하지 않는다. 점수 항목의 전부 Miss는 0%·F다([glossary](../../docs/context/glossary.md#점수-항목과-무점수-miss)).

- 탭 노트는 down, 명시 릴리즈는 up을 소비한다. 바디·틱 노트는 입력을 소비하지 않으며 숨은 연결 up 소비는 없다. [consume](../../docs/context/glossary.md#consume-구-표기-흡수소비)을 따른다.
- preheld는 차트상 시작에서, 시작 창 안의 유효한 새 down은 그때 충족한 몫을 시작한다. 건강한 짧은 바디 승계와 탭 노트 담당 몫의 기존 유지 실패 대기·실제 down 기준을 함께 보존한다. [바디 판정과 실패 종속](../../docs/context/glossary.md#바디-판정과-실패-종속)을 따른다.
- 실제 시작·정상 완료·릴리즈 대기는 별개이며 릴리즈 경계·1→2·2→1의 승계와 새 시작을 구별한다. 바디 사이에는 실패를 전파하지 않으며 2→1에서 두 몫이 모두 탈락해도 뒤 single은 자기 조건으로 새로 시작할 수 있다. 경계에 탭 노트도 릴리즈도 없는 같은 수 연결은 배치 금지라 실행하지 않는다. 금지에서 빠지는 트릴 바디와 일반 바디의 탭 노트 없는 경계(두 방향)도 메인 레인에서는 `trillExclusive`(트릴 → 일반)와 `trillLongInvalid`(트릴 바디의 시작 트릴 탭 노트)가 막고 보조 레인은 판정하지 않아 판정 대상이 되지 않는다. 일반 진행에서는 확정 실패와 소멸한 점수 기회를 복구하지 않는다. 일시정지의 고정 되감기는 별도 상태 복원이다. [바디 판정과 실패 종속](../../docs/context/glossary.md#바디-판정과-실패-종속)을 따른다.
- 틱 노트는 자체 창 없이 바디의 정상 유지·시작/회복 대기·이른 종료를 따르고 한 몫당 Perfect 3점·콤보 +1·일반 Perfect 고도 기여를 갖는다. [틱 노트](../../docs/context/glossary.md#틱-노트-tick)를 따른다.
- Grace 릴리즈도 실제 up을 요구한다. 싱글 바디의 더블 릴리즈에도 해당 시작 탭 노트를 처리한 같은 키 재누름 예외만 적용한다. [릴리즈 노트](../../docs/context/glossary.md#릴리즈-노트)·[release 판정](../../docs/context/glossary.md#release-판정)을 따른다.
- 현재 `trillZone` 안에는 바디 끝을 포함해 명시 릴리즈를 도입하지 않으며, 새 트릴 바디 끝에도 자동 점수가 없다([RFD 0038](../../docs/rfd/0038-release-notes-in-trill-zones.md)). 구형 `trillLong`의 보존 의미와 구별한다.
- 확정 효과·현재 상태·화면 수명을 분리한다. 틱 노트 성공 글자·타격, 동시 최저 대표 등급과 그 등급의 표시 가능한 실제 입력 최대 절대 오차는 [판정 효과](../../docs/context/glossary.md#판정-효과-confirmedjudgmenteffects)를 따른다.
- 실제 입력·AutoPlayer·튜토리얼은 같은 세션과 일회성 효과를 소비하고 반복마다 새 판정·표시 인스턴스를 쓴다. 상세 계약은 [게임 코어](../../docs/spec/game-core.md#autoplayer튜토리얼과-입력-수명), 미정·이행은 [PRD §12](../../docs/prd.md#12-미정-사항)를 따른다.

### 과도기 구형 판정 설명

구형 읽기·표시·편집과 현행 런타임·과거 논의의 대조를 위해 보존한다. 아래의 “후속”·“현재”는 당시 모델의 시점이며 새 채택 계약을 덮지 않는다. 제거 시점은 [구형 차트와 과도기](../../docs/context/glossary.md#구형-차트와-과도기)를 따른다.

<summary>등록 키·자동 끝점·연결 보류에 관한 기존 설명</summary>

아래 등록 키·연결 보류는 기존 엔진 기준이다. 후속 설계는 패턴별 허용 입력·기대 결과를 먼저 정하며, release와 Grace의 역할 및 현재 합의 범위는 [glossary](../../docs/context/glossary.md#release-판정)를 따른다. 연결 head를 처리한 single 사례는 이르거나 늦은 실제 head down부터 뒤 바디의 유지를 판단하고 임시 20ms 유지 유예를 적용한다([glossary](../../docs/context/glossary.md#유예-시간-grace-period)). head를 놓쳐도 계속 유지한 뒤 바디의 실제 release는 처리한다([glossary](../../docs/context/glossary.md#release-판정)). 연결 head 창 안에서 hold가 끊기고 head도 놓친 사례는 head Miss 하나와 뒤 끝 종속 0점으로 정리한다. head 기한까지 유지한 뒤 새로 유지가 끊기면 20ms 유예 후 유지 Miss를 추가하고 끝은 종속 0점으로 정산한다. 같은 double 끝의 두 release는 서로 다른 키를 요구하되, 같은 키를 다시 눌러 그 double 바디가 시작하는 연결 head를 처리했다면 그 누름의 up으로 남은 release를 처리할 수 있다. 나머지 적용 범위와 엔진 이행은 아직 남아 있다.

- 같은 레인의 바디 열린 구간은 겹치지 않는다. 다중 unit 구간은 `doubleLong`, 순차 구간은 `connection`으로 표현한다. 판정 창은 겹칠 수 있어 앞 release 대기와 뒤 시작 준비가 함께 존재할 수 있다.
- 바디는 head·시작 입력·정당한 승계로 활성화한다. 등록된 유지 키 수와 release 권한을 구분하며, 고정 물리 owner나 임의의 raw held로 설명하지 않는다.
- 유효한 새 head·미처리 시작은 해당 누름에 새 release 권한을 준다. 같은 double 끝에서 그 물리 키를 이미 썼어도 새 권한은 유효하며, 임의의 재누름에는 권한을 주지 않는다.
- `connection`은 차트상 끝점과 시작점이 맞닿는 관계이다. 같은 unit 수의 경계에는 head 또는 `holdOnly`가 필요하고, unit 수 변화는 그 자체로 경계를 드러낸다.
- 일반 승계 성공에는 점수·콤보가 없다. 감소에서 이어지지 않고 끝나는 unit은 일반 끝처럼 실제 release(감소 release)를 요구하되 `holdOnly`가 이를 면제할 수 있다. 후속 모델에서는 head가 있는 2→1 감소 경계에도 감소 release가 있다. 경계 근처의 첫 up이 감소 release를, 연결 head 창 안의 다음 up이 연결 release를 맡는다(RFD 0032 §6-3, 엔진 이행 전).
- 유지 부족은 같은 timestamp 입력을 반영한 뒤 확인한다. 연결 교대 후보로 보류한 up은 연결 head 기한까지 부족으로 확정하지 않고, 교대가 끝내 성립하지 않으면 경계 전 교대 실패와 같게 정리한다. 이미 실패한 unit은 되살리거나 건너뛰어 승계하지 않는다.
- 같은 키·시각의 입력에서 서로 다른 키의 동시 up을 내부 배정한 순서만으로 후속 성공·Miss가 달라지면 안 된다. 세부 요구와 영향은 glossary의 동시 입력 결과 일관성을 따른다.
- 트릴 교대 추적에는 head를 소비한 키만 등록하며 바디 유지·승계·release 키는 추가하지 않는다. 구간 귀속과 동시 입력의 세부는 glossary의 트릴 노트를 따른다.

풀 정의는 [glossary](../../docs/context/glossary.md#롱노트-판정-모델), 채택 근거는 [RFD 0020](../../docs/rfd/0020-note-judgment-units-and-inheritance.md), 입력별 기대 결과는 [판정 사례 명세](../../docs/spec/note-judgment-cases.md)를 따른다. 현재 엔진과 상세 구현 명세의 이행 상태는 [PRD §12](../../docs/prd.md#12-미정-사항)에서 추적한다.

기존 Language 정의의 대조 기록:

창과 키 자격을 충족한 가장 이른 Point 또는 실제로 부족한 시작이 keydown 하나를 소비한다. 이미 정당하게 승계한 unit은 추가 시작 입력을 소비하지 않는다. 길이 0 `holdOnly`의 held 상태 확인은 별개이다.

같은 double 끝의 두 실제 release는 서로 다른 물리 키를 요구하며 처음 유지한 키와 달라도 된다. 그 double에서 쓴 키도 뒤 독립 노트의 release에는 다시 쓸 수 있다. 연결 head의 교대·유지 중 탭에서 연결 release에 배정한 up은 뒤 실제 release에 쓰지 않는다. 연결 release는 head보다 뒤 끝의 release보다 먼저, head와 같거나 앞선 감소 release보다 나중에 배정한다(RFD 0032 §6-4). 연결 head 전에 경계보다 먼저 뗀 up은 앞 바디를 끝낸다(RFD 0032 §4-2·§8-2). 나머지 up은 끝 창 안의 적격 대상(바디의 시작 여부와 무관) 중 차트상 끝 시각이 가장 이른 것 하나를 처리하며, `holdOnly` 끝도 자기 Good 창 안의 up 하나를 가져간다(RFD 0032 §2-3·§7-1). 입력 자격·소비와 Grace의 역할, 사례별 합의와 이행 상태는 [glossary](../../docs/context/glossary.md#release-판정)를 따른다.

보류 판정은 확정 순서로 현재 콤보에 반영하며 입력 시각으로 소급하지 않는다. 최대 콤보수 통계는 제공하지 않는다. 확정 순서와 동시 Miss 처리의 세부는 [glossary](../../docs/context/glossary.md#롱노트-판정-모델)를 따른다.

**`AutoEvent`**의 노트를 합성 입력(press/release)으로 변환하는 순수 상태머신이다. `InputSystem`(실제 키보드)과 같은 판정 엔진 입력 seam에 서는 두 번째 어댑터다(시간 주입, 엔진·렌더러 무지). 풀 정의는 glossary "게임 입력".

확정 판정의 점수 정산·통계·고도·표시 효과를 구분하는 순수 데이터이다. `NoteJudgmentSession`이 정산하고 `SessionRendererAdapter`가 확정 묶음과 unit 상태를 실제 플레이·튜토리얼 렌더러에 전달한다. 풀 정의는 [glossary의 판정 효과](../../docs/context/glossary.md#판정-효과-confirmedjudgmenteffects)를 따른다.

## Language

**곡 메타데이터**:
제목·아티스트·자켓은 같은 곡의 모든 차트가 공유하며, 이 표시 정보만 수정하면 기존 기록과 랭킹을 유지한다([glossary](../../docs/context/glossary.md#곡-메타데이터)).

**곡 타이밍**:
같은 곡의 모든 차트가 공유하는 초기 BPM·BPM 변경 목록·박자표·변박 정보·음원 정렬용 오프셋이다. 곡 단위 공유는 채택 규칙이며 런타임 반영은 후속 작업이다([glossary](../../docs/context/glossary.md#곡-타이밍)).

**플레이 세션**:
유저가 하나의 차트를 시작해서 결과 화면에 도달하기까지의 한 번의 플레이이다. 곡 종료 시 3초 이내의 건너뛸 수 없는 종료 연출을 보여준 뒤 자동으로 결과 화면으로 이동하며, 풀콤보·올퍼펙트 달성 시 전용 연출로 일반 클리어 연출을 대체한다. 풀콤보와 올퍼펙트 조건을 모두 충족하면 올퍼펙트 종료 연출만 보여준다. 곡 도중 실패가 확정되면 즉시 곡 재생·입력 판정을 종료하고 같은 흐름을 따른다. 실패 종료 시 판정 통계는 종료 시점까지 확정된 판정만 집계하며 최종 달성률은 차트 전체 이론 가중치를 기준으로 계산한다([glossary](../../docs/context/glossary.md#플레이-종료와-결과)).
_Avoid_: 게임 실행

**Observer 계열**:
실패 조건 없이 차트를 관찰·학습하는 흐름이다. 옵저버는 원곡의 음높이를 유지하는 감속 재생과 전곡 또는 미니맵의 지정 구간 반복·직접 연습을 제공하며, Auto는 집계에서 제외하고 수동 집계는 구간 종료·Retry·구간 변경에 초기화한다. 명시적으로 나갈 때 리절트 없이 복귀한다([glossary](../../docs/context/glossary.md#옵저버-모드-observer-mode)).
_Avoid_: 쉬운 플레이

**곡 선택**:
유저가 플레이할 곡과 차트를 고르는 흐름이다.
_Avoid_: 파일 선택

**클리어 상태**:
종료한 한 플레이를 실패·성공·풀콤보·올퍼펙트 중 하나로 나타내는 내부 용어이며 점수 랭크와 구별한다([glossary](../../docs/context/glossary.md#클리어-상태)).

**올퍼펙트**:
곡을 끝까지 연주하고 모든 점수 노트를 Perfect로 처리하며 바디 실패를 포함한 Miss가 없는 달성 상태이다([glossary](../../docs/context/glossary.md#올퍼펙트-all-perfect)).

**일반 플레이용 차트**:
점수 노트를 최소 1개 포함한 차트이며, 무점수 문서의 제작 중 저장·테스트와 튜토리얼 바디 연습은 이 진입 조건과 구별한다([glossary](../../docs/context/glossary.md#점수-항목과-무점수-miss)).

**개인 플레이 기록**:
차트 선택에서는 올퍼펙트를 달성하면 풀콤보 표시 대신 올퍼펙트를 표시한다. 로그인한 플레이어의 완주 기록과 `flightRule`에 따른 곡 도중 실패 종료의 획득 점수는 기록·랭킹 반영 대상에 포함하며 클리어 여부는 독립적으로 보존한다. 직접 중단한 플레이는 기록을 남기지 않는다. 현재 차트 버전의 최고기록(최고 점수)·클리어 여부·풀콤보 여부는 곡·차트 선택에서 바로 표시하고, 플레이 횟수는 통계창에서 확인한다. 세 기록은 Normal/Easy별로 분리하고, 같은 판정 설정 안에서는 미러 사용 여부와 관계없이 같은 차트 버전의 서로 다른 플레이에서 달성해도 각각 독립적으로 보존하며, 노트 배치가 바뀌거나 곡 타이밍 수정으로 실제 입력 시각이 달라지면 이전 기록을 보관하고 해당 차트의 새 버전 기록을 쌓는다. 차트 삭제 후에도 기록은 원래 버전에 보관하고 현재 선택·랭킹에서 제외하며 재등록 시 승계하지 않는다([glossary](../../docs/context/glossary.md#개인-플레이-기록)).

**프로필**:
로그인 플레이어의 사용자 정보이며 게임 설정의 프로필 탭에서 닉네임을 변경한다. 비로그인 상태에도 탭을 표시하고 로그인 버튼을 제공하며, 로그인 상태에서는 로그아웃 버튼을 제공한다([glossary](../../docs/context/glossary.md#프로필)).

**닉네임**:
랭킹에 표시하는 플레이어 이름이며 처음 닉네임이 없으면 Guest 뒤에 6자리 숫자 난수를 공백 없이 붙여 자동 생성한다. 중복과 이후 변경을 허용한다. 기존 랭킹에도 조회 시점의 현재 닉네임을 표시한다([glossary](../../docs/context/glossary.md#닉네임)).

**랭킹**:
같은 버전·판정 설정에서 점수와 독립 보존한 풀콤보·올퍼펙트 배지를 함께 표시하며, 올퍼펙트가 풀콤보를 대체한다. 배지는 점수 순위·동점 최초 달성 시각에 영향을 주지 않는다. 같은 차트 버전·판정 설정의 최고 점수를 비교하고, 기록 수치는 점수만 표시한다. Normal/Easy 모두 제공하되 차트 버전·판정 설정별로 순위를 따로 집계하는 비교이며, 동점은 해당 점수를 먼저 달성한 순서로 정한다. 플레이어가 선택한 경로에서 확인한다([glossary](../../docs/context/glossary.md#랭킹)).

**곡 프리뷰**:
곡 선택에서 미리 듣는 음원으로, 본편과 별개인 전용 파일을 곡마다 필수로 제공하며 파일 길이를 5초 이상 15초 이하로 제한한다. 곡 선택 화면에서 같은 곡에 1초 동안 머문 뒤 반복 재생하며, 브라우저에 저장해 다음 접속에도 재사용한다([glossary](../../docs/context/glossary.md#곡-프리뷰)).

**로딩**:
차트·음원을 서버에서 불러와 재생 전에 준비하는 흐름으로, 본 플레이 로딩 중 취소·복귀 조작은 제공하지 않고 응답 제한 시간을 넘기면 해당 시도를 실패로 처리한다. 차트 파일 전송·음원 로딩의 자동 재시도 후에도 실패하면 재시도와 곡 선택 복귀를 제공하고, 차트 자체의 형식·검증 오류에는 오류 안내와 곡 선택 복귀만 제공한다([glossary](../../docs/context/glossary.md#로딩)).

**서버 점검**:
새 접속·새 플레이 진입을 막되 이미 재생 중인 곡은 끝까지 진행하고 결과를 표시하는 운영 상태다. 플레이 중에는 점검 안내를 띄우지 않고 결과 화면에서 알린다([glossary](../../docs/context/glossary.md#서버-점검)).

**플레이 화면**:
차트가 재생되고 유저 입력이 판정되는 화면이다.
_Avoid_: 게임 화면

**튜토리얼**:
메트로놈에 맞춘 시연 후 직접 연주에서 항목별로 표시한 달성률·추가 조건을 모두 충족하면 1회 성공하며, 항목별 요구 횟수만큼 누적 성공으로 통과하는 선택적 학습 흐름이다. 롱노트 중 탭 한 항목에서는 기존 키 유지 방법의 목표를 먼저 달성한 뒤 `다음`으로 유지 키 교대 방법에 진입하고 두 방법을 완료해야 전체 통과한다. 재진입·재실습은 첫 방법 0회부터 시작하며, 중간 방법 완료는 저장하지 않고 과거 항목 전체 통과 기록은 유지한다. 항목 전체 통과 여부와 마지막 선택 탭·항목은 로그인 없이도 브라우저에 저장하고 로그인하면 계정과 동기화한다. 열람과 통과를 구별하고 단계별 키 추가·손배치 발견 과정은 두지 않으며, 차트 선택의 선행 조건으로 사용하지 않는다([glossary](../../docs/context/glossary.md#튜토리얼)).

**결과 화면**:
기록 갱신 안내는 최고 점수 갱신만 표시하며 클리어 상태 갱신은 별도로 알리지 않는다. 한 플레이의 클리어 상태는 실패·성공·풀콤보·올퍼펙트 중 하나로 표시한다. 플레이 세션이 끝난 뒤 판정 집계, 달성률, 랭크, 풀콤보 여부, `flightRule`의 클리어/실패 여부를 보여주는 화면이다. 로그인한 플레이의 기록 전송에 실패하면 실패 안내와 전송 재시도 버튼을 제공하며, 결과 화면을 나가도 미전송 기록을 브라우저에 보관하고 다음 접속 때 원래 계정으로 로그인되어 있으면 자동 재전송한다([glossary](../../docs/context/glossary.md#개인-플레이-기록)).
_Avoid_: 스코어 화면

**입력-노트 매칭**:
유저 입력을 판정 윈도우 안의 노트에 연결하는 판정 전 단계이다.
_Avoid_: 키 이벤트 처리

**가장 이른 노트 매칭**:
창·레인·키 자격을 충족한 가장 이른 명시 탭 노트 또는 릴리즈에 down/up을 배정한다. 바디·틱 노트는 소비하지 않는다. 풀 정의는 [glossary](../../docs/context/glossary.md#가장-이른-노트-매칭)를 따른다.
_Avoid_: 가장 가까운 노트 매칭

**release 판정과 keyup 소비**:
명시된 릴리즈만 실제 up 하나를 소비한다. 바디에 붙으면 실제 시작과 남은 기회가 전제이고 정상 완료 뒤의 창은 유지한다. 같은 키 예외·감소 귀속·Grace는 [glossary](../../docs/context/glossary.md#release-판정)를 따른다(#342에서 구현, 일반·명시 테스트 재생에서 검증).
_Avoid_: 익명 keyup, 실제 release의 이진 판정

**빈 레인 입력**:
시각적으로 비어 보이는 레인에 입력했지만 판정 윈도우 안의 노트와 연결될 수 있는 입력이다.
_Avoid_: 무시 입력

**처리된 노트**:
판정이 끝나 더 이상 플레이어가 읽거나 입력할 필요가 없는 노트이다.
_Avoid_: 지나간 노트

**콤보**:
Miss 없이 이어진 점수 판정 수이다. 무점수 연결 성공은 증가시키지 않고, 무점수 유지 Miss도 콤보를 끊는다.
틱 노트 성공도 몫당 +1이며 종속 0점은 새 콤보 이벤트가 아니다. 확정 순서·같은 timestamp/phase의 Miss 우선과 최대 콤보 통계 미제공은 [glossary](../../docs/context/glossary.md#판정-효과-confirmedjudgmenteffects)를 따른다.
_Avoid_: 연속 입력 수

**풀콤보**:
무점수 유지 실패를 포함해 Miss 없이 곡을 끝까지 연주한 결과 상태이다. 미완주 플레이는 인정하지 않으며 달성률 100%와는 별개이다([glossary](../../docs/context/glossary.md#풀콤보-full-combo)).
_Avoid_: 올콤보

**달성률**:
차트에서 얻을 수 있는 총점 대비 실제 획득 점수의 비율이다.
_Avoid_: 정확도

**랭크**:
달성률을 구간별로 요약한 결과 등급이다.
_Avoid_: 난이도 등급

**`gameplayRange`** (구 표기: 인게임 구간):
원본 음원 중 플레이 세션에서 실제로 재생하고 판정 시간의 0ms 기준으로 삼는 구간이다.
_Avoid_: 프리뷰 구간

**마스터 볼륨**:
게임·에디터·프리뷰의 전체 오디오 음량을 조절하며, 기기별 브라우저에 저장하고 계정 설정 동기화에서 제외하는 설정이다([glossary](../../docs/context/glossary.md#마스터-볼륨-master-volume)).

**입력 오프셋**:
입력 장치 지연이나 개인 체감 타이밍을 보정하기 위해 입력 기준을 이동시키는 설정이다(`inputOffsetMs`, 실제 ±1000ms, SLOW면 −). 기기별 브라우저에 저장하고 계정 설정 동기화에서 제외하며, 정의는 [glossary](../../docs/context/glossary.md#입력-오프셋-input-offset).
_Avoid_: 오디오 오프셋

**시각 오프셋**:
노트를 그리는 시각만 옮겨 화면 표시 지연을 보정하는 설정이다(`visualOffsetMs`, 실제 ±1000ms, 화면이 늦으면 +). 기기별 브라우저에 저장하고 계정 설정 동기화에서 제외하며, 정의는 [glossary](../../docs/context/glossary.md#시각-오프셋-visual-offset).
_Avoid_: 화면 오프셋

**오프셋 구분**:
입력·시각 오프셋(실제 시간, ms)과 판정선 오프셋·기어 y 오프셋(화면 위치, 논리 px)은 기준과 부호가 다른 별개의 값이라, 어느 오프셋인지 이름을 붙여 쓴다. 표는 [glossary](../../docs/context/glossary.md#오프셋-구분).
_Avoid_: 이름 없는 "오프셋"

**`GameClock`**:
한 플레이 세션의 시간 권위이다. 고정 출력 지연 L₀와 실제 배속 r로 **판정 시간** J = P − L₀·r, **시각 시간** V = J + visualOffsetMs·r, **입력 시간** J − handlerDelay·r + inputOffsetMs·r을 만든다. 재생 전 L₀ 준비·일시정지·곡 끝 뒤 P 진행은 `AudioEngine`이 소유한다. 세부는 [오디오·비주얼 동기화](../../docs/spec/audio-visual-sync.md)를 따른다.
_Avoid_: songTime을 호출자가 직접 계산

**`AutoPlayer`**:
바디 hold 요구와 명시 탭 노트·릴리즈를 만족하는 합성 down/up을 만드는 입력 어댑터다. 실제 키보드와 같은 세션을 쓰며 Grace 릴리즈에도 up을 만든다. 새 계약은 [게임 코어](../../docs/spec/game-core.md#autoplayer튜토리얼과-입력-수명), 구형 구현 경계는 [glossary](../../docs/context/glossary.md#autoplayer)를 따른다.
_Avoid_: 오토 판정(판정은 여전히 판정 엔진이 한다)

**`ConfirmedJudgmentEffects` (판정 효과)**:
확정 정산·통계·콤보·고도·글자·타격을 현재 상태와 구별하는 효과다. 표시 복구·반복으로 재실행하지 않으며 새 계약과 구형 구현의 경계는 [glossary](../../docs/context/glossary.md#판정-효과-confirmedjudgmenteffects)를 따른다.
_Avoid_: 화면 콜백에서 판정 규칙 재구현

**리프트**:
판정선 위치를 위로 올려 유저의 시야 중심을 조정하는 플레이 설정이다.
_Avoid_: 스크롤 속도

**서든**:
레인 상단 일부를 가려 노트가 보이는 시간을 줄이는 플레이 설정이다.
_Avoid_: 리프트

**녹숫**:
노트가 레인에 보이기 시작해 판정선에 닿기까지의 시간으로, 스크롤 속도·리프트·서든이 이 값 하나로 모인다. 차트 Lv.별 기준값은 추정 녹숫이다. 풀 정의는 [glossary의 녹숫](../../docs/context/glossary.md#녹숫-green-number)을 따른다.
_Avoid_: 스크롤 속도(녹숫을 정하는 요소 중 하나다)

**흰숫**:
서든과 리프트가 줄이는 레인 높이를 레인 위끝부터 리프트 0% 판정선까지 = 1000으로 놓고 잰 값이다. 위쪽 흰숫(서든 %의 10배)과 아래쪽 흰숫(리프트 %의 10배)이 따로 있고, 숫자 하나로 말하면 보통 둘의 합계다. 노트가 보이는 레인은 426 × (1000 − 합계 흰숫) / 1000이다. 풀 정의는 [glossary](../../docs/context/glossary.md#흰숫-white-number)를 따른다.
_Avoid_: 녹숫(흰숫은 높이, 녹숫은 시간이다)

**게이지**:
플레이 중 실패 여부를 결정하는 생존 지표이다.
_Avoid_: 달성률

**비행 배경**:
기어 모션과 별도의 설정으로 움직임을 끄면 어두운 고정 배경을 표시하고 노트·기어·고도 게이지는 유지한다. 기본 켬이며 일반 플레이·옵저버에 공통 적용한다. 설정 런타임 반영은 후속 작업이다([glossary](../../docs/context/glossary.md#비행-배경)).

**기어**:
플레이 화면에서 레인 영역을 둘러싼 장식 그림과 그 위의 `gearMotion`(장식 애니메이션)·유리관 게이지·키 덱이다. 레인 창을 레인 영역에 맞추고, 판정선과 함께 화면 아래보다 기어 y 오프셋 `GEAR_OFFSET_Y`(10, +가 아래)만큼 내려 고정한다(설정 `Gear Motion`으로 `gearMotion`을 끈다). 레인은 키 윗면(레인 끝 `laneEndY`)에서 끝난다. 양옆 유리관 게이지는 비행 배경과 같은 `altitude`를 두 유리관에 아래 기준 채움으로 보여 준다(약 300ms에 걸쳐 따라가고 색은 바꾸지 않는다). 풀 정의는 [glossary](../../docs/context/glossary.md#기어-gear), 배치는 [RFD 0029](../../docs/rfd/0029-frame-aspect-fit-narrow-lanes.md)를 따른다.
_Avoid_: 프레임(화면 한 장과 헷갈림)

**`flightRule`**:
`Liftoff`는 Miss 없이 완주하면 클리어 조건을 충족하도록 게이지 상승량을 설정한다. Play의 고도 상태와 클리어/실패를 다루며, 차트 난이도명 `Liftoff → Infiltration → Breakthrough`에 대응하는 시나리오와 연결된다. 이름 표시와 배경은 적용했으며 세부 비행 규칙은 미구현이다. 풀 정의는 [glossary](../../docs/context/glossary.md#flightrule-flight-rule), 현재 배치는 [RFD 0022](../../docs/rfd/0022-flight-difficulty-names-and-visuals.md)를 따른다.
_Avoid_: 차트 레벨

**`altitude`**:
`flightRule`의 상태와 고도 연출을 연결하는 지표다. `Breakthrough`의 저고도는 정상 비행이므로 낮은 시각 고도를 모든 단계의 실패 위험으로 해석하지 않는다. 풀 정의는 [glossary](../../docs/context/glossary.md#altitude-altitude)를 따른다.
_Avoid_: 달성률

## Relationships

- **플레이 세션**은 하나의 **차트**와 그 난이도명에 대응하는 비행 시나리오를 대상으로 진행된다.
- **Observer 계열**은 실패 조건 없이 차트를 관찰하고 학습하는 흐름이며, 기록 대상 Play와 구분된다.
- **곡 선택**은 **플레이 세션** 전에 곡과 차트를 결정한다.
- **플레이 화면**은 입력을 **입력-노트 매칭**으로 연결하고 판정을 만든다.
- **가장 이른 노트 매칭**은 노트 배치 순서와 판정 순서를 일치시킨다.
- `NoteJudgmentSession`은 판정 코어를 생성 함수 `createCore`로 받는다. 넘기지 않으면 실제 게임이 쓰는 `NoteJudgmentCore`를 만들며, 다른 코어를 같은 세션 경로(drain, `advance`, finalize, 확정 효과)로 시험할 때만 넘긴다. 세부는 [게임 코어 명세](../../docs/spec/game-core.md#판정-실행-구조)를 따른다.
- **처리된 노트**의 새 표시 계약은 정상 완료 바디·성공 틱 노트의 즉시 숨김과 실패색 잔존을 구별한다. 명시 릴리즈 대기를 바디와 함께 닫지 않는다([glossary](../../docs/context/glossary.md#판정-효과-confirmedjudgmenteffects), #343에서 구현, 일반·명시 테스트 재생에서 검증).
- 구형 싱글·더블의 연결 켜짐·터미널 전파 기록과 새 모델의 마감 없음·몫별 상태·표시 수명은 [glossary](../../docs/context/glossary.md#판정-효과-confirmedjudgmenteffects)에서 구분한다. `heldEffect: false` 스킨도 부분 실패·실패를 표시하는 [RFD 0028](../../docs/rfd/0028-skin-held-effect.md)의 원칙은 보존한다.
- **결과 화면**은 **달성률**, **랭크**, **콤보**, **풀콤보**, **`flightRule`** 결과를 보여준다.
- Play는 **`flightRule`**에 따라 실패할 수 있으며, 실패 조건 없는 완주와 관찰은 **Observer 계열**이 담당한다.
- **`altitude`**는 **게이지**의 비행 콘셉트 표현이며, **달성률**이나 **랭크**와 구분한다.
- **입력 오프셋**과 **시각 오프셋**은 각각 입력 지연·체감과 화면 표시 지연을 보정한다. 출력 지연은 고정 L₀로 자동 보정한다.
- **`GameClock`**은 **입력 오프셋**·**시각 오프셋**·L₀에 실제 배속을 반영한다. 입력 오프셋은 입력 시간에만, 시각 오프셋은 시각 시간에만 적용한다.
- **`gameplayRange`**가 있으면 플레이 화면의 songTime 0ms는 원본 음원의 해당 구간 시작점에 대응한다.
- **리프트**와 **서든**은 판정 규칙이 아니라 시야 조절 설정이다.

## Example dialogue

> **Dev:** "빈 레인에서 누른 입력은 그냥 버리면 되나요?"
> **Domain expert:** "판정 창과 자격을 충족한 앞 노트가 있으면 그 입력을 소비합니다. 뒤 입력 계획이 달라질 수 있으니 화면이 비어 보인다는 이유로 무시하면 안 됩니다."
>
> **Dev:** "끝까지 쳐보고 싶은데 Play에서 `flightRule` 실패가 나면 어떻게 하나요?"
> **Domain expert:** "완주와 관찰은 **Observer 계열**이 담당합니다. Play는 **`flightRule`**에 따른 클리어/실패가 있는 기록 대상 흐름입니다."

## Flagged ambiguities

- **랭크**는 결과 등급이고 **난이도 등급**은 차트 레벨 구간이다.
- **입력 오프셋**과 **시각 오프셋**은 합치지 않는다. 오디오 오프셋은 제거했다.
- **`flightRule`**은 **난이도명**에 대응하는 시나리오와 연결된다. **Lv.**·**난이도 등급**과는 다르다.
- **`Infiltration`**에는 하향 시선 회전, **`Breakthrough`**에는 전방을 보는 지속 저공비행을 배치한다. 이름만으로 종전 규칙의 회복·실패 조건을 승계하지 않는다.
- **`altitude`**는 **달성률**이나 **랭크**와 다르다.
- **기어**는 레인을 둘러싼 장식이고, 프레임은 렌더 프레임(`renderFrame`, 프레임 시간)이다. `gearMotion`의 애니메이션 경과 시간이 "렌더 프레임마다" 나아간다는 말에서 둘을 섞지 않는다.
- **`gearMotion`**은 기어 위 장식 애니메이션이고, "움직이다"는 위치가 바뀌는 것(노트 스크롤, 리프트)에만 쓴다. 기어는 리프트로 움직이지 않는다.
