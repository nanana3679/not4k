# 돌파 절단면 광원 + A~H 건축 모델 비교

2026-09-10. **독립 시연. 미술 검수는 사용자가 한다.** 기존 돌파의 사각뿔 절단면, 직선·삼각형·혼합, 채움·윤곽선, Primary/Secondary 색상, 짧은 잔상 사이에서 A~H 모델을 하나씩 바꿔 본다. E 하나의 통합에 이어 8종 선택을 추가했고, E에는 입체 주변 건축·하부 연결을 따로 켜는 공간 비교를 더했다. 이후 사용자 설명에 맞춰8종 모두에 먼 건축 배경 그림을 추가하고, E 외의7종에도 고정부와 이어지는 긴 몸통을 더했다. 최신 변경은8종의 긴 연결부를 관제실·작업층·환승층·적재층이 붙는 수직 시설로 재설계한 것이다. 원래 시연·8종 갤러리·게임 본편은 수정하지 않는다. 최종 제품 기본안을 바꾸는 단계가 아니다.

## 실행과 검수

새 체크아웃에서는 먼저 저장소 루트에서 `pnpm install --frozen-lockfile`를 실행한다. 브라우저 검사는 Playwright Chromium 설치가 필요하다. [저장 범위·초기 설정](../../README.md)을 참고한다.

```sh
cd output/prototypes/breakthrough-hangar-integration-20260910
npm start
npm test
npm run check:browser
node arrival-browser-check.mjs
node models-browser-check.mjs
node space-browser-check.mjs
node backdrop-browser-check.mjs
node recursive-browser-check.mjs
node zoom-stability-browser-check.mjs
node connections-browser-check.mjs
```

`npm start`가 출력하는 비공개 Tailscale 주소로 접속한다. 호스트 PC가 켜져 있고 같은 Tailscale에 연결된 동안 접근할 수 있으며 24시간 후 만료한다. 실행 HTML·CSS·명시한 모듈·공유 표면 그림 다섯 장·원경 배경 그림 한 장만 메모리에서 제공한다. 테스트·로그·접속 상태·프로젝트 파일은 제공하지 않는다. 파일 변경 후 해당 서버만 재시작하고 `--reuse-link`를 지정하면 유효한 링크와 만료 시간을 유지한다.

- `배경`은 `검은 배경`과 `먼 건축 배경`을 전환한다. `backdrop=architecture`는 새 그림을 선택한다. 기본 밝기는50%이며0~100%로 조절하고 URL에 명시한 기존 밝기는 유지한다. 기존 URL의 배경 선택은 검정이며 모든 모델에 유지한다.
- `배경 움직임`은 `연속 확대`와 `고정 그림`을 비교한다. 확대 속도는0~300%이며 기본100%다. 비행1000%에서 기본 한 주기는80초, 4배 확대다. 정지·비행 속도0은 확대도 멈춘다.
- `공간 연결 비교`의 `구조 연장`은 A~H 모델마다 용도 있는 층이 붙은 수직 시설을 표시한다. `extensions=1`로 켜고 생략 또는0이면 원래 길이와 비교한다. `E · 입체 주변 건축`은 E의 원경·뒤 골조를 `surroundings=1`로 별도 표시한다. 다른 모델에서는 이 주변 건축 조절만 비활성화하며 E로 돌아오면 선택을 복원한다.
- 모델 버튼 A~H로 바꾸면 현재 고도·전진 거리·속도·광원·정지/재생 상태를 유지한다. 모델 이름과 설명을 선택에 맞춰 표시하고 URL에 `module`을 저장한다. 기본과 잘못된 ID는 기존 E다.
- `중거리에서 보기`는 깊이160(진행72%)에서 정지한다. 작은 모델과 전체 하단 형태를 같은 시점에서 비교할 때 사용한다.
- 기본은 기존 선호값 **광원 크기10%·속도1000%·직선·잔상120ms**. `격납고 표시`를 꺼서 동일 시간의 광원과 비교한다.
- `먼 곳부터 재생`은 깊이1600에서 다시 접근한다. `근거리에서 보기`는 깊이44(진행77.8%)에서 정지한다. 낮음·중간·높음 및 고도 슬라이더를 비교한다. 진행 슬라이더는 정지 비교, 재생은 이어서 진행한다.
- `고도 연출`의 기본은 기존 최신 근접 시점(`clearance=1`). `A 상하 이동`은 그 이전의 `clearance=0`과 A 이동5배를 선택한다. 두 모드의 계산은 원본에서 가져온 그대로다.
- 직선·삼각형·혼합, 광원 크기0~100%, 속도0~1000%, 건물 크기50~180%, 윤곽선·보조색 비율·밀도·잔상0~300ms·단면 높이·A 이동 배율·길이 강조를 조절한다.
- 절단면 가이드·레인 참고선·건물 표면 그림·고도 반복을 개별 전환한다. 설정과 마지막 조절 당시의 진행은 URL로 복원한다. 레인은 실제 게임이 아닌 기존 시간 규칙의 모의 표시다.
- 16:9 화면 아래에 조절을 둔다. 움직임 줄이기에서는 정지 시작하고 명시적 재생 선택을 따른다. 숨긴 탭은 시간을 누적하지 않고 오래된 잔상을 비운다.

## 보존한 것과 바꾼 것

`legacy/`는 기존 `~/.gstack/projects/nanana3679-not4k/designs/apex-height-prototype-20260909/`의 광원 계산과 의존 파일8개를 수정 없이 복사했다. `source-manifest.json`에 경로·SHA-256을 기록했다. A~H 도안·공통 도안 도구·표면 렌더러·Three.js0.186.0·라이선스도 8종 시연의 그대로다. 기존 모델의 표면 그림은 다시 생성하거나 배경을 제거하지 않았다. 이후 먼 건축 배경 한 장을 별도 생성했다.

`worldFaces()`의 점·색·cycle ID·절단된 열린 윤곽선을 사용한다. Three 카메라는 원래 `project()`의 초점거리·주점·높이를 맞추며 old +Z를 Three −Z로 바꾼다. 320×180·844×475·1440×810, 고도0/50/100%, 두 시점의 표본 투영 오차가 0.000001px 미만이다.

건물 중심은 화면상에서 왼쪽 외곽 절단면의 A→가까운 배치점과 같은 직선을 따라 접근한다. 광원은 유한한 사각뿔 내부의 원래 세계 좌표를 유지하지만, 건물 중심은 이 유한한 삼각면에 한정하지 않는다. 건물의 원거리 출발을 위해 동일한 화면상 소실점으로 수렴하는 경로를 깊이1600까지 연장한다. 건물 자체는 고정 입체·UV·회전·배율을 유지한다. 공간 경로의 수렴과 건물 변형을 분리한다. 건물 전체를 절단면에 눌러 붙이거나 보이지 않는 사각뿔 경계로 자르지 않는다. 고도·진행·화면 밖으로 나가는 상황에서도 건물을 재생성하거나 축소하지 않는다.

원본 `advanceMotion()`을 사용하여1000%는 전진량280/초다. 광원의 `centerAt()`이 전진에 .956을 적용하므로 건물 위치에도 같은 .956을 사용한다. 광원의 기본 깊이200은 유지한다. 건물은 깊이1600에서−400까지 간격2000으로 반복하여1000%의 한 주기는 약7.47초다. 기본 시작은 진행25%·깊이1100이다. 안개는650~1400에서만 적용해 작게 보이는 원거리 구간을 남긴다. 선택한 모델 하나만 표시하며 몸 전체가 카메라 뒤로 지난 후 빈 구간을 거쳐 재배치한다. 모델8종은 한 번 만들어 두고 선택할 때 다시 사용한다. 건물 속도를 별도 계수로 늦추지 않는다. 가까운 배치점의 중심 높이는 근접 시점에서 `바닥 기준+모델 높이/2`, 이전 A 이동 시점에서는 `단면 중심−29.205+모델 높이/2`다. 따라서100%에서 각 모델의 하단 기준이 같고, E의 기존 위치는 유지한다. 건물 크기 조절은 별도 균등 배율이다.

불투명 E와 광원·발광·잔상은 동일 Scene·카메라·깊이 버퍼를 사용한다. 빛은 깊이를 검사하지만 자기 깊이를 쓰지 않는다. 건물 윤곽선도 깊이를 쓰지 않는다. 잔상은 지난 세계 정점을120ms 기록하고 원본의 감쇠 함수·최대12보간·cycle 불일치 보호를 따른다. 카메라 변경에도 세계 위치를 재투영하며 수동 고도/형태/크기/진행 변경 시 기존 잔상을 비운다. 정지는 시간과 잔상 밝기를 함께 멈춘다.

**렌더 방식의 차이:** 원래 Canvas2D의 화면 잔상과 축소 버퍼의 blur4px를 그대로 겹치지 않는다. GPU에서 깊이가 있는 면 잔상을 그리고 3px·8px의 약한 가장자리 발광을 사용한다. 따라서 광원 도안·색 선택·흐름은 보존하지만 발광 픽셀이 원래 Canvas와 완전히 같다는 의미는 아니다. 이 차이도 사용자가 검수한다.

이 비교에는 선택한 건축 모델과 절단면 광원을 둔다. 원래 장갑 장애물·바닥/천장 그림은 포함하지 않는다. E의 열린 주변 공간은 아래 추가 비교에 별도 구현했다. 원래 시연에서 비교할 수 있으며 RFD0025의 기본 화면을 교체하지 않았다. 8종의 동시 혼합 배치, 충돌, 판정, 플레이 규칙, 본편 연결은 구현 범위 밖이다.

## 검증과 성능 범위

**첫 통합 검증: 단위48개·브라우저63개 통과, 페이지·콘솔·CSP 오류0개.** 두 시점×고도3단계의 실제 E 앞뒤 가림 픽셀, 1000% 통과와 반복, 정지 잔상 픽셀, URL 복원, 320·390·844·1440px 화면을 검사했다.

단위 검사는 기존 투영·도안 보존, 속도/노트 시간 분리, 외곽면과 일치하는 화면상 이동 경로, 고정 입체와 전면 통과, 세계 잔상과 cycle·열린 경계·정지, URL 및 버퍼 재사용을 검사한다. 브라우저 결과는 `browser-check.json`, 실제 화면은 같은 폴더의 PNG에 둔다.

브라우저의 가림 검사는 실제 E 입체를 동일 카메라로 렌더링하고 보이는 면의 앞/뒤에 같은 광원 렌더러를 배치해 픽셀을 읽는다. 뒤의 본체·잔상은 건물색 그대로, 앞은 밝아져야 한다. 단순히 `depthTest=true`만 확인하는 검사가 아니다.

A~H 각 한 개와 공통 텍스처5장은 한 번 만들고 재사용하며 선택 모델만 표시한다. 광원 본체·발광·잔상은 각각 하나의 동적 버퍼로 묶는다. 버퍼는 용량이 부족할 때만 늘어나지만 CPU의 면·잔상 표본은 아직 프레임마다 객체를 만든다. 건물 내부 메시 병합·여러 건물 인스턴싱·종류별 풀링을 완료한 것이 아니다. 헤드리스 소프트웨어 GPU 검사는 실제 휴대폰 FPS·프레임 예산·미술 승인으로 해석하지 않는다.

## 원거리 접근 수정 (2026-09-10)

사용자가 “멀리서부터 오는 게 아니라 갑자기 생기는 것처럼 보인다”고 지적했다. 첫 구현은 건물 출발 깊이가200뿐이고 안개가90~215여서 작은 건물이 읽히는 구간이 없었다. 기본 진행20%에서는 건물의 투영 경계 높이가 화면의 약95%였다. 안개만 바꾸거나 출발 거리만 바꾸어도 충분한 원거리 구간을 확보하지 못함을 재현했다.

`arrival.test.ts`의 두 회귀를 수정 전에 실행하여 실패를 확인했다. 수정은 실제 원근의 거리·안개·초기 진행에 적용하며 건물 배율을 거리별로 변경하지 않는다. 유한 A를 넘어서 같은 AD 평면을 그대로 연장하면 반대편으로 넘어가므로, 건물은 같은 **화면상** A→가까운 배치점 경로로 연장한다. `x=d`, `y=nearY+(apexHeight-cameraHeight)×z/(depth+8)`이며 이 점들의 투영은 기존 외곽면의 경로와 일치한다. 고도·깊이 변경 시에도 이를 검사한다. 건물은 이미지 교체 없이 고정 입체 한 개를 사용한다.

최대180% 건물의 모든 면이 출발점에서 안개 끝보다 멀고, 회수점에서는 전부 카메라 뒤에 있으므로 재사용 순간에 보이는 건물을 켜거나 끄지 않는다. 화면상 높이·대비로 원거리 접근 시간을 검사하고, `arrival-browser-check.mjs`는 실제 렌더 픽셀에서 출발·원거리1100·900·600·300·근거리·반복 순간을 비교한다. 기본 시점에서는 처음부터 작은 실루엣이 읽히지만, 이전 A 이동 모드의 극단 고도처럼 소실점 자체가 화면 밖인 조합에서는 원거리 건물도 화면 밖일 수 있다.

수정 후 **단위52개·기존 브라우저63개·원거리 회귀10개 통과**, 페이지·콘솔·CSP 오류0개. 기본1000%에서 화면 높이12% 이하·안개 대비15% 이상의 구간은 계산상2.47초다. 실제 캡처에서도 깊이1100의 작은 건물32px가900→600→300에서47→69→142px로 증가했다(프레임 높이651px). 반복 끝→출발에서 변한 건물 픽셀은0개다. 이 수치는 검증 조건의 관찰이며 사용자의 체감이나 실물 기기 성능을 대신하지 않는다.

## 8종 선택 추가 (2026-09-10)

사용자는 저고도의 E가 너무 높아 다리가 중간에 끊긴 것처럼 보인다고 지적하고, 다른 모델도 먼저 보고 싶다고 요청했다. 원래 형태를 바꾸지 않고 같은 돌파 공간에서8종을 교체하는 비교를 구현했다. 8종 선택 단계에서는 지지부·본체 길이를 연장하지 않았다. 이후 E에만 아래 공간 연결 비교를 추가했다. 모양을 화면에 맞춰 자동 확대/축소하거나 모델에 따라 카메라 고도를 다시 맞추지 않는다.
