# PROTOTYPE — 건축 모듈 8종 공통 검수

> 이전 미술 탐색의 설명 기록이다. 당시 이미지·실행 코드·검사 결과는 로컬 원본과 백업에 보관한다. [현재 실행 대상과 보관 범위](../../README.md).

2026-09-10. **서로 다른 건축 실루엣 A—H를 같은 ‘고정 입체 + 2D 표면 그림’ 방식으로 구현했을 때, 고도와 거리 변화가 계속 자연스럽게 이어지는가?**를 확인한다.

사용자는 남은 모듈 구현을 서브에이전트에 위임하고, 주 에이전트가 최적화 계획·기존 오브젝트 연출과의 통합·새 천장/바닥 배경을 구상하도록 요청했다. 이어 직접 시각 검수를 할 수 있는지 물어 공통 링크를 제공했다. **형태·분위기·고도 감각의 사용자 평가는 진행 중이다.** 기술 검수 통과를 디자인 승인으로 기록하지 않는다.

여섯 신규 모듈의 참조 확인·형상 단위 검사·기술 캡처는 `modules/bc-NOTES.md`, `modules/df-NOTES.md`, `modules/gh-NOTES.md`에 둔다. 모듈별 담당 파일과 테스트만 각 에이전트가 수정했고, 공통 렌더러·뷰어·공유 서버·계획은 주 에이전트가 구성했다.

각 모듈은 `createBlueprint()`와 `metadata`를 내보낸다. `blueprint-kit.mjs`의 고정 다면체·보·상자·표면 패널을 사용하며 H의 수평 분기는 동일한 면 데이터를 회전한 정점으로 구성한다. 문 1.6×2.8과 난간 높이 약 1을 유지해 큰 건물의 척도를 드러낸다. 기존 외벽·밑면·장갑판·창문·문 다섯 텍스처를 공유한다. 신규 모듈을 위해 그림을 다시 생성하지 않았다.

## 공통 시연

```sh
cd output/prototypes/module-fleet-20260910
npm start
```

Tailscale과 호스트 실행이 필요하다. 서버는 24시간 유효한 개별 비공개 URL을 출력하며 `preview-state.json`에 현재 주소·만료를 둔다. 이 시연 서버만 종료한 뒤 `node preview-server.mjs --reuse-link`로 실행하면 만료되지 않은 링크를 유지한다. 시작 때 파일을 메모리에 읽으므로 런타임 변경 뒤에는 이 서버를 재시작한다. 명시한 HTML/CSS/실행 모듈·Three.js/라이선스·표면 5장·참고 8장·배경 구상 2장·계획/프롬프트만 제공하며 테스트·다른 파일·접속 상태는 공개하지 않는다.

기본은 B 둘러보기·고도 65%·정지다. A—H 전환은 고도·관찰 각도·진행률·크기를 유지한다. 선택한 건물 하나만 보이며 재선택 시 이미 만든 동일 객체를 사용한다. 모든 모듈의 실제 원래 크기를 보존하며 둘러보기 카메라는 건물 전체 경계에 맞춰 관찰 거리를 조절한다. 따라서 둘러보기 화면 크기만으로 A와 E의 실제 척도를 비교하지 않는다.

- **둘러보기:** 고도·각도 −70~70°를 연속 조절한다. 실제 빈 공간·밑면·지붕·그림 끄기를 확인한다.
- **비행하기:** 카메라는 수평 전방으로 고정된다. 고도만 높이를 바꾸며 건물 자체의 정점·UV·텍스처는 유지한다. 비대칭 투영의 전방점은 가로 60%다. 근거리에서 화면을 크게 채우는 부분은 자연스러운 클리핑이며 배율을 줄이지 않는다.
- **속도:** 0~1000%, A/E 단독 시연과 같은 세계 속도인 100% 약 6.04 길이/초. 이동 구간은 각 모듈 최대 치수의 7배, 최소 145이므로 큰 건물이 더 오래 걸린다. 기존 사각뿔 광원 시연의 1000%와 세계 속도가 같다는 의미는 아니다.
- **크기·옆면 거리:** 50~180%와 2~18을 독립 조절한다. 실제 경계 상자의 가장 가까운 가로 끝으로 이격을 계산한다. 같은 고도에서도 건물을 크게 키우면 최고 시점이 지붕을 넘지 못할 수 있다.
- **비교:** 원거리·중거리·근거리·통과 버튼은 정지 비교, 재생으로 이어간다. 12초 고도 반복, 표면 그림, 중앙 4레인 참고선, 모든 설정의 URL 복원을 제공한다. 참고 시안 8개와 표면 원본 5개를 직접 연다.
- **읽기:** 16:9 화면 아래에 조절을 두고 320px부터 가로 넘침 없이 제공한다. ‘최적화·기존 연출 연결·새 위아래 배경 구상’ 링크는 별도 `plan.html`이다.

Three.js 0.186.0과 라이선스는 이전 E 시연에서 복사했다. 기존 A/E와 이전 오브젝트 비행 시연·본 게임은 그대로다. 한 건물을 확인하는 현재 재사용은 종류별 다수 오브젝트 풀·인스턴싱·LOD를 구현했다는 의미가 아니다.

## 계획과 배경 구상

[전체 설계 제안](../../../docs/design/module-integration-plan-20260910.md)에 풀링·그리기 호출·측정 순서, 기존 사각뿔 광원의 투영/경로와 일반 3D 건물의 차이, 가림·잔상·속도 단위의 연결을 구체화했다. 다음 구현의 첫 단계는 E 한 개와 기존 직선 광원의 공통 투영·가림 검증이다. 기존 시연의 기본 채택안을 바꾸기 전 RFD 갱신이 필요한 범위도 명시했다.

[상하 배경 구상 두 장](../../imagegen/open-depth-backgrounds-20260910/README.md)은 내장 imagegen의 스타일 참고 모드로 생성하고 원본·프롬프트를 저장했다. 위쪽은 매달린 거대 시설과 공극, 아래쪽은 여러 높이의 지붕과 낙차다. 시안에는 중근경도 포함되며 최종 배경 레이어로 바로 적용한 결과가 아니다. 새 배경·기존 연출 통합·최적화는 이번에는 계획까지만 진행했다.

## 검증

```sh
npm test
npm run check:browser
```

단위 **66개** 통과: 신규 여섯 모듈 52개, 공통 비교와 URL·고도·거리·속도 14개. 담당 에이전트들은 고도·각도가 다른 실제 캡처에서 면 뒤집힘·뜬 패널·접합 파손을 검사했고 발견된 기술 문제는 없다. 주 에이전트는 전환 시 이전 모듈명이 100ms 남는 HUD 갱신을 즉시 반영하도록 수정했다.

공통 브라우저 **146개** 통과, 페이지·콘솔·CSP 오류 0개. 8종 선택·재사용·저고도/고고도 픽셀·고도 중간값·실제 배율·그림/레인 토글, 1000% 전진·반복, 정지·자동 고도·URL 복원, 320·390·844·1440px의 16:9·하단 조절·44px 버튼·가로 넘침, 실행 코드/PNG 바이트, 비공개 경로와 구상 페이지를 확인했다. 참고 원본 8개도 HTTP 200과 바이트 일치를 별도로 확인했다.

결과는 `browser-check.json`, 실제 캡처는 `orbit-A.png`~`orbit-H.png`, `flight-*-low/high.png`, `viewport-*.png`, `plan-*.png`에 둔다. 한 번에 한 모듈을 표시하는 헤드리스 Chromium/소프트웨어 WebGL 검사이며, 목표 PC의 다수 건물 FPS 검증이 아니다. 부품 수와 실제 그리기 호출 수를 별도로 기록한다.
